# flint-terrain: the terrain package's crate (moved out of the root CLAUDE.md by #755)

- **A standard package since #1623** (`packages/terrain/package.toml`, ADR 0138 decision 5): this folder is four levels below the repo root (`../../../..`); its schemas (`terrain` component and archetype) are `packages/terrain/schemas/`, its book page `packages/terrain/docs/concepts/terrain.md`. `terrain = false` builds a player and a `flint` with no flint-terrain in `cargo tree` (procgen's `terrain_v1` is procgen's `[with.terrain]` part, `flint-procgen/terrain`), and a scene's `terrain` is `unlisted-package`. The features: none (heights, spec, bake: what physics' tests and `terrain_v1` read), **`render`**, **`player`** (`player::PACKAGE`), **`cli`** (`cli::extensions()`), each listed by the launchers from the manifest's `[rust]`.
- **The renderer links no terrain crate** (#1615): a chunk's mesh (`TerrainChunk`), the grass settings (`GrassConfig`), and since #1623 the height grid (`heightmap::Heightmap`, `HeightGrid`), `ground::GroundField` and `ground::SceneGround` are flint-geometry's plain data, re-exported here. What needs an image codec or a terrain's config stays here as `HeightmapFiles` (`from_png`, `save_png`, `sample_world`: bring the trait into scope). **`render`** adds `scene::bind_terrain(renderer, device, queue, world, &mut bound) -> Option<LoadedTerrain>`: a scene's first `terrain` built into the renderer (chunks, material, the style mask's entity, its grass unless `bound.grass` already holds a `grass_ground`'s), which `SceneRenderer::bind_scene` did itself until #1615; `LoadedTerrain::ground()` is the kernel's `SceneGround` (grid, origin, heightmap, size, height scale, chunk count).
- **The scene binder** (`player::bind`, `Registry::scene_binder`, `flint_package::bind`): not an asset maker, since a maker runs only where a host makes assets and is lent no `BoundScene`. Every host runs the registered binders right after `bind_scene`, naming no package: the player (`stage_scene_in_renderer`: `registry().bind_scene(core.packages, ..)`, then `register_terrain_collider` from the ground (physics is the kernel's until #1617) and the ground into `core.resources`), `flint render` (`bind_capture_scene`, the scene's `[packages]` passed in), and the viewer (`stage_scene`, through `flint_package::cli::points()`'s `SceneBinders`, which flint-cli's `points_of` fills from the player's registry). A left-out package's binder builds nothing. **The subsystem** (every scene) hands the `terrain` module the ground in the run's resources as module state (`TerrainHeight`); `terrain_height` is the drawn surface wherever the terrain's transform puts it (#1691: world (x, z) less `SceneGround::origin`, sampled as `sample_world`, the origin's y added; off the map, the nearest edge's height; until #1691 it read world (x, z) from the map's corner), 0.0 with no terrain and in a capture. **The editor** (`cli/editor.rs`, was flint-cli's `commands/terrain_edit.rs`) opens through `flint_viewer::host::TerrainEditors`; the kernel keeps `flint terrain-edit`'s args and asks the point (`commands/terrain_edit.rs`), naming the package without it. Tests: flint-render's `tests/frame_inputs.rs::a_bound_scene_draws_its_terrain_masked_and_the_next_forgets_it`, `tests/stylize.rs`, the viewer's `app_binding_tests.rs` (handed this crate's binder), `player::module::tests`
- **One bake, one encoding** (#719, `bake.rs`): `bake(spec, seed) -> TerrainMaps` is the only spec-to-maps path (the editor's regenerate and flint-procgen's `terrain_v1`, which `flint gen x.terrain.toml` runs since #1168; `height_samples` is the one quantization, which `encode_heightmap_png` and `terrain_v1`'s L16 image share), and `encode_heightmap_png` / `encode_splat_png` the only encoders (`Heightmap::save_png`, the editor's Ctrl+E, the CLI), so the editor's export and the CLI write the same bytes. image 0.25 takes 16-bit samples in **native** byte order: the old `to_be_bytes` export wrote byte-swapped heightmaps that read back as static (`the_heightmap_png_reads_back_as_the_heights`)
- **Unknown keys** (`TerrainSpec::parse_checked` / `from_file_checked` -> `Vec<SpecIssue>`): the raw TOML is walked against the parsed spec re-serialized with its defaults, so a key no field reads is named by path with `diagnostic::did_you_mean`; a new field needs nothing more, but a field with `skip_serializing` would be reported as unknown. A splat rule's `layer > 3` is reported too (the generator skips it). `the_fixtures_have_nothing_unread` holds the fixtures' `*.terrain.toml` clean
- **A terrain made from its recipe** (#1697, `source.rs`): `terrain.spec` names a `.terrain.toml`. `make_terrain(view, project, scene_dir) -> MadeTerrain` (no GPU: config, grass, heightmap, `SplatMap`, the `Recipe`) is the one path, `scene::build_terrain` uploads it, and the binder, the player's rebake and `flint check` share it. Settings layer as `TerrainConfig::from_spec` (spec's `[geometry]`, `[textures]` paths rewritten from the spec's folder to a `./..` name from the scene's, `[grass]`) then `TerrainConfig::over(view, base)` / `GrassConfig::over(view, &base)`: a key written wins. **That needs the schema to write no defaults** (the loader writes them into every listed component): `packages/terrain/schemas` has none, each description ends with the number, and `the_described_defaults_are_the_readers` holds them to `TerrainConfig::default()` / `GrassConfig::default()`. **The cache** (`baked`): keyed by `BakeKey` (geometry, height layers, splat rules, seed, `BAKE_REVISION`: bump it when the bake's output changes), the last 4 in memory, 16 on disk as `<hash>.terrain-maps` in procgen's cache folder (`cache_dir`, its rule; procgen's trim reads only its own extension). **Pixels**: `TerrainMaps::png_heights` quantizes as the PNG does, and the splat goes up through `flint_render::TerrainSplat::Pixels` as the same sRGB texture the file makes, so `crates/flint-cli/tests/terrain_spec_cli.rs` holds a spec scene and a baked-PNG scene byte for byte. `SceneRenderer::load_terrain` removes the splat and layer textures before loading (a rebake, or the next scene's terrain, takes its own). **Hot reload** (`player/watch.rs`): `SpecWatch` (player only, not a capture, not `--no-hot-reload`) asks `file_watch::stamp` every 15 frames at `Stage::PreScripts`, bakes on a spawned thread, then rebuilds and puts `SceneGround`, `TerrainHeight` and the kernel's `Surfaces` back, which physics' `refresh_surfaces` takes at `Stage::Scripts` the same frame. **Check** (`cli/check.rs`, on the kernel's `SceneChecks` point): `overrides-spec` per disagreeing `SPEC_KEYS` / `[grass]` key (texture paths compared by the file each resolves to), `bad-terrain-spec` for a spec that won't parse (error) or its unread keys (warning). Tests: `source::tests`, `tests::a_component_key_wins_*`, the CLI file above
- `procgen.rs` builds each octave's noise once per layer (`OctaveNoise`): `Perlin::new` per texel was 43 s of a 512² debug bake (now 1 s), with the same bits. Hydraulic erosion returns under 3x3 (a raindrop needs an inside)
