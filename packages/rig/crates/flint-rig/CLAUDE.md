# flint-rig: the rig package (#1621)

The `rig` package's crate (`packages/rig/`, ADR 0139): skeletons, node clips, layers composed joint by joint, two-bone IK and bone probes, played as clip kinds on the animation package's clock, and the model previewer. The clock, the `animator` rules and the kind seam: `packages/animation/crates/flint-animation/CLAUDE.md`. The skinned pipeline gotcha: `crates/flint-render/CLAUDE.md`. The previewer's flags: `crates/flint-cli/CLAUDE.md`.

- **Two kinds, no subsystem** -- `kind.rs`: `SkeletalKind` (the moved `SkeletalSync`, the skinned entities whose bones go up, and an `IkPass`) and `NodeKind` (`NodeSync`), at `SLOT_SKELETAL` and `SLOT_NODE`, so a game with every package on steps as before the split (the goldens and #1621's skeletal/IK stills are byte-identical). The skeletal kind's `pose` is `publish_bone_probes` then IK, at the player's `Stage::Pose` after its `skins` go to the GPU (scope names `animation::skeletal`, `animation::node`, `animation::ik`, `publish_bone_probes` kept for the profiler's coverage test). `Rig` is the rig's calls on an `AnimationSystem` spelled as the system had them (`add_skeletal_clip`, `bone_matrices`, `skeletal_layers`...), found through `kind_of`; a registering call adds the kind it needs. `player.rs` puts both on animation's `ClipKinds` point (`make` from `KindCtx::models`; the skeletal entry's `late` takes a spawned model's skeleton, #1107), fills `flint_package::StillPose` (a still with no `--anim-time` solves IK once) and names `skeleton` / `ik_two_bone` / `bone_probe` when a project leaves the package out. `tests/pose_in_the_system.rs` holds the slots and the pose
- **The model previewer is this crate's `cli` part** (`cli/preview.rs`, moved from flint-cli): `cli::extensions()` adds no command and fills the viewer's `ModelEditors` point (`flint edit <model>.glb`, the hidden `preview`, whose flags stay flint-cli's `PreviewArgs` and arrive as a plain `flint_viewer::host::ModelEdit`) and the `ModelStill` point (the ai package's refine draws a candidate with it). Without the package both commands name `rig` (`absent::tests::without_rig_the_model_previewer_names_it`). It is tool code reading the disk, so the module allows `disallowed_methods`
- **Nodes above a joint are part of its pose** (#294) -- `ImportedJoint::parent_offset` is the matrix of the non-joint glTF nodes between a joint and its parent joint (or the scene root), `Skeleton::parent_offsets` applies it before the local pose, so `global_matrices` are model space and bind-pose bone matrices are identity. Mixamo's `Armature` (scale 0.01, +90 X) rides there; skipping it made every animated YBot 100x and lying down, which scenes had hidden with `[90, yaw, 0]` / `0.015`. Test: `mixamo_armature_node_is_part_of_the_pose`
- **A glTF clip starts at its first key** (#872) -- `SkeletalClip::from_imported` and `NodeClip::from_imported` pass their tracks through `skeletal_clip::slide_to_first_key`, which moves every key back by the clip's earliest one and makes `duration` last key minus first. Blender writes frame N at N/fps, so the frozen YBot's idle began at 1/30 s and the sampler's clamp held the first pose for frames 0 and 1 of a 48 fps capture (and on each loop seam) while physics moved. `flint_import`'s `ImportedSkeletalClip` keeps the file's times; only the playable clip slides. Tests: `skeletal_clip::tests`, `render_anim_cli.rs::the_first_step_of_a_span_moves`
- **Two-bone IK** (ADR 0070) -- `ik_two_bone` component on the second bone of a transform chain names `target`, `pole` and `tip` entities; `IkPass` (flint-rig) solves after scripts/physics/animation each frame and before the renderer reads world matrices, writing only the two bones' `rotation_quat` from their captured rest. Lengths come from the model's rest offsets. `flint render` runs it once, through the `StillPose` point
