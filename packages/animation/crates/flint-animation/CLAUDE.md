# flint-animation: the animation package's core (moved out of the root CLAUDE.md by #755)

Skeletons, node clips, layers' composition, IK and the model previewer are the `rig` package's since #1621: `packages/rig/crates/flint-rig/CLAUDE.md`. Sequences and the previewer's flags: `crates/flint-cli/CLAUDE.md`.

- **The animation package** (ADR 0139, #1620) -- this crate is `packages/animation`'s (standard; `animation = false` drops it and `flipbook`). Its `player` feature (`player/`) is the package: `player::PACKAGE` registers the `Animation` scene subsystem (every scene gets one; built from `SceneCtx::models`, the scene's `ModelLoadResult`, plus `.anim.toml`, each `ClipKinds` kind and `.sequence.toml`), the `animation` policy (`POLICY`, out of `flint_runtime::BUILTIN_SYSTEMS`), the `animation` and `tween` modules and the `ClipKinds` point. Its stages: `Stage::Tweens` (the field tweens, `tween.rs`'s `FieldTweens`, moved from flint-script; `tween()` queues a `TweenField` module command the subsystem takes), `Stage::Animate` (`update`, then `on_animation_end` / `on_sequence_cue` through flint-script's plain-data `call_animation_ends` / `call_sequence_cues`) and `Stage::Pose` (each kind's `skins` to the renderer, then each kind's `pose`: the rig's bone probes and IK); `late_models` hands a spawned model to each kind's `late` hook. A capture runs neither: `flint render --anim-time` asks the `flint_package::CapturePoses` point this package fills for a `player::HeadlessAnimation`, a `CapturePose` (step, settle, upload, `report`) the capture's game steps in `bones_posed`; no CLI module names this crate (#1621). `player.rs` became `property.rs` (the name is the player part's)
- **Clip kinds** (`kind.rs`) -- `ClipKind` is what another package plays on this clock: `AnimationSystem::add_kind` inserts by `slot()` (`SLOT_SKELETAL` 10, `SLOT_NODE` 20, `SLOT_FLIPBOOK` 30), so the frame is property, sequences, then the kinds in that order whatever order the packages registered; stepped by `seek_sequence` too (each kind `reset`, then stepped with the sequence); one-shot ends go to `drain_clip_ends`. A package registers a `player::KindEntry` (`package`, `name`, `make(&KindCtx, say)`, optional `late`) on the `ClipKinds` point; the scene's builder makes only the kinds of packages the project keeps (`ClipKinds::of`). `pose` (after every kind advanced) and `skins` (bones for the GPU) default to nothing; `as_any` lets a package reach its own kind (`kind_of::<K>()`). Each kind keeps its own `ClipPlaybackState`s and follows the one rule set; a kind that steps its own frames ends a one-shot with `ClipPlaybackState::finish_at` and turns a crossfade into a cut with `cut_to`. The flipbook kind (`packages/flipbook`) steps frames in `f32` ms as the old `sprite_sync` did, since an `f64` second lands a step apart at boundaries either way (`every_frame_lands_on_the_step_it_did_before`, 24-144 fps over a minute). `Animator::of` and `animator::write` read and write a retired `sprite_animator` for an entity with no `animator` (one release; its schema lists the fields under `retired`, which a field-less schema now still reports, `ComponentSchema::is_open`)

- **`animator.rs` is the one file that spells the `animator` component's keys** (#733) -- read with `Animator::of` / `animator::layers` (ADR 0115's typed view), write with `animator::write(&mut comps).clip(..).playing(..)` / `animator::edit_layer(comps, i, |layer| ..)`, never `set_field(comp::ANIMATOR, "<key>", ..)`; `tests/animator_keys.rs` scans every crate's non-test `src/` for a key beside `comp::ANIMATOR`. The property, node and skeletal syncs share one `ClipPlaybackState` (one clock, `advance_time`) and one rule set: `Animator::start` on first sight, `Animator::apply_to` after (a new clip cuts to its start, `playing` is live, a finished one-shot replays, `speed`/`loop` are dials; #732's rules), and `animator::publish` once a frame after advancing, which writes `clip`/`playing` back when the runtime moved them (`unpublished`: a one-shot ended, a crossfade settled, `autoplay` started), so `apply_to` never reads a stale value as a script's. A new animator field is a key there and a line in `read`; a new kind of clip calls the three. flint-rig's `clip_rules_tests.rs` runs one set of behaviour tests on property, node and skeletal clips; its `tests/node_clip_in_the_system.rs` holds node clips to them through `AnimationSystem` (`initialize`, then `update`), watching the child's transform (#1225)
