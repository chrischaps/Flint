# flint-animation: two-bone IK (moved out of the root CLAUDE.md by #755)

The skinned pipeline gotcha: `crates/flint-render/CLAUDE.md`. Sequences and the model previewer: `crates/flint-cli/CLAUDE.md`.

- **The animation package** (ADR 0139, #1620) -- this crate is `packages/animation`'s (standard; `animation = false` drops it and `flipbook`). Its `player` feature (`player/`) is the package: `player::PACKAGE` registers the `Animation` scene subsystem (every scene gets one; built from `SceneCtx::models`, the scene's `ModelLoadResult`, plus `.anim.toml`, each `ClipKinds` kind and `.sequence.toml`), the `animation` policy (`POLICY`, out of `flint_runtime::BUILTIN_SYSTEMS`), the `animation` and `tween` modules and the `ClipKinds` point. Its stages: `Stage::Tweens` (the field tweens, `tween.rs`'s `FieldTweens`, moved from flint-script; `tween()` queues a `TweenField` module command the subsystem takes), `Stage::Animate` (`update`, then `on_animation_end` / `on_sequence_cue` through flint-script's plain-data `call_animation_ends` / `call_sequence_cues`) and `Stage::Pose` (bone upload to the renderer, bone probes, IK); `late_models` takes a spawned model's skeleton. A capture runs neither: `flint render --anim-time` makes a `player::HeadlessAnimation`, a `flint_package::CapturePose` the capture's game steps in `bones_posed`. `player.rs` became `property.rs` (the name is the player part's). The model previewer and the render commands still name this crate (package-check's and the names check's one exception each) until #1621 moves skeletons, IK and the previewer to `rig`
- **Clip kinds** (`kind.rs`) -- `ClipKind` is what another package plays on this clock: `AnimationSystem::add_kind`, run after property, sequences, skeletal and node (the flipbook's slot), stepped by `seek_sequence` too; one-shot ends go to `drain_clip_ends`. Each kind keeps its own `ClipPlaybackState`s and follows the one rule set; a kind that steps its own frames ends a one-shot with `ClipPlaybackState::finish_at` and turns a crossfade into a cut with `cut_to`. The flipbook kind (`packages/flipbook`) steps frames in `f32` ms as the old `sprite_sync` did, since an `f64` second lands a step apart at boundaries either way (`every_frame_lands_on_the_step_it_did_before`, 24-144 fps over a minute). `Animator::of` and `animator::write` read and write a retired `sprite_animator` for an entity with no `animator` (one release; its schema lists the fields under `retired`, which a field-less schema now still reports, `ComponentSchema::is_open`)

- **`animator.rs` is the one file that spells the `animator` component's keys** (#733) -- read with `Animator::of` / `animator::layers` (ADR 0115's typed view), write with `animator::write(&mut comps).clip(..).playing(..)` / `animator::edit_layer(comps, i, |layer| ..)`, never `set_field(comp::ANIMATOR, "<key>", ..)`; `tests/animator_keys.rs` scans every crate's non-test `src/` for a key beside `comp::ANIMATOR`. The property, node and skeletal syncs share one `ClipPlaybackState` (one clock, `advance_time`) and one rule set: `Animator::start` on first sight, `Animator::apply_to` after (a new clip cuts to its start, `playing` is live, a finished one-shot replays, `speed`/`loop` are dials; #732's rules), and `animator::publish` once a frame after advancing, which writes `clip`/`playing` back when the runtime moved them (`unpublished`: a one-shot ended, a crossfade settled, `autoplay` started), so `apply_to` never reads a stale value as a script's. A new animator field is a key there and a line in `read`; a new kind of clip calls the three. `clip_rules_tests.rs` runs one set of behaviour tests on all three kinds; `tests/node_clip_in_the_system.rs` holds node clips to them through `AnimationSystem` (`initialize`, then `update`), watching the child's transform (#1225)
- **Nodes above a joint are part of its pose** (#294) -- `ImportedJoint::parent_offset` is the matrix of the non-joint glTF nodes between a joint and its parent joint (or the scene root), `Skeleton::parent_offsets` applies it before the local pose, so `global_matrices` are model space and bind-pose bone matrices are identity. Mixamo's `Armature` (scale 0.01, +90 X) rides there; skipping it made every animated YBot 100x and lying down, which scenes had hidden with `[90, yaw, 0]` / `0.015`. Test: `mixamo_armature_node_is_part_of_the_pose`
- **A glTF clip starts at its first key** (#872) -- `SkeletalClip::from_imported` and `NodeClip::from_imported` pass their tracks through `skeletal_clip::slide_to_first_key`, which moves every key back by the clip's earliest one and makes `duration` last key minus first. Blender writes frame N at N/fps, so the frozen YBot's idle began at 1/30 s and the sampler's clamp held the first pose for frames 0 and 1 of a 48 fps capture (and on each loop seam) while physics moved. `flint_import`'s `ImportedSkeletalClip` keeps the file's times; only the playable clip slides. Tests: `skeletal_clip::tests`, `render_anim_cli.rs::the_first_step_of_a_span_moves`
- **Two-bone IK** (ADR 0070) -- `ik_two_bone` component on the second bone of a transform chain names `target`, `pole` and `tip` entities; `IkPass` (flint-animation) solves after scripts/physics/animation each frame and before the renderer reads world matrices, writing only the two bones' `rotation_quat` from their captured rest. Lengths come from the model's rest offsets. `flint render` runs it once
