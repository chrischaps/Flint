### A trace's save costs the frame thread a copy, not a conversion: `profile::snapshot_records`, `Records::scopes`, `warm_copies` (#1267)
**What changed.** Saving a trace (`--trace-on-hitch`, the `save_trace` key, a capture's `trace.json`) used to turn every scope in the window into a named, timed copy on the frame thread: 3.6 ms for 90 000 scopes in release, a frame of its own. The frame thread now copies the records as they lie in the rings, about 0.35 ms for the same window (0.7 ms the first time, into fresh memory), and the trace's writer thread turns them into scopes. The file is the same. A key's or a capture's trace is now taken two frames after it is asked for, so the copy's memory can be readied on another thread meanwhile. In Rust, `flint_core::profile::snapshot_records(since_ns)` returns a `Records`, whose `scopes()` gives what `snapshot(since_ns)` does, on any thread, and `warm_copies()` readies the next copy's memory. `snapshot` still works, both halves on one thread.
**What to do.** Nothing. A host that saves its own traces on the frame thread can call `snapshot_records` there and `scopes()` on the thread that writes the file.
