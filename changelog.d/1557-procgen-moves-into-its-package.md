### The procgen package has its own folder, and a game's generators go in through `PlayerExtension::resources` (#1557)
**What changed.** `flint-procgen` moved to `packages/procgen/crates/flint-procgen`, and its commands (`flint gen` for a spec, the previewer, the texture graph editor, `flint check`'s spec passes) to a new crate beside it, `flint-procgen-cli`. The player and the CLI now reach procgen through the Package API's points, and name none of it. `flint gen`, `flint edit`, `gen-preview` and `tex-edit` stay where they were, with the same flags and output: every spec generates byte for byte as before. `PlayerExtension::register_generators(&mut GeneratorRegistry)` is gone. The new hook is `PlayerExtension::resources(&mut Resources)`. In a flint built with procgen but without living, `flint check` no longer judges `[living]` / `[wooze]`, since nothing in that build reads them.
**What to do.** A game binary that registers generators moves the body into `fn resources(&mut self, resources: &mut flint_package::Resources)`, inside `if let Some(generators) = flint_procgen::player::generators_mut(resources) { .. }`, and adds `flint-package` to its dependencies. A game that names `flint_player::GpuSink` or `HeadlessGame::resolve_procgen` uses `HeadlessGame::make_assets`. Otherwise nothing changes.
