### `material.color` colours a model entity too (#884)
**What changed.** `[entities.x.material] color = [r, g, b]` (or `[r, g, b, a]`) used to colour only an entity drawn from its bounds; on an entity with a `model` it did nothing, and `flint check` said nothing either. Now it replaces the model's base colour, the way `base_color_r/g/b` does, and the GLB's texture is still multiplied in. Expanded GLB child nodes take their model root's `color`. A model under a bounds-drawn parent does not take that parent's box colour. What wins, first to last: `material_overrides` for the named glTF material, `base_color_r/g/b` (what `set_material_color` writes, so a script still recolours a model the scene gave a `color`), `color`, the GLB's own. A scene that carried a `color` on a model and got the GLB's own colour will now render in that `color`.
**What to do.** Render any scene that has `color` on a model entity and check it looks the way you want. If you want the GLB's own colour back, remove the key.
