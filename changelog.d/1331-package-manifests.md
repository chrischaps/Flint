### `flint package list`: the engine's packages, each from its `packages/<name>/package.toml` (#1331)
**What changed.** The engine now says what its packages are without compiling anything. Seven manifests sit under `packages/`: `engine` (the kernel, holding for now physics, audio, animation, particles, terrain and the ocean, grass, stylize and panels features), the standard `procgen` and `debug-hud`, and the features `living`, `music`, `rhythm` and `ai` (ADR 0136). `flint package list [--json] [--dir d]` prints each one's tier, version, requirements, build features, and the crates, components, archetypes, scene tables, script modules and commands it owns. A game's `flint package list` reads its `engine/packages`. A manifest that doesn't read is a new `bad-package` diagnostic naming its file and key, and the command exits 1. In Rust, `flint_core::package` reads a manifest (`package::read`, `Packages::read(dir)`, `Packages::owner(kind, item)`). Nothing else changes yet: a game can't list packages in `flint.toml` until `[packages]` arrives (#1334).
**What to do.** Nothing. A game binary that adds its own top-level command named `package` now clashes with the engine's: rename it.
