### A frame capture writes behind the game, and a hitch while it writes says so (#1178)
**What changed.** The player's frame-capture writer (`--capture-frame-at`, `--capture-on-hitch`, Shift+F2) and its encoder threads now run at background priority: the scheduler's background mode on Windows (CPU, disk and memory priority), nice 10 on Linux, the background QoS class on macOS. Each frame while a capture is being written carries a new frame note, `capture write <folder>`. A hitch on such a frame names the write as its likely cause in the hitch log, the exit report, `--perf` and the F2 graph, unless a script took the time itself (`script stall.rhai:on_update 150.2 ms (also: capture write)`). `--capture-on-hitch` passes over a hitch while a capture is being written, because it may be that capture's own cost, and says so once. A capture taken while `--trace` records no longer fails with `holds more than a frame capture (trace.json)` when the trace's writer reaches the folder first.
**What to do.** Nothing.
