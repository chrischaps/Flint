### Script errors are counted once each, shown on screen, and `--strict-scripts` fails a run on them (#693)
**What changed.** A script that fails in a callback used to print the same warning every frame, with the scene's `source` and no entity. Now each failure (same file, callback, line and message) is logged once, `[script] scripts/hud.rhai:4:5: hud_controller, on_update: ...`, then counted, with a line at its 10th, 100th, 1000th time. A script that isn't found or doesn't compile counts too, and is loaded again when its file is saved. The player draws a card in the bottom-left corner naming each failing script (debug HUD builds). `flint-player --exit-after` and `flint render --scripts` end with `[script] N errors` and a line each, `flint render --report json` has a `script_errors` list, and `--strict-scripts` on `flint-player`, `flint play` and `flint render` exits 1 on any. A game binary reads them from `app.core.script.errors()`. Log lines that matched `on_update error (file.rhai)` now read as above.
**What to do.** Nothing. Add `--strict-scripts` to a headless check of your game so a script error fails it.
