### List your packages, then build with `flint build` (#1337)
**What changed.** The book has a Packages chapter (concepts/packages.md): what a package is, the seven the engine has, `[packages]` in `flint.toml`, `flint package list`, `flint package used` and `flint build`. Each concepts chapter now names its package on its first line, and the Script API Reference groups its modules by package. A project made by `flint init` explains packages in its `AGENTS.md` and `CLAUDE.md`, and builds with `flint build` instead of a bare `cargo build`. Nothing in the engine's behaviour changed: a game with no `[packages]` table still has every package.
**What to do.** To give a game only what it uses, run `flint package used --write` in the project. It adds a `[packages]` table to `flint.toml` that lists every package the scenes, prefabs and scripts reach. Check it with `flint check`, then run `flint build` (`--release` for optimized binaries) and use the `flint` and `flint-player` it prints from then on. In a game that carries the engine as a subtree, the first build is `cargo run --manifest-path engine/Cargo.toml -p flint-cli -- build --release`, run from the project root.
