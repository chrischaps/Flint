### A scene declares its own fields, `[field.<name>]`, and scripts sample them with `field_sample` (#1014)
**What changed.** A scene can declare a field of named numbers by place: `[field.weather] keys = { wind = { min = 0, default = 1 }, fog = { min = 0, max = 1, default = 0 } }`, with `[[field.weather.zone]]` entries written as `[[wooze.zone]]` ones are (`name`, `shape`, `center`, `radius` or `size`, `falloff`, and any of the keys). Scripts read a key by place with `field_sample("weather", "wind", get_world_position(me))` (or `x, y, z`), every key and the zones there with `field_at`, and change it with `field_set`, `field_set_zone` and `field_remove_zone`, each with an optional seconds to ease over; a write is read back at once. They are the `field` module, enabled in a scene with a `[field]` table, in the player, `flint playtest` and `flint render --scripts`. `flint check` and `flint validate` report a wrong key or zone as `bad-field`, by field and key or zone; the player warns and plays without it. The schema is `[table.field]` (`flint schema field`). The wooze field is unchanged.
**What to do.** Nothing. A game that scripted "windier here" from trigger volumes can declare a field instead.
