### `spline_is_gap` and `spline_gap_at` are gone: a spline's control points carry `attrs`, read with `spline_point_attr` and `spline_point_attr_span` (#855)
**What changed.** A `[[control_points]]` entry in a `.spline.toml` takes `attrs = { surface = "ice", speed = 0.6 }`: each value holds from that point to the next, and neighbours with equal values make one span (on a closed spline a span can run through the first point). `spline_point_attr(spline, name, t)` returns the value at `t`, `()` where it is unset; `spline_point_attr_span(spline, name, t)` returns `#{value, start_t, end_t}` or `()`. A point's `gap_after = true` reads as the attribute `gap_after`, `true` over each gap. The two gap functions are removed (a call to either is now an unknown function), and `spline_data`'s `gap_starts`, `gap_ends` and `gap_count` are replaced by `attrs.<name>.starts`, `.ends` and `.values`. `attrs` may not name `gap_after`. Gaps sweep and collide exactly as before.
**What to do.** A game with gap logic: `spline_is_gap(s, t)` becomes `spline_point_attr(s, "gap_after", t) == true`, and `spline_gap_at(s, t)` becomes `spline_point_attr_span(s, "gap_after", t)` (same `start_t` and `end_t`, `()` outside a gap). A script reading `gap_*` through `get_field` reads `attrs` instead.
