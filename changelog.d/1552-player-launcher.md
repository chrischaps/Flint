### The player is a launcher: `flint_player::packages::launch` and `flint build`'s launcher line (#1552)
**What changed.** The player no longer finds a scene's subsystems by a list `build.rs` wrote from its source folder. A launcher hands the kernel its packages once, at the top of `main` (`flint_player::packages::launch(&list)`), and each `flint_package::Package` registers its scene subsystems, game-state policy names, script modules and debug keys into the run's `flint_package::Registry`. The stock `flint-player`, `flint` and web player list every package the build has (`packages::stock()`), so every scene plays as before. Whether a binary has a package a project lists (`flint play`'s and `flint-player`'s "built without" refusal) is now read from that list, not from Cargo features. `flint build --dry-run` (and `--json`'s new `launcher` object) names the launcher and the packages it registers: `launcher  flint-player, its stock list from these features: engine, procgen`.
**What to do.** Nothing. A game binary that embeds `PlayerApp` gets the stock list without a call; one that wants its own list calls `flint_player::packages::launch(&[..])` before anything else, with `flint_player::packages::stock()` or the packages it picks, and may add a `Package` of its own.
