### `ocean` waves, `material_overrides`, `water_body` shapes and `camera_tuning` say when a value is the wrong type (#1068)
**What changed.** These components were the last ones read by hand, so a value of the wrong type took its default and nothing said so. They now read through the typed view, as the rest do: the default is still used, and a `bad-type` line names the entity, component and field once (`error[bad-type] entity 'sea' ocean.amplitude: expected a number, got string "high"`, `material_overrides.Glass.emissive`). The same goes for `joint.motor_target` read by `get_joint_target`, a `bone_probe`'s `joint` and the Ocean and Camera panels' starting values. `ocean.seed` and `ocean.num_waves` are integers: `12.0` still reads as 12, but `12.5`, which used to be cut to 12, is now the default and a report. Engine code gains `ComponentView::table(field)`, a table field as a view whose reports name it by key.
**What to do.** Nothing, unless the log now names a mistake in one of your scenes or scripts: fix the value it names.
