### A game binary's `Cargo.lock` from before wgpu 30 needs one `cargo update`; `flint check` warns `stale-cargo-lock` (#995)
**What changed.** Nothing in the engine. A game binary whose lock was written under wgpu 23 (any lock from before #945) fails on Windows inside wgpu-hal, with ten errors such as ``expected `ID3D12Device`, found a different `ID3D12Device` ``. When cargo moves that lock forward it gives gpu-allocator 0.28 a `windows` the lock already holds (0.58 or cpal's 0.54) while wgpu-hal 30 is on 0.62. `cargo update -p gpu-allocator` doesn't fix it. `flint check <game>` now warns `stale-cargo-lock` once cargo has moved the lock, with the command for that lock's versions.
**What to do.** In the game's workspace root, run `cargo update -p windows@0.54.0 -p windows@0.58.0` (every `windows` the lock holds except 0.62.2). It keeps the game's other locked versions. [Upgrading the Engine](https://docs.chaps.dev/guides/upgrading-the-engine.html#cargo) has the details.
