### A callback that ends in a value no longer fails: "Output type incorrect: i64 (expecting ())" (#1031)
**What changed.** A Rhai function's last expression is its value. Since `play_sound` and `play_sound_at` started returning a handle (#699), an `on_update` that ended in `if t <= 0.0 { play_sound_at(..) }` returned that handle, and the engine, which called every callback expecting `()`, counted the call as a failure and warned with `Output type incorrect: i64 (expecting ())` each time the sound played. The same was true of any callback ending in a getter, a `random()` or a bare variable. The rest of the callback had already run, so the sound played and nothing was lost but the warning. Now every callback's return value is dropped and the call counts as a success.
**What to do.** Nothing. A trailing `;` never silenced it (Rhai's block keeps its last call's value); a `()` added as a callback's last line to silence it can come out.
