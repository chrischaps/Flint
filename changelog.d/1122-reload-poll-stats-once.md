### The script hot-reload poll no longer touches the disk on the frame (#1122)
**What changed.** Every frame, the script hot-reload poll used to work out the search's `scripts/lib/` folders again, which stat'd the disk: 0.2-0.3 ms a frame, and 1-35 ms when the disk was busy. The folders are now worked out once, when a scene's script search is set. The whole poll is now about 0.02 ms (worst 0.08 ms in a traced showcase run, against 14 ms before). A trace shows its steps as `script::poll_take_finished`, `script::poll_failed_at_load`, `script::poll_scan_libs` and `script::poll_each_script`, under `script::poll_scripts`. For a host calling `ScriptSync::lib_dirs()`, it now returns `&[PathBuf]`, not a `Vec`.
**What to do.** Nothing. A `scripts/` folder that appears mid-run beside the scene is still picked up: the folders listed are the ones the search would read, whether they exist yet or not.
