### A texture pipeline op with a bad key is an error naming `ops[i].key`, and every op key has help (#720)
**What changed.** Each `[[params.ops]]` op of a `texture_v1` pipeline is now read through one descriptor that holds its defaults, ranges and help. A value that used to fall back to the default silently is now an error that stops generation: a wrong type (`target = 3`, `columns = "x"`), a choice that isn't one of the op's (`mode = "addd"`), or a number outside the op's range (`columns = 0`, `octaves = 17`). `color_ramp` with `stops = []` is an error now, where it panicked before. `edge_erode` takes `noise_type = "voronoi"`, which it always ran but its schema left out. `cell_color`'s schema default now reads `#735947`, the nearest hex to the colour it applies; it used to say `#735A47`. A valid spec renders byte for byte as before. Every op key has a help line in the node editor's tooltips and in the flint-procgen README's new op catalog.
**What to do.** Run `flint gen` on your pipeline specs. If one fails, fix the key the error names.
