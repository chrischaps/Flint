### A hitch's `cause` names its frame notes only when they explain it (#1124)
**What changed.** The cause in `--hitch-log`'s lines, the exit report's `[perf] hitches` line, `--perf`'s line and `?perf=1` used to name a hitch's frame notes whenever it had any. Now the notes are named as the cause only when their times add up to at least half of how far the frame ran over the median. That is the same rule a script callback is blamed by. Otherwise the line names the script, the phase or `elsewhere` first, and the notes follow it: `sync +9.1 ms (also: reload poll 1.2 ms)`. `physics steps` is never a cause now. Like `clock stall`, it is the long frame itself: the clock paying back game time. It is still listed in the log line's `notes`. The `causes:` tally in the report follows the same rule, so a run that tallied `physics steps` now tallies `render` or `elsewhere`.
**What to do.** Nothing, unless a tool of yours matches cause strings. If it does, expect the phase and the `(also: ..)` form.
