### A script's `print` goes to the log, and `--perf` times every callback (#703)
**What changed.** Rhai's `print(x)` and `debug(x)` no longer write to stdout: they log at info under the target `script`, with the script's `file` and `entity` (`debug` adds the `line`), so `flint render --scripts --report json` keeps stdout for the report. The script system's reload and load lines and the player's transition and quit lines moved from stdout to the same log. `flint` and `flint-player` now show `script=info` by default, which also makes `log()` visible without `RUST_LOG`. The perf readout (`--perf`, `?perf=1`) times every callback, named `file.rhai:callback` (`hud.rhai:on_draw_ui`), not only `on_update`; `[load, on_init]` is now `[load]`, and `[events]` / `[expression]` are gone (their callbacks are listed by name). `ScriptSystem::set_update_timing` / `update_times` are now `set_timing` / `take_times`, which empties them.
**What to do.** A game binary with its own `tracing_subscriber` adds `script=info` to its filter to see what scripts print. A host that read `update_times()` calls `take_times()` after each batch of script calls.
