### `flint validate` checks effect and sequence names, the asset catalog and lone colliders; `color` takes arrays only (#804)
**What changed.** `particle_effect.effect` and `animator.sequence` are `asset` fields now: a name no visible `particles/*.particles.toml` or `animations/*.sequence.toml` states as its `name` (an effect stating none goes by its file's stem) is a `missing-asset` error listing the folders read. A model or texture registered only in the project's `assets/*.asset.toml`, with its content in `.flint/assets`, passes where it was `missing-asset`, and `flint check` lets an `asset_def` name pass as `validate` does, so the two agree. A `collider` on an entity with no `rigidbody` (not a terrain or spline mesh) is a `needs-component` warning at validate and load, not only once the game runs. A `color` field written as a `{ r, g, b }` table or a `0xRRGGBB` integer is `bad-type`: no reader ever took either, so the colour was never drawn.
**What to do.** Run `flint validate` or `flint check`. Rewrite an old colour as the array the error gives (`[1.0, 0.533, 0.0]`), fix a misspelt effect or sequence name, and give a lone collider a `rigidbody` (`body_type = "static"` for scenery) or remove it.
