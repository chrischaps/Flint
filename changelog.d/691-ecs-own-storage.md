### Despawning an entity takes its children; `get_components_mut` returns a guard (#691)
**What changed.** `despawn_entity(id)` in a script, and `FlintWorld::despawn` / `despawn_by_name` in Rust, now remove the entity's whole subtree. Before, its children stayed as roots and jumped, since a child's transform is in its parent's frame. `despawn` returns the ids it removed, the entity's first. `FlintWorld::get_components_mut` returns a `ComponentsMut` guard instead of `&mut DynamicComponents`. Its `set`, `set_field`, `merge_component`, `merge`, `remove` and `set_archetype` keep the component index, it reads through `Deref`, and `get_mut(name)` changes one component's value in place. `world.get_component_mut(id, name)` does the same in one call. `rebuild_component_index` is gone: nothing can put the index out of step now. flint-ecs no longer depends on hecs or bimap.
**What to do.** A script that despawns a parent but wants a child kept calls `set_parent` on the child first. In Rust, bind the guard `mut` (`let mut comps = world.get_components_mut(id)?`). Write `comps.set_archetype(Some(..))` where you wrote `comps.archetype = Some(..)`, and pass a function that took `&mut DynamicComponents` the guard instead. Drop any `rebuild_component_index()` call.
