### `flint asset resolve` reads every `asset` field your schemas declare (#968)
**What changed.** `resolve` used to read four fields (`model.asset`, `material.texture`, `sprite.texture`, `audio_source.file`) and five old top-level keys (`mesh`, `texture`, `material`, `audio`, `script`), and it only asked the asset catalog. Now it reads every field your loaded schemas declare as `type = "asset"`. That includes your game's own fields, scripts, terrain maps, particle textures, spline files, prefab entities and `[environment] skybox`. A reference counts as found when the catalog holds it or the engine's file search finds it, the same lookup `flint check` uses. So a scene that plays no longer reports 0 found. `--json` gains a `references` list. `audio_source.file` is now `type = "asset", kind = "audio"`, so `flint check` checks it like other assets. `resolve` takes `--schemas`. In Rust, `flint_asset_gen::batch::resolve_scene` and `scan_scene_assets` are replaced by `resolve_missing`, which takes a `SceneNeeds` (the count and the missing list). `flint_scene::asset_references` builds that list.
**What to do.** Nothing for scenes. Move an entity's top-level `mesh = "..."` into its component (`model.asset`). Batch strategies now exit 1 when a missing reference is one no provider makes, such as a script.
