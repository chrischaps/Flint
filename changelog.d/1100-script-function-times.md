### Script profiling names the function inside a callback: `--perf`, traces, `take_function_times` (#1100)
**What changed.** While scripts are timed (`--perf`, F2, `--hitch-log`, `--trace-on-hitch`) or a trace is recording, each function a callback calls is timed as well. That covers engine functions by name (`raycast()`, all overloads together) and the script's own functions (`hud.rhai:draw_bar()`), each with its call count and total and worst time. In a trace they are scopes nested inside the callback's scope. `--perf`'s worst-scripts entries now end with the callback's slowest function: `stall.rhai:on_update 0.33/100.1 (hold() 100.0)`, or `(raycast() x400 3.1)`. A host reads the same numbers from `ScriptSystem::take_function_times()`. Closures, functions that read `this` and the functions of imported modules aren't timed on their own: their time is counted in their caller's. With timing off, scripts run as before. With it on, a call to the script's own function costs about 0.5 µs more in release, and a timed call gets twice Rhai's call-level limit, so a deep recursion fails at the same depth either way.
**What to do.** Nothing. A tool that parses the perf line's `worst scripts:` part should allow for the `(...)` that may now follow each entry.
