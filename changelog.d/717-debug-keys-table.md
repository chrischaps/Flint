### Debug keys: `[debug_keys]` in an input config, F1 and `--list-keys`, and a key the game binds is the game's (#717)
**What changed.** The player's debug keys are a table. An input config's `[debug_keys]` block moves an action (`stats = "F10"`, `living_pick_next = "Shift+F7"`), unbinds one (`= "none"`) or turns them all off (`enabled = false`). A key any of the game's actions binds now goes to the game only: binding F5 to a quicksave or backquote to a console no longer also fires the debug key. A debug key's press never reaches the game's input either (a game binary's `app.input.is_key_down(KeyCode::F2)` no longer sees it). F5-F9, backquote and backslash act only in a scene with living props or a charted music session; elsewhere they are ordinary keys, and backquote, backslash and F9 no longer put up a "no chart is playing" note. F1 shows the table over the game, and `flint play <scene> --list-keys [--json]` prints it. The start-up banner names F1 instead of four keys.
**What to do.** A shipped game that wants no debug keys adds `[debug_keys] enabled = false` to its `config/input.toml`. A game binary that read a debug key from `app.input` binds it to an action instead, which makes it the game's. Otherwise nothing.
