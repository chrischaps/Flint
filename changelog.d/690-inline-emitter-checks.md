### A bad inline `particle_emitter` is an error naming its key, never the default emitter (#690)
**What changed.** `flint validate` and `flint check` hold every inline `particle_emitter` to the emitter's own reader: a key it doesn't read (`emision_rate`) or a value it can't use (`color = "orange"`, a zero `lifetime`, `shape = "donut"`) is a new `bad-emitter` error naming entity and key, so the run exits 1 where it used to warn or pass. Keys the emitter reads but the schema doesn't list (`lifetime = [a, b]`, `size` and `color` curves, a `shape = { kind = .. }` table) are no longer flagged in those commands. While playing, such a table used to become the default emitter (white dots, 10 a second); now a bad value set at run time leaves the emitter as it was, a table bad at load makes no emitter until fixed, and the warning names entity and key. In Rust, `EmitterConfig::from_toml` returns `Result<_, EmitterProblem>`, and `EmitterDef::KNOWN_KEYS` is `EmitterDef::known_keys()`.
**What to do.** Run `flint check` on your project and fix any `bad-emitter` it lists. Rust callers of `from_toml` handle the `Result`; replace `KNOWN_KEYS` with `known_keys()`.
