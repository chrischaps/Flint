### `flint check` reads every look file and judges its user-style tables (#1272)
**What changed.** `flint check` (and `flint bundle`'s check) now reads every `*.look.toml` a project holds, named by a scene or not. One that doesn't read is a `bad-look` error on its file. A look's `[post_process.styles.<name>]` table for a style that isn't built in is now judged against the user styles of the folders that can take the look. A style none of them has (`[styles.hologramm]`, with `did you mean`) or a key that style doesn't take is a `bad-style-setting` warning naming the look file. Before, a typo there showed only as a load warning in a scene that took the look. Checking one scene (`flint check <scene>`, `flint validate`) judges the scene's look the same way.
**What to do.** Nothing. A look table for a game's own Rust style is warned about, since only the game's binary knows that style: allow it in `[project.diagnostics] allow` if it is one.
