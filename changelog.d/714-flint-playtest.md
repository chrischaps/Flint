### `flint playtest`, input-script `expect` / `wait`, and the script `test_*` functions (#714)
**What changed.** `flint playtest <scene> [--input-script f] [--exit-after T | --timeout T] [--strict] [--dump name] [--report out.json]` plays a scene with no window, GPU or sound device on a fixed clock. It writes one JSON report, the same bytes every run, and exits 1 on a failure: a failed `test_assert`, a `test_fail`, an input-script check that didn't hold, any script error, a failed transition or a timeout. Input scripts take `expect <entity> <condition>` and `wait <...> [within S]` lines (flint-query conditions, plus `entities where`, `persist`, `log` and `event`); `flint play --input-script` now exits 1 when one fails. Scripts get `test_assert(cond, msg)`, `test_fail(msg)`, `test_pass()` and `test_log(key, value)`, which `flint play` only logs. A query field may name a vector's axis (`transform.position.y`). `play_sound_at` no longer warns on every call when there's no sound device.
**What to do.** Nothing. To guard a level, write an input script that walks it with `wait` and `expect` lines and run `flint playtest` in your tests (book: Playtesting).
