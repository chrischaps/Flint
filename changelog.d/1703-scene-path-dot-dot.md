### A scene path with `..` keeps its project; `flint capture` names a take that lost it, and `--strict` fails it (#1703)
**Package.** engine
**What changed.** A scene named through a folder and back (`flint play ../x.scene.toml` from a subfolder, or `C:\game\shots\..\x.scene.toml`) used to lose its project when `flint.toml` sat above the `..`: the walk up to it stopped there, so no schemas were loaded and `load_data` / `load_ui` read under the wrong folder. The path is now cleaned first (`flint_core::project::clean_path`), everywhere a project is looked for and in `flint play`, `flint-player` and `flint playtest`. `flint capture` hands each take its scene and input script cleaned, so a shot list in a `shots/` folder naming `../x.scene.toml` films the scene with its schemas. A take whose player found no schemas or had a script error is now named in the run's summary and its `take.json` / JSON record (`warnings`, and `warned` for the run); `flint capture --strict` fails such a take.
**What to do.** Nothing. A shot list kept in a subfolder that worked around this with an absolute scene path can go back to `../x.scene.toml`. Add `--strict` to an unattended capture so a scene that lost its project fails the run.
