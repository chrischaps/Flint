### An `ocean` with only `tint` set draws its own sea, not a crimson one (#1041)
**What changed.** `tint_preset` has no default now: unwritten, it names no preset, so the `tint_*` fields fall back on the sea's own colours (`deep_color`, `shallow_color`, `sss_color`, `foam_color`), and everything else (`tint_sky`, `tint_ramp_steps`, `tint_band_wobble`, `tint_pools`, `tint_keep_light`, `tint_below`) falls back on changing nothing. A scene that set `tint` alone used to draw the `blood` preset's sea of blood, because #1035 made `blood` the unwritten preset; now it draws the sea it had. An unknown preset name reads as no preset, and is reported once. In flint-music, `SuiteManifest::reintegration` and `Conductor::previous_re_entry` are gone. The manifest keeps every top-level table it doesn't read in `SuiteManifest::tables`, and flint-rhythm reads its `[reintegration]` from there (`flint_rhythm::Reintegration::of`, `previous_re_entry`). `SuiteSession::schedule_seam` is renamed `schedule_jump`. Suite files are unchanged.
**What to do.** If a scene that set `tint` should still draw the crimson tide, name it: `tint_preset = "blood"`. Float's port (#1035) already names its preset everywhere it sets the tint. Rust that called `schedule_seam` calls `schedule_jump`.
