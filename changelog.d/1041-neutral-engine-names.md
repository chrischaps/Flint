### An `ocean` with only `tint` set draws its own sea, not a crimson one (#1041)
**What changed.** The `ocean` component's `tint_*` defaults were one game's palette, a crimson tide in pools, so a scene that set `tint` alone drew a sea of blood. A tint now names the colours it moves toward: `tint_deep_color`, `tint_shallow_color`, `tint_sss_color` and `tint_foam_color` left out are the sea's own (`deep_color`...), and the rest default to changing nothing (`tint_sky` white, `tint_ramp_steps` 0, `tint_band_wobble` 0, `tint_pools` 0, `tint_keep_light = false`). The deprecated render modes 2 and 5 keep their palettes (`flint_render::render_mode::blood_tint` / `underside_tint`). In flint-music, `SuiteManifest::reintegration` and `Conductor::previous_re_entry` are gone: the manifest keeps every top-level table it doesn't read in `SuiteManifest::tables`, and flint-rhythm reads its `[reintegration]` there (`flint_rhythm::Reintegration::of`, `previous_re_entry`); `SuiteSession::schedule_seam` is `schedule_jump`. Suite files are unchanged.
**What to do.** A scene that set `tint` and wanted the old red names it: `tint_deep_color = [0.10, 0.005, 0.01, 1.0]`, `tint_shallow_color = [0.45, 0.04, 0.05, 1.0]`, `tint_sss_color = [0.85, 0.05, 0.03, 1.0]`, `tint_foam_color = [0.95, 0.78, 0.76, 1.0]`, `tint_sky = [1.1, 0.3, 0.32, 1.0]`, `tint_ramp_steps = 2.0`, `tint_band_wobble = 0.15`, `tint_pools = 0.08`, `tint_keep_light = true`. Rust that called `schedule_seam` calls `schedule_jump`.
