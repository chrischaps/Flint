### UI documents: `scroll = true` on a `list`, and a `text_input` element (#1229)
**What changed.** A `list` with `scroll = true` clips its items to its box and scrolls: it keeps the focused item in view as the arrows or a pad move focus, a mouse wheel over it moves it a row a notch (focus follows onto a row in view), and a finger dragged along it scrolls it. An overflowing list draws a thumb (`scrollbar_color`, `scrollbar_width`). A new `type = "text_input"` takes typing while it has focus (`placeholder`, `max_length`; style `caret_color`, `placeholder_color`): characters, Backspace, Delete, Left, Right, Home, End, and Enter, which sends `on_ui(id, "activate")`; each edit sends `change`. New script functions `ui_get_text(id)` and `ui_editing()`. `ui_set_text` on a text input puts its caret after the text. Draw items made by UI documents now carry the clip of the scrolling lists they are in. A list without `scroll` lays out and draws as before.
**What to do.** Nothing. To scroll a long list, add `scroll = true` and give its class a `height` (not `height_auto`). A game that reads movement from letter keys can skip it while `ui_editing()` is true.
