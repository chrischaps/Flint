### `flint build` builds a game's own binary, and that binary refuses a package it lacks (#1532)
**What changed.** A crate at the project root that depends on `flint-player` (a game embedding `PlayerApp`) is now built by `flint build` too, in a run of its own: `cargo build -p <game> --no-default-features --features flint-player/<f>,...`, from the same `[packages]` plan as the stock player, plus the crate's own defaults. Its JSON adds `games` and `runs`. It refuses, naming the line, a dependency that takes the player's defaults or pins a left-out package. And the binary now holds the list to its build: `PlayerApp` won't start when `flint.toml` lists a package it lacks, and `run_failure()` names `flint build` (`PlayerApp::unbuilt_packages()` asks first).
**What to do.** Give the game crate's `flint-player` dependency `default-features = false` and no package in `features`, and build with `flint build`.
