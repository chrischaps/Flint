### A package is a folder and one command: `scripts/package-sync.py` (#1560)
**What changed.** The stock `flint-player` and `flint` take a new engine package from its folder. Create `packages/<name>/` (its `package.toml`, `crates/`, `schemas/`) and run `python3 scripts/package-sync.py`. The script writes the generated block in `crates/flint-player/Cargo.toml` and `crates/flint-cli/Cargo.toml`: a `packages` feature that lists every package, and for the new one its feature and an optional dependency on its crate. Delete the folder and run the script again to take the package out. flint-player's `default` is now `["packages", "audio", "gamepad", "frame-history"]`, the same set as before. `scripts/ci.sh` fails on a stale block, and on a `feature = "<package>"` gate or a package crate's path in the player's or CLI's source (`scripts/package-names-check.py`). CI adds a toy package by its folder alone, plays it and removes it again (`scripts/package-toy.py`).
**What to do.** Nothing, for a game that carries the engine as a subtree. A game whose own `Cargo.toml` turns flint-player's packages on one by one may name `packages` instead. Don't edit between the `# package-sync:` markers: rerun the script.
