### `cargo clippy` in the engine fails on a read past the vfs in every crate (#979)
**What changed.** The root `clippy.toml`'s rules (the vfs reads, `toml::Value::as_float`, the wgpu and egui seams) were warnings in most engine crates and errors only in the five that draw (#761). They are now `disallowed_methods = "deny"` in `[workspace.lints.clippy]`, and every engine crate takes it with `[lints] workspace = true`; the five drawing crates' own `[lints.clippy]` tables are gone. Native-only code (`cfg(not(target_arch = "wasm32"))`) is held too, which only the wasm check did before. `scripts/ci.sh` refuses a member without `[lints] workspace = true` or with a `[lints.*]` table of its own. Nothing in the engine called a listed method, so nothing was annotated.
**What to do.** Nothing for a game's own build or clippy: engine crates lint as members of the engine's workspace, not the game's. A game that patches engine code in `engine/` and runs `cargo clippy` there must route a new read through `flint_core::vfs`, or mark a deliberate one with `#[allow(clippy::disallowed_methods)] // <reason>`.
