### `tune_living`, `set_wooze`, `compare_living` and `conducted_*` are modules a feature owns: a call where it isn't running is an error (#698)
**What changed.** The `living`, `wooze`, `debug` (`commit_living` and the A/B) and `conducted` script modules are declared by the player's living props and music, and enabled in a scene where that feature runs: `living`, `wooze` and `debug` with living props, a `[living]` or `[wooze]` table, a `shallow_wooze` entity or woozy grass; `conducted` when the scene's `music_session` has a chart. There every call works as before, from `on_init` on (the player now builds a scene's subsystems before its scripts load, as `flint render --scripts` did). Anywhere else a call is a script error, `tune_living: the living module is not enabled here; it is enabled when ...`, which stops that callback, where before it logged once and went on. `flint script api` names each module's condition. In Rust, `ScriptSystem::set_conducted`, `flint_script::ConductedSnapshot` and the living `ScriptCommand` variants are gone: a module command is `ScriptCommand::Module`, and a script system with the player's whole API is `flint_player::script_system()`.
**What to do.** Nothing for a scene that has the feature. A script shared with scenes that don't should call these only where it does.
