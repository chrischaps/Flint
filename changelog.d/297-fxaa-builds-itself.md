### `fxaa = true` draws FXAA however the config was set (#297)
**What changed.** The renderer builds FXAA's pipeline and intermediate texture on the first frame the config asks for it, as it already did for styles (#262). Before, only the F4 menu and a resize built them, so `flint edit` drew no FXAA after a hot reload that turned `fxaa` on (the frame stayed byte-identical to FXAA off), and a game that switched `fxaa_enabled` through `SceneRenderer::set_post_process_config` without calling `ensure_fxaa_resources` drew none until the window was resized. FXAA set at load looks the same as before.
**What to do.** Nothing. A game binary may drop its own `ensure_fxaa_resources` calls; keeping one after setting a config still moves the shader compile off the frame that first draws FXAA.
