### `flint frame open` opens the profiler on the frame a file was saved for, and `hitch` means one frame everywhere (#1289)
**What changed.** A `--trace-on-hitch` trace opens on the hitch its header names (`saved on hitch at t=6.004 s`), not the worst hitch in it. A capture's Profiler tab opens on the frame the capture holds (the manifest's `frame.index`), or on its hitch when it was taken on one, so P switches between two views of one frame; it used to fall back to the longest frame, which a short trace might not even hold. `flint profile frame|explain <trace> hitch` and `--trace-frame hitch` now follow one rule: the hitch a `--trace-on-hitch` file was saved for, matched by its game time, else (for a trace saved on exit, a key or a capture) the worst hitch. Before, `flint profile` took the last hitch on the track, which for an exit trace with several hitches was a different frame.
**What to do.** Nothing. A script that read `flint profile explain <exit trace> hitch` as "the last hitch" asks for that frame by number instead.
