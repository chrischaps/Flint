### A game's own procgen generators, through `PlayerExtension::register_generators` (#195)
**What changed.** A game binary can now give the player procgen generators the engine doesn't ship. `PlayerExtension` has a new hook, `register_generators(&mut flint_procgen::GeneratorRegistry)`, called once from `add_extension` with the registry the player resolves every scene's `*.procgen.toml` through; it already holds the built-ins. A spec whose `generator` names a type registered there resolves like a built-in's: generated at load or queued, cached in memory and on disk, ahead of a model file of that name. Registered under a built-in's name, it replaces the built-in. `ProcGenResolver` has `registry()`, `registry_mut()` and `with_registry(config, registry)`. Only the player sees a game's generators: `flint gen`, `flint edit`, `flint render` and the stock `flint-player` know the built-ins alone. ADR 0119; example `crates/flint-player/examples/cave_game/`.
**What to do.** Nothing, unless you want one: implement the hook in your extension and add the extension before the event loop starts.
