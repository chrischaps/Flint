### Property and node clips follow `animator.playing` like skinned ones; `flint_animation::layer_edit` is `animator::edit_layer` (#733)
**What changed.** Property, node and skinned clips now follow the `animator` component by one rule set (`flint_animation::animator::Animator::apply_to`), the one #732 gave skinned clips. So `stop_clip` now pauses a property clip (it kept playing), a node clip started by `autoplay = true` keeps playing (it stopped after one frame), a finished node one-shot replays when played again, and a clip played backwards starts at its end. Every kind writes back what plays: `playing` turns `false` when a one-shot ends and `true` when `autoplay` starts one. For Rust code: `player::PlaybackState` is gone (one `ClipPlaybackState` for every kind, without the legacy `layer_clip` / `layer_weight` / `layer_time` fields; read `layers[0]`), `AnimLayer::to_toml` is gone, and `layer_edit::edit_layer_table(comps, i, |table| ..)` is `animator::edit_layer(comps, i, |layer| layer.clip(..).weight(..))`; write animator fields with `animator::write(&mut comps).clip(..).playing(true)`.
**What to do.** Nothing in scenes or scripts. A player extension that called `layer_edit` or read `ClipPlaybackState::layer_*` moves to the calls above.
