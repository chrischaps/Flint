### UI documents get `button`, `list` and `slider`, focus and `on_ui`; `.ui.toml` mistakes are errors (#731)
**What changed.** A `.ui.toml` has three controls the engine drives from the arrows, a pad, the mouse and touch (built-in `ui_up`/`ui_down`/`ui_left`/`ui_right`/`ui_accept`/`ui_back` actions; Escape left to the game), with `[styles.<class>.focus|pressed|disabled]` tables, and the loading script hears `on_ui(element_id, event)`. New: `ui_focus`, `ui_focused`, `ui_get_value`, `ui_set_slider`, `ui_select`, `ui_set_items`, `ui_set_enabled`, `ui_is_shown`, `scripts/lib/menu.rhai`. The loader is strict: an unknown type, anchor, key, parent, class or style property is a script error at `load_ui` (it returned -1) and `flint check`'s `bad-ui`. Siblings stack in file order, not by id. An `anchor` on a child places it in its parent, outside the stack; a centred text, or an auto-height root, now centres on its measured size. A hidden element hides its grandchildren too. `ui_set_value(entity, v)` is `set_fill`. `flint render --scripts` draws the HUD; `--ui-show`, `--ui-focus`.
**What to do.** Run `flint check`; fix what `bad-ui` names. Reorder elements written for alphabetical stacking. Rename `ui_set_value` to `set_fill`.
