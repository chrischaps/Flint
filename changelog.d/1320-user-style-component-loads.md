### A user style's `<name>_style` component loads in `flint render` and the player without a schema file (#1320)
**What changed.** A per-entity user style (a `styles/<name>.shader.toml` with `"mask"` in its `inputs`) gives entities a `<name>_style` component, as the book says. Every drawing host (`flint render`, `flint play`, `flint-player`, `flint edit`) used to log it on each load as `error[unknown-component] ... no component named `<name>_style``, asking for a `components/<name>_style.toml` the book never asks for, though `flint check` and `flint validate` accepted it. The loader now leaves a `<name>_style` to the user style the scene finds in `styles/`, and the host checks its fields once the styles load (a misspelt field is still one `unknown-field` warning). A `<name>_style` for a style that reads no mask does nothing, and `flint check` and the hosts now say so as a `bad-style-setting` warning that names the fix, where `flint check` gave an `unknown-component` error. The examples' open `schemas/examples/components/hologram_style.toml` is gone: nothing needs it.
**What to do.** Nothing. A game that declared an open schema for its own user style (`[component.<name>_style]` with no fields) can delete the file.
