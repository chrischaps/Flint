### A wrong type in an animator, sprite, terrain, material or 2D UI component is now said once (#802)
**What changed.** The animation, renderer and script systems read `animator` (and each of its `layers`), `sprite_animator`, `ik_two_bone`, `sprite`, `material`, `lod`, `bounds`, `model`, `terrain` and its `grass.*`, `grass_ground`, `sky`, `ocean`, `water_body`, `spline`, `spline_mesh`, `screen_anchor`, `parallax`, `ui_fill`, `ui_text`, `script` and `interactable` through the typed view, as physics and audio already did. A value of the wrong type, or an unknown `sprite.mode`, `material.blend_mode`, `screen_anchor.anchor`, `ui_text.align`, `ui_fill.direction` or layer `mode`, still reads as the default it always did, and is now logged once per entity and field (`error[bad-enum-value] entity 'hero' animator.layers[1].mode: ...`). Nothing behaves differently. For Rust: `SkyParams`, `OceanVisuals`, `OceanTint`, `WaterBodyLook`, `GrassConfig` and the new `TerrainConfig::from_component` take a `&ComponentView` (`world.view(id, name)`), and `ComponentView::tables(field)` reads an array of tables.
**What to do.** Fix what the log names. Rust that called one of those `from_component`s with a `toml::Value` passes `&world.view(id, name)`.
