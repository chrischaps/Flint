### flint-procgen has a `living` Cargo feature for the wooze field (#1516)
**What changed.** flint-procgen no longer links flint-wooze in every build. The wooze field is behind a new `living` feature, on by default: `WoozeDef::field`, `LivingKnob::in_sample`, `wooze_knobs_of`, and the checks that hold `[wooze]`, `[living.species]` and a `wooze/<name>.wooze.toml` to the field's ranges and built-in preset names. The engine's workspace takes flint-procgen with default features off, and the `living` features of flint-player, flint-viewer, flint-debug-ui and flint-cli (and flint-living) turn it on. So a build without the living package (`flint build` for a game that doesn't list it, or `--no-default-features`) has no flint-wooze. In such a build the tables still read and settle, and a preset file is still laid in, but `flint check` holds `[wooze]` only to its schema. With `living` on, nothing changes: the same diagnostics, the same pictures.
**What to do.** Nothing, if your game depends on flint-player or flint-living, or on flint-procgen with its default features. If your game takes flint-procgen with `default-features = false` and calls `WoozeDef::field`, `in_sample` or `wooze_knobs_of`, add `features = ["living"]`.
