### A user style whose `.shader.toml` doesn't load is on the error card (#425)
**What changed.** `flint_render::stylize::custom::errors()` now also lists each `styles/*.shader.toml` that registered nothing (a TOML typo, a `name` that isn't the file's, an unknown stage or input, a default outside its range), as `(style, message)` with the style named by the file and the message starting with its path, ahead of the loaded styles' errors. The player's and viewer's card shows it as "style 'x' doesn't load" within a poll of the save, and drops it when the file loads or is deleted; before, it went to the log only. `custom::load_errors()` gives just these. A host that read `errors()` as "styles that are registered" now also gets names `stylize::find` doesn't know.
**What to do.** Nothing, unless your own UI looks each name from `errors()` up in the registry: skip the ones it doesn't find, or call `load_errors()` for them.
