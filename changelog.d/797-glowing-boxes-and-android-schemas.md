### A `bounds` box glows with `material.emissive`; `transform.rotation_quat` is declared; Android reads `[project] schemas` (#797)
**What changed.** An entity drawn from its `bounds` box now gives off its `material.emissive` (`[r, g, b]`, linear, so above 1 it blooms), times `emissive_scale`. The key used to be an `unknown-field` warning that nothing read. A box without it draws exactly as before. On a model the key is still not read: recolour a GLB's glow with `material_overrides`. `transform.rotation_quat` (`[x, y, z, w]`), which physics, IK and `set_rotation_quat` write and `Transform` always read, is now in the schema, so a scene that writes it gets no warning. On Android the schemas come from your packed `flint.toml`'s `[project] schemas`, as on desktop, so a game can list `engine/schemas/examples`. With no list it still loads `engine/schemas`, then `schemas`.
**What to do.** Nothing. If a scene set `material.emissive` on a box and you don't want it to glow, delete the key. An Android game that uses `furniture`, `wall` or the other room-builder archetypes adds `"engine/schemas/examples"` to its `[project] schemas`.
