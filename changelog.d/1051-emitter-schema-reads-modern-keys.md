### An inline `particle_emitter`'s `rotation` and `angular_velocity` take effect, and its modern keys load without warnings (#1051)
**What changed.** The `particle_emitter` schema declares every key the emitter reads: `lifetime`, `speed`, `size`, `color`, `alpha`, `size_scale`, `brightness`, `rotation`, `angular_velocity`, `speed_curve`, `bursts`, `forces`, `on_death`, `on_birth`, `trail`, `lighting`, `fog` and `name`, so a scene that writes them no longer logs an `unknown-field` warning per key at every load. The keys that take several forms (a number or `[min, max]`, a curve, `shape` as a name or a `{ kind = .. }` table) use a new schema field type, `any`: the key is known and documented, and the component's reader checks its form. `rotation_min` / `rotation_max`, `angular_velocity_min` / `angular_velocity_max` and `shape_radius` have no schema default any more. The loader wrote those defaults into every emitter, so an inline `rotation = [0, 90]` or `angular_velocity = 180` was replaced by 0 to 360 and 0, and every legacy `shape = "cone"` spawned from a 0.5 m disc instead of a point. A scene that writes the legacy keys plays as before.
**What to do.** Nothing. A legacy cone that was meant to spawn from a 0.5 m disc now spawns from a point: write `shape_radius = 0.5`.
