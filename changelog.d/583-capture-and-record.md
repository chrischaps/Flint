### The window's frame on request, and `--record` (#583)
**What changed.** A line with a `capture` key on `--expression-listen`, `{"capture": "look.png", "id": 7}` or `{"capture": true}`, writes the next frame the window presents (scene and HUD) to `--capture-dir` (default `captures/` at the project root) and answers on the same connection: `{"captured": "<absolute path>", "id", "width", "height", "t", "frame", "state"}`, `state` being the last expression state the scripts heard, or `{"capture_error": "<why>"}`. Such a line is not a state: scripts never hear it, and a state object that carries a `capture` key is now refused instead of delivered. `flint play --record DIR --record-fps N` (default 8) writes the window's frames as `frame_000001.png`... with `frames.jsonl` (game, wall and Unix time) and `frames.ffconcat` for ffmpeg. Neither waits on the GPU, so the frame clock is unchanged. Desktop only.
**What to do.** Nothing, unless a game's socket states use a top-level `capture` field: rename it.
