### `SceneRenderer::bind_scene` and `prepare(&world, &FrameInputs)`: one way to drive the renderer (#739)
**What changed.** A host that embeds `flint_render::SceneRenderer` now has two entry points the player and `flint render` use. `SceneBinding::new(scope)` registers the scene's user styles (before its `[post_process]` is read); `bind_scene(device, queue, &world, &binding)` sets the asset scope, forgets the last scene (style history, bone buffers, lighting levers, terrain, grass) and loads the scene's terrain and grass, masking a styled terrain. Each frame, `prepare(device, queue, &world, &FrameInputs { time, dt, .. })` takes every per-frame input and reads the world: a field left at its default is off that frame, so a world line or boil no longer outlives the frame that set it. The old fields and setters (`ocean_time`, `grass_time`, `style_dt`, `pixels_per_point`, `set_boil`, `set_shallow_wooze`, `set_world_lines`, `set_terrain_entity`, `update_from_world`) still work for now; a later #739 change removes them.
**What to do.** Nothing yet. A game that drives the renderer itself can move to `bind_scene` and `prepare` now (`crates/flint-render/CLAUDE.md`, "Host protocol").
