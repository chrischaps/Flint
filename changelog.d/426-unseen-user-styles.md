### A scene no longer draws a user style only an earlier scene's folder had (#426)
**What changed.** User styles stay registered for the whole run, so after a transition a scene's `[post_process.styles.<name>]` could reach a `<name>.shader.toml` that only the previous scene's `styles/` folder held, and look different from the same scene loaded first or drawn by `flint render`. Now the player leaves such a table out, with a warning naming the file, and `flint check` of a folder reports it for that scene whatever order it meets the scenes in. Of two styles of one name, the one nearest the scene still wins (#781). The rule is ADR 0112's #426 addendum; `flint_render::stylize::custom::drop_unseen` is the check for a game binary that builds its own config.
**What to do.** If a scene relied on a style from another scene's folder, copy the `.shader.toml` and its WGSL into a `styles/` folder that scene searches (`flint asset where styles <name> --scene <scene>` lists them). A copy added while the scene runs is drawn at the next reload.
