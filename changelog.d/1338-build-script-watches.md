### A build with nothing changed no longer rebuilds flint-player and flint (#1338)
**What changed.** flint-player's build script told cargo to watch each package's `schemas/archetypes` and `schemas/scene` folder, and some packages have none (git keeps no empty folder). Cargo takes a missing watched path as changed, so every `cargo build` and every `flint build`, a change or none, recompiled flint-player and flint-cli: about 2 minutes in release, now 0.6 s. A new schema folder in a package is still seen, since the whole `packages/` folder is watched.
**What to do.** Nothing. A game's `build.bat` that bootstraps `flint build` with cargo should run cargo from inside `engine\`, as `flint build` does: the engine's `.cargo/config.toml` adds a linker flag that cargo reads only there, and a build from the game's root (`--manifest-path engine\Cargo.toml`) shares no compiled crate with one from inside, so the second builds everything again.
