### A trace's `engine_commit` and a capture's `engine.commit` name the engine the binary was built from (#1290)
**What changed.** Both were the HEAD of the repository the player ran in, so a player run in a game's checkout named the game's commit as the engine's. They are now the commit the engine's sources were at when the binary was built, stamped at compile time by `flint-player`'s build script; `engine_dirty` / `engine.dirty` is whether that tree has uncommitted changes. A player a game builds from its `engine/` subtree names the game's commit (which pins the engine) with `engine_subdir` / `engine.subdir` = `engine/`. A build that couldn't tell writes no `engine_commit` (`commit: null`), and the views say `at an unknown commit`. The project's checkout is kept beside it: a trace's `project_commit` / `project_dirty`, a manifest's `project { commit, dirty }`. `flint frame replay` compares a capture's commit with the replaying binary's build. Older traces and captures still read.
**What to do.** Nothing. A tool that read `engine_commit` as the game's revision reads `project_commit` now.
