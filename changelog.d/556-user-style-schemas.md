### A user style's `<name>_style` component is checked: a misspelt or mistyped field says so (#556)
**What changed.** A user style that reads the mask gives entities a `<name>_style` component. That component had no schema file, so the engine dropped `hologram_style { glwo = 2 }` or `glow = "bright"` without a word. The engine now makes the component's schema from the style's `.shader.toml`: each `[params]` entry a number with its range, each option one of its choices, and `enabled`, `blend` and `blend_source`. `flint check` and `flint validate` report a misspelt field as `unknown-field` (a warning, with the nearest name as its hint), a wrong type as `bad-type` and a value past its range as `out-of-range`. `flint play`, `flint render` and `flint edit` log the same lines when they bind the scene. A game's `<name>_style` with no schema file is no longer an `unknown-component` error in `flint check`. A schema file you wrote with fields of your own is kept.
**What to do.** Nothing, beyond fixing any field the new lines name. A game that declared its user style's component open in `schemas/components/` to quiet `unknown-component` can keep that file: the loader in `flint play` still needs the name.
