### Flint is on wgpu 30 and egui 0.36: a game's own Rust and egui code moves with it (#945)
**What changed.** The engine now builds on wgpu 30.0.2 (naga 30.0.2), egui, egui-wgpu and egui-winit 0.36.2, and egui-snarl 0.12; it was wgpu 23 and egui 0.30. Scenes, scripts, styles and user-style WGSL are unchanged, and script HUD colours keep egui 0.30's premultiply, so translucent HUD drawing looks as before; text is rasterised by egui's new font renderer, a pixel different here and there. Flint's own shaders are made without naga's loop bounding (every built-in loop has a constant or clamped bound), which keeps the ASCII style as fast as on wgpu 23; `FLINT_SHADER_CHECKS=all` turns bounding back on. A Kuwahara `radius` above 32 is now drawn at 32. `flint_debug_ui::run_headless_frame` hands its closure the frame's root `egui::Ui`, and `CurveEditor::new` / `GradientEditor::new` want an id that is also `Debug`. egui-winit is patched (`vendor/egui-winit`) so the web build compiles.
**What to do.** A game whose own Rust calls wgpu or egui (a `PlayerExtension` with an egui UI, a style built on `stylize::kit`, a window of its own) ports those calls to wgpu 30 and egui 0.36 (note that egui 0.31+'s `Color32::from_rgba_unmultiplied` draws translucent colours darker than 0.30's did); step 3 of the upgrade (#946) brings the full migration note. A game carrying the engine as a subtree that builds for the web copies the root `Cargo.toml`'s `[patch.crates-io]` entry into its own workspace root, as `egui-winit = { path = "engine/vendor/egui-winit" }` (native builds don't need it).
