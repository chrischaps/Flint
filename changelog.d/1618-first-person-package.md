### First person is a package: the character controller leaves physics (#1618)
**Package.** first-person
**What changed.** The character controller, its `character_controller` component and the `player` archetype are the `first-person` package's (`packages/first-person/`, crate `flint-first-person`), a standard package that requires `physics` and is on unless `[packages]` says `first-person = false`. With it off, a scene's `character_controller` is `unlisted-package` and nobody walks it. It plays as before: the same player (the first `character_controller` by name), the same six actions, the same walk, look and eye. For a game's own Rust: `flint_physics::character` is `flint_first_person` (`ACTIONS`, `find_player`, `CharacterController`, which now takes the `PhysicsSystem` to walk in); `PhysicsSystem::character_frame_input`, `update_character`, `enter_player_view` and `place_eye` are gone; `PhysicsSystem` gains `collider_of`, `gravity` and `drive(entity)` (a kinematic body its controller moves itself). The walk's profiler scope is `first_person::walk`, where it was `physics::character`.
**What to do.** Nothing for a game that writes no Rust. A game with its own controller can add `first-person = false`. A game that writes `physics = false` writes `first-person = false` beside it, since first person requires physics (`flint check` says so, naming the line).
