### A misspelt callback is a load warning; a callback at the wrong count is no longer called (#700)
**What changed.** Loading a script now warns about an `fn` one edit from a callback that nothing in the script calls: `fn on_updte()` logs "`fn on_updte` is not a callback, and nothing in this script calls it (did you mean `on_update`?)". Before, it loaded and never ran, in silence. A callback defined with a parameter count the engine doesn't call it with (`fn on_update(dt)`, `fn on_sequence_cue(seq)`) is warned at load as before (and `on_sequence_cue` is now checked too) but is no longer called, where it used to fail with a script error every frame. The callbacks are one table, `flint_core::callbacks::CALLBACKS` (`Callback`, `CallbackSpec`); for extension code, `ScriptInstance`'s `has_on_*` fields are gone (use `defines(Callback::Update)`), and `flint_script::api::registry::CallbackDoc` is now `CallbackSpec`.
**What to do.** Look for the new warnings when a game loads, or run `flint script check`: each names the callback meant. Rename a helper that starts with `on_` and is near a callback's name if it is called only from another script.
