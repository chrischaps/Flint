### A parent cycle is refused: `parent = "<itself>"`, `a` under `b` under `a`, and `set_parent` (#680)
**What changed.** An entity parented to itself, or a ring of entities parented to each other, used to load and then kill the player with a stack overflow and no message. Now `FlintWorld::set_parent` refuses the link that would close the loop with `FlintError::ParentCycle { child, parent, chain }` and stores nothing, so such a scene fails to load with a message naming the entities and the chain. `flint check` and `flint validate` report it before you play, as the new error code `parent-cycle`. A script's `set_parent` that would close a loop is a script error at its line. World matrices are walked with a loop, not recursion, so no depth of hierarchy overflows the stack, and every matrix is the same bits as before.
**What to do.** Nothing, unless a scene of yours crashed on load: run `flint check` on it and fix the `parent` it names. A Rust host that matches every `FlintError` variant adds `ParentCycle`.
