### `flint edit` keeps its undo history over a reload, F4's Commit is in `.flint/viewer-edits.jsonl`, and `flint validate --fix` writes prefab overrides (#1046)
**What changed.** When the scene file changes on disk while the viewer has it open (an agent editing it), the reload keeps every undo and redo step whose field still holds what the step left there, so Ctrl+Z still undoes your last edit; a field the other writer changed ends that field's history. F4's **Commit to scene** appends a line for each `[post_process]` key it wrote to `.flint/viewer-edits.jsonl`, with `entity: null`, `component: "post_process"` and `table` naming the table (`post_process.styles.ascii`). `flint validate --fix` writes a fix to an entity a prefab instance makes into `[prefabs.<instance>.overrides.<entity>.<component>]`, the same place the viewer's save writes it. Before, it printed `not written`. It still refuses archetype, parent and whole-component changes there.
**What to do.** Nothing. A tool that reads `viewer-edits.jsonl` should expect `entity` to be `null` on a commit's lines.
