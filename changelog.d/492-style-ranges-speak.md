### `set_style_param` and a style component's colours say when a value is past its range (#492)
**What changed.** Scripts' `set_style_param`, `set_post_style_param`, `tween_style_param` and `tween_post_style_param` still clamp a number, `blend` or a colour channel to its range, and now log a warning naming it (`set_style_param: ascii on 'barrel': cell=400 is outside its range 4..32; clamped to 32`); a tween says it once, when it starts. A schema field of type `vec2`, `vec3`, `vec4` or `color` with `min`/`max` now checks each member, and `ascii_style.tint`, `pencil_style.paper`/`lead` and `watercolor_style.paper` take 0 to 1, so `tint = [3, 0, 0]` is an `out-of-range` error in `flint check` and `flint validate` and a warning at load. A user style's `<name>_style` field past its `[params]` range is the same error in `flint check`, and a warning when the scene is bound. The JSON Schema export puts a vector's range on each member.
**What to do.** Run `flint check` on your scenes: a colour channel above 1 or below 0 in one of those components is now reported; it draws as it did before. A game schema with `min`/`max` on a vector field now has them enforced.
