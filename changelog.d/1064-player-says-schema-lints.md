### `flint play` and `flint-player` say what is wrong with a game's schema files (#1064)
**What changed.** A schema file of the game's that spells a type the old way (`type = "float"`), names a type that is none (`type = "integr"`, checked as a string) or writes a key the loader ignores used to be reported only by `flint validate` and `flint check`. The player now says it too, once, when it first reads the schemas: one warning summary a file, as a scene load prints its diagnostics, `schemas/components/lantern.toml: 1 warning (the full list: flint check)` and then `warning[old-type-name] lantern.brightness: ...`. A transition says it again only for a schema directory it had not read before. The engine's own files (an `engine/` subtree) are never reported. The start's `Loaded` line counts these warnings, and so does `flint playtest`, so `flint playtest --strict` fails on one.
**What to do.** Nothing, or fix what it names: `flint check` lists every one with its hint.
