### `flint validate --fix` fails when a fix doesn't reach the file, and reports the file as written (#1116)
**What changed.** `--fix` reads the scene back after writing it and reports on that file. If a fix didn't make it into the file (for example, a prefab entity that two instances' prefixes could both make), the run ends with `N of M fix(es) not written to <scene>, which still has what they fixed: <entities>` and exits 1, whatever the constraint's severity. Before, it printed `not written` and exited 0. The JSON's `fix` object has a new `dropped` list, the actions the file doesn't hold. The diagnostics and `remaining_violations` now describe the file as written, so a value a fix put back in range is no longer reported as `out-of-range`. Before, that stale error made `--fix` exit 1.
**What to do.** A script that runs `flint validate --fix` should treat exit 1 with a `dropped` or `not_written` entry as "fix by hand". Nothing else.
