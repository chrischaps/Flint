### `--vsync`, `--frame-latency` and `--no-pacing` on `flint play` and `flint-player`; `lod_scale` and `draw_distance_scale` are quality keys (#1149)
**What changed.** The present mode, the swapchain's frame latency and vsync pacing have real flags: `--vsync off|mailbox|fifo`, `--frame-latency 1..3` and `--no-pacing`. `FLINT_VSYNC`, `FLINT_FRAME_LATENCY` and `FLINT_PACING` still work as aliases, read only when the flag isn't given. The distance levers are quality keys: `--quality lod_scale=0.5,draw_distance_scale=2`, the web page's `?quality=`, an Android dev profile's `[quality]` and a script's `set_quality(#{ lod_scale: 0.5 })` all set them, and `get_quality()` lists them. `set_lod_scale` / `set_draw_distance_scale` set the same two keys. `FLINT_LOD_SCALE`, `FLINT_DRAW_DISTANCE_SCALE`, `FLINT_SHADOWS` and `FLINT_SHADOW_RES` are those keys' aliases. `flint env` and each command's `--help` name the flag or key every aliased switch stands for. A game embedding `PlayerApp` has `launch.vsync`, `launch.frame_latency` and `launch.pacing`, all `None` (the variables, then the defaults) unless it sets them. `RenderContext::with_present(window, PresentOptions)` takes the present mode as an argument; `RenderContext::new` still reads the variables.
**What to do.** Nothing. A perf script can say `--vsync off` in place of `FLINT_VSYNC=0`.
