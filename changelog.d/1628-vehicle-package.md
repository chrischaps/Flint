### The `vehicle` package: `vehicle`, `vehicle_wheel`, `vehicle_input`, `vehicle_state` and the `vehicle` module (#1628)
**Package.** vehicle
**What changed.** A new feature package. An entity with a dynamic `rigidbody`, a `collider` and a `vehicle`, with children carrying `vehicle_wheel`, drives on Rapier's raycast wheels once each fixed physics step, with arcade assists (`grip`, `yaw_assist`, `upright`, `scrub`: 0 turns each off). It handles the same at any frame rate. A player's actions (`accelerate`, `brake`, `steering`, `drift` by default) or a script fill `vehicle_input`, which also takes modifiers (`speed_bonus`, `grip_scale`, `slip_target`, `spin`...) and a one-shot `push`. The package writes `vehicle_state` for scripts, and poses the wheel children. The `vehicle` module adds `vehicle_place(id, x, y, z, yaw)`, `vehicle_wheels(id)` and `vehicle_ids()`. With debug-hud, F3 has a Vehicles panel with tuning sliders. Book: Concepts, Vehicles.
**What to do.** Nothing, unless you want vehicles: list `vehicle = "*"` under `[packages]` in `flint.toml`. A project that doesn't list it builds without the crate, and `flint check` says `unlisted-package` for a scene that uses its components.
