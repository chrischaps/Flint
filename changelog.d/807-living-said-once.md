### A `[living]` or `[wooze]` mistake is said once, and an unsettled preset is named (#807)
**What changed.** `flint validate` and `flint check` used to report one misspelt or mistyped key in `[living]` or `[wooze]` twice: an `unknown-field` warning (or `bad-type` error) naming the field, and a `toml-parse` error naming only the table. Now the first is the error, hint ending "the scene does not load until the table fits", and the second is gone. A `[wooze] preset` that names neither a `wooze/<name>.wooze.toml` file nor a built-in is now named by `flint_procgen::settle_scene` (and `apply_preset_file`) and taken out. A host that loads a scene and never calls `settle_scene` now gets a warning from the wooze field: `preset 'x' was never filled in ... this host didn't call it`. Before, it lost the preset file's knobs without a word.
**What to do.** A game binary that loads scenes itself: call `flint_procgen::settle_scene(&mut scene_file, path)` after `flint_scene::load_scene`, or call `PlayerApp::apply_scene_settings`, which does it for you. Anything that matched the old `toml-parse` text for these tables should match the field's diagnostic instead.
