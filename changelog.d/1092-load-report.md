### `--load-report`: where a load's time went, on `flint play`, `flint-player` and `flint render` (#1092)
**What changed.** `flint play` and `flint-player` take `--load-report`, and `--perf` and the web page's `?perf=1` turn it on too. The start-up, every scene transition and every chunk print a table: each stage's ms, share and count (scene read, window, GPU device, audio device, renderer, procgen, models, textures, pipelines, scripts, `on_init`, physics, audio, the first frame...), what no stage named, and the five slowest assets by name. `flint render --load-report` prints the same table up to the first capture, and `--report json` carries it as `load`. Seven new frame-note kinds (`scene read`, `scene teardown`, `physics build`, `audio load`, `animation load`, `particle load`, `on_init`) name a transition's steps in the hitch log and the F2 graph, where that time had no name before.
**What to do.** Nothing. To find a slow load, run once with `--load-report`.
