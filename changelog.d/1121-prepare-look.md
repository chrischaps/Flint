### `prepare_look(name)`: build a look's styles before it is shown (#1121)
**What changed.** The first `set_look` to a look whose styles had never been drawn built them on that frame, one pipeline after another: ASCII's stopped the game for about a second (976-1083 ms measured on Vulkan, 825-1491 ms on DX12). `prepare_look("ascii_noir")` builds a look's styles on worker threads now, while the game goes on drawing, and the `set_look` that shows it later costs its frame nothing. A frame that needs a style still building waits for that build rather than starting another. Rust hosts have the same through `SceneRenderer::prepare_styles(device, &config)` and `PlayerApp::prepare_look(name)`. On the web there are no threads, so the build happens at the call: make it where a stop is hidden (a loading screen, a fade to black). `flint render` captures ignore it (they build what they draw before drawing it).
**What to do.** Nothing, unless a game switches looks mid-play: call `prepare_look` for each look it will show, early (`on_init`), and the switches stop hitching.
