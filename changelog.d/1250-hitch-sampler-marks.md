### `--hitch-log` marks each hitch on a sampling profiler's timeline (#1250)
**What changed.** With `--hitch-log FILE`, every hitch is also marked where a sampler records it, named `hitch <ms> ms <class>: <cause> (frame N, wall_time T)` after its log line. On Linux it is samply's marker file, `marker-<pid>.txt` beside `FILE`, so `samply record` shows each hitch as a span on the main thread. On Windows it is an ETW event from the `Flint.Player` provider (`89d78a2a-cb1c-507a-4e4b-896621b7b194`), which a trace recorded with xperf carries into WPA and `samply import --unknown-event-markers`. The exit report's `[perf] hitch log:` line ends with where the marks went. A run without `--hitch-log` marks nothing.
**What to do.** Nothing. To line a sample up with a hitch, see the Profiling guide's "Lining a sample up with a hitch". On Linux, delete the `marker-*.txt` files beside your hitch logs when you no longer need them.
