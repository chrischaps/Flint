### A game adds a component to an engine archetype with `extend = true` (#1054)
**What changed.** A schema file's `[archetype.<name>]` may say `extend = true`: the components it lists are then appended to the archetype an earlier schema directory declared (one already listed is not listed twice), each `[archetype.<name>.defaults.<component>]` merges into the earlier one key by key, a key named again taking the new value, and a `visual` replaces the earlier one. An extension of a name nothing earlier declares fails the load, naming the file and the nearest name. Without `extend`, a later layer still replaces an archetype whole, so existing files mean what they did. A key an archetype doesn't hold (a misspelt `extned`), and an extension's `description`, are now `ignored-schema-key` warnings. `flint schema <archetype>` prints `Declared in:` and `Extended by:` and tags each component and default with its file's number; `--format json` adds `declared_in`, `extended_by`, `component_files` and `default_files`. For Rust: `SchemaRegistry::archetype_origin` returns an `ArchetypeOrigin`, and `ArchetypeSchemaDefinition` gained `extend` and `stray`.
**What to do.** A game that copied a whole engine archetype file to add a component or a default can cut it to `extend = true` and what it adds, and stop tracking the engine's copy.
