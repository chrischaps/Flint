### User styles warn about a derivative under a branch, which the browser refuses (#573)
**What changed.** `flint style check`, `flint render`, `flint check` and `flint bundle` now warn, at the line and column, about a `dpdx`, `dpdy`, `fwidth` or `textureSample` in a user style where the pixels of a quad may not all be: under an `if` or `switch` on a value that can differ per pixel, in a loop whose turns can, or after a `return` only some take. Natively such a style draws, but the browser's WebGPU refuses the whole module, so on the web it drew its input unchanged. A branch on `params` counts: it is a per-pixel `var<private>`. The style still loads and packs; nothing is refused.
**What to do.** Run `flint style check styles/` on your game. For each warning, take the derivative before the branch and use the result inside it, or put `@diagnostic(off, derivative_uniformity)` on the function when a quad's pixels always agree.
