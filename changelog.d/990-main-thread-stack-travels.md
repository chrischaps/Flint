### `flint` and `flint-player` link an 8 MB stack on Windows however they're built (#990)
**What changed.** A Windows exe's main thread gets the stack the exe asks for, 1 MB unless told otherwise. The engine asked for 8 MB only in `.cargo/config.toml`, which cargo reads only when it runs inside the engine's checkout, so `cargo build --manifest-path engine/Cargo.toml` from a game's root linked 1 MB. The two binaries now ask for it in their build scripts (`/STACK:8388608` on MSVC, `-Wl,--stack,8388608` on MinGW), and a build from a game's root gets 8 MB. Measured in debug, a `flint init` scene needs 778 KB for `flint render --scripts` and 905 KB for `flint-player` to play it, so a game's deeper scripts could overflow 1 MB.
**What to do.** Nothing for the engine's binaries. A game binary of its own (one embedding `PlayerApp`) isn't reached by another package's build script: copy the short `build.rs` in guides/player-extensions.md ("A Game Binary") to give it the same stack.
