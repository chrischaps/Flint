### A scene's entity ids, and every walk of the world, are the same every run (#688)
**What changed.** Ids came from one counter shared by the whole process, and scenes spawned in `HashMap` order, so an entity's id changed from run to run and `entities_with_component` walked entities in a different order each time (a pile of dynamic bodies settled differently each load). Now each `FlintWorld` counts its own ids from 1 and a scene spawns in name order, so a scene's ids are its names' ranks in every process. A scene transition and an editor reload start past the last world's ids (`FlintWorld::after`, `flint_scene::load_scene_after`), so an id a script kept never names a new entity. `entities_with_component` returns a `BTreeSet` in id order; `all_entities`, `entity_names` and `get_children` are ordered too; `SceneFile::entities`, `prefabs` and `EntityDef::components` are `BTreeMap`s, so a saved scene lists entities and components by name. `EntityId::new()`, its `Default` and `ensure_counter_above` are gone.
**What to do.** Nothing for scenes and scripts. Rust that minted an id with `EntityId::new()` uses `EntityId::from_raw(n)` or `world.spawn`; code that named `HashSet<EntityId>` for `entities_with_component`'s result names `BTreeSet`. A seed meant to survive edits to the scene still comes from the entity's name: adding an entity moves the ids after it.
