### Ask a running game for its world: `--inspect-listen`, `flint query --attach`, `--dump-world` (#713)
**What changed.** `flint play` and `flint-player` take `--inspect-listen 127.0.0.1:<port>`: a loopback socket that answers `flint query` strings and `flint entity show` against the live world, a JSON line for each line asked. `flint query "<query>" --attach <port>` and `flint entity show <name> --attach <port>` ask it and print exactly what they print for a scene file; `flint query --data` adds each entity's component values, for a file or a game. `--dump-world out.json --dump-world-at 2,5 [--dump-query "<query>"]` writes the world at game times as one JSON document (default time: `--exit-after`'s), and a run that never reaches a time exits 1. `flint query`'s JSON keys now come out in alphabetical order, as `flint entity show`'s always have.
**What to do.** Nothing. To see a scripted run's state, add `--dump-world` to it; to poke a game you're playing, start it with `--inspect-listen` and ask with `--attach`.
