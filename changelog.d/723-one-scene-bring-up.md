### A scene reached by `load_scene()` starts as it would at startup (#723)
**What changed.** A transition now runs the same bring-up as the first scene, so the new scene's `[scene] input_config` is loaded (it was ignored), and a scene with no `[post_process]`, no `[environment] skybox`, no ambient or no `[camera]` gets the defaults instead of the last scene's bloom, fog, styles, script post overrides, skybox, lighting and camera. `on_init` at a transition can reach the persistent store and state machine. A target that can't be loaded no longer leaves an empty world: the current scene keeps playing, the error names the path it was read from, and the run exits non-zero. `flint play` now takes the scene's ambient, shadow and shading settings, as `flint-player` always did. `PlayerApp::scene_post_config()` returns a `PostProcessConfig`, not an `Option`.
**What to do.** A game that relied on a setting carrying over must author it in each scene that needs it. Drop `.unwrap_or_default()` after `scene_post_config()`.
