### A frame capture keeps each style's history, so `flint frame replay` draws a moving ASCII frame exactly (#1136)
**What changed.** A capture (`flint render --frame-capture`, the player's `--capture-frame-at`, Shift+F2) now writes `replay/history/`: ASCII's tone and edge cells as the frame read them, and a user style's `history` targets, named with their keys in `inputs.json`'s `renderer.style_history`. `flint frame replay` hands them back before it draws, so a frame of moving ASCII that replayed with whole glyphs off (205,431 of 921,600 pixels on the motion bench) is byte-identical, and a `history:` line (JSON `history`) says what each style took or why it drew fresh. `replay.fresh_only` no longer lists `ascii: temporal history` or a user style's history targets. A capture from before this has no history and replays as it did. A game's Rust style that keeps state between frames can hand it out too (`StylePass::export_history` / `import_history`, `flint_render::stylize::history`); one that doesn't draws fresh on replay, as before.
**What to do.** Nothing.
