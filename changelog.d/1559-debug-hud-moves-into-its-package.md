### The debug-hud package has its own folder, and the player names none of it (#1559)
**What changed.** `flint-debug-ui` moved to `packages/debug-hud/crates/flint-debug-ui`. The F3/F4 panels, F2's frame-time graph and the corner cards for script and style errors reach the player through the Package API: the crate's new `player` part registers a `flint_package::hud::DebugHud`, and flint-player has no `debug-hud` code of its own. The panel trait (`DebugPanel`, `PanelLayout`, `PanelCtx`, `PanelHost`, `DebugPanels`, `ScenePanels`) is now `flint_package::panels`, which flint-debug-ui re-exports at the old paths. It gains `outlives_scene()`, which defaults to `false`, and the graph's data types are now `flint_package::hud`'s. The keys, panels and graph behave as before, with one exception: closing F4 now catches the cursor only when no other panel is open.
**What to do.** A game whose `Cargo.toml` names `engine/crates/flint-debug-ui` names `engine/packages/debug-hud/crates/flint-debug-ui`. A panel of a game's own that should survive a scene change returns `true` from `outlives_scene`. A game binary that called `StatsView::next()` passes whether the run has a debug HUD: `next(true)` in a stock build. Otherwise nothing changes.
