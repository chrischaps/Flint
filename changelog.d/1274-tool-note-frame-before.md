### A hitch the frame after a screenshot names its own cause, not the screenshot (#1274)
**What changed.** A screenshot, trace-ring or F2-overlay note from the frame before no longer counts toward a hitch's cause. A tool waits for its own work, and its frame already gets its own `tooling` hitch. A render stall on the frame after a `--screenshot-every` shot used to read `screenshot .., 74.8 ms (frame before)` in the hitch log, the exit report, `--perf`, `?perf=1` and the F2 graph. It now reads `render +58.0 ms`. A script stall there no longer has `(also: screenshot ..)` after it, and the screenshot stays in the line's `notes`. The overlay's note is still shown beside a stall as `(also: stats overlay .. the frame before)`, because its next frames do draw more HUD.
**What to do.** Nothing. A tally of `causes:` from a run with screenshots may move from `screenshot` to the phase or script that stalled.
