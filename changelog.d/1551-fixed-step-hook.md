### A package acts inside each physics step: `Subsystem::fixed_update` (#1551)
**What changed.** The Package API (`flint-package`, ADR 0137) has a hook in the fixed physics step: `Subsystem::fixed_update(&mut FixedCtx)` runs once a step, after the character controller and the physics sync-in and before Rapier's step, lent the world, the physics (`PhysicsSystem::body_of`, `bodies_mut`, `colliders`, `queries`, `rapier_mut`), the step's `dt` and index, held input, the event bus, the game state's policy and the resources. A force a package applies there is integrated by that step, so it acts the same at 30 frames a second (two steps a frame) as at 144 (none on most frames). `Stage::FixedStep` names the point in the schedule; `update` never hears it. `PhysicsSystem::fixed_update_with(world, dt, events, between)` runs `between` at the same point for any host, and `flint_physics::rapier` (`flint_package::physics::rapier`) is the engine's Rapier. A paused state and a capture skip the hook, as they skip Rapier. With no subsystem in a scene the step is the same as before.
**What to do.** Nothing. A game's `PlayerExtension` is unchanged; `vehicle` and a game's own package use the hook.
