### The player names a left-out package as `flint check` does, and runs none of it (#1528)
**What changed.** In a project whose `[packages]` leaves a package out, `flint play` and `flint-player` now say `unlisted-package` with the line to add (`add `living = "*"` under [packages] in flint.toml`) in a scene's or chunk's load summary, where they said `unknown-component`. A player built with the package runs none of it there: living props stand still as still models, the living and music subsystems aren't built, the package's script modules are "not enabled" (`module_enabled("living")` is false), and one line at the scene's entry names `[packages]` and what doesn't run. `SchemaRegistry` gains `packages()` and `set_packages()`: `SchemaRegistry::resolve` fills it from `SchemaDirs::packages`, and `flint_scene::load_scene` words its diagnostics by it (`flint_scene::name_unlisted` for a host that diagnoses a scene file itself). A project with no `[packages]` table changes nothing.
**What to do.** Nothing. A game binary that builds its own registry with `SchemaRegistry::load_from_directories` and hands it to `PlayerApp::set_schemas` gets the list from the `SchemaDirs` it passes beside it.
