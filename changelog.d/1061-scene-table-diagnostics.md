### A wrong type in `[camera]`, `[environment]` or `[post_process]` is `bad-type` by field, and every scene-table diagnostic has a line (#1061)
**What changed.** `[camera] fov = "wide"` used to be serde's `toml-parse` with a snippet, and stopped at the first such table. `flint validate` and `flint check` now say `error[bad-type] 6:1 [camera] fov: expected f32, got string` with the hint `the scene does not load until the table fits`, once a table, and still check the rest of the scene. Every diagnostic about a scene-level table (a typo in `[living]` or `[wooze]`, an `unknown-table`, a value out of range) now carries the line and column of the key it names, in the text (`5:1 [living] shadowz`) and as `line` / `column` in the JSON; the load's warning summary has it too. A tool that matched `toml-parse` for these tables, or the text `[table] field` at the start of a location, should read the code and fields instead. `scene.version` stays informational: nothing reads it to decide what a scene means (ADR 0115).
**What to do.** Nothing.
