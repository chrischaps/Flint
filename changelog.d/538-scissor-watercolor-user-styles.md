### Per-entity watercolor draws only near its entities; a user style can say `reach = <points>` (#538)
**What changed.** Per-entity watercolor (a `watercolor_style` or `style_mask`, or a table with `scope = "entities"`) now runs its wash, blur and paint passes only inside its entities' screen bounds, grown by how far each reads; the frame is byte-identical. A `.shader.toml` that reads the mask may now declare `reach = <points>` (0 to 512): the promise that further than that from its entities `style` returns `p.color` unchanged. The framework then draws the style's last pass only inside that, and the style's own passthrough around it. A pixel the shader changes past its reach is cut back to the input there. The web page takes `?scissor=0` to draw the full passes, for measuring. An engine before this one refuses a `.shader.toml` with `reach` (an unknown key).
**What to do.** Nothing for watercolor. For a per-entity user style that passes through off its entities, add `reach` (`0` when it draws only on their own pixels, as `examples/styles/hologram` does; more when it draws a rim or reads neighbours' mask ids) to make it cheaper.
