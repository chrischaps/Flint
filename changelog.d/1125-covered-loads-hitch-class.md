### A scene load behind a fade is a `loading` hitch, not a gameplay one: `--max-hitches-of loading` (#1125)
**What changed.** When a script ends a transition's exiting phase with `complete_transition()`, the load's long frame (and the frame after it) is drawn under the script's cover. A hitch there is now classed `loading`: the hitch log's `class` says so, the exit report gives it a `[perf] loading hitches` line, the F2 counters show `+N loading`, and the perf report has `hitches.loading`. The game's counts leave it out (`[perf] hitches`, the perf line, `hitches.after_start`), and so do `--max-hitches` and `--max-hitches-startup` unless `--max-hitches-of loading` names it. A scripted run that walks through a covered door no longer fails `--max-hitches 0`. A transition no script covers (none calls `complete_transition()`, or the 10 s timeout ended its fade) is still a gameplay hitch.
**What to do.** Nothing. To hold loads to a limit, gate them by name: `--max-hitches N --max-hitches-of loading`.
