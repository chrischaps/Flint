# Changelog: November 2026

What changed this month for games built on Flint, newest first. How to read
it and how to add an entry: [CHANGELOG.md](../CHANGELOG.md).

## 2026-11-11

### `flint check`: one pre-flight for a project; a constraint with a bad query now fails, and so do a few other things that passed in silence (#687)
**What changed.** New command: `flint check [dir|scene] [--json] [--strict]`
lists everything wrong with a project in one run (schemas, entity references,
every asset and file a scene names with the paths tried, styles, constraints)
and exits 1 on an error. `flint validate` and `flint bundle` run the same
checks, and `flint init` prints `flint check` as its first next step.

What now exits non-zero that did not:

| Case | Was | Now |
|---|---|---|
| A constraint whose `query` (or `query_rule` `rule`) does not parse, or selects `components` | skipped: it passed every scene | an error naming the constraint, its file and the parse error, in `flint validate`, `flint check` and the viewer |
| A query with text after its one condition (`entities where a == 1 and b == 2`), in `flint query` too | read as `a == 1`, the rest dropped | a parse error: there is no `and`, `or` or `not` |
| A `joint.parent` naming no entity (the schema now types it `entity`, as #684 typed `ik_two_bone`'s); an `ik_two_bone.tip` that is not a child of its entity | exit 0 | `error[unknown-entity]` / `error[not-a-child]`, exit 1 |
| `flint validate --fix` with an error-level violation no fix covers; `--dry-run` on a scene with one | exit 0 | exit 1: the exit code says whether the file, as the run left it, has an error |
| `flint validate --format` other than `text` or `json` | printed text | refused (exit 2) |
| `flint bundle`: a model whose only source is a `<name>.procgen.toml` that is empty or does not parse | packed | `error[bad-spec]` or `error[missing-asset]` |

A scene with none of these passes `flint validate` as before. Also:
`--fix` and `--dry-run` honour `--format json` (a `fix` object in the same
document); each JSON diagnostic has a new `tried` array; `flint bundle`'s
refusal lists problems as `flint check` prints them.
**What to do.** Run `flint check`. Rewrite each `bad-constraint` query as one
condition (it was never being checked, so expect real violations once it
runs); fix or empty (`""`) each dangling `joint.parent` and IK field. A CI
step that reads the exit code of `flint validate --fix` or `--dry-run` now
gets "the scene still has an error". Use `flint check` as the gate before
playing or bundling.

### `collider`, `rigidbody` and nine other schemas load their fields; a schema file with keys outside `fields` fails; `audio_listener` is gone (#792)
**What changed.** Ten engine schemas (`collider`, `rigidbody`, `character_controller`, `audio_source`, `audio_trigger`, `joint`, `parallax`, `screen_anchor`, `ui_fill`, `ui_text`) declared their fields under `[component.x]` and loaded with none. They now load, so `flint validate` checks them: `collider.shpae` warns, `rigidbody.body_type = "dynamc"` is an error, and `audio_source.bus`, `screen_anchor.anchor`, `ui_fill.direction` and `ui_text.align` are enums. Their defaults are written in at load and each equals the reader's fallback, so nothing plays differently. A component schema file with any key under `[component.x]` besides `description` and `fields` now fails to load, naming the file and keys. `audio_listener` is deleted: nothing read it, since the listener is the camera, and the `player` archetype no longer lists it.
**What to do.** Run `flint validate` on your scenes. Delete any `[entities.x.audio_listener]` table, which now warns as an unknown component. If one of your own schema files fails to load, move its fields under `[component.<name>.fields]`.

### Schemas check references: `entity` and `asset` fields, exact-length vectors, `flint schema --list` and a JSON Schema (ADR 0115, #684)
**What changed.** `flint validate` (and the player's load summary) now
reports two new errors: `unknown-entity` for a field or `parent` that names
no entity (`ik_two_bone.target`, `spline_mesh.spline`), and `missing-asset`,
with every path tried, for `model.asset`, `script.source`, `material` and
`sprite` textures and the spline, terrain and grass files. `""` means "not
set". `material.blend_mode`, `sprite.mode` and `particle_emitter.blend_mode`,
`.shape`, `.sort` are enums. `vec2`/`vec4` are exactly 2 and 4 numbers; a
`color` is 3 or 4. Schema files gain `entity`, `asset` (with `kind`) and
`table` with `fields`; `float`, `boolean`, `integer` and `entity_ref` still
load, with an `old-type-name` warning for your own files. `flint schema`
gains `--list`, `--format json` and `--format json-schema --output <file>`
(editor completion), and exits 1 for an unknown name.
[Schemas](docs/book/src/concepts/schemas.md) has the type list and codes.

**What to do.** Run `flint validate`: a reference it flags was already
dangling, so fix the name, add the file, or set `""` when a script fills it.
A `vec2`/`vec4` field of yours holding another count becomes
`{ type = "array", element = "f32" }` or `color`. Respell old type names when
warned.

### Physics and audio say when a value is wrong, and an integer is a number (ADR 0115, #685)
**What changed.** Physics and audio now log a wrong component value once per
entity and field instead of taking the default in silence: an unknown
`rigidbody.body_type`, `collider.shape`, `joint.type` or `audio_source.bus`
(with the allowed values and the nearest one), a value of the wrong type, and
a `collider` on an entity with no `rigidbody`, which has never collided
(`needs-component`). What they fall back to is unchanged. Two behaviours do
change: `character_controller.move_speed`, `jump_force` and `height` written
as integers (`move_speed = 8`) used to read as the defaults (5.0, 6.0, eye
height 1.5) and are now read as written, and `material.base_color_r/g/b/a`
written as integers used to drop the tint and now apply it.

**What to do.** Run the game and read the log for `flint_ecs::view` lines;
each says what to write. If a character moves or jumps differently, or a
model gains a tint, the scene had an integer the engine ignored: write the
value you want. Rust in a game binary can read the same way with
`world.view(id, "collider").f32("friction", 0.5)`
([book](../docs/book/src/guides/player-extensions.md#reading-components)).

### The changelog is a page of months; `scripts/changelog.sh since <date>` prints what is new (#788)
**What changed.** `CHANGELOG.md` no longer holds the entries: it is a short
page that links one file a month, `changelog/YYYY-MM.md`, newest first. The
entries up to 2026-11-11 are in `changelog/2026-11.md`, unchanged. An entry
waiting to be assembled is a file in `changelog.d/`.
**What to do.** After an engine pull, run
`bash engine/scripts/changelog.sh since <the day of your last pull>` instead
of reading `engine/CHANGELOG.md` top down. It needs bash and git, as the
pull does. A game's agent guide written by an older `flint init` still says
to read `CHANGELOG.md`; that page now says where to look.

### Save data moves to the OS user directory for a game with an id; saves are atomic, a corrupt file is kept as `.bak`, and there are slots and a version (#726)
**What changed.** Where the `persist_*` store is saved, how it is written, and
what a script can ask of it.

**Where saves live.** Decided once at startup; no scene transition moves it.

| The game | Was | Now |
|---|---|---|
| `flint.toml` has `[project] id = "kart"` | `<project>/save/persist.toml` | `<config>/kart/saves/default.toml` |
| no manifest id, but the input config sets `game_id = "kart"` | `<project>/save/persist.toml` | `<config>/kart/saves/default.toml` |
| no id at all, or an id that can't be a folder name | `<project>/save/persist.toml` | the same file |
| the web | `localStorage`, `flint:/config/flint/save_<game_id>.toml` | the same entry, keyed on `[project] id` when the manifest has one, else on `game_id` as before |
| Android | the app's files directory, `files/save/persist.toml` | the same file |

`<config>` is `%APPDATA%` on Windows, `~/.config` on Linux and
`~/Library/Application Support` on macOS, where input rebinds already go.
Nothing is written into the game's folder any more, so a game installed
read-only can save.

**The old file is read once and left in place.** When a game with an id starts
and has no `default.toml` under the user directory, the player reads
`<project>/save/persist.toml` (then, for a scene two folders deep, the older
guessed place #706 already read), logs one warning saying where the save now
lives, and writes it there within a second. The file in the project is not
changed, moved or deleted, and is not read again once the new one exists. On
the web, when the manifest's `id` differs from the input config's `game_id`,
the entry keyed on `game_id` is read once the same way. These reads last one
release.

**Writes are atomic.** Every save is a temp file (`<file>.tmp`) flushed and
renamed over the save, so a crash or power cut mid-save leaves the old file
whole. Input rebinds are written the same way. A save now costs a disk flush
(about 4 ms measured, against 0.2 ms), at most once a second.

**A save file that doesn't parse is kept.** It used to be logged, ignored and
then overwritten by the next save. Now it is renamed `<file>.bak`
(`.bak.1`, `.bak.2`, ... if that name is taken), an error names both paths,
the game starts with an empty store, and `persist_corrupt()` returns
`#{ slot, file, backup, error }` so a menu can tell the player.

**New in the script API.**

| Function / callback | What it does |
|---|---|
| `persist_slot()` | the slot held, `"default"` at startup |
| `persist_slot(name)` -> `bool` | saves the slot held if it changed, then loads `name` (empty if new). Names: 1-32 of `a-z 0-9 _ -` |
| `persist_slots()` | the slots that have a save, in name order |
| `persist_version()` | the version of the save loaded; 0 for a file with no `[meta]` |
| `persist_set_version(n)` | stamp it by hand (a game with no manifest) |
| `persist_corrupt()` | `()` or the report above |
| `fn on_persist_migrate(from)` | called before `on_init` when the save loaded is older than `[project] save_version`; the store is stamped with the game's version afterwards |

**New manifest key**: `[project] save_version = <whole number>` (0 when left
out). **New flag**: `--save-dir <dir>` on `flint play` and `flint-player`
keeps a run's saves in `<dir>/<slot>.toml` and reads no other save.

**The file format** is unchanged for existing saves: a file with no `[meta]`
table is version 0 with every top-level key the game's, and a store at
version 0 is still written without one. The engine keeps the one top-level
name `meta` (`[meta] version = 2`). A game key called `meta` keeps working
(it is saved as `meta.key_meta`), with one exception: an old save whose
`meta` key was exactly a table holding only an integer `version` is read as
the engine's table.

**What to do.**
- A game with an `id`: nothing, the save follows on first launch. Tell
  players (and your own tooling) that saves are under `<config>/<id>/saves/`
  now; anything that read or deleted `save/persist.toml` in the project to
  reset progress should look there, or pass `--save-dir`. Once every player
  has launched the new build, the old `save/` folder can go.
- A game with no `id`: nothing changes. To move its saves out of the project,
  add `id = "..."` under `[project]` in `flint.toml`.
- A `log`/CI check that greps for `persist: failed to load`: the message is
  now an `error` that names the `.bak`.
- A script that stores a key named `meta` holding only `#{ version: <int> }`:
  rename the key before upgrading.

### Scenes say everything that is wrong with them, and `flint validate` fails on it (ADR 0115, #683)
**What changed.** A scene is checked against the schemas in one pass that
never stops at the first problem, and each problem names its entity,
component and field, with a suggestion:

```
scenes/hall.scene.toml: 4 errors, 1 warning

  error[unknown-archetype] entity 'hero' field 'archetype': no archetype named `playr`, so the entity gets no defaults
      hint: did you mean `player`?
  error[bad-type] entity 'hero' transform.scale: expected vec3, got string
  error[unknown-component] entity 'lever' component 'interactible': no component named `interactible`, so nothing checks it
      hint: did you mean `interactable`?
  error[bad-enum-value] entity 'pond' water_body.shape: "lak" is not a value of `shape`
      hint: did you mean `lake`? allowed values: lake, river
  warning[unknown-field] entity 'hero' transform.postion: `transform` has no field `postion`
      hint: did you mean `position`?
```

- **Errors:** a value of the wrong type (`bad-type`), a string that is none
  of an enum's values (`bad-enum-value`), a number outside `min`/`max`
  (`out-of-range`), a required field that is missing (`missing-field`), a
  component no loaded schema directory declares (`unknown-component`), an
  archetype none declares (`unknown-archetype`), a file that is not TOML
  (`toml-parse`, which now names the file, as the loader's own error does).
  Until now an unknown archetype or component was skipped in silence, and
  the rest stopped at the first problem per component without naming the
  field.
- **Warning:** a field its component's schema doesn't declare
  (`unknown-field`). It used to be allowed without a word.
- **`flint validate <scene>`** prints the whole list (text, or
  `--format json` with a `diagnostics` array beside `violations`) and
  **exits 1 on any error**. It now loads and checks the scene even when no
  schema directory has constraint files; it used to print "No constraints
  found" and exit 0 without reading the scene's entities. JSON's `valid`,
  `errors` and `warnings` count both lists.
- **`flint validate --strict`**, or `strict = true` under `[project]` in
  `flint.toml`, makes an unknown field an error.
- **The player and every command that loads a scene** (`flint play`,
  `flint-player`, `flint render`, the viewer) log one summary line and the
  first five problems at each load, transitions and chunks included, and
  carry on: nothing that loaded before stops loading. The per-component
  `[scene] entity '<name>' component '<comp>': <reason>` warnings are gone.
- `flint examples --check` fails an example on an error diagnostic. The
  engine's examples are clean of them; the components only their scripts
  read (`film`, `story`, `tour`, `orbit`, `hologram_style`) are open schemas
  in `schemas/examples/components/`.
- The engine's `material` schema now declares `color` and
  `base_color_r/g/b/a`, which the renderer always read.

**What to do.** Run `flint validate` on your scenes; expect it to fail where
it used to pass.

- A typo: fix it; the hint usually names what you meant.
- **A field of your own on an engine component** (read by your scripts):
  declare it in your schema layer by overriding the component file with the
  engine's fields plus yours (a later schema directory replaces a component
  of the same name whole), or keep it in a component of your own. Until then
  it is a warning and nothing fails, unless you turn `strict` on.
- **A component of your own** (in a scene, read only by scripts): declare it
  in your schema layer. One with fields is checked; one with a name and no
  fields is known and unchecked:

  ```toml
  # schemas/components/inventory.toml
  [component.inventory]
  description = "Read by scripts/inventory.rhai"
  ```

  A component a script attaches at run time and no scene file writes needs
  nothing.
- **An `archetype = "..."` used as a label** with no archetype file: add
  `schemas/archetypes/<name>.toml` (`[archetype.<name>]` and a `components`
  list), or drop the line.
- A game binary that embeds `PlayerApp`: `set_schema_paths` and
  `set_schema_dirs` work as before. `set_schemas(registry, dirs)` hands over
  the registry you loaded the first scene with, so the player never reads it
  again (see the next entry).
- Rust callers: `FlintError::InvalidFieldType` and `InvalidEnumValue` gained
  a `field`; `flint_schema::validate_component` returns every problem as
  `flint_core::Diagnostic`s, and `flint_scene::diagnose` does it for a file.

### A scene transition never loads with an empty schema registry (#683)
**What changed.** The player re-read every schema directory at each scene
transition and each `load_chunk`, and when that read failed (a schema file
that had stopped parsing, say) it loaded the scene with an empty registry
and logged one line: archetype defaults and schema defaults vanished for
that scene. The registry is now read once and kept. A chunk uses it as it
is; a transition reads the disk again only when the next scene's schema
directories differ (another project's `flint.toml`, or a `schemas/` beside
the new scene), and a read that fails logs an error and keeps the registry
already loaded. In the web player, the engine schemas compiled into the
player now survive a transition too.

**What to do.** Nothing. One thing to know: a schema file edited while the
game runs is no longer picked up by the next transition; restart the player.

### `flint entity create/delete` edit one table and leave the rest of the file alone (#678)
**What changed.** Both commands used to re-serialise the whole scene: a
string with a `:` in `--props` was rewritten (`"a:b.glb"` became
`"a=b.glb"`), every prefab instance was baked into plain entities and
`[prefabs]` emptied, every `[post_process]` default was written out (which
stopped a scene's `look` from applying), comments were dropped and entity
order changed on every run. Now `create` adds only `[entities.<name>]` after
the last entity, and `delete` removes only that entity's tables. `create`
writes the archetype, parent and props given, not the archetype's defaults
(they're filled in at load, as before). Deleting an entity with children is
an error unless you pass the new `--recursive`, which deletes the subtree.
Either command refuses, and leaves the file as it was, when the edited scene
would not load or a prop doesn't fit its component's schema; a `null` in
`--props` is now an error.
**What to do.** Nothing for scenes. A script that deleted a parent and
relied on the children staying (they then broke the next load) must delete
the children first or pass `--recursive`. A scene that a past `entity`
command baked or filled with defaults stays as it is; `git log -p` on it shows
what was lost.

### The room-builder archetypes left the engine's schema set; `model`, `light`, `spline` and `spline_mesh` have schemas (#681)
**What changed.** Three things, of which the first can stop a game from
bundling.

1. **`furniture`, `wall`, `floor`, `ceiling`, `pillar`, `room` and `door`
   (the archetypes), the `door` component and the three constraints about
   rooms and doors are no longer in `engine/schemas`.** They are the
   vocabulary the engine's example scenes are written in, and they moved to a
   layer of their own, `engine/schemas/examples`. In a game that lists only
   `engine/schemas`:
   - `flint bundle` and `flint export web` refuse a scene that names one:
     `archetype "furniture" (in no bundled schema)`;
   - `flint entity create --archetype room` fails with `Unknown archetype`,
     and `flint schema furniture` finds nothing;
   - at load, an entity that names one takes no defaults from it. One that
     writes its own `bounds` (or has a `model`) looks the same, since the
     renderer still colours a box by the archetype's name; one that leaned on
     the default box (`furniture`'s 1 m cube, a `wall`'s 10 x 4 m slab) draws
     nothing, and a `door` no longer gets its `audio_trigger`;
   - `flint validate` in a game with no constraints of its own now says `No
     constraints found in provided schema directories.` and exits 0, where
     the three room-and-door rules used to run on every game.
2. **`flint schema model`, `flint schema light`, `flint schema spline` and
   `flint schema spline_mesh` print their fields**, with each fallback in its
   description. The fields are the ones the engine already read; nothing a
   scene wrote before means something else now. The loader checks these
   components against the schemas and warns, as it does for every other
   component: a `light` whose `type` is not `directional`, `point` or `spot`
   (it lit nothing before, in silence), a `model` with no `asset`, a
   `spline_mesh` without `spline`, `width` and `height`, a number where a
   list belongs. Loading fills in three defaults on a `light` that leaves
   them out, the values the renderer already used: `type = "directional"`,
   `color = [1, 1, 1]`, `intensity = 1.0`. A script that reads
   `get_field(light, "light", "intensity")` now gets `1.0` rather than
   nothing.
3. **`flint_core::components::HEALTH` and `PLAYER` are gone.** No engine code
   read a `health` or `player` component; a player extension that used the
   constants writes the strings `"health"` and `"player"`.

**What to do.** Search your scenes and prefabs for the seven archetype names:

    grep -rnE 'archetype = "(furniture|wall|floor|ceiling|pillar|room|door)"' scenes prefabs

If there are none, nothing. If there are, either keep the vocabulary by
listing the layer between the engine's set and your own, in `flint.toml` (and
in `bundle.toml`, if it has a `schemas` key of its own):

    [project]
    schemas = ["engine/schemas", "engine/schemas/examples", "schemas"]

or, better for a game that only ever wanted a box, copy the one or two
archetype files you use from `engine/schemas/examples/archetypes/` into your
own `schemas/archetypes/` and leave the layer out. A command line that passes
`--schemas engine/schemas --schemas schemas` needs `--schemas
engine/schemas/examples` between them in the first case. To run one of the
engine's examples from inside a game, pass all three.

While you are in the scenes: nothing has ever read a
`[entities.x.directional_light]` or `[entities.x.point_light]` table, and a
scene whose only lights are spelled that way is lit by the engine's built-in
key and fill. `flint schema light` shows the real table: `[entities.x.light]`
with `type = "directional"`, and a `direction` that points *toward* the
light, so a sun written as the way its rays travel (`[-0.5, -0.6, -0.3]`)
becomes `[0.5, 0.6, 0.3]`. Twenty-seven of the engine's own example scenes
were written that way and now carry real lights, so they look different:
longer shadows, the lantern and fire lights lit. Nothing reads `cast_shadows`
on a `light` either (it is a `material` field).

### Viewer Ctrl+S and `flint validate --fix` keep the rest of the scene file (#677)
**What changed.** Both used to rewrite an existing scene from its entities
alone, which deleted `[camera]`, `[environment]`, `[post_process]`,
`[living]`, `[wooze]`, `[prefabs]`, the `[scene]` description and
`input_config`, and every comment; `--fix` also renamed the scene "scene" and
baked prefab entities into the file. Now:

- **Ctrl+S in `flint edit`** writes only the fields you edited, each in place
  with its comment. With nothing edited it writes nothing, so saving an
  untouched scene leaves it byte for byte as it was. A file with CRLF line
  endings keeps them.
- **`flint validate --fix`** writes only what its fixes changed
  (`SceneDocument::apply_world_diff`). A fix to an entity that comes from a
  prefab is printed as `not written` rather than baked in. `--output-diff` is
  the diff of the file.
- **`flint_scene::save_scene` refuses a path that already exists** and
  returns an error saying so. It is for new scenes only.

**What to do.** A scene that lost its tables to an earlier save needs them put
back by hand (git has them). Rust code calling `save_scene` on an existing
file: load a `SceneDocument` and call `patch_field`, `remove_field`,
`add_entity` or `apply_world_diff`, then `save`.

### `flint init` writes a real game project: manifest, lit scene, HUD, input config, agent guide (#707)
**What changed.** `flint init <name>` used to write a room and a door with no
light, camera, player or script, its own copies of the engine's `transform`,
`bounds` and `door` schemas (which shadowed the engine's), a `furniture`
archetype, and a `CLAUDE.md` naming folders it hadn't made. It now writes the
game-project pattern, from templates compiled into the binary:

- `flint.toml` with `[project] id`, `schemas`, `scene` and `input`, so none of
  the commands it prints needs `--schemas` and `flint play` needs no scene;
- `scenes/main.scene.toml`: lit (a `light` with a `type`), with a `[camera]`,
  a ground and something to see; `scripts/hud.rhai` on a `hud_controller`;
  `config/input.toml`; `bundle.toml`; `.gitignore`; `renders/`;
- an **empty** `schemas/components` and `schemas/archetypes`: no engine schema
  is copied into the game, and there is no `schemas/constraints`, `levels/`
  or `assets/` folder any more;
- `CLAUDE.md` and `AGENTS.md`, which name only paths and commands that exist.

New flags: `--template walk|blank|2d` (default `walk`: a first-person player
facing a lit ring of stones), `--engine path|subtree|none`, `--engine-path
<dir>` and `--force`.

- `--engine path` (the default) names the Flint checkout the `flint` binary
  was built from, by absolute path, in `flint.toml` and in `bundle.toml`'s
  `[mount]`. The printed commands work at once; the path is right on that
  machine only.
- `--engine subtree` names `engine/schemas`, the pattern the games use.
  `flint init` runs no git and no network commands: it prints the `git
  subtree add`, and until that has run every command stops with `schema
  directory not found`.
- `--engine none` names only the game's `schemas/`. The scene validates and
  renders, engine archetypes resolve to nothing, and it does not offer
  `flint play`.

It refuses a directory that already holds files (it used to refuse any
existing directory). With `--force` it writes into one and keeps every file
already there. The "Next steps" no longer print the hidden `flint serve`
alias.

**What to do.** Nothing for an existing game: `flint init` only writes new
projects. A script that ran `flint init x` and then read `x/levels/demo.scene.toml`
or `x/schemas/components/*.toml` must read `x/scenes/main.scene.toml` instead,
and will find the game's `schemas/` empty. A game still carrying the old
scaffold's `schemas/components/transform.toml`, `bounds.toml` or `door.toml`
should delete them: they hide the engine's (the old `transform` has no
`shear` or `rotation_quat`).

## 2026-11-10

### `flint play` and `flint bundle` read `flint.toml`; saves, `load_ui`, `load_data` and the procgen cache use the project root (#706)
**What changed.** The last pieces of the project manifest (ADR 0114). Every
key of `flint.toml`'s `[project]` table now has a reader, and nothing in the
engine guesses the project root any more.

- **`flint play` and `flint-player` with no scene argument** open the
  manifest's `scene`. With no such key the error says what to pass and that
  `[project] scene` can name a default.
- **`flint bundle` and `flint export web`** take the bundle's name from
  `[project] id` and its start scene from `[project] scene` when `bundle.toml`
  doesn't say (`--name` / `--scene`, then `bundle.toml`, then `flint.toml`,
  then the folder's name and the only scene). `bundle.toml` is still the
  packing rules, and may now hold nothing else. `flint.toml` is packed with
  the game, and the player reads it from the bundle.
- **Paths written "from the project root"** are joined to the project's root,
  the folder with the `flint.toml` (or the `.flint/`, or the `schemas/` +
  `scenes/` layout), whichever scene is playing: `load_ui("ui/hud.ui.toml")`
  and a style sheet's `tokens`, `load_data("data/x.toml")`, a
  `music_session`'s `manifest` and `chart`, the save file
  `save/persist.toml`, the procgen disk cache `.flint/procgen-cache/` and the
  project-local input override `.flint/input.user.toml`. Each used to guess
  the root as "the scene folder's parent", in its own copy.
- A terrain's `splat_map` and `layer*_texture`, and the path
  `load_chunk(path)` takes, are found by the one search (from the scene's
  directory, then each directory above it), as the heightmap already was. The
  particle editor finds an effect's textures the same way, from the effect's
  folder. `flint bundle`'s reference check walks to the root and the engine
  too, so a nested scene's references pass where the runtime finds them.

**Nothing moves for a scene directly in `scenes/` or `levels/`**: the scene
folder's parent *is* the project root there, by every marker, and a game with
no marker at all keeps the old guess. Two layouts differ:

| Layout | Was | Now |
|---|---|---|
| a scene two or more folders deep, `scenes/act1/a.scene.toml` | `scenes/save/persist.toml`, `scenes/ui/...`, and a cache at `scenes/act1/.flint/procgen-cache/` | `save/persist.toml`, `ui/...`, `.flint/procgen-cache/` at the root: the same files a scene in `scenes/` uses |
| a `.flint/` folder beside the scenes (an old procgen cache, a shipped `input.user.toml`), which marks that folder as a root | the parent of the scenes' folder | the scenes' folder |

So a save no longer moves when a transition enters a deeper scene (the first
half of #726).

**For one release the old place is still read.** When a UI document, a data
file, a music session's manifest or the save file is not at the root and is
at the old guessed place, it is read from there, with a warning on stderr
naming both paths. The save is written at the root from then on; the old file
is left where it is. A `.flint/input.user.toml` beside the scene is still read
(and saved back to) when the root has none. The procgen cache is not carried
over: it regenerates once.

**What to do.** Nothing for a game whose scenes sit directly in `scenes/` or
`levels/`. If a warning names an old place, move the file to the path it
gives. To use the new defaults, give `flint.toml` a `scene` (and an `id`),
and drop `name` / `scene` / `schemas` from `bundle.toml` if they only repeated
them. A stray `.flint/` folder beside your scenes makes that folder a project
root of its own (the nearest marker wins, hiding a `flint.toml` above it):
delete it if it holds only an old `procgen-cache/`.

### Looks, palettes, glyph sets, fonts, paper and stroke images and user styles are found by the one search rule; the working directory is no longer searched (#706)
**What changed.** The last kinds join the engine's one asset search: beside
the scene, then beside each directory above it up to the project root, then
under `engine/` at the root. With them every kind of asset a scene names is
found the same way. What each looks for at a directory `D` of that walk:

| Kind (`flint asset where <kind>`) | Named by | Tried at each `D` |
|---|---|---|
| `looks` | `[post_process] look = "dusk"`, `--look dusk`, `set_look("dusk")` | `D/styles/dusk.look.toml`, then `D/dusk.look.toml` |
| `palettes` | a style's `palette = "dusk"`, `--ascii-palette` | `D/palettes/dusk.palette.toml`, then `D/dusk.palette.toml` |
| `glyph-sets` | a style's `font = "terminal"`, `--ascii-font`, `ui_text.font = "terminal"` | `D/fonts/terminal.glyphs.toml`, then `D/terminal.glyphs.toml` |
| `fonts` | `ui_text.font = "fonts/ui.font.toml"` | `D/fonts/ui.font.toml` (the path from `D`), then `D/fonts/<path>` |
| `font-faces` | the script HUD's fonts; a `fonts/fonts.toml` alias's `file` | every `.ttf` / `.otf` in `D/fonts/` |
| `papers` | `paper_image = "cold_press"` (pencil, watercolor) | `D/papers/cold_press.png`, `.jpg`, `.jpeg`, then the same in `D` |
| `strokes` | `stroke_image = "graphite"` (pencil) | `D/strokes/graphite.png`, `.jpg`, `.jpeg`, then the same in `D` |
| `styles` | user styles: `[post_process.styles.glow]` | every `D/styles/*.shader.toml` |

A name written as a path (`--look out/tuned.look.toml`, `palette =
"art/dusk.palette.toml"`, `paper_image = "scans/linen.jpg"`) is that path from
each `D`.

**Built-ins come after the search**, as before: the built-in palettes
(`cga`, `phosphor`, `amber`, ...) and looks (`graphite`, `matrix`, ...) are
used when the search finds no file of the name, and a file it finds wins. The
glyph set `builtin` is never searched for. `flint asset where palettes amber`
says when the answer is the built-in, and exits 0.

**Found now where nothing was found before** (no warning: nothing loads
differently, something loads that did not):

- **A scene more than one folder below the project root** finds the project's
  `styles/`, `palettes/`, `fonts/`, `papers/` and `strokes/`. Each of these
  searches stopped one level above the scene before, so a look or palette
  named from `scenes/act1/cave/` fell back to a built-in or a warning.
- **The engine subtree's files.** `engine/styles/*.look.toml`,
  `engine/palettes/`, `engine/fonts/` and `engine/styles/*.shader.toml` are
  searched last. The eight shipped looks are files in `engine/styles/`, so a
  game with an engine subtree now reads them from the subtree instead of the
  copies compiled into the binary. They are the same looks unless the subtree
  and the binary are different engine versions.
- **The script HUD's fonts are every `fonts/` the scene can see**, not the
  first one that exists. A `fonts/` beside a scene used to hide the project's
  `fonts/` whole; now it adds to it, hiding only files of the same name. The
  `fonts/fonts.toml` read is the nearest one. A `ui_text.font` naming a
  `.font.toml` was read from the scene's own folder only; now from each folder
  above it too.
- **A user style in a `styles/` two or more folders up**, and one in
  `engine/styles/`.

**The working directory is no longer searched.** Before, a look was also
looked for in `styles/` of the directory the command was run from, a palette
in its `palettes/`, a glyph set in its `fonts/` (in the ASCII style), a paper
or stroke image in it and its `papers/` / `strokes/`; and `--look
some/file.toml`, or a `.palette.toml` / `.glyphs.toml` path, was read as a
path from the working directory. Now the only places are the ones in the rule.
Run from the project root this changes nothing: the root is the last
directory of the walk, so `flint render levels/a.scene.toml --look
out/tuned.look.toml` from the root still finds `out/tuned.look.toml`. It
changes when a command is run from somewhere else, or the file is outside the
scene's project. With no scene at all (`flint edit model.glb --style ...`,
`--list-styles` with no scene), the working directory stands in for the
scene's folder, as before.

**User styles of one name.** With a `glow.shader.toml` in two `styles/`
folders, a scene gets the one nearest to it. Before, the first scene loaded in
a run decided `glow` for every later scene and the other file was skipped
with a warning (and `flint bundle` refused the game). Now each scene's
nearest takes the name when that scene loads, and a nearer file dropped in
while the scene is open takes over at the next reload poll.

**What to do.** Usually nothing. Where a pick changed, the engine says so for
one release, once per file, on stderr when the scene loads and as a `note` in
`flint asset where`:

```
look 'dusk': the search order changed (ADR 0114). Before, the engine loaded styles/dusk.look.toml; now it loads none: that file is outside the project. Move it into the project, or put a flint.toml at the folder that holds both
```

If you see it, move the file into the project (or run from, or put a
`flint.toml` at, the folder that holds both). A missing look, palette, glyph
set, font or image now lists every path tried in its warning. A font named
`Body.TTF` is still loaded; other extensions are matched as spelled
(`cotton.PNG` is not found by `paper_image = "cotton"`; name it `cotton.PNG`
in full).

**For a game that embeds the engine** (`PlayerApp`, `flint_render`): the
lookups take the scene's project now. `GlyphSetCache::new` and
`PaletteCache::new` take a `flint_core::project::AssetScope` (a project and a
scene directory; `AssetScope::for_scene(path)` finds one) in place of a list
of directories; `BitmapFont::resolve`, `SceneRenderer::load_ui_font` and
`stylize::images::ImageSlot::get` take one in place of a directory;
`ChoiceScope` has `assets: Option<&AssetScope>` in place of `scene_dir`, and
`ChoiceScope::files` takes an `AssetKind`; `stylize::custom::style_dirs` takes
a scope. `SceneRenderer::set_asset_scope` gives the renderer the project (a
host that only sets `scene_dir` gets the project found from it). The
path-taking `look::find` / `resolve` / `list`, `custom::load_dir` /
`reload_changed`, `load_user_styles` and `project_font_definitions` keep
their signatures and find the project themselves; each has an `_in` / `_for`
twin that takes the scope.

### `demo/` is now `examples/`, with an index and `flint examples` (#763)
**What changed.** The engine's example scenes moved from `demo/` to
`examples/`, and four scenes that only the render goldens used
(`stylize_props_ascii`, `stylize_props_pencil`, `stylize_props_plain`,
`stylize_blend`) left it for `tests/fixtures/scenes/`, where frozen copies of
every scene a golden or CLI test loads now live. The stray `build-tavern.ps1`,
`explore-tavern.ps1`, `view-showcase.ps1` and `luminarium_preview.png` are
gone. `examples/index.toml` gives every example a topic and a one-line
purpose; the new `flint examples` lists them (`--topic`, `--json`), and

### Scripts, procgen specs, prefabs, wooze presets, the input config and path-named scene files are found by the one search rule (#706)
**What changed.** These kinds join models, textures, sounds and particle
effects (the entries below) on the engine's one asset search: beside the
scene, then beside each directory above it up to the project root (the folder
with `flint.toml`, `.flint/`, or `schemas/` + `scenes/`), then under `engine/`
at the root. What each looks for at a directory `D` of that walk:

| Kind | Named by | Tried at each `D` |
|---|---|---|
| scripts | `script.source = "hud.rhai"`; `import "ui_kit"` | `D/scripts/hud.rhai`; `D/scripts/lib/ui_kit.rhai` |
| procgen specs | `model.asset`, `material.texture`, `sprite.texture`, `living_prop` | every `*.procgen.toml` under `D/specs/`, then `D/models/`, subfolders included, by the `[meta] name` inside |
| prefabs | `[prefabs.x] template = "kart"` | `D/prefabs/kart.prefab.toml` |
| wooze presets | `[wooze] preset = "misty"`, `load_living_preset` | `D/wooze/misty.wooze.toml` |
| the input config's game layer | `[scene] input_config`, else `config/input.toml` | the path from `D` |
| path-named files | `terrain.heightmap`, `terrain.splat_map`, `grass_ground.mask`, `spline.file`, `[environment] skybox` | the path from `D` |
| particle textures | an effect's or emitter's `texture` | `D/particles/<file>`, then `D/<file>` |
| a transition's target | `load_scene("levels/two.scene.toml")` | the path from `D`, starting at the current scene |

**Found now where nothing was found before.** No warning is printed for
these: nothing loads differently, something loads that did not.

- **A `scripts/` folder beside a scene no longer hides the project's.** Before,
  the engine read one `scripts/` folder, the first that existed of "beside the
  scene" and "one level up". With one beside the scene, a `script.source` or an
  `import` that lived only in the project's `scripts/` logged `File not found`
  (or a module error) and did not run. Each script and each module is now found
  on its own, nearest first. **A script that was silently missing will start
  running.** To see whether you have one: before pulling, run a scene that has a
  `scripts/` beside it and look for `File not found:` lines.
- **A scene two or more folders deep** (`scenes/act1/cave/x.scene.toml`) finds
  the project's scripts, specs, prefabs, presets, `config/input.toml` and
  path-named files. Before it saw nothing above `scenes/act1/`; a prefab there
  failed the load.
- **Specs are read from more folders**: `specs/` and `models/` at every level up
  to the root (before: `models/` and `specs/` beside the scene and `specs/` one
  level up), and under `engine/`. A model or texture name that now has a spec
  is generated from it instead of loaded from its file, since procgen comes
  before files. To see which specs a scene sees: `flint asset where specs <name>
  --scene <scene>`.
- **`engine/` is a last resort** for every kind here: `engine/scripts/`,
  `engine/prefabs/`, `engine/config/input.toml` and so on, when the game has
  none of that name.

**Arrangements that now resolve to a different file.** Each prints the warning
below, once, on stderr, when the scene loads.

- **Specs:** two specs stating the same `[meta] name`, one under `models/` and
  one under `specs/`, both beside the scene: `models/` used to win, `specs/`
  wins now. Two files in one folder stating the same name: the one read later
  used to win, the first by file name wins now. (A spec beside the scene still
  beats the game's of the same name; that did not change.)
- **Particle textures:** a file in `particles/` one level above the scene and a
  file of the same name loose beside the scene: `particles/` used to win, the
  file beside the scene wins now.
- **Transition targets:** a target that exists as a path from the working
  directory *and* as a path from the current scene's directory or one above it,
  as two different files: the working directory's used to win, the scene's
  wins now. A target found nowhere by the search is still opened as written.
- **A chunk's scripts:** `scripts/<file>` beside the chunk, else beside the
  scene, was the old rule; the chunk's script is now searched for from the
  chunk's folder upward first, then from the scene's.
- **Anything outside the project:** a scene at the project root whose scripts,
  specs, prefabs or presets sat one level above it, outside the root. That
  folder is no longer read; the warning says the file is outside the project.

The warning names both files:

```
WARN procgen spec 'oak_tree': the search order changed (ADR 0114). Before, the engine loaded levels/models/oak.procgen.toml; now it loads levels/specs/oak.procgen.toml. Move or rename one of them if that is the wrong file
```

`flint asset where <kind> <name> --scene <scene>` prints the same as a `note`
line (and `order_change` in `--json`). **The warning and the note are there for
one release (#765) and then go**; after that the new file simply loads.

**Also changed.**

- A missing script, prefab, preset-named file, heightmap, splat map, grass
  mask, spline file, skybox or particle texture now lists every path tried
  (`script 'hud.rhai' not found. Tried:` and a line a path). A missing prefab
  still fails the load, with that list in the error.
- **The input config's game layer** is, in order: the scene's `input_config`
  (found by the search; not found is a warning and no game layer, where before
  it was skipped in silence), else the file `flint.toml`'s `[project] input`
  names from the project root (new: nothing read that key before), else
  `config/input.toml` found by the search.
- **Hot reload follows the search**: a script or `scripts/lib` module written
  nearer to the scene than the one running takes over without a restart, and
  every visible `scripts/lib/` is watched.
- **Saving a wooze preset** (the Living Props panel, `save_living_preset`)
  writes into the nearest `wooze/` folder that exists between the scene and the
  project root, or a new `wooze/` beside the scene. Before: `wooze/` beside the
  scene or one level up, whichever existed.
- `flint asset where --help` lists the new kinds: `scripts`, `specs`,
  `prefabs`, `wooze`, `files`, `particle-textures`, `scenes`.
- For a game binary that embeds the player:
  `ScriptSystem::load_scripts_from_scene(scene_path, &project)` and
  `HeadlessScripts::load(scene_path, &project, ..)` take the scene's
  `flint_core::project::Project` (`PlayerApp::project()`, or
  `Project::for_scene(path)`); `ScriptSystem::load_script_named(id, source,
  from_dir)` loads a script by name; `flint_particles::texture_search_dirs` and
  `resolve_particles_dir` are gone (`flint_render::load_scene_particle_textures`
  takes the project); `ScriptEngine::module_base()` returns a `ModuleBase`.

**What to do.** Run your scenes once and read stderr for `the search order
changed` lines; each names the two files, so move or rename the one you don't
want. If a script that used to be missing now runs and shouldn't, remove its
`script` component or the file. Nothing to do for a game whose scenes sit one
folder below the root with one `scripts/`, `specs/`, `prefabs/` at the root.

### Models, textures, UI sprites, animations and sounds are found by the one search rule (#706)
**What changed.** These kinds join particle effects (the next entry) on the
engine's one asset search: beside the scene, then beside each directory above
it up to the project root (the folder with `flint.toml`, `.flint/`, or
`schemas/` + `scenes/`), then under `engine/` at the root. Before, each
looked beside the scene and one level up, in an order of its own. What each
kind looks for at a directory `D` of that walk:

| Kind | Named by | Tried at each `D`, in order |
|---|---|---|
| models | `model.asset = "barrel"` | `D/models/barrel.glb`, `D/models/barrel.gltf` |
| textures | `material.texture`, `sprite.texture` | `D/<name>`, then `D/textures/<name>`; a name with no extension as `<name>`, `<name>.png`, `<name>_color.png` in each |
| UI sprites | `draw_sprite(.., "heart.png")` | `D/sprites/heart.png`, `D/heart.png` |
| animation clips | every `*.anim.toml` | `D/animations/` |
| sprite animations | every `*.sprite.toml` | `D/animations/` |
| sequences | every `*.sequence.toml` | `D/animations/` |
| sounds | `audio_source.file = "audio/hit.ogg"` | `D/audio/hit.ogg` (the name as a path from `D`), then `D/audio/<name>` |
| the sound preload | every `.ogg` `.wav` `.mp3` `.flac` | `D/audio/` |

What a game can notice:

- **A scene two or more folders deep finds the project's assets.**
  `scenes/act1/cave/deep.scene.toml` now sees `models/`, `textures/`,
  `sprites/`, `animations/` and `audio/` at the root. Before it saw nothing
  above `scenes/act1/`, and drew grey boxes in silence.
- **The engine's own assets are a last resort.** A name found nowhere in the
  game is looked for under `engine/` (`engine/models/`, `engine/audio/`, ...).
- **A missing asset's warning lists every path tried**, in order:
  `model 'barrel' not found. Tried:` and a line a path, in place of
  `Model file not found: barrel`. The same for a texture, a UI sprite (once,
  not every frame) and an `audio_source`'s file. For a model or texture the
  player adds what it asked before the files: `and before the files: the asset
  catalog, a procgen spec of the same name`. An `animator.sequence` that no
  loaded file gives lists the `animations/` folders that were read.
- **A name written as a path is tried as written first.** `texture =
  "../shared/wall.png"` and `asset = "./local/barrel"` are taken from the
  scene's directory before the search (and then go through it, so every
  spelling that loaded still loads); an absolute path is that one file. This
  is new for models, which had no way to name a file outside `models/`. A
  model name ending `.glb` or `.gltf` is now taken as written
  (`asset = "barrel.gltf"`); it used to become `barrel.gltf.glb` and miss.
- **Animations: a folder beside the scene no longer hides the project's.**
  The three animation loaders read one `animations/` folder, the one beside
  the scene if it existed. Now they read every one the scene can see, and a
  nearer file hides a farther one of the same file name; the nearest is
  registered last, so its clips win where two files define one clip name. A
  clip that was silently missing may start to play.
- **Sounds: `audio/` is one of the places a `file` is looked for.**
  `file = "hit.ogg"` used to be found only loose beside the scene or one level
  up; it is now also found in `audio/` at each level. The preload still keeps
  each file as `audio/<file name>`, which is the name `play_sound` uses.
- **`flint asset where <kind> <name> --scene <scene>`** answers for each of
  these: `models`, `textures`, `sprites`, `animations`, `sprite-animations`,
  `sequences`, `audio` (`--help` lists them with their folders).
- **Where the order differs from before**, the engine says so for this
  release, once per file, on stderr (and as a `note` in `flint asset where`):
  `UI sprite 'heart.png': the search order changed (ADR 0114). Before, the
  engine loaded sprites/heart.png; now it loads scenes/heart.png. ...`.
  There are three cases:
  1. *A scene at its project's root with assets one level above*, outside the
     project. Every kind used to look there; the search now stops at the
     root, so they are not loaded (`now it loads none: that file is outside
     the project`). A folder with no project marker keeps its one level up.
  2. *UI sprites*: a file loose beside the scene used to lose to
     `sprites/<name>` one level up. Each level is now finished before the
     next, so the file beside the scene wins.
  3. *Sounds*: `file = "hit.ogg"` with one `hit.ogg` loose a level up and
     another in `audio/` beside the scene used to take the loose one; it now
     takes `audio/hit.ogg` beside the scene.

  Models and textures looked in the same places in the same order as the
  first two levels of the new search, so only case 1 applies to them.
- Extensions are matched as spelled, as they were: `hit.OGG` is not
  preloaded, and textures and sprites are named with their extension.
- Not changed: terrain heightmaps and splat maps, grass masks, the skybox and
  a particle effect's `texture` are still paths from the scene's directory or
  its parent. Scripts, procgen specs, prefabs, fonts and style assets keep
  their own searches until they move over.
- For a game with its own binary: `flint_render::model_loader::ModelLoadConfig`
  gains `project` and `asked_first` (build one with
  `ModelLoadConfig::in_project(app.project().clone(), scene_path)` or
  `from_scene_path`, not a struct literal), and `resolve_model_path` /
  `resolve_texture_path` return `Result<PathBuf, flint_core::project::NotFound>`.

**What to do.** Nothing for a game that keeps these folders at its root or
beside its scenes. If you see the order-change warning, move or rename one of
the two files it names (or, for case 1, move the asset into the project or put
a `flint.toml` in the folder that holds both). If something now draws or plays
where it didn't, a scene was naming an asset the old rule could not reach.

### Living props: `softness`, a soft silhouette at rest (#582)
**What changed.** A living prop's body can feather at its outline without
moving any more than it did. `softness` (0 to 1, default 0) fades the body
where its surface turns away from the eye; its cards (a tree's leaves, a
form's marks) keep their edges, and its echoes feather with it. It can be set
wherever echoes and variance can:

- a spec's `[living] softness = 0.45`;
- a scene's `[living] softness`, or one species' `[living.species.<spec>] softness`;
- a `wooze/<name>.wooze.toml` preset's `[living]` tables;
- a script: `tune_living(#{ living: #{ softness: 0.6 } })` for every prop,
  `tune_living(#{ species: "my_form", softness: 0.6 })` for one species, and
  `clear_living("my_form", ["softness"])` to give it back;
- the F3 Living Props panel's **Silhouette** slider.

A value outside 0 to 1 is refused: a spec fails to parse, `flint validate`
fails a scene whose `[living.species.<spec>]` has one, the player warns about
a scene-wide one and keeps each spec's, and a script's tune names it and
leaves the knob alone. `flint render --report json` lists each prop's `softness` and the layer
that set it. A body with softness above 0 draws after everything opaque, still
writes depth and still casts its whole shadow.

**What to do.** Nothing. At the default of 0 every prop draws exactly as
before, and old specs, scenes and presets load unchanged.

### Particle effects are found from any depth, by one search rule; `flint asset where` (#706)
**What changed.** A `particle_effect` (and `play_effect` from a script) used
to find its `particles/<name>.particles.toml` in one folder only: `particles/`
beside the scene if that folder existed, else `particles/` one level up. Now
the engine looks, in order, in `particles/`

1. beside the scene;
2. beside each directory above the scene, up to the project root (the folder
   with `flint.toml`, `.flint/`, or `schemas/` + `scenes/`);
3. under `engine/` at the project root, where a game keeps the engine.

and loads every effect it can see, a nearer file hiding a farther one of the
same file name. This is the engine's one search rule for assets (ADR 0114);
particle effects are the first kind on it, and the other kinds follow in later
releases. What a game can notice:

- **A scene two or more folders deep finds the project's effects.**
  `scenes/act1/cave/deep.scene.toml` now sees `particles/` at the root; before
  it saw nothing above `scenes/act1/`.
- **A `particles/` folder beside a scene no longer hides the project's.** It
  used to be the only folder read; now its files override the project's of the
  same name and the rest of the project's still load. An effect that was
  silently missing may start to draw.
- **A missing effect's warning lists every path tried**, for both
  `particle_effect` and `play_effect`:
  `particle effect 'ice' not found. Tried:` and a line a path.
- **`flint asset where particles <name> [--scene <scene>] [--json]`** prints
  the file the engine would load and the paths tried before it; with nothing
  to find it lists them all and exits 1.
- **Where the order differs from before.** Only when a scene sits *at* its
  project's root and its effects are in `particles/` one level above, outside
  the project: the search stops at the root now, so those are not loaded.
  For this release the engine says so, once per effect, on stderr when a
  scene names such an effect (and as a `note` in `flint asset where`):
  `particle effect 'rain': the search order changed (ADR 0114). Before, the
  engine loaded ../particles/rain.particles.toml; now it loads none: that file
  is outside the project. ...`. A folder with no project marker at all keeps
  its one level up. The warning goes away in a later release; the order stays.
- An effect's `texture` is searched where it was, and then in the other
  `particles/` folders of the search, so an effect found at the root finds a
  texture beside it.
- For a game with its own binary: `flint_particles::load_particle_effects_from_world`
  and `texture_search_dirs` take a `&flint_core::project::Project` first
  (`Project::for_scene(scene_path)`, or `PlayerApp::project()`).

**What to do.** Nothing for a game that keeps `particles/` at its root or
beside its scenes. If you see the order-change warning, move the effect into
the project, or put a `flint.toml` in the folder that holds both. If an effect
now draws where it didn't, a scene was naming one that the old rule could not
reach: remove the entity or keep the effect.

### `flint.toml`'s `schemas` is read by every command; `--schemas` is the whole list (#706)
**What changed.** One rule now decides which schema directories load, the same
in `flint play`, `flint-player`, `flint render`, `flint validate`, `flint
query`, `flint entity`, `flint schema`, `flint edit` (the scene viewer and
`--spline`) and `flint prefab view`:

1. the `--schemas` flags, if any were given;
2. else `[project] schemas` in the `flint.toml` of the project the scene is
   in (the working directory's project for `flint schema`);
3. else, as before, `schemas/` in the working directory, beside the scene and
   one level up, whichever exist.

So a game whose `flint.toml` says `schemas = ["engine/schemas", "schemas"]`
needs no schema flags on any command, from any folder of the project. What a
game can notice:

- **`flint query` and `flint entity` take `--schemas`**, repeatable, and read
  the manifest. `query` used to load only `schemas/` in the working directory
  (and hid a schema file that didn't parse: that is an error now); `entity`
  took one directory.
- **`flint edit <scene>` loads every `--schemas`**, and constraints from each.
  It used to take the first and drop the rest, so a game's scene opened with
  the engine's archetypes and none of its own.
- **`--schemas` is the whole list.** `play`, `render`, `validate`, the spline
  editor and `flint-player` used to add any `schemas/` beside the scene or one
  level up to the flags; with flags they no longer do. A game run from its
  root with `--schemas engine/schemas --schemas schemas` loads what it did.
  For this release, those commands print a line on stderr for each directory
  they would have added and now leave out: `warning: schemas is no longer
  added to --schemas: the flags are the whole list now. Pass it with another
  --schemas, or list it under [project] schemas in flint.toml`. The warning
  goes away in a later release; the behaviour stays.
- **A named directory that doesn't exist is an error** in every command,
  where it used to be skipped: `schema directory not found: nope (named by
  --schemas)`, or `(named by `schemas` in <root>/flint.toml)`. This includes a
  manifest listing `engine/schemas` in a checkout with no engine subtree.
- With no flags and no `schemas` key, each command finds what it found
  before. In the player, a scene transition into another project reads that
  project's manifest.
- `flint bundle` uses the manifest's `schemas` when `bundle.toml` has no
  `schemas` key (it used to assume `engine/schemas` and `schemas`).
- For a game with its own binary: `PlayerApp::set_schema_paths` works as
  before; `set_schema_dirs` takes the answer of
  `flint_schema::SchemaRegistry::resolve(scene, flags)`, which is how to get
  the same directories the commands do. `flint_schema::discover_schema_dirs`
  is deprecated.

**What to do.** Add `schemas = ["engine/schemas", "schemas"]` under
`[project]` in your `flint.toml` and drop the flags from your scripts, or keep
the flags: both load the same thing. If a command now stops with `schema
directory not found`, the flag or manifest entry it names was being ignored
before: fix the path or remove it. If you relied on a `schemas/` folder beside
a scene being added to your flags, name it with another `--schemas`.

### `random()` no longer repeats, and scripts can `seed_random(n)` (#580)
**What changed.** `random()` and `random_range(min, max)` used to hash the
wall clock on every call, so calls close together (two in a row in one
`on_update`, say) often returned the same number. They now draw from one
sequence shared by every script. It starts from the clock once, when the
player starts, so plain runs still differ from each other, but no two calls
repeat. The new `seed_random(n)` restarts that sequence at `n` and gives
the numbers `--seed n` gives, every run. It reseeds every script's draws,
not only the caller's. `--seed`, `--frame-step` and `flint render --scripts`
are unchanged.
**What to do.** Nothing. A script that wants a replayable run calls
`seed_random(n)` in `on_init`, not at the top of the file: top-level
statements run again before every callback, so a seed there restarts the
sequence every frame.

### `flint.toml` gains a `[project]` table, and a bad one is refused (#706)
**What changed.** The `flint.toml` at a project's root, until now only a
marker, may hold `[project]` with `id` (a string), `schemas` (a list of
folders relative to the root, in override order), `scene` and `input` (paths
relative to the root). Every key is optional, an empty file is still a valid
marker, and other tables are left alone. `schemas` is read (the entry above);
`id`, `scene` and `input` are parsed and checked and not yet acted on: the
scene argument and the input config work as before. The commands that look for a project root (`flint
asset ...`, `flint gen --register`, anything given `--project <dir>`) now stop
with an error naming the file and the key when `[project]` holds a value of
the wrong type or a key Flint doesn't know.
**What to do.** Nothing, unless your `flint.toml` already has a `[project]`
table with other keys in it: move those to a table of another name. You can
add `id` and `schemas = ["engine/schemas", "schemas"]` now (ADR 0114).

### Escape reaches the game when the game binds it (#639)
**What changed.** If any action in the loaded input config binds Escape, a
press no longer closes the window: it goes to the game like any other key.
With nothing bound to Escape, it quits as before. Alt+F4 and the close button
still quit.
**What to do.** A game that binds Escape (to a pause menu, say) must offer its
own way out. `quit_game()` (#659) ends the run as closing the window does.

### A scripted run with a missing screenshot fails (#639)
**What changed.** `flint-player` and `flint play` exit 1 when a requested
screenshot was never written, when a `--screenshot-every` sequence lost
frames, or when the player failed to start. They used to exit 0.
**What to do.** Nothing, unless a capture script relied on exit 0. A run that
now fails was already missing its output.

### Entity setters warn on a missing entity (#635)
**What changed.** `set_field`, `set_position`, `set_rotation`,
`set_rotation_quat`, `set_scale`, `set_shear`, `clear_shear`, `rotate_local`,
`set_visible`, `set_joint_target`, `set_parent`, `set_material_color` and
`set_material_override` warn, once per script and function, when given `-1`
(what `get_entity` returns for a name it can't find) or a despawned id. They
used to do nothing in silence.
**What to do.** Read the new warnings: each is a script acting on an entity
that isn't there.

### `--frame-step` runs draw the same random numbers every time (#635)
**What changed.** Under `flint-player --frame-step`, scripts' `random()` and
`random_range()` are seeded by default, so two stepped runs are identical.
`--seed N` (and the web page's `?seed=`) picks another sequence. A normal,
unstepped run is unchanged.
**What to do.** Nothing. For variety in a stepped capture, pass `--seed`.

### OGG loops play at their true length (#632)
**What changed.** OGG Vorbis files are decoded gapless: the padding an encoder
adds at the end is dropped, so a loop is exactly as long as its audio. Before,
each pass of a loop carried a short gap. WAV is unchanged.
**What to do.** If a loop was edited to hide the old gap, or music was timed
against the padded length, re-check it.

### Sounds can be named by their stem (#629)
**What changed.** `play_sound("whoosh")`, `play_sound_at` and `audio_source`
names find `audio/whoosh.ogg` (or `.wav`, `.flac`, `.mp3`). The full
`audio/whoosh.ogg` still works and wins when both could match. A miss now
names the nearest sound.
**What to do.** Nothing.

### Contour ink is a style; `kuwahara_boil` and `contour_*` have new homes (#599)
**What changed.** Contour settings live in `[post_process.styles.contour]`
(`width`, `threshold`, `strength`, `luma`, `color`, `fade`, `boil`), and
Kuwahara's boil is `boil` in `[post_process.styles.kuwahara]`. The old flat
keys (`contour_enabled`, `contour_*`, `kuwahara_boil`) still load and are
folded into those tables. A plain `flint render --contour` now draws its ink;
on the previous engine it drew none.
**What to do.** Nothing. Prefer the tables in new scenes.

### A sun of intensity 0 casts no shadows; scenes can switch lighting off (#627)
**What changed.** A directional light with `intensity = 0` no longer runs the
shadow pass (the picture is the same; the cost is gone). Three new keys:
`[environment] shadows = false`, `[environment] default_lights = false` (a
scene with no lights is lit by its ambient alone, not the built-in key and
fill), and `material.unlit = true`.
**What to do.** Nothing. A scene that kept a dummy zero-intensity sun only to
keep the built-in lights away can use `default_lights = false`.

### glTF `doubleSided` materials draw from both sides (#623)
**What changed.** A glTF material marked `doubleSided` is drawn, lit and
shadowed from both faces. The flag used to be ignored and back faces were
culled.
**What to do.** Check models whose export set `doubleSided` by accident: their
back faces now show and cost fill. Clear the flag in the asset.

### New for scripts
`audio_position(entity)` (#658), `quit_game()` (#659), `safe_area()` and
`is_touch_device()` (#660), `set_scale` and `set_visible` (#628), and a
`shear` on `transform` with `set_shear` / `clear_shear` (#625).

## 2026-11-09

### Sound, gamepads and file dialogs are Cargo features (#221)
**What changed.** `flint-player` has `audio` and `gamepad` features and
`flint-cli` has `audio`, `gamepad` and `dialogs`. All are on by default. The
workspace's device crates are declared with `default-features = false`.
**What to do.** A game binary that depends on `flint-player` with
`default-features = false` must name `audio` and `gamepad` (and `debug-hud`)
to keep sound, pads and the debug panels. With default features, nothing.

### A GLB with `LOD_0`, `LOD_1`... root nodes draws one level at a time (#193)
**What changed.** The importer recognises a chain of root mesh nodes named
`LOD_<n>` and switches between them by distance. Before, every level drew at
once. A chain that carries its own `extras.flint_lod` bands is left alone.
**What to do.** Nothing for trees made by `flint gen` with `[[lod]]` tables:
they now look right. A hand-made model whose nodes are named `LOD_<n>` but are
meant to draw together needs other names.

### Sprite text draws through the glyph atlas (#283, ADR 0113)
**What changed.** `ui_text.font` can name `builtin`, a glyph set (a
`.glyphs.toml`, so a TTF too) or a `.font.toml`. A `.font.toml` still works.
Its glyphs no longer pick up a sliver of the neighbouring cell when filtered.
**What to do.** Nothing. Text from a `.font.toml` may look very slightly
cleaner at its edges.

### A glyph ramp that steps backwards in ink is reported (#281)
**What changed.** A project glyph set whose ramp gives a brighter step less
ink than a darker one logs the offending pairs. `map = "coverage"` in
`[ramps.<name>]` re-orders a ramp by measured ink.
**What to do.** Nothing. Add `map = "coverage"` if the warning names your ramp
and the banding bothers you.

`flint export web <game>` packs any game as a folder a static server plays,
and `bundle.toml` gains `[web]` and `[mount]` (#106). `flint play` and
`flint-player` take `--width`, `--height`, `--position`, `--borderless`,
`--always-on-top` and `--no-activate` (#613).

### `--style` refuses a number outside its range (#355)
**What changed.** `flint render --style ascii:cell=400` (and `--style` on
`flint play`, `flint-player` and `flint edit`) fails with the allowed range. A
scene table with an out-of-range value warns and keeps the value.
**What to do.** Fix the value the error or warning names.

### Unknown `[post_process]` keys warn (#354)
**What changed.** A key in a scene's `[post_process]` that the engine doesn't
know is reported with the closest real name. It used to be ignored.
**What to do.** Read the warning: it is usually a typo that had been doing
nothing.

### Kuwahara's settings live in `[post_process.styles.kuwahara]` (#298)
**What changed.** `radius` (whole pixels, 1 to 8), `sharpness`, `hardness` and
`anisotropy` are keys of the style's table. The old flat `kuwahara_*` keys
still load and are folded into it; a table made that way is on only with
`kuwahara_enabled = true`, as before.
**What to do.** Nothing. Prefer the table in new scenes.

### A style colour is one key (#315)
**What changed.** `tint = [1.0, 0.7, 0.25]` or `tint = "#ffb340"` in a style's
table or a per-entity style component. On the command line,
`--style ascii:tint=#ffb340` or `tint=1/0.7/0.25`. The single channel keys
(`tint_r`, `tint_g`, `tint_b`) still read.
**What to do.** Nothing.

### The ASCII spike's flags are gone (#293)
**What changed.** `flint render --ascii=full|entity|entity-object`,
`--ascii-entities` and `--ascii-scene-background` were removed. `--ascii` is a
plain switch for the whole frame.
**What to do.** For ASCII on some entities only, give them an `ascii_style`
component (or a `style_mask`), or pass `--ascii-scope entities`; for the
object-anchored grid, `grid = "object"` or `--ascii-grid object`.
