# flint-cli: `flint render`, `flint edit`, `flint gen`, goldens, export (moved out of the root CLAUDE.md by #755)

The root file keeps the short edit -> validate -> play loop; this is the rest of it. The styles the flags switch on: `crates/flint-render/src/stylize/CLAUDE.md`. `flint play` and `flint-player` flags: `crates/flint-player/CLAUDE.md`. `flint bundle` and the vfs: `crates/flint-core/CLAUDE.md`.

## Output: `--json`, stdout and the exit path (#710)

- **`src/output.rs` is the one way out of a command.** `--json` is a global flag on `Cli` (main sets `output::set_json`); a subcommand never declares its own `--json` (clap would take it into the subcommand and the global would read false). Under it a command prints exactly one JSON document on stdout. The pieces: `output::emit(&impl Report)` (text or JSON, and `Err(Failed)` when `Report::failed`), `output::Answer::new(text, json).failed_if(b)` for a report built in place, `output::when_json(|| value)` for a command whose text is written as it goes, `output::document(&v)` / `document_text(s)` for one that builds its own, `output::format_or_json(&format)` for a command with its own `--format`. Human lines go through `say!` (`crate::output::say!`: stdout, or stderr once stdout is reserved by `--json` or `render --report json`); a line about work in flight through `progress!` (always stderr). render.rs and gen.rs keep their own `say!` macros, which also check `output::stdout_reserved()`.
- **Failures return, never `std::process::exit`.** A report that is a failure (check errors, a lookup with no answer, a style that fails) is printed and then `Err(output::failed())`; any other error is returned. `main` ends in `output::finish`: exit 0, or 1 with `Error: ...` on stderr and, under `--json` when no document was printed, `{"error": {"message", "causes"}}` on stdout. A clap error under `--json` is `{"error": {"message", "usage"}}` with clap's exit 2 (main parses with `try_parse_from`); `--help`/`--version` print as ever.
- **Window commands refuse `--json`** (`Commands::interactive` in lib.rs: play (unless `--list-keys`, #1184), serve, spline-edit, the music windows, preview, gen-preview, terrain-edit, tex-edit, prefab view; `edit_router::run` refuses unless it is a `--render` still, of any kind since #712, which answers `{"written": [path]}`; the scene viewer's load lines go to stderr for it). `render --watch` refuses it in main. `render`'s `--json` sets `--report json` (main, only when `--report` isn't given) and is filtered out of the words `--variant` re-parses.
- **A child process inherits stdout**: `export web`'s trunk build is pointed at stderr under `--json`; a new `Command` in a non-window command must be too. Library code on these paths writes stderr (`flint_asset_gen::batch::resolve_missing`, the renderer's `Loaded skybox`), and `ValidationReport::summary_text` returns what `print_summary` printed.
- **`tests/json_cli.rs` holds it**: in a project `flint init` makes, every command runs with `--json` and its whole stdout must parse as one value (renders, goldens and `edit --render` skip without a GPU); it walks `flint --help` at every depth and fails on a command that is neither run there nor in its `WINDOWS`. A new command adds a case or a window entry. `play_answers_json_only_for_its_key_table_wherever_json_goes` (#1199) runs `play` with `--json` on either side of it: `--list-keys` answers (the same bytes as `flint-player`'s, when its exe is beside flint's), a plain play is refused with exit 1.

## A game's own commands: `run_with` and `CliExtension` (#1140, ADR 0133)

- **flint-cli is a library and the `flint` binary.** `src/lib.rs` is what `main.rs` was (`Cli`, `Commands`, `run`, `stack_tests`); `src/main.rs` is `flint_cli::run_with(Vec::new())`. The public surface is `run_with` and `extension` only: every other module stays private, so a game can't reach into a command's internals. Unit tests under `src/` are `--lib` tests (`cargo test -p flint-cli --lib`).
- **One parser** (`run_with`): `extension::Added::new` collects each extension's `clap::Command`s and refuses a name or alias that is the engine's (a `Commands` name, hidden ones included, or alias, and `help`) or an earlier extension's; `Added::augment(Cli::command())` adds them; one `try_get_matches_from`; if `Added::owns` the chosen name, the default log, `output::set_json`, `set_project` (the one `--project` path, shared with `run`), the window refusal and `CliExtension::run`, through `output::finish`; else `Cli::from_arg_matches` and the old path. A parse error goes through `parse_failed` (the `--json` error document, then clap's exit). An extension answers with `extension::{emit, Answer, Report, document, failed, json, say}`, the `output` module's own. `extension::subcommands(|cmd: S| ..)` wraps a derived `Subcommand` (`Derived`, `.opens_window_when`).
- Test: `tests/cli_extension.rs` (`harness = false` in Cargo.toml) is a game binary: with `CLI_EXTENSION_GAME=game` its `main` is `run_with` with `hello` / `peek`, otherwise it spawns itself and checks help, text, `--json` on either side, `--project`, a failed answer, a clap mistake, the window refusal, `env --json` and a `render` clash. `extension::tests` holds the name checks and dispatch. A new engine top-level command can collide with a game's: that game's binary then refuses to start, naming it.

## `flint render` flags

**The list is `flint render --help`** (#708), grouped by heading: Output, Camera, Styles and post-processing, Quality and lighting, Time, Sequences, Sweep and variants, Measure and report, Refine a look, and Debug, lists, GPU and schemas. What a flag's values can be is asked of the binary too: `flint render --list-effects [--json]` (every `[post_process]` key with its kind, default and tuned range: each a `--set post.<key>=v`), `--list-styles --json` (every style and its keys: `--style <name>:k=v`, `--set <style>.<key>=v`; with a scene, its user styles too), `--look help` (every look and its tune sweeps) and `--style help`. Don't copy a flag list here again: it goes stale, and the help doesn't.

- **`--set KEY=VALUE`** (#708, `commands/render_post.rs`), repeatable: `post.<key>=v` is a `[post_process]` key, checked against the effects' descriptors (`flint_schema::post_effects`, #741) at parse, kind and all (`post.fog_color=0.7,0.75,0.82`, `post.fxaa=true`; a value past the tuned range draws and warns), written with `PostProcessConfig::param_mut(..).set(..)`. `<style>.<key>=v` is a key of a style's table, written with `StyleSpec::apply_settings`, which leaves the style on or off as it was (`--style` turns it on; `enabled`/`on`/`off` are refused); the style is checked once the scene's user styles are registered, as `--style` is. The keys are `--sweep`'s, one value each, and a `--set` of a key a `--sweep` turns is refused. A render's post is built in one order (`render_post::post_process_config`): the scene's block, the look and a sweep column's `post.` value as a table, then `--no-postprocess`, the deprecated `--render-mode`, `--set` in the order given, and `--style` last. The stage path lays `apply_flags` (the render mode and `--set`) again over a sweep column's preset `[boil]`.
- **The per-effect flags are gone** (#1144): the 67 that #708 hid (`render_post::LegacyPostArgs`, its `SPELLINGS` test and the three goldens that held them to their spellings went with them). `commands/render_retired.rs` is what's left: `RETIRED`, each old name and what it is now (`Now`: a post key, a post key that also switched its effect, a style key that turns the style on or leaves it, a switch), and `explained(clap_error, words)`, which turns clap's unknown-argument error for one into an error listing every old flag on the line with its `--set`/`--style` words (exit 2, as clap's; under `--json` the `usage` carries it). `lib.rs`'s `parse_failed`, `variants::parse_render` and a golden case's in-process parse call it. Its tests hold each row's spelling to parse and build a config. The deprecated `--render-mode` / `--mode-mix` / `--mode-params` (#746) are still flags, `render_post::RenderModeArgs` (`args.render_mode`), until #1036 retires them with the Rhai shim once Float is ported. `--ascii-text`, `--ascii-text-ansi`, `--pixels-per-point`, `--grain-time`, `--boil-time`, `--oren-nayar` and `--sheen-*` are not post keys and stay
- **`RenderArgs` is a struct a heading** (`commands/render_args.rs`): `args.camera.distance`, `args.clock.time`, `args.seq.frames`, `args.sweeps.sweep`, `args.measure.report`, `args.shading.msaa`, `args.out.watch`, `args.refine`, `args.debug`, `args.render_mode`; `scene`, `output`, `width`, `height`, `look`, `set`, `style` and `no_postprocess` are on it. A new flag goes in its heading's struct. It is for the stack: a debug build's derived `augment_args` is one frame of about 8 KB a flag, and the 130-flag struct needed 1346 KB to parse any `flint` command line, past Windows' 1 MB (about 600 KB now, 579 to 643 KB as top-level commands come and go; every `Commands` variant boxed, 1744 to 96 bytes, which moved nothing). `lib.rs`'s `stack_tests::the_parser_fits_in_windows_default_stack` holds it, and `cargo test -p flint-cli --lib stack_use -- --ignored --nocapture` measures it. Keep a struct to a dozen or so flags. The binary itself links 8 MB on Windows from `build.rs` (#990, however it's built: a game's root never reads the engine's `.cargo/config.toml`; `tests/stack_reserve_cli.rs` reads it off the exe), so the 1 MB test is headroom, not the limit; root CLAUDE.md has the measured use
- **`--frame-dump frame.json` and `--frame-capture out.flintframe`** (#1084, #1085, ADR 0126; `render_frame_dump.rs`, `args.measure.frame_dump` / `frame_capture`): the rendered frame's `FrameDescription` as JSON, and the same frame captured (`manifest.json` last, then `targets/NN-<target>.<ext>`). Both go through `arm()` before the frame (`describe_next_frame`, the timer on and recording for it; `capture_next_frame` with ctx's colour and depth textures, both `COPY_SRC`) and `write()` after the read-back (`Wanted` says which of the two). Still path: column 0; stage path: the first cell's last capture. Refused with `--frames`/`--mesh`/`--sweep`. With both, the JSON carries the capture's `capture` block; the last `-surface.png` is the -o PNG byte for byte (the same `image::save_buffer` encoder); `--report json` carries `frame_dump` and `frame_capture`. The `Captured ...` line ends its read-back clause with `CaptureDescription::gpu_copy_words()` (`copied in N ms on the GPU`, #1160; nothing on an adapter that can't time). Test: `tests/render_frame_capture_cli.rs` (the still's copies are all timed or none)
- **`--load-report`** (#1092; `args.measure.load_report`): `render` begins a `LoadKind::Render` load right after the scene check (a `SceneRead` note to `load_settled`), spans `host.context` as `Device` and each `new_headless` as `Renderer`, calls `bring_up_done` before the first draw (still path) or after the stages load (stage path), and `first_capture_done` after the first `draw_pixels` / `Stage::capture` finishes it and says the table (`say!`: stderr under `--report json`). `RenderReport::load` carries it (left out without the flag). Under `--variant` each variant's `render` begins its own. Test: `tests/render_load_report_cli.rs`
- **What the help can't say** (the code behind a flag): `--debug-mode` is one name table, `common_args::DEBUG_MODES` (#308; `style` runs `mask_view` alone and prints a legend, #263/#309/#334; `edges` shows ASCII's edge passes, #349). `--select` draws `flint_render::selection_outline` over the finished image (#602). `--gpu-time` keeps every frame raw (`GpuTimer::record`/`flush`, `gpu_timer::spread`, #292). `--mesh` bakes a multi-node GLB flat (`mesh_seq.rs`, #222). `--frames` is byte-identical run to run, and `--flip-stats` counts from the style's own grid (#345, #478). `--anim-time` is `flint_player::HeadlessAnimation` (#307, `tests/render_anim_cli.rs`). `--set post.motion_hold=12` is `tests/render_motion_hold_cli.rs` (#405). The deprecated `--render-mode` is `flint_render::render_mode` (#746; golden `render-mode-shim-matrix`). `--look` merges a look over the scene's block and a scene's own `look` goes under its keys (#279, #356, `flint_render::look::resolve`). `--report` and `--reference-text` measure in `look_measure.rs` (#357, #495); the ASCII grid reads back once a frame, so read it once and share it. `--ai-refine` goes through `CostMeter` (#357). `--sweep` is one `Sweep` type in `sweep.rs` and one sheet in `style_sheet.rs` (#353); a render with clocks draws a `Stage` a cell (#487, #596); `--sweep-crop` is `sweep::Crop` (#501); two `--sweep` make a grid (#358). `--variant` is `variants.rs` (#291: `args_override_self`; `--set` and `--style` add; `lib.rs` and `render_goldens` fill `RenderArgs::command_line`). `--watch` is `render_watch.rs` (#432: what it watches, `Written`, `Watch::redraws` for a still or sweep, a full render otherwise). `--style` and `--style-time` are also on `flint play`, `flint-player` and `flint edit scene.toml`, kept through transitions and hot reloads, and the web's `?style=` (#328). `--sweep post.<key>` refuses a value past the key's tuned range, where `--set` warns. `--time` spans, lists and `--scripts` are the next section

## `flint render` over time

- **Where a render path lives** (#1145): `render.rs` is `RenderHost`, `run`/`run_in`, the dispatch (`render()`: checks, the load, every column's post) and what every path draws with (`draw_pixels`, `bind_capture_scene`, `set_up_capture`, `still_inputs`); `render_still.rs` the one-renderer still and sweep (`render_still`, `StillRender`), `--gpu-time`, `--ai-refine` and the measures; `render_sequence.rs` `--frames`/`--mesh`; `render_stages.rs` the clocked path (`run_stages`, the stage sheet, `strip_sheet`); `render_stage.rs` `Stage`. Each is a child module of `render` (`#[path]`, as `replay_host`), so it shares render.rs's imports and `say!` through `use super::*`; what crosses modules is `pub(super)`. A new flag's code goes in its path's file
- **`flint render` over time** (#216) -- `run_stages` (`render_stages.rs`) loads a `Stage` per sweep column, each a world, renderer and clocks of its own. The world is a `flint_player::HeadlessGame` (#725): the player's game core, with every scene subsystem the player's files build (`start_subsystems`, #1252), whose living subsystem is the player's living-prop step with no window and no budget (`flint_living::LivingProps::step_now`); props are resolved (`resolve_procgen`) only in a scene with `living_prop` entities, whose plain renders were empty before; every other scene's plain render stays byte-identical. To match the player it keeps the authored camera position (going through `update_orbit` rounds it, which changed 7,000 pixels at 1280 x 720) and draws no grid. `--screenshot-at` has a tolerance, since 210 steps of 1/60 sum to a hair under 3.5. Stdout is the JSON report's: flint-cli's tracing goes to stderr, and so do the load path's progress lines, so a new `println!` on that path breaks `--report json`. GIFs go through `gif_writer.rs`, one palette and transparent unchanged pixels, because `image`'s encoder shimmers still pixels. Not a new dep: `gif` and `color_quant` were in the tree through `image`
- **Scripts in a capture** -- `--scripts` steps the `HeadlessGame` (the player's `GameCore` through `game_core::step`, with or without scripts; seeded `random()`, no `timestamp()`, name-ordered; what can't be drawn is warned). **The HUD is drawn** (#731): a `Stage` with scripts holds a `flint_player::HeadlessHud`, made before `start_scripts` so its measurer is the scripts' and the UI documents'; `capture` paints `game.hud()` (the last step's draw calls and UI documents) into `HeadlessContext::hud_view()` after `render_frame_to`. Scripts are told the screen in points (`width / pixels_per_point`). `--ui-show ID` (repeatable) and `--ui-focus ID` (`ClockArgs`, folded into `--scripts` by `fold_script_time`) show and focus elements after `start_scripts`, before the first step; an id no loaded document has is an error. Test: `render_scripts_cli::a_ui_document_is_drawn_over_the_capture` (exact pixels). Commands go through the core's dispatcher (#697): styles, tweens and boil tunes land on the renderer as asked and style reads see them the next step; `set_look` waits for the capture (`Stage::lay_script_requests`: every request since the last capture in the order asked, each fade from the frame at its own moment, #1157), then the post overrides. Particles made at load step on the clock (`Stage::step_particles_to`); what a capture can't do is `PRESENTATION_ONLY`. `--script-time T` is `--scripts --time T`, folded at the top of `render::run_in` (`fold_script_time`, #371) so goldens and variants get it; a render that doesn't run a scene's scripts names them (`scripts_not_run`). `--strict-scripts` (#693) implies `--scripts`, exits 1 after the picture when any stage's game has a script error, and `run_stages` merges every stage's `ScriptErrors` into stderr's `summary()` and `--report json`'s `script_errors` (`tests/render_scripts_cli.rs`). `--expression-timeline` feeds `expression()` on the render's clock and implies `--scripts`
- **Spans and moments** -- `--time 0..4 -o x.gif` shares one palette, so a still pixel never flickers; frames wait on disk as deflated deltas (`x.gif.frames~`), so memory stays flat (#588); `-o frames/f-%05d.png` writes a PNG a frame. `--time 2,5,9.5` is moments of one run, simulated once, each byte-identical to `--time <moment>` alone on the step (#614). `--strip` (#574, `render_args::StripArgs`; `render_plan::strip_times` / `strip_columns` / `check_strip_output`, `render_stages.rs::strip_sheet`, `style_sheet::compose` with `SheetText::per_row`, `compose_plain` for `--label off`) makes a span (a tile every `--every`, its end included when a step lands on it) or a list one PNG; `Stage::forget_history` before each tile's capture (style history, `captured`, `style_dt`) makes a tile byte-identical to `--time <t>` alone at the tile's size (default 640x360), ASCII history included (`render_time_cli::a_strip_is_a_sheet_of_its_moments_each_as_rendered_alone`). `--sweep wooze.<knob>` columns: `.preset` is a `wooze/<name>.wooze.toml` first, species tables and all (#249). `--sweep living.echoes.<count|spread|alpha>` (#531, `SweepKey::Echoes`) writes the value into each cell's own `SceneFile::tables["living"]["echoes"]` (`SweepGrid::lay_living`, in `run_stages` right after each cell's `load_settled`, before anything reads `[living]`), so a column is the scene with that table byte for byte; values are held to `EchoConfig::check` at parse; a scene with no living props is refused; it does not make the render a moment (`is_moment`), so the grid stays as on a plain render. `render_time_cli::an_echoes_sweep_draws_what_scenes_with_those_echoes_draw` finds each column, pixel for pixel, in the sheet. `--report json` is each living prop's lineage seed, pose indices, wooze values and every species value with the layer that set it (#246). `--shadow-resolution` defaults to 2048, the renderer's construction default, and is a real control since the texel-size upload (ADR 0049)

## `flint edit`

   ```bash
   flint edit levels/demo.scene.toml --spline      # Spline/track editor
   flint edit models/character.glb --watch         # Model previewer with file watching
   flint edit specs/stone_wall.procgen.toml        # Texture pipeline editor (if pipeline pattern)
   flint edit terrain.terrain.toml                 # Terrain editor
   flint edit fx/fire.particles.toml               # Particle effect editor (curves, forces, bursts, scrub timeline;
                                                   #   --preset fire|smoke|sparks|rain creates a missing file;
                                                   #   --render out.png --anim-time 1.5 = deterministic snapshot)
   ```
   Supported extensions: `.scene.toml`, `.chunk.toml`, `.procgen.toml`, `.terrain.toml`, `.particles.toml`, `.glb`, `.gltf`.
   **One host** (#712, `flint_viewer::host`): every editor is an `Editor` (`init` on a `Gpu` that is a window's or an offscreen target's; `orbit()`/`camera()`; `watched_files` (alone) / `watched_folders` (recursive) / `file_change_counts(path)` (asked on the frame's thread; a batch none of whose paths counts calls nothing) / `on_file_changed`; `early_event` before egui, `event` after; `update(Tick)`, `draw(&Target)`, `ui(&mut Ui)`; `still` for `--render`). `host::run` owns the one `initialize` (window, `RenderContext`, egui into `hud_view`, as #428), resizes (zero sizes skipped), surface loss, frame timing and fps, the debounced file watch, the shared orbit controller's mouse/WASD and O / `[` / `]` (an editor that returns `Flow::Handled` keeps a key), and runs egui. **The scene viewer and track editor are on the same orbit** (#1153): `ViewerApp::orbit()` returns its `OrbitCameraController`; it holds no orbit fields. What it needed is the controller's: `orbit_button` (the track editor's is `Middle`, its left picks points), `set_tool_under_pointer` (the viewer says before each left press whether the transform gizmo has it; that press never orbits), `snap_to` / `orbit_by` / `perspective` (the view cube: an eased snap, orthographic at once, left for perspective by the next orbit) and `Camera::PITCH_LIMIT` (1.56) for every editor. The viewer's `--watch` is `SceneWatch`: the scene file, its folder and the schema folders recursive, `file_change_counts` = not `StyleSources::owns` (#429), which owns the style folders themselves too: Windows reports a folder changed ~200 ms after a new file in it, as a batch of its own, and that reloaded the scene (main did too). The host logs each batch's paths at debug (`RUST_LOG=warn,flint_viewer=debug`). Its `event` keeps only its own keys and picking (a left click that moved at most `CLICK_SLOP` px picks) and passes the rest; `app_orbit_tests.rs` drives events in the host's order. It runs egui in **one pass** (`max_passes = 1`: an editor's `ui` applies what its panels report, so a second pass would act twice). `host::render_still` is `init`, the camera flags (`CameraFlags`, laid over the editor's framing), `still`, `draw`, read back; an editor whose still is images returns them (`host::image_sheet`: procgen textures, texture pipelines). `InitCx::window` is `None` for a still: the model previewer then poses only on request and the particle editor keeps the renderer's clear colour, so both stills are byte-identical to before #712. Each module has `editor(args) -> Result<App>`; `edit_router::Launch::go` opens it or writes the still. **Flags**: `edit_router::flag_kinds` is the one table of which `EditorKind` takes which flag (`--width`/`--height`/`--watch`/`--render` take all); `check_flags` turns anything else into an error naming where it applies, before a window or GPU. A procgen spec is `Mesh` or `Texture` by its generator's `output_kind` (`gen_preview::draws_images`). A new editor adds an `EditorKind`, its rows in the table and a `Launch::go`; `edit_router::tests::every_editor_opens_through_the_one_host` fails on a window, render context or egui-winit state made anywhere else in flint-cli or flint-viewer (`play_chart_window.rs` excepted). Tests: `tests/edit_render_cli.rs` (a still of every kind, a camera flag moving each view, flag errors).
   **Debug keys and F1, in the host** (#1170): an editor's F-keys are `Editor::debug_keys() -> Option<DebugKeyGroup>` (the player's `flint_runtime` types: action, default key, what it does), `debug_keys_live()` (off: dimmed on the card, the press passes on; the procgen previewer's need a mesh) and `on_debug_key(action)`. The host builds `host::debug_key_table(group, live)` (its own `HOST_KEYS`, F1 `keys`, first; `InputConfig::default()`, so no `[debug_keys]` rebinds in an editor) on each press in `window_event`, after egui and the WASD hold, before `Editor::event`: a hit never reaches the editor or the orbit, a repeat does nothing. F1 paints `flint_runtime::debug_key_card::paint` (the player's card, behind flint-runtime's `egui` feature) after `ui` and `overlay`. Viewer: `app::VIEWER_KEYS` (F2 `stats`, F3 `normal_arrows`, F4 `render_panel`); previewer: `gen_preview::PREVIEW_KEYS` (F2 `wireframe`, F3 `normal_arrows`, F4 `skeleton`, F5 `debug_mode`, once F1). `edit_router::tests::no_editor_matches_a_function_key_by_hand` fails on a `KeyCode::F<n>` in an editor source outside tests. Tests: `host::tests::f1_is_the_list_in_every_editor_and_the_viewers_keys_are_its_own`, `gen_preview::tests::f1_is_the_list_and_the_previewers_keys_are_f2_to_f5`.
   **Frame times for an editor that asks** (#1110): `Editor::times_frames()` is asked once a frame; while it says yes the host's `FrameTimer` laps `update`, `acquire`, `draw`, egui (`ui_ms`) and `present` and hands the frame to `Editor::frame_timed(&FrameTimes)` when the next begins (its wall time runs to there), with the monitor's refresh (asked once, again after `Moved`/`ScaleFactorChanged`). Saying no opens nothing: one branch a lap. The scene viewer says yes while F2 is open; `flint_viewer::panels::FrameStats` judges hitches (2x the median of 120 and median + 24 ms, on `GameClock::advance_wall`'s paced time) and draws `FrameGraph` with `band_legend_of`'s four bands. Tests: `host::tests::a_frame_nobody_asked_to_time_keeps_nothing`, `panels::frame_stats::tests`.
   **What an editor paints over its view** (#1154): `Editor::overlay(&egui::Context)` is part of the picture, not a panel. The window paints it after `ui` in the same egui pass (hidden with the panels by `show_ui`); `render_still` runs one egui pass of it alone (one pixel a point, clock 0) and paints it into `HeadlessContext::hud_view` (#428's display-space blend), and an editor that paints nothing gets no egui renderer or pass, so every other still is byte-identical. The track editor's spline, control polygon, points and index labels are its overlay (`ViewerApp::overlay` -> `SplineEditor::draw_overlay`), so `flint edit <scene> --spline --render` shows them as the window does. - **`--engine`**: `path` (default) names `built_from()` (`CARGO_MANIFEST_DIR/../..`, as `flint bundle`'s `engine_schemas` does) or `--engine-path`, absolute with forward slashes, in `flint.toml`'s `schemas` and `bundle.toml`'s `[mount] "engine/schemas"`; it is refused unless the directory has `schemas/components/transform.toml`. `subtree` names `engine/schemas` and prints the `git init` ... `git subtree add` lines: init never runs git or touches the network, and until the subtree exists every command fails with `schema directory not found` (the output says so). `none` lists only `schemas`: validate and render work (a component is a table with or without a schema), archetypes resolve to nothing, so `flint play` is not printed. - **Never deletes or overwrites**: a directory with files is refused without `--force`; with it, a file already there is kept and listed as kept.
- **The printed "Next steps" and the generated `CLAUDE.md` are tested as written** (`tests/init_cli.rs`): every printed `flint` line is run in a fresh project of each template (render: luma mean and spread, so a black or flat frame fails; then `--scripts --time 0.5` with no script error), every inline-code path in the guide must exist in the project (or, for `engine/...` in a subtree project, in this repo), every `flint <word>` must take `--help`, and every `flint` line in a code block is run. So a path or command added to a template must exist, and prose there says "Flint", not "flint", unless it names a command. `flint play` opens a window: the test resolves its default scene and the window is checked by hand (`flint-player --exit-after 2 --no-activate --screenshot x.png` in a fresh project draws the HUD too, which a headless render does not).

- `flint script api [--json] [--filter x]` (ADR 0116, #695, `commands/script.rs`): every function a script can call, from `ScriptSystem::new().api_listing()`. Declared ones (the builder's registry, by module) carry named parameters with kinds, the return's kind and shape, a one-line doc, and `typed` for `run_typed`; every engine function is declared, so the undeclared part (from Rhai's metadata: flint-cli turns on flint-script's `metadata` feature; `declared: false`, Rust parameter types, no names or docs) is only ever an extension's raw `rhai_engine_mut()` registration. - `flint script api --book [DIR]` / `--check-book [DIR]` (#695, `commands/script/book.rs`; DIR is the book, default `docs/book`): `--book` writes `src/reference/script-api.md` whole (conventions, callbacks, one table per module in declaration order, grouped since #1337 by the package that provides it: `book::by_package` over the manifests at `<book>/../../packages`, packages by tier then name, a module no manifest names under "No package", and with no manifests there the old flat list; a deprecated entry's row starts **Deprecated:** with its note, #702, and a chapter region leaves deprecated entries out, a selector naming only deprecated ones being an error) and the body of every `<!-- script-api:begin <selector> -->` ... `<!-- script-api:end -->` region in any chapter (selector: space-separated `module:<name>`, function names, or `callbacks`; an unknown name is an error). Both then run the ghost check: every `name(` in an inline span that opens with a call, `fn` or `let`, and in fenced blocks tagged `rust`/`rhai`/untagged that don't look like Rust (`looks_like_rust`: `use`/`impl`/`pub`/`#[`, `&mut`, `->`...), must be a declared function at a declared arity, a callback, a Rhai package function (`gen_fn_signatures(true)` less `(false)`) or keyword, a function some book example defines with `fn`, or allowed in `docs/book/script-api-allow.txt` (`page: names` for one page, a bare name for all; Rust, WGSL and the roadmap's proposals). Arity: a row's `f(a, b[, c])` claims 2 and 3, `..` claims nothing, and a bare `f()` in a prose span names the function rather than calling it. `--check-book` writes nothing and exits 1 on a stale page or any ghost; CI's headless job runs it (the binary `flint examples --check` built), and so does `scripts/ci.sh --full`. Compares in LF, writes LF. The book's `RHAI_KEYWORDS` and `package_signatures` are the checker's (`flint_script::check`)
- **`flint script check [dir|scene|file.rhai] [--json] [--schemas d] [--allow name]... [--api listing.json]...`** (#694, ADR 0116 step 4; `commands/script.rs` `check`, the pass in `check/scripts.rs`, the checker in `flint_script::check`, flint-script's `check` feature = `metadata` (Rhai's `internals`, the walk, is in every build since #692), which flint-cli turns on unconditionally so `--no-default-features` keeps it). It is `check::run(&subject, Checks::SCRIPTS)`: a dir is `Subject::project` (every scene's scripts, each with its scene's search, then every `.rhai` under the dir, `ScriptFile::found` guessing the scene folder as the one holding `scripts/`), a scene is `Subject::scene` (its scripts only: `scripts::of_scene` loads the world so a prefab's count, else reads the file's entities, and resolves each enabled `script.source` with `project.explain(Scripts, ..)`; a miss is `missing-asset` with `tried` unless the asset pass runs), a `.rhai` is checked alone. `Checks::scene_pass()` false skips `scene::check`. The checker compiles with `engine::compiler()` and the optimizer off, walks every statement and fn body (`Stmt::walk`; a `MethodCall`'s args are walked by hand, Rhai's walk skips them) and judges each call against: Rhai keywords, `--allow`, the file's own fns (a method call at n or n+1), the registry's entries at that arity (then literal kinds, `deprecated`, decision 5), extension raw registrations and `--api` names (`Api::add`), Rhai's packages (`gen_fn_signatures(true)` less `(false)`, `$` names dropped), a variable of that name (a fn pointer), a map literal's key (`obj.f()` on a closure). Else `wrong-arity` (declared signatures as the hint) or `unknown-function` (`diagnostic::did_you_mean` over every name; `alias::f` named when an import has it). `alias::f()` is held to the imported module's public fns; an unknown namespace is skipped. Imports resolve through `ModuleBase` (the player's), are reported `missing-module` with `tried`, and are checked as modules (`module: true`: no callback checks). Callbacks are the one table, `flint_core::callbacks::CALLBACKS` (the 16, #700), judged by `engine::instance::callback_problems`, which the engine's load warning uses too, so the two say the same thing: a callback with no definition at the table's count is `callback-arity`; an fn named `on_*` (or folding to a callback) that `diagnostic::closest` puts within reach of one, never called nor named in a string in the file, is `unknown-callback`. `mixed-numbers` (warning, decision 5): a non-typed declared fn with 4+ `num` params, called in `on_update`/`on_draw_ui` or a file fn they reach, whose literal args in num slots hold both ints and floats. `Diagnostic` gained `line`/`column` (`.at(l, c)`, serialized only when set, shown as `12:5` in `location()`); text is `file:line:col: error[code]: message` with `hint:`/`tried:` under it and `checked N scripts (M scenes): ...`; `--json` is `check::json` (`scripts` added) with that summary. The engine's API is built once a process (`scripts::engine_api`, a `OnceLock`); `ScriptApiArgs` (`--allow`, `--api`, flattened into `script check`, `check` and `validate`, which is now boxed in `Commands`) adds to a clone; `--api` reads `functions[].name` and `params` length. `Checks::ALL` and `Checks::VALIDATE` have `scripts: true` (`check::scene` takes the `Api`), `BUNDLE` not: a bundle of a game with extension functions packs. On the repo (2026-11-11): 69 scripts (55 of the examples, 10 `showcase_game/`, 4 templates) pass; the only findings were the showcase pause menus' 16 `draw_line` calls at 8 of 9 arguments, fixed. Tests: `flint_script::check::tests`, `tests/script_check_cli.rs`

## `flint profile`

- **`flint profile top | frame | explain | diff`** (#1098, epic #1094; `commands/profile/`, `Commands::Profile(Box<ProfileArgs>)`, a subcommand as ADR 0126 decision 7 made `flint frame` one): reads a scope trace (`flint-player --trace`, `--trace-on-hitch`, Shift+F3, a capture's `trace.json`; ADR 0128, #1097) and nothing else. A **summed record** (args `calls`, `worst_us`: `Scope::summed`, `calls()`, `worst_ns()`) is a leaf in `Thread::new` (never pushed as a parent) and counts as its calls in `per_frame` and `frame_tree`. `Trace::key(s, split)`: the name, plus a text detail with `split` (`script::call (scripts/stall.rhai)`), never a count (`Detail::Count`). `stats.rs`: `per_frame` (each frame's keys: inclusive, a scope inside its own key counted once; self; calls; worst), `quantile` / `mean_sd` over N frames where a frame a key didn't run in is 0, and `normal_frames` (`trace::stats`, shared with the tab's Compare: not the first or last covered frame, not a hitch on the track, not over `NORMAL_FACTOR` = 2x the median, not the frame asked about). Frames are named by the trace's own index; `pick_frame`: a number, `worst`, `hitch` (`Trace::meant_hitch_frame`, the profiler tab's frame: the hitch a `--trace-on-hitch` file was saved for, else the worst, of the covered ones; #1289). `explain.rs`'s answer is `Profile::carrier` over `baseline_except(Some(frame))` (the tab's Compare walk and medians, #1287): down the frame thread's paths from the frame's excess, into the child of largest excess while it carries `CARRIES` (half) of its parent's and at least `FLOOR_MS` (0.25), so the answer is the deepest scope that explains the frame; none -> the phase with the largest excess (`a wait, not work` for acquire/present). Its first line is `answer` in the JSON. `diff.rs` keys by name over each trace's frames but the edges; a delta under `NOISE_SE` (2) standard errors of the difference of means is `within_noise`, hidden unless `--all` (marked `~`). Each view builds text and a `serde_json` value from the same numbers; tables are `frame::table::Table`. Tests: `tests/profile_cli.rs` (each cause in `explain`'s first line, text against JSON for each view, refusals), the unit tests in each file, `json_cli.rs`' `profile` cases. ## `flint check` and the shared check module

- **One implementation, three callers** (#687, ADR 0115 step 5; `src/check/`, a module of the CLI crate beside `commands/`, since it needs `flint-scene`, `flint-constraint`, `flint-render`'s style and look loaders, `flint-procgen` and `flint-player` at once) -- `check::run(&Subject, Checks) -> Report { scenes, files, diagnostics }` reads everything through `flint_core::vfs`, so it runs over the disk and over a bundle's `MemorySource` alike. `Subject { root, files, scenes, schemas, strict, follow, preliminary }` is what is looked at, paths `/`-separated under `root`: `Subject::project(dir, files, flags)` (every scene under a folder; `files` is `bundle::project_files(dir)`, the default pack rules without `bundle.toml`'s excludes), `Subject::scene(path, flags)` (one scene; `follow` adds the scripts and prefabs it reaches), `Subject::packed(files, Schemas::Listed(dirs))` (a bundle; root `""`; `check_packed` sets its `allow` from the packed `flint.toml`, read inside `vfs::scoped`, so bundle and check leave out the same, #1060). `Checks { schema, files, styles, tables, constraints }` picks the checks: `Checks::ALL` is `flint check`, `Checks::BUNDLE` (no field-level schema pass, no tables, no constraints) is `flint bundle` (`bundle::check_packed`, inside `vfs::scoped`), `Checks::VALIDATE` (no files, no constraints) is `flint validate` through `check::scene(path, &SceneSchemas, checks, strict)`, which then evaluates the constraints itself because it can fix them. `SceneSchemas::resolve(scene, flags)` / `listed(dirs, scene)` is the registry, the directories and the constraints of those directories (`ConstraintRegistry::extend`, which keeps each constraint's file), with `problems`: a constraint file that doesn't read and each constraint whose query doesn't parse, as `bad-constraint`. **Never add a check to `bundle.rs` or `validate.rs`**: add it to `check/` under the `Checks` flag it belongs to (`tests/check_cli.rs::no_copy_of_the_checks_remains_in_bundle_rs` greps for the old function names)
- **What runs** (`check/scene.rs` per scene, `check/references.rs` per file): `flint_scene::diagnose` (parse, prefabs, archetypes, components, fields, and every reference a schema types, #684: `unknown-entity` for a `parent` or an `entity` field, `missing-asset` for an `asset` field, plus `not-a-child` for an `ik_two_bone.tip`; for an `ASSET_FIELDS` field its `missing-asset` is dropped when `Checks::files` runs, since that pass asks the catalog and specs first; the game's schema lints ride in `SceneSchemas::problems`); `load_scene_diagnosed` (`scene-load` when it fails and no dangling `parent` explains it); every inline `particle_emitter` of the loaded world through `flint_particles::EmitterDef::problems` (`bad-emitter`, under `Checks::schema`, #690; the schema pass's form diagnostics of that component are dropped for it); **assets by kind** (`ASSET_FIELDS`: `model.asset`, `material.texture`, `sprite.texture`, `audio_source.file`, `script.source`, `terrain.heightmap`/`splat_map`, `grass_ground.mask`, `spline.file`, `particle_emitter.texture`; plus `[environment] skybox` and `[scene] input_config`) through `Project::explain`, a miss being `missing-asset` with `Resolution::tried`, one diagnostic a (kind, name) with the other entities counted in the message; a name an `asset_def` of the scene declares passes (`flint_scene::declared_assets`, as in `diagnose`; #804); a model or texture is found first in the asset catalog (`flint_asset::HeldAssets`, the one catalog check `diagnose` shares, so `validate` and `check` agree), then as a procgen spec the scene can see (`Project::list(Specs)`, which must parse: `bad-spec`), then as a file, and `model.runtime = true` is skipped; **every other file-looking string** in a scene, prefab, particle effect, glyph set, chunk, user style and Rhai literal (`references.rs`, lifted whole from bundle: `looks_like_file`, `candidates` over every asset folder at each step of the walk, `missing-file` with the candidate list as `tried`; user styles (`StyleRegistry::for_scene`, once a scene directory, kept in `Memo` and read against for that directory's scenes, #742, messages split into file / line / text; loaded by `Memo::styles_for` before `diagnose_all`, so each style's component schema stands in for an open or missing one, #556: `with_style_schemas`, and a user style's `out-of-range` hint adds that it draws clamped), `[post_process.styles]` warnings, the look (`look::resolve`; its "Tried:" list becomes `tried`); `[wooze]` and `[living.species]`; the constraints (`constraint`, at the constraint's severity, `info` as a warning). `ASSET_FIELDS` stays a hard-coded list beside #684's `asset` type because it asks more than the type can say (the catalog, a spec that must parse, `model.runtime`, one diagnostic a name); a field typed `asset` that is not in it is still checked, by `diagnose`. Scripts: their string literals here, and `Checks::scripts` (#694) holds every `.rhai` to the script API (`flint script check`, above). ## The edit -> validate -> play loop (the root's examples, #992)

Flint uses an **edit -> validate -> play** loop:

1. **`flint render`** -- Headless scene-to-PNG snapshot. Primary validation tool for AI agents.
   ```bash
   flint render levels/demo.scene.toml --output test.png --width 1280 --height 720
   flint render levels/demo.scene.toml --output test.png \
     --distance 20 --pitch 30 --yaw 45 --target 0,1,0 --no-grid
   ```
   Every flag: `flint render --help`, `--list-styles --json`, `--look help`, and `crates/flint-cli/CLAUDE.md`.

2. **`flint edit <file>`** -- Unified interactive editor. Auto-detects file type and opens the right tool:
   ```bash
   flint edit levels/demo.scene.toml              # Scene viewer (hot-reload)
   flint edit models/character.glb                 # Model previewer (orbit camera)
   flint edit specs/oak_tree.procgen.toml          # Procgen previewer (mesh/texture)
   ```
   More: `crates/flint-cli/CLAUDE.md`.

3. **`flint gen`** -- Run a procedural generation spec to produce meshes (GLB) or textures (PNG).
   ```bash
   flint gen specs/oak_tree.procgen.toml -o tree.glb
   flint gen specs/stone_wall.procgen.toml -o wall.png
   flint gen specs/oak_tree.procgen.toml --dry-run
   flint gen flint-examples/rolling_meadow.terrain.toml -o terrain/   # terrain_v1: heightmap + splat PNGs, no window
   ```
   More, and the goldens: `crates/flint-cli/CLAUDE.md`.

4. **`flint play`** -- Full game runtime with physics, scripting, audio, and input.
   ```bash
   flint play flint-examples/phase4_runtime.scene.toml
   flint play flint-examples/phase4_runtime.scene.toml --width 1920 --height 1080
   ```
   More: `crates/flint-player/CLAUDE.md`.

5. **`flint capture`** -- A shot list (`[[shot]]` scene, seconds, look, input script) captured as
   deterministic frame sequences, each take a stepped `flint play`; `--verify` runs each twice and
   names the frames that differ, `--encode mp4` with ffmpeg. More: `crates/flint-cli/CLAUDE.md`.
   ```bash
   flint capture showcase_game/trailer.shots.toml --verify --encode mp4
   ```

**For AI agents:** Before playing, rendering or bundling, `flint check <dir|scene> [--json]` is the pre-flight (#687): every problem of a project in one run, each with its file, entity, field, a hint and the paths tried, exit 1 on an error, scripts included (`flint script check` alone gives each script's mistakes as `file:line:col`, #694; `crates/flint-cli/CLAUDE.md`). Every command that opens no window takes the global `--json` (#710): exactly one JSON document on stdout, everything else on stderr, exit 1 on a failure with the report or an `{"error": ...}` document still on stdout; read answers from it, not from the text (`crates/flint-cli/CLAUDE.md`, "Output"). After a gameplay change, `flint playtest <scene> --input-script <file>` (#714) plays it headless on a fixed clock and fails on what didn't happen: an input script's `expect` / `wait` lines, the scripts' `test_assert` / `test_fail`, any script error; one JSON report, byte-identical run to run (`crates/flint-player/CLAUDE.md`, book: guides/playtesting.md). After visual changes, always run `flint render` to verify before moving on. The render command loads models (found by the project's one asset search: `models/` beside the scene, beside each directory up to the project root, then `engine/`; `flint asset where models <name> --scene <scene>` shows it), generates geometry, and computes the full transform hierarchy.

## Windows' stack and the clap parser (from the root's gotchas, #992)

- Windows gives a main thread the stack its exe asks for, 1 MB unless linked otherwise. **`flint` and `flint-player` ask for 8 MB in their `build.rs`** (`main_thread_stack`, #990: `/STACK:8388608` on msvc, `-Wl,--stack,8388608` on gnu), so they carry it however they're built: cargo reads `.cargo/config.toml` only from the directory it runs in and its parents, so a game building the engine from its own root (`--manifest-path engine/Cargo.toml`) never read the engine's and linked 1 MB. `tests/stack_reserve_cli.rs` and flint-player's `tests/stack_reserve.rs` read the 8 MB off each built exe. `.cargo/config.toml`'s entries stay, for the checkout's other binaries, tests and examples; a build script reaches only its own package, so a game binary asks in its own `build.rs` (book: guides/player-extensions.md). Measured on 1 MB copies of a debug build (#990, `editbin /STACK`): `flint --help`, `render --help`, `check`, `script check` and a still `render` each need 651 KB (the parser), `render --scripts --time 0.5` of a `flint init` scene 778 KB (Rhai's evaluation recurses: a deeper script goes past 1 MB), `flint-player --help` 397 KB, and `flint-player` playing that scene for 2 s 905 KB: a debug game binary is about 120 KB from the edge. A release build needs 31 KB for `--help` and 270 KB for either run. The clap parser was what overflowed (a derived `augment_args` is one frame of about 8 KB a flag in debug: 1346 KB while `flint render` was one 130-flag struct, about 600 KB (579 to 643 as commands come and go) since #708 made a struct a help heading and boxed every `Commands` variant). Keep an `Args` struct to a dozen or so flags; `stack_tests::the_parser_fits_in_windows_default_stack` in `lib.rs` fails past 1 MB.
