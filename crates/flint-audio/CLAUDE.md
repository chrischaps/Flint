# flint-audio: audio clock, decoding, device features (moved out of the root CLAUDE.md by #755)

Web audio (the worklet mixer): `crates/flint-player/CLAUDE.md`. The device-features note covers flint-music, flint-input-capture and flint-cli too.

- **Audio clock** (#658) -- Rhai `audio_position(entity)` (seconds into an `audio_source`'s playing sound, wrapped for a loop; -1 before it's mixed and after it ends) and `audio_output_latency()` (the browser's figure, -1 on the desktop). `AudioSync::sample_positions` runs every frame before scripts, paused or not; each source's `flint_audio::clock::PlayClock` runs kira's per-callback position on between samples. On the web the sync `watch()`es each source's voice (`Command::VoiceWatch`), the worklet's `Mixer::report` is posted every 1024 frames stamped with `currentTime` at the quantum's start (kira's position is where its last 128-frame chunk began), lands in `Link::receive_report`, and the page reads the context's `currentTime` through `Link::clock`. Demo `examples/audio_clock.scene.toml`
- Decode sounds with `flint_audio::decode::decode_all` / `Decoding` (gapless, #632), not kira's `StaticSoundData::from_cursor`, which keeps a Vorbis stream's end padding (+64 to +840 frames) and so gaps a loop at every wrap. symphonia 0.5 trims that only on streams of several Ogg pages, so `Decoding` also stops a Vorbis stream at its stated length. ffmpeg trims it too, so check a loop's length through Flint, not ffmpeg. flint-music's stems still use kira's loader
- Device crates are features (#221): kira's `cpal` is flint-audio/flint-music `device`, gilrs is flint-input-capture `gamepad`, rfd is flint-cli `dialogs`; the workspace declares flint-audio/music/input-capture/player with `default-features = false`, so a dependent names what it wants. Read pads through `flint_runtime::pad` (gilrs, or an uninhabited stand-in; `flint-runtime`'s `gamepad` feature is off by default, flint-player's and flint-input-capture's turn it on, #748), never `gilrs` directly, and file dialogs through flint-cli's `file_dialog::FileDialog`
- **`audio_source` and `audio_trigger` are read through the typed view** (ADR 0115 step 4, #685; `crates/flint-core/CLAUDE.md`) -- `world.view(id, comp::AUDIO_SOURCE)` in `AudioSync::sync_new_sources` and `read_audio_params` (every frame per synced source: the happy path takes no lock). `bus` is a `choice` over `Bus::NAMES` (`sfx`, `music`); an unknown one is reported once and plays on sfx, as it always did. A source waiting for a late sound is re-read every pass and still reports once. Test without a device: `AudioEngine::silent()` + `start_remote(Link::default())` is "available" (`an_unknown_bus_and_a_wrong_volume_are_reported_once`)
