# flint-core: vfs, hot reload, transform shear, the project (moved out of the root CLAUDE.md by #755)

The root file keeps the vfs rule in short. The wooze field (`flint_core::wooze`): `crates/flint-procgen/CLAUDE.md`. Quality settings (`flint_core::quality`): `crates/flint-render/CLAUDE.md`.

- **Every runtime read goes through `flint_core::vfs`** (#97) -- `vfs::read` / `read_to_string` / `read_dir` / `exists` / `is_file` / `is_dir`, never `std::fs` or `Path::exists` in a runtime crate. The default source is the disk; the web player installs a `MemorySource` filled from a game bundle (`vfs::install`; `flint bundle <game>` packs one, `flint_core::bundle` is the format, `flint-player --bundle` plays one natively, audio arrives in a late bundle and `vfs::generation()` tells the player to load it; docs/design/web.md), and tests use `vfs::scoped` (this thread only). Decode images with `flint_render::open_image` (not `image::open`) and glTF through `flint_import::import_gltf` (not `gltf::import`), both of which read via the vfs. Writes (scene save, saves, replays) and hot-reload mtime polling stay on `std::fs`, natively; input overrides go through `flint_player::user_files` (OS config dir, or `localStorage` on the web, #100), and on the web so does the `persist_*` store (`save_<game_id>.toml`, #104). Tests and the CLI keep `std::fs`
- **Hot reload never waits on the disk** (#633) -- every reload poll (scripts and `scripts/lib`, UI documents, user styles, glyph sets, palettes, style images) asks `flint_core::file_watch` (`stamp` / `modified` / `list` / `tree`), never `std::fs::metadata`. Direct mode (the default: tools, tests) stats then and there; the player's `file_watch::start()` (in `resumed`) switches to a watcher thread that publishes a change once a file held still for two 250 ms looks and was read through once; `--no-hot-reload` / `file_watch::disable()` is Off. A poll's baseline stamp must come from `file_watch` too, or the cached and direct answers never agree. Scripts read and compile on `flint-script`'s `reload_worker` thread (`engine::compiler()`, a bare engine with Flint's parse limits: keep a parser setting there, not in `ScriptEngine::new`), reading with `file_watch::read_settled`; a changed lib is compiled there into `VfsModuleResolver::with_compiled`
- **Transform shear** (#625) -- optional `transform.shear = { xz = 0.25 }` (any of `xy xz yx yz zx zy`, `ab` = how far a moves per unit of b), composed `T * R * H * S` in `Transform::to_matrix` (`flint_core::Shear`; no shear is bit-identical to before). Renderer needs nothing more: normals use `mat4_inv_transpose`, culling `transform_aabb`, both general. Rhai `set_shear(id, map)` / `get_shear` / `clear_shear`; physics warns on a skewed world matrix (`mat4_skew`) and ignores it. Demo `demo/shear_road.scene.toml` (generated by `demo/tools/shear_road.py`, `--yaw` writes the gapped before)
- **Project and manifest** (ADR 0114, #706) -- `flint_core::project::Project { root, found, id, schemas, scene, input }`, over the vfs: `Project::discover(scene_or_dir)` walks up to a `flint.toml`, a `.flint/` or `schemas/` + `scenes/`|`levels/` (an engine checkout passes through to the game above), then reads `flint.toml`'s `[project]` (`id`, `schemas`, `scene`, `input`; all optional; a wrong type or unknown key is a `ProjectError` naming file and key). `Project::current()` / `for_path(scene)` honour the CLI's global `--project <dir>` (`Project::at` + `project::set_override` in `main.rs`). A relative start is joined to the working directory only when that directory is in the file source; in a bundle it is walked as given. `flint_asset::ProjectStore` (a trait to import) adds the `.flint/` store paths. **One schema resolver** (step 2): `project::schema_dirs(scene: Option<&Path>, flags) -> Result<SchemaDirs { dirs, source }, SchemaDirsError>` is the only place the directories are decided: `--schemas` flags if any (the whole list), else the manifest's `schemas` under the root (`SchemaSource::Manifest(file)`), else discovery (`schemas/` in the working directory, beside the scene, one level up; only what exists, maybe none). A directory a flag or the manifest names that isn't there is `SchemaDirsError::Missing { dir, named_by }`; `FlintError::SchemaDirs` carries it. `flint_schema::SchemaRegistry::resolve(scene, flags) -> (registry, dirs)` builds the registry; the CLI's `common_args::load_schemas`, the viewer's `flint_viewer::app::load_schemas` (schemas + constraints of every dir, #704) and `flint-player` call it, and a new command that loads schemas must too (its `--schemas` is a `Vec<String>` with no default, so "no flags" is visible). `host_schema_dirs(listed, scene)` is a list the host settled (a bundle's manifest, `PlayerApp::set_schema_paths`): existing ones plus what's beside the scene, never an error. The player keeps a `SchemaDirs` (`set_schema_dirs`) and asks `for_scene(next)` at a transition or chunk: flags stay, a manifest is re-read for the new scene's project, discovered and host lists grow. For one release (decision 3, #765) `SchemaDirs::dropped` lists the `schemas/` near the scene that flags used to gain and no longer do (compared by `same_dir_key`), and play/render/validate/spline-edit/`flint-player` print `dropped_warnings()` on stderr; remove both with the warning. `flint-android` still builds its own two-directory list. Nothing consumes `scene`/`input` yet, and `flint init` writes no manifest
- **One asset resolver** (ADR 0114 step 3, #706; `project/assets.rs`) -- `project.resolve(AssetKind::Particles, "fire", &scene_dir) -> Result<PathBuf, NotFound { kind, name, tried }>` is the one search, over the vfs: `D/<folder>/<name><ext>` for `D` = the scene's directory, each directory above it up to and including the root, then `<root>/engine` (`engine_mount()`: only if that directory exists, never in `Found::Engine`). A kind is data, `AssetKind::info() -> &KindInfo { label, noun, folders, extensions }`, and the walk never branches on the kind: a new kind is an enum variant, a `static KindInfo` and its entry in `AssetKind::ALL` (which `flint asset where --help` and the book's table follow). A name ending in one of the kind's extensions is taken as written; a name may carry subfolders. `explain` is `resolve` with its working shown and nothing logged (`Resolution { found, tried, order_change }`, what `flint asset where` prints); `list(kind, scene_dir)` is every file visible by the same rule, a nearer name hiding a farther one (files directly in the folder only); `search_dirs` the folders in order, existing or not. Paths keep the scene directory's spelling (relative stays relative, which is what a bundle needs) and go absolute only when the spelling runs out; print them with `project::shown` (forward slashes). Two edges, the same for every kind: a scene outside the root is searched beside itself, then the root, then the engine; and a `Found::Fallback` project (no marker, root = the scene's directory) also searches one level above the scene, since with no manifest the engine behaves as it did. `Project::for_scene(scene)` is `for_path` for a loader that must carry on: a bad manifest is a warning and the project without it. TEMPORARY, for one release (decision 3, #765): `KindInfo::old_rule` is a kind's search before the one rule, as `fn(name, scene_dir) -> Option<PathBuf>`; when it would have picked another file than the one rule does (compared by `same_dir_key`; the old rule finding none is not a change), `resolve` and `list` log an `OrderChange` through `tracing::warn!` once a process per (kind, name, old, new), never on stdout. Particles' is `old_particles` (first of `particles/` beside the scene or one level up that exists, and only that folder). Remove `old_rule`, `OrderChange` and `Resolution::order_change` with the schema `dropped` warning. **Kinds on it** (`AssetKind::ALL`): `Particles`; `Models` (`models/`, `.glb` `.gltf`); `Textures` (folders `""` then `textures/`; extensions `""`, `.png`, `_color.png`; named by file); `Sprites` (`sprites/` then `""`; no extensions; named by file); `Animations` / `SpriteAnimations` / `Sequences` (all `animations/`; `.anim.toml` / `.sprite.toml` / `.sequence.toml`); `Audio` (`""` then `audio/`; `.ogg` `.wav` `.mp3` `.flac`; named by file). Three things the walk gained for them, each the same for every kind: (1) a folder of `""` is the walk's directory itself (how `audio/hit.ogg` and a loose `wall.png` are found), searched by `resolve` but never by `list`, which is of named folders only; (2) `KindInfo::named_by_file`: a name with a dot in its last part is a file name taken as written, and `Listed::name` is the whole file name (`hit.ogg`), otherwise a name is a stem; an extension of `""` is the bare name; extensions match as spelled; (3) the **as-written step**, first: a name that is a path of its own (starts `./` or `../`, or is absolute or rooted) is tried from the scene's directory with the kind's extensions, then a relative one goes through the walk and an absolute one nowhere else. `candidates(kind, name, scene_dir)` is the whole ordered list, each path once, and `tried` is its prefix. A kind loaded as a whole (the three animation kinds, the audio preload) also has TEMPORARY `KindInfo::old_list`, the files its old loader took: `list` compares the two lists (`list_order_changes` returns them unlogged), which catches a file the old search loaded and the one rule no longer reaches; kinds without it are compared name by name. The catalog and procgen stay ahead of the file search for models and textures and outside the resolver (`ModelLoadConfig::overrides`, `asked_first`). `tests/demo_asset_sweep.rs` runs every asset the engine's 88 scenes name through `explain` and fails on any order change. Not on it yet: scripts, specs, prefabs, wooze presets, input configs, fonts, glyph sets, palettes, looks, paper/stroke images, user styles; and the path-named scene files (terrain heightmap and splat, grass mask, skybox, spline files, a particle effect's texture), which still try the scene's directory then its parent. A new kind converts by adding its row, expressing its old search as an `old_rule`, and calling `resolve`/`list` from its loader with the host's `Project` (the player's `PlayerApp::project()`; `Project::for_scene` elsewhere); it gets a nested-scene test and a row in the book's table (concepts/assets.md)
