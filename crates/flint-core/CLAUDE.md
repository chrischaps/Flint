# flint-core: vfs, hot reload, transform shear, the project (moved out of the root CLAUDE.md by #755)

The root file keeps the vfs rule in short. The wooze field (`flint_wooze`): `crates/flint-procgen/CLAUDE.md`. Quality settings (`flint_core::quality`): `crates/flint-render/CLAUDE.md`.

- **Every runtime read goes through `flint_core::vfs`** (#97) -- `vfs::read` / `read_to_string` / `read_dir` / `exists` / `is_file` / `is_dir`, never `std::fs` or `Path::exists` in a runtime crate. The default source is the disk; the web player installs a `MemorySource` filled from a game bundle (`vfs::install`; `flint bundle <game>` packs one, `flint_core::bundle` is the format, `flint-player --bundle` plays one natively, audio arrives in a late bundle and `vfs::generation()` tells the player to load it; docs/design/web.md), and tests use `vfs::scoped` (this thread only). Decode images with `flint_render::open_image` (not `image::open`) and glTF through `flint_import::import_gltf` (not `gltf::import`), both of which read via the vfs. Writes (scene save, saves, replays) and hot-reload mtime polling stay on `std::fs`, natively; input overrides go through `flint_player::user_files` (OS config dir, or `localStorage` on the web, #100), and so does the `persist_*` store on every platform (#726; `save_<game_id>.toml` on the web, #104). Tests and the CLI keep `std::fs`
- **Hot reload never waits on the disk** (#633) -- every reload poll (scripts and `scripts/lib`, UI documents, user styles, glyph sets, palettes, style images) asks `flint_core::file_watch` (`stamp` / `modified` / `list` / `tree`), never `std::fs::metadata`. Direct mode (the default: tools, tests) stats then and there; the player's `file_watch::start()` (in `resumed`) switches to a watcher thread that publishes a change once a file held still for two 250 ms looks and was read through once; `--no-hot-reload` / `file_watch::disable()` is Off. A poll's baseline stamp must come from `file_watch` too, or the cached and direct answers never agree. Scripts read and compile on `flint-script`'s `reload_worker` thread (`engine::compiler()`, a bare engine with Flint's parse limits: keep a parser setting there, not in `ScriptEngine::new`), reading with `file_watch::read_settled`; a changed lib is compiled there into `VfsModuleResolver::with_compiled`
- **Transform shear** (#625) -- optional `transform.shear = { xz = 0.25 }` (any of `xy xz yx yz zx zy`, `ab` = how far a moves per unit of b), composed `T * R * H * S` in `Transform::to_matrix` (`flint_core::Shear`; no shear is bit-identical to before). Renderer needs nothing more: normals use `mat4_inv_transpose`, culling `transform_aabb`, both general. Rhai `set_shear(id, map)` / `get_shear` / `clear_shear`; physics warns on a skewed world matrix (`mat4_skew`) and ignores it. Demo `examples/shear_road.scene.toml` (generated by `examples/tools/shear_road.py`, `--yaw` writes the gapped before)
- **Project and manifest** (ADR 0114, #706) -- `flint_core::project::Project { root, found, id, schemas, scene, input, strict, save_version }`, over the vfs: `Project::discover(scene_or_dir)` walks up to a `flint.toml`, a `.flint/` or `schemas/` + `scenes/`|`levels/` (an engine checkout passes through to the game above), then reads `flint.toml`'s `[project]` (`id`, `schemas`, `scene`, `input`, `strict`, `save_version`; all optional; a wrong type or unknown key is a `ProjectError` naming file and key). `Project::current()` / `for_path(scene)` honour the CLI's global `--project <dir>` (`Project::at` + `project::set_override` in `main.rs`). A relative start is joined to the working directory only when that directory is in the file source; in a bundle it is walked as given. `flint_asset::ProjectStore` (a trait to import) adds the `.flint/` store paths. **One schema resolver** (step 2): `project::schema_dirs(scene: Option<&Path>, flags) -> Result<SchemaDirs { dirs, source }, SchemaDirsError>` is the only place the directories are decided: `--schemas` flags if any (the whole list), else the manifest's `schemas` under the root (`SchemaSource::Manifest(file)`), else discovery (`schemas/` in the working directory, beside the scene, one level up; only what exists, maybe none). A directory a flag or the manifest names that isn't there is `SchemaDirsError::Missing { dir, named_by }`; `FlintError::SchemaDirs` carries it. `flint_schema::SchemaRegistry::resolve(scene, flags) -> (registry, dirs)` builds the registry; the CLI's `common_args::load_schemas`, the viewer's `flint_viewer::app::load_schemas` (schemas + constraints of every dir, #704) and `flint-player` call it, and a new command that loads schemas must too (its `--schemas` is a `Vec<String>` with no default, so "no flags" is visible). `host_schema_dirs(listed, scene)` is a list the host settled (a bundle's manifest, `PlayerApp::set_schema_paths`): existing ones plus what's beside the scene, never an error. The player keeps a `SchemaDirs` (`set_schema_dirs`) and asks `for_scene(next)` at a transition or chunk: flags stay, a manifest is re-read for the new scene's project, discovered and host lists grow. For one release (decision 3, #765) `SchemaDirs::dropped` lists the `schemas/` near the scene that flags used to gain and no longer do (compared by `same_dir_key`), and play/render/validate/spline-edit/`flint-player` print `dropped_warnings()` on stderr; remove both with the warning. `flint-android` still builds its own two-directory list (`data_dir/engine/schemas`, `data_dir/schemas`; unbuildable here, left as it was). **Every manifest key has a reader**: `schemas` (above); `scene` is `Project::default_scene()`, what `flint play` / `flint-player` open with no scene argument (`NoDefaultScene`'s message says what to pass) and `flint bundle`'s start scene when `bundle.toml` has none; `id` is the bundle's name when `bundle.toml` has none (`commands/bundle.rs::read_project`; `flint export web` follows); `input` is the player's game input layer (`player_app/input_config.rs`); `strict` (a bool) is read by `flint_scene::diagnose`, which makes `unknown-field` an error (ADR 0115); `save_version` (a whole number, 0 unsaid) is the version the game's saves are at, which the player gives the `persist_*` store (#726). `flint.toml` is packed into a bundle, where `Project::discover` reads it through the vfs (`tests/project_done_when_cli.rs`). `flint init` writes the manifest (#707; `crates/flint-cli/CLAUDE.md`)
- **The project root, for paths that are not searches** (`project/root.rs`, #706) -- `project.root_for(scene_dir)` is the directory a path "from the project root" is joined to: `root`, except for a `Found::Fallback` project, which keeps `guessed_root(scene_dir)`, the scene directory's parent, since with no marker the engine behaves as it did. `guessed_root` is the ONE copy of the old "scene dir's parent" guess; nothing outside `flint_core::project` may derive a root from a scene path (deriving the scene's *own* directory from its file is fine). Its callers: `load_ui` / `load_data` (`ScriptCallContext::project_root_holding`; the project arrives with `ScriptSystem::set_current_scene(path, &project)`), `music_session`'s base, the save file of a game with no id (`flint-player`'s `persist.rs`: `<root_for>/save/persist.toml`; a game with `[project] id` saves under the OS user directory instead, #726, `crates/flint-player/CLAUDE.md`), the procgen disk cache (`<root_for>/.flint/procgen-cache`) and the project-local input override (`<root_for>/.flint/input.user.toml`). What the engine writes goes under `root_for` so a `.flint/` it makes marks the root already in use. Known edge, not changed here: the nearest marker wins, so a `.flint/` beside nested scenes (an old procgen cache) is a root of its own and hides a `flint.toml` above it

- **One asset resolver** (ADR 0114 step 3, #706; `project/assets.rs`) -- `project.resolve(AssetKind::Particles, "fire", &scene_dir) -> Result<PathBuf, NotFound { kind, name, tried }>` is the one search, over the vfs: `D/<folder>/<name><ext>` for `D` = the scene's directory, each directory above it up to and including the root, then `<root>/engine` (`engine_mount()`: only if that directory exists, never in `Found::Engine`). A kind is data, `AssetKind::info() -> &KindInfo { label, noun, folders, extensions }`, and the walk never branches on the kind: a new kind is an enum variant, a `static KindInfo` and its entry in `AssetKind::ALL` (which `flint asset where --help` and the book's table follow). A name ending in one of the kind's extensions is taken as written; a name may carry subfolders. `explain` is `resolve` with its working shown and nothing logged (`Resolution { found, tried, order_change }`, what `flint asset where` prints); `list(kind, scene_dir)` is every file visible by the same rule, a nearer name hiding a farther one (files directly in the folder only); `search_dirs` the folders in order, existing or not. Paths keep the scene directory's spelling (relative stays relative, which is what a bundle needs) and go absolute only when the spelling runs out; print them with `project::shown` (forward slashes). Two edges, the same for every kind: a scene outside the root is searched beside itself, then the root, then the engine; and a `Found::Fallback` project (no marker, root = the scene's directory) also searches one level above the scene, since with no manifest the engine behaves as it did. `Project::for_scene(scene)` is `for_path` for a loader that must carry on: a bad manifest is a warning and the project without it. - **Scene diagnostics** (ADR 0115 step 2, #683; `diagnostic.rs`) -- `flint_core::Diagnostic { severity, code, file, entity, component, field, message, hint }` with `Severity::{Error, Warning}` is the one shape for what is wrong with a scene; `Serialize` only (`code` is a `&'static str`). Built with `Diagnostic::error(code, msg)` / `warning` then `.file() .entity() .component() .field() .hint()`. **Codes** are the consts of `diagnostic::codes`, each with a row in `codes::ALL` (code, the severity it is raised with, meaning; a test holds the two together and the book's table in concepts/schemas.md follows it): `unknown-field` (the one warning a game meets; `promote_strict` makes it an error for `--strict` / `[project] strict`), `bad-type`, `bad-enum-value`, `out-of-range`, `missing-field`, `unknown-component`, `unknown-archetype`, `toml-parse`, `file-unreadable`, `bad-prefab`, `no-schemas`. A code never changes meaning; a new problem gets a new one. `Display` is `error[bad-type] entity 'crate' collider.friction: expected f32, got string` (no file, no hint: `one_line()` adds both, `flint validate` puts the hint on its own line). `summary_lines(scene, list, limit)` / `log_summary` (through `tracing::warn!`, `SUMMARY_LIMIT` = 5) are what a load prints: one count line, the first few with errors first, "... and N more". `closest(name, candidates)` / `did_you_mean` are the suggestion rule (same letters in another case or with `_`/`-` moved, else edit distance within a third of the name's length, 1 to 3, a swap of neighbours counting once; ties to the first by name so a HashMap's order never shows). **Who produces it**: `flint_schema::validate_component(schema, data) -> Vec<Diagnostic>` (every problem of one component table, component and dotted field set: `points[2]`, `position[1]`; missing required fields by name, then written fields by name; a schema with **no fields is open** and checks nothing, which is how a game declares a script-only component; `validate_component_data` is the old first-error `Result` over it, and `FlintError::InvalidFieldType` / `InvalidEnumValue` carry `field`), and `flint_scene::diagnose(scene_file, registry, project) -> Vec<Diagnostic>` (reads through the vfs, never stops early: unreadable file, parse error, prefab that won't expand, then `diagnose_scene(&SceneFile, file, registry)` over the expanded entities in name order: unknown archetype, unknown component, each component's fields; a `missing-field` that an archetype default or the field's own default supplies is dropped; an empty registry is one `no-schemas`, not an error per table; applies `project.strict`). **Who prints it**: every `flint_scene::load_scene` / `reload_scene` / `load_scene_string` logs the summary once and loads anyway (`load_scene_diagnosed` returns the list and logs nothing); the player's `load_chunk` does the same for a chunk; `flint validate` prints all of it and exits 1 on an error. A scene's TOML parse error names the file (`FlintError::TomlParseError("<file>: ...")`). Entity-reference and asset checks and the new field types are the next bullet (#684). `Diagnostic::tried` (#687) is every path looked at for a file that is not there (empty otherwise; `.tried(paths)`); `codes::ALL` has `flint check`'s fourteen codes after the scene's, the typed view's and #684's seventeen (`missing-file`, `not-a-child`, `scene-load`, `bad-manifest`, `bad-schemas`, `bad-constraint`, `constraint`, `bad-user-style`, `bad-style-setting`, `bad-look`, `bad-wooze`, `bad-species`, `bad-input-config`, `bad-spec`; 31 in all, and `flint check` raises `missing-asset` too, from its own asset pass). `not-a-child` (an `ik_two_bone.tip` whose `parent` is not the entity naming it) is raised by `diagnose_scene_in` beside the references; a prefab that does not expand silences `unknown-entity` in `diagnose`, since its entities are the names that went missing. The rest come from the CLI's `check` module (`crates/flint-cli/CLAUDE.md`). Not here yet: scene-level tables (#686), a viewer panel. A schema file with any key under `[component.x]` but `description` and `fields` fails to load, naming the file, component and keys (#792: eleven engine files once declared their fields there and loaded open, with nothing checked and no default applied). Known gap: a user style's `<name>_style` component has no schema of its own, so a scene that writes one needs an open schema for it (the examples' `hologram_style` is in `schemas/examples/components/`)

- **Schema types and references** (ADR 0115 decision 4, #684; `flint-schema`'s `component.rs`, `validation.rs`, `lint.rs`) -- one spelling per type, `flint_schema::TYPE_NAMES`: `bool i32 i64 f32 f64 string entity asset vec2 vec3 vec4 color transform enum array table`; `OLD_TYPE_NAMES` (`float boolean int integer entity_ref`) still load and are linted; `type_name_of(name)` maps either to the one spelling. `FieldType` gained `Entity`, `Asset { kinds: Vec<AssetKind>, unless }`, `Vec2`, `Vec4` and `Fields { fields }` (a `type = "table"` with `fields`), lost its serde derives, and has `describe()` (`asset<models|specs>`, `array<vec2>`, `table{xy, xz}`); `FieldSchema::of(type)`; `ComponentSchema::is_open()`. Codes added: `unknown-entity`, `missing-asset` (errors), `old-type-name`, `unknown-type`, `ignored-schema-key` (warnings; 17 codes in all with #685's `needs-component`)

- **Scene tables** (ADR 0115 decision 4, #686) -- a scene's top-level tables other than `[scene]`, `[prefabs]` and `[entities]` are declared as **`[table.<name>]`** in a schema directory's `scene/*.toml`, written exactly as a `[component.<name>]` is (`flint_schema::TableSchema` is `ComponentSchema`; `SchemaRegistry::{get_table, tables, table_names, register_table, load_table_file, load_table_string}`; `load_directory` reads `scene/` first; `lint::SchemaKind::{Component, Table}` and `lint_table_file`, and each kind in the other's directory is an `ignored-schema-key` whose hint names the right one). The engine's five are `schemas/scene/{camera,environment,post_process,living,wooze}.toml` (the first three are fields of `SceneFile`; `[living]` and `[wooze]` are living props' own, kept in `tables` and typed by `flint_procgen::LivingTables`, `crates/flint-procgen/CLAUDE.md`); `[[wooze.zone]]` is `[table.wooze]`'s `zone` field (an array of tables with fields), so there is no `wooze_zone` and **`schemas/components/` holds only components** (`crates/flint-schema/tests/scene_tables.rs`). **`SceneFile`** (hand-written `Deserialize`, so a typed table's error keeps its line; a derive with `#[serde(flatten)]` would lose it) keeps every top-level key it has no field for in **`tables: toml::Table`**, as written, and serializes it back (`#[serde(flatten)]` on the way out); `SceneFile::parse(text)` (what the loaders and `diagnose` use; `toml::from_str` does not) also records what the typed tables wrote in `written` (`SceneFile::TYPED_TABLES`), which is where a key serde dropped is still visible, and sets `PostProcessDef::authored` from it. `scene_file.table(name)` / `scene_tables()` hand them out. **Diagnosed in the one pass** (`diagnose`, `diagnose_scene_in`, `diagnose_scene`; `diagnose_tables` in `flint-scene/src/diagnose.rs`), tables first, in name order: no schema for the name is **`unknown-table`** (warning, hint = nearest declared table or where a game declares one; `promote_strict` makes it an error with `unknown-field`), else `flint_schema::validate_table(schema, data)` (= `validate_component` with `Diagnostic::table` set and no component) plus its `entity`/`asset` references. `Diagnostic` gained `table: Option<String>` (serialized only when set) and `.table()`; `Display` is `warning[unknown-field] [post_process] bloom_intesity: ...`. Nothing is said about tables when the registry has **no** table schema (a schema directory from before the kind), and a typed table with no schema is passed over. With `[table.post_process]` loaded the loader's older `[post_process] has no field` log line (#354) is not printed (the same keys are diagnostics). A wrong TOML type in a typed table is still serde's `toml-parse`. `flint check` and `flint validate` (`crates/flint-cli/src/check/scene.rs`) drop the pass's *error* diagnostics of `[wooze]` when `flint_procgen::WoozeDef::check` has produced `bad-wooze` for it (same mistakes, in the field's words, one a zone). 32 codes with #687's. `crates/flint-scene/tests/table_schemas.rs` holds each of flint-scene's three table schemas to the struct that reads it (`post_process`: same field set and same defaults as `PostProcessDef`). The player hands the tables to extensions: `PlayerApp::scene_tables` (set by `apply_scene_settings`, `flint play` and a transition), `ExtensionCtx::{scene_tables, scene_table(name), scene_table_as::<T>(name)}` (`crates/flint-player/CLAUDE.md`). What the first run found in `examples/` is pinned as `NOTHING_READS` in the flint-schema test: `[camera] orthographic = true` in four 2D examples (the key is `projection`), `[camera] distance/pitch/yaw` in rolling_meadow, `[lights.*]` in campfire

- **Component constants, schemas and readers agree** (ADR 0115 decision 3, #681) -- `flint_core::components` holds a name only for a component engine code uses, and `crates/flint-schema/tests/engine_schemas.rs` fails when: a constant has no `[component.<name>]` in `schemas/components/` (exempt, by name and reason, in `NO_SCHEMA`: `spline_data` and `spline_chunk`, which the engine writes and no scene authors); a constant is used by no code outside tests (`comp::NAME` / `components::NAME` under `crates/*/src`, test modules cut off), which is how `HEALTH` and `PLAYER` went; a schema is mentioned by no code outside tests, by constant or as a string literal (`NO_READER`, empty since #792 deleted `audio_listener`: the listener is the camera); a room-builder name is back in the engine's set, or the root `flint.toml` stops listing `schemas/examples`; a scene or prefab anywhere in the repo writes a value one of `CHECKED_AGAINST_SCENES` (`model`, `light`, `spline`, `spline_mesh`, and since #792 the physics, audio, joint and 2D UI ten) rejects, or a field it doesn't declare; an example (not a frozen fixture) carries a `directional_light`, `point_light` or `spot_light` table; or the `model`, `light`, `spline` or `spline_mesh` schemas' field lists, or which fields carry a `default`, changes without the test's list changing too. The search can't tell a reader from a writer: it catches a schema nobody mentions, not one nobody honours. A new component: the constant, the schema file with the fields its reader takes, and the reader, in one change
- **Every schema file loads** (#333) -- `crates/flint-constraint/tests/schema_files.rs` walks every `.toml` under `schemas/` and `showcase_game/schemas/` and loads each on its own with the loader its directory is read by (`components/`, `archetypes/`, `scene/` through `SchemaRegistry`, failing on its lints too; `constraints/` through `ConstraintRegistry`, failing on a query `problems()` reports, or a file with no `[[constraint]]`), so one bad file doesn't hide the next. It fails a `.toml` in any other directory (nothing reads `schemas/component/`), and in each layer stack of `STACKS` (what the root and `showcase_game` `flint.toml` name; a new schema layer goes there) an archetype naming a component, or a `defaults` table, no `components/` file of the stack declares, which the registry skips in silence. It lives in `flint-constraint` because that crate sees both registries. A component, archetype or table file that isn't its TOML is an error naming the file (`TOML parse error: <path>: TOML parse error at line ...`); before #333 the first two said only the parser's message
- **Typed component reads** (ADR 0115 step 4, #685; `crates/flint-ecs/src/view.rs`) -- `world.view(id, comp::COLLIDER) -> ComponentView` (`Copy`; `ComponentView::of(entity_name, component, Option<&Value>, &ReadReports)` for a table already in hand): `f32`/`f64` (integer or float), `i64` (an integer, or a float with no fraction), `bool`, `str`, `choice(field, &allowed, default)` (returns the `&str` from `allowed`, so list aliases in it), `vec3` (array of 3+, or a table with any of x/y/z over the default), `vec4`, `color` (3 or 4), each with a default, and `opt_*` for a field with none (`character_controller.height`, `material.base_color_r`). Also `exists()`, `has(field)`, `raw(field)`, `report(field, || Diagnostic)`. **Missing field or component: the default, in silence. Wrong type or unknown choice: the default, and reported once** per (entity NAME, component, field) to `world.read_reports()` (`ReadReports`: `once`, `snapshot`, `take`, `len`, `clear`; keeps `KEPT_REPORTS` = 512, logs every one with `tracing::warn!("{}", d.one_line())`). The codes are step 2's `bad-type` / `bad-enum-value`, at their listed severity (error), plus `needs-component` (warning; physics' collider with no rigidbody), so `codes::ALL` is 12 and the book's table (concepts/schemas.md) has the row. The once-set is 64-bit hashes of the three names behind a `Mutex`: no clock, no file (same on wasm), and **a read that finds nothing wrong takes no lock and allocates nothing**; the entity's name is looked up only to report (`get_name` walks the name map, so never call it per read). `FlintWorld::clear` empties the reports, so a reloaded scene speaks again. Ported so far: flint-physics, flint-audio, and the renderer's `ecs_base_color_override`; every other reader still chains `.get().and_then()` and stays quiet about a wrong type. **`toml::Value::as_float` is denied in runtime crates** by `scripts/wasm-clippy/clippy.toml` (the wasm check: every crate flint-player links, libs and bins, deny level, fails a PR; tests, flint-cli, flint-viewer and `cfg(not(wasm32))` code are outside it, and native `cargo clippy` does not know the rule). `toml_util::toml_f64` is its one allowed caller (`#[allow(clippy::disallowed_methods)]`).
