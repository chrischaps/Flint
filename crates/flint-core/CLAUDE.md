# flint-core: vfs, hot reload, transform shear, the project (moved out of the root CLAUDE.md by #755)

The root file keeps the vfs rule in short. The wooze field (`flint_wooze`): `crates/flint-procgen/CLAUDE.md`. Quality settings (`flint_core::quality`): `crates/flint-render/CLAUDE.md`.

- **Every runtime read goes through `flint_core::vfs`** (#97) -- `vfs::read` / `read_to_string` / `read_dir` / `exists` / `is_file` / `is_dir`, never `std::fs` or `Path::exists` in a runtime crate. The default source is the disk; the web player installs a `MemorySource` filled from a game bundle (`vfs::install`; `flint bundle <game>` packs one, `flint_core::bundle` is the format, `flint-player --bundle` plays one natively, audio arrives in a late bundle and `vfs::generation()` tells the player to load it; docs/design/web.md), and tests use `vfs::scoped` (this thread only). Decode images with `flint_render::open_image` (not `image::open`) and glTF through `flint_import::import_gltf` (not `gltf::import`), both of which read via the vfs. Writes (scene save, saves, replays) and hot-reload mtime polling stay on `std::fs`, natively; input overrides go through `flint_player::user_files` (OS config dir, or `localStorage` on the web, #100), and so does the `persist_*` store on every platform (#726; `save_<game_id>.toml` on the web, #104). Tests and the CLI keep `std::fs`
- **One tween service** (#734; `tween.rs`) -- every "ease a value over N seconds" in the engine names `tween::Easing` (`linear`, `smooth` (default), `ease_in`, `ease_out`, `ease_in_out`; `NAMES`, `from_name`, `parse(name, fn)`, `refusal`, `apply` in f64, `apply_f32` in f32, `over(elapsed, seconds)`) and rides one of two shapes over any `Lerp` (`f32`, `f64`, `[f32; N]`, `Vec<f64>`): `Ramp<T = f32>`, a pure function of time (`constant`, `at`, `head_for`, `head_for_eased`, `arrived`, `target`), and `Tween<T>`, a ramp stepped by frame times that lands exactly on its target (`new`, `step(dt)`, `value`, `done` with `ARRIVAL_SLACK` 1e-9 of its length, `retarget`). `field::Ramp` is `tween::Ramp` re-exported: the wooze field samples it and it must stay **bit-identical** (an `f32` ease is computed in `f32`; `tests::an_f32_ramp_is_the_old_field_ramp_bit_for_bit` holds the old formula). On it: the field and its zones, Living Props' knob ramps (#514), `step_clock::eased`, the look fade, the player's style tweens, animation layer fades (`fade_easing`) and the crossfade weight, and flint-script's field tweens (`crates/flint-script/CLAUDE.md`). A new timed change takes an `Easing` and a `Ramp`/`Tween`, never its own smoothstep. Not on it, on purpose: keyframe tracks and particle curves (their own interpolation of authored keys) and kira's audio `Tween`
- **Parameter fields** (#747, ADR 0123; `field.rs`, `field/scene.rs` #1014) -- `ParamField<N>` over a `static FieldKeys<N>` (the wooze field) and `SceneField`, a field whose keys a scene declares (`[field.<name>] keys = { wind = { min, max, default } }`, `SceneKey`), share one zone reader through the private `KeySet` trait and `ZoneOf<S: Slots>` (`Zone<N>` = `ZoneOf<[Option<Ramp>; N]>`, `SceneZone` = `ZoneOf<Vec<..>>`), so a zone is read and refused in the same words in both. `SceneField::sample_index(i, pos, time)` samples one key with no allocation and the same bits as `ParamField::sample(..)[i]` (`scene_tests::a_scene_field_samples_the_bits_a_param_field_does`); keep the arithmetic in `lay` and `ZoneOf::share` shared, or the wooze field's bits move. `SceneFields::read(&value) -> (fields, Vec<FieldIssue>)` collects every mistake (a field with a bad key is dropped; a bad zone is dropped and its field kept); `FieldIssue::place()` is the diagnostic's field (`weather.keys.wind`, `weather.zone.storm`), code `bad-field` (`flint check`'s `check/scene.rs::fields`). The player's side: `crates/flint-player/CLAUDE.md`, "Fields a scene declares"
- **Frame notes** (#1077; `frame_notes.rs`) -- what the engine did on a frame, said by the code that did it: `note(kind, || detail, ms)`, `timed(kind, || detail, || work)` and `begin(kind, || detail) -> Timing` (timed until it drops, for work with a `continue` or an early return). A per-thread channel, write-only from below: nothing under the player reads it, and the host that wants it calls `listen(true)` on its frame thread and `take(&mut Vec)` once a frame (the player's frame history, `crates/flint-player/CLAUDE.md`). Not listening, a call site is one thread-local flag read (about 1 ns; the detail closure never runs, no clock read). A worker thread's notes are never seen, and each test thread has its own channel. Bounded at `MAX_NOTES` (64) between takes, the rest counted. `timed`/`begin` take their slot when the work begins, so an outer note comes before the notes inside it, each with its `depth`; an inner note's time is inside the outer's. `NoteKind` is a closed enum with a `label()` each; a new kind is a variant, its row in `ALL` and its label. Two predicates sort the kinds: `is_symptom` (the clock stall, the physics steps: the long frame itself, never a cause) and `is_tooling` (#1129: `Screenshot`, `StatsOverlay`, and since #1288 `TraceRing`, the player's own tools looking at the game; a hitch they explain is classed `tooling` and counted apart, `crates/flint-player/CLAUDE.md`). A new debug tool that does real work on the frame thread gets a tooling kind. A third, `is_count` (#1091: `GpuObjects`, the renderer's created objects, noted with no `ms`), marks a note that counts rather than times: unlike an untimed load it never explains a hitch by itself, so the hitch names it in `(also: ..)`. Chosen over riding out through `RenderStats` (ADR 0118 keeps the renderer's *inputs* explicit; this is an output nobody below reads) because the scripts, audio and the player's own loads report too. Call sites below the player: `pipeline_cache::timed(label, ..)` (every pipeline built through the cache or the style kit), `StyleSet::ensure` (`StyleBuild`), `model_loader::load_models_from_world` and `TextureCache::load_file_with` (after the cached check), `RenderContext::resize` / `recreate_surface`, flint-script's `ScriptSync` (load, reload compiled on the frame, the swap, the poll when it took >= 1 ms) and `load_script_for_entity`, flint-audio's `load_sound`, `decode_queued` and the small-sound `decode_now`
- **Load reports** (#1092; `load_report.rs`) -- where one load's time went. `begin(LoadKind::{Start, Transition, Chunk, Render}, name)` (or `begin_at(.., Instant)`, a process's start) records on this thread until `finish() -> Option<LoadReport>` (`begin` finishes and returns one still open). While recording, **every timed frame note** (`frame_notes::begin` / `timed`, listened for or not: `begin` checks `listening() || load_report::recording()`, two thread-local flags) opens a span of `Stage::of_note(kind)` (an exhaustive match: a new `NoteKind` names its stage, or `None` for a container such as `SceneTransition` / `ChunkLoad`), and a host adds what no note names with `span(Stage, || detail) -> Span` / `timed` (`Window`, `Device`, `AudioDevice`, `Renderer`, `Hud`, `Procgen`; `Span::discard` drops one that did nothing, its time staying with its parent). A stage's row is its spans' time **less the spans inside them**, so rows plus `unnamed_ms` are `total_ms`. `bring_up_done()` starts the `FirstFrame` row: the time from there to `finish` less the top-level spans closed meanwhile. A span with a detail is an asset; `slowest` keeps the `SLOWEST` (5) by whole time. An untimed `note(.., Some(ms))` is **not heard** (its time may hold spans already): code that times by hand wraps the work in a `span` too (`procgen_assets::resolve_scene`, `tick_procgen`). `LoadReport::table()` is the text `--load-report` prints; the struct is `Serialize`. The seven note kinds #1092 added for the bring-up (`SceneRead`, `SceneTeardown`, `PhysicsBuild`, `AudioLoad`, `AnimationLoad`, `ParticleLoad`, `ScriptInit`) are frame notes too, so a transition's hitch names them. Callers: `crates/flint-player/CLAUDE.md` ("Load reports"), `flint render --load-report`
- **Profiler scopes** (ADR 0128, #1095; `profile.rs`) -- `flint_core::scope!("name")` / `scope!("name", detail)` (a count: `usize`/`u32`/`u64`; text: `&str`/`String`/`&Path`, copied, so rare scopes only; a `&Path` is read only while recording, and every detail expression is still evaluated in a build without the recorder, so keep it a field read) is the engine's one scope; the name must be a string literal (a per-site `static Site`). It expands to a `profile::Scope` guard for Flint's recorder and `profiling::scope!` for Tracy (re-exported as `profile::__profiling`, so a scoping crate needs flint-core alone). **The gate is decided here**: the macro is defined twice under `cfg(any(debug_assertions, feature = "trace"))`, never by a `cfg` inside an expansion (that would read the *calling* crate's features), so no crate forwards a feature to scope its code. Compiled out (a default release build), `scope!` is `profiling::scope!` alone, nothing without Tracy. Compiled in, nothing records until `set_recording(true)`: a scope is one relaxed load (0.6 ns release, 6 ns dev). Recording: about 40 ns release, 64 dev (ADR 0128's table; `crates/flint-core/examples/scope_bench.rs` on branch `spike/1095-scope-sinks`). Records (40 bytes: site, start and duration in clock ticks, `frame`, `depth`, detail) go to a per-thread `Ring` (`DEFAULT_RING_CAPACITY` 65 536, or `set_ring_capacity` before the thread's first record; allocated once, oldest overwritten), each behind an uncontended `Mutex` in a global list that `with_rings` reads; written when a scope closes, so a parent follows its children. `clock` is the TSC on x86_64 (`ns_per_tick` calibrates against `Instant` at read-out; `Record::start_ns` / `dur_ns` convert), `web_time::Instant` elsewhere. `finish_frame()` is Tracy's frame mark and the recorder's frame index; the player calls it after each `RedrawRequested`. **Reading it out** (#1097): `set_ring_capacity(0)` keeps every record (the ring and its text grow: a whole session); `ring_capacity()` reads it back. `snapshot(since_ns) -> Vec<ThreadScopes>` copies every thread's records that closed at or after `since_ns` (ns from the epoch, `None` all) as owned `TakenScope`s (name, file, line, `start_ns`, `dur_ns`, frame, depth, `TakenDetail::{Count, Text}`), each ring locked only while copied, with `held`/`written`/`capacity` (`wrapped()`). `clock::instant_ns(instant)` / `now_ns()` put a host's own `Instant`s on the scopes' timeline. `site_named(&str) -> &'static Site` interns a site for a name made at run time (one leaked `Site` a distinct name; ask only while `recording()`), entered with `Scope::enter(site)`: flint-script's `ScriptEngine::call` makes each callback a scope `<source>:<callback>` this way. **Summed records** (#1288): `Call::enter()` opens a level with no record and `close(site)` returns `(start, ticks)` for the caller to sum, unless a record was written inside it (the per-thread `RECORDED` count), when it records itself as a scope and returns `None`; `record_calls(site, start, total, calls, worst)` writes one record at the current depth with `Detail::Calls { calls, worst }` (8 bytes, so a record stays 40), taken as `TakenDetail::Calls { calls, worst_ns }` and written by `chrome` as args `calls` and `worst_us`. It is a leaf that may overlap its siblings: both trace readers never push it as a parent. flint-script's engine-function calls use it. `ThreadScopes::cut_at_ns()` is where a copy's record begins when its ring wrapped inside the window (wrapped, and every held record copied): the oldest held record's close. **Rings grow** (#1288): `set_ring_growth(seconds, max_records)` makes `Ring::push` check once a lap (when `next` comes round to 0, so the records are oldest-first in place) whether the lap spanned less than `seconds`, and if so double (`grow_if_short`, up to the max) with nothing moved; each growth is a `NoteKind::TraceRing` frame note (tooling) with its copy's ms. The player sets it to 1.25 x the look-back and 8 x the first size. `profile::chrome` is the file: `ChromeTrace` (`track(name) -> tid`, `complete`, `instant`, `scopes(&ThreadScopes)`, `finish(header) -> String`; `"ph":"X"` events, µs to the ns, `thread_name` + `thread_sort_index` per track, the header as `otherData`), with `Arg::{Str, Num, Int, Bool}`. **The taken types, `chrome` and stubs of every name above are in every build** (`off` has `COMPILED_IN = false`, `snapshot` empty, `clock` zeros, a ZST `Scope`), so a host writes one path guarded by `COMPILED_IN` and the optimizer drops it from a default release build. The player's use: `crates/flint-player/CLAUDE.md`, "Scope traces". **Coverage** (#1096): about 120 sites below the frame's phases, named `<crate>::<step>` in the runtime crates (`physics::step`, `script::call` by file, `animation::skeletal`, `particles::simulate`, `audio::decode`, `procgen::generate`, `living::fill_rings`) and by function in the player and renderer (`extract::*`, `cull_lod`, `encode_part` by label for each post effect and style part, `build_pipeline` by label, `import_model` / `decode_image` / `load_texture` by file); the book's guides/profiling.md lists them by phase. Never a scope an entity or draw: a loop gets one, with its count. `cargo test -p flint-core --release --features trace --lib scope_cost -- --ignored --nocapture` measures one (about 35 ns recording, 55 with a file name, 1 ns not); `flint-player`'s `scope_coverage_tests.rs` holds each phase's scopes and a mid-play model's `import_model`
- **Environment switches** (#715; `env.rs`) -- every `FLINT_*` variable the engine or its tests read is a row of the `vars!` table: a `pub static <ID>: Var { name, kind, default, help, group }`, listed in `env::ALL`. `Kind` is `Flag` (`1|on|true|yes` / `0|off|false|no`), `Number { min, max, whole }`, `Choice(words)`, `Path`, `PathOrOff` (procgen cache) or `Secret` (the provider API keys: `status()` shows `(set)`, never the key). Getters: `raw()` (the one `std::env::var_os` of a `FLINT_*` name; empty is unset), `is_set`, `get() -> Option<Value>`, `flag`, `number`/`f32`/`u32`, `choice` (the table's lowercase word), `path`, `secret`. A value the kind refuses returns `None` and is said once per process through `tracing::warn!` (`FLINT_VSYNC="fasle" is not 1|on|fifo|0|off|immediate|mailbox: using the default (vsync (fifo))`); `parse(raw)` is the pure check, for a unit test. `default` is prose for `flint env`, not a value: the reader keeps its own default, and where both are numbers a test holds them together (hitch.rs). `Group` (`Window`, `Render`, `Player`, `Assets`, `Tests`) picks what `help_section(groups)` prints at the end of `flint render --help` (render) and `flint play` / `flint-player --help` (`PLAYER_GROUPS`). `book_page()` is `docs/book/src/cli-reference/environment.md` (`flint env --book`, CI's `--check-book`). A new switch: its row, its getter at the read, `flint env --book`; `tests/env_table.rs` fails a `var("FLINT_`/`var_os("FLINT_` outside env.rs and a `"FLINT_X"` literal with no row (an `option_env!` line is build time and skipped), and `scripts/ci.sh` greps for the first. `WGPU_*`, `ANTHROPIC_API_KEY` and `RUST_LOG` are other tools' names and stay outside it
- **Hot reload never waits on the disk** (#633) -- every reload poll (scripts and `scripts/lib`, UI documents, user styles, glyph sets, palettes, style images) asks `flint_core::file_watch` (`stamp` / `modified` / `list` / `tree`), never `std::fs::metadata`. Direct mode (the default: tools, tests) stats then and there; the player's `file_watch::start()` (in `resumed`) switches to a watcher thread that publishes a change once a file held still for two 250 ms looks and was read through once; `--no-hot-reload` / `file_watch::disable()` is Off. A poll's baseline stamp must come from `file_watch` too, or the cached and direct answers never agree. Scripts read and compile on `flint-script`'s `reload_worker` thread (`engine::compiler()`, a bare engine with Flint's parse limits: keep a parser setting there, not in `ScriptEngine::new`), reading with `file_watch::read_settled`; a changed lib is compiled there into `VfsModuleResolver::with_compiled`
- **Transform shear** (#625) -- optional `transform.shear = { xz = 0.25 }` (any of `xy xz yx yz zx zy`, `ab` = how far a moves per unit of b), composed `T * R * H * S` in `Transform::to_matrix` (`flint_core::Shear`; no shear is bit-identical to before). Renderer needs nothing more: normals use `mat4_inv_transpose`, culling `transform_aabb`, both general. Rhai `set_shear(id, map)` / `get_shear` / `clear_shear`; physics warns on a skewed world matrix (`mat4_skew`) and ignores it. Demo `flint-examples/shear_road.scene.toml` (generated by `flint-examples/tools/shear_road.py`, `--yaw` writes the gapped before)
- **Project and manifest** (ADR 0114, #706) -- `flint_core::project::Project { root, found, id, schemas, scene, input, strict, save_version, allow }`, over the vfs: `Project::discover(scene_or_dir)` walks up to a `flint.toml`, a `.flint/` or `schemas/` + `scenes/`|`levels/` (an engine checkout passes through to the game above), then reads `flint.toml`'s `[project]` (`id`, `schemas`, `scene`, `input`, `strict`, `save_version`; all optional; a wrong type or unknown key is a `ProjectError` naming file and key). `Project::current()` / `for_path(scene)` honour the CLI's global `--project <dir>` (`Project::at` + `project::set_override` in `main.rs`). A relative start is joined to the working directory only when that directory is in the file source; in a bundle it is walked as given. `flint_asset::ProjectStore` (a trait to import) adds the `.flint/` store paths. **One schema resolver** (step 2): `project::schema_dirs(scene: Option<&Path>, flags) -> Result<SchemaDirs { dirs, source }, SchemaDirsError>` is the only place the directories are decided: `--schemas` flags if any (the whole list), else the manifest's `schemas` under the root (`SchemaSource::Manifest(file)`), else discovery (`schemas/` in the working directory, beside the scene, one level up; only what exists, maybe none). A directory a flag or the manifest names that isn't there is `SchemaDirsError::Missing { dir, named_by }`; `FlintError::SchemaDirs` carries it. `flint_schema::SchemaRegistry::resolve(scene, flags) -> (registry, dirs)` builds the registry; the CLI's `common_args::load_schemas`, the viewer's `flint_viewer::app::load_schemas` (schemas + constraints of every dir, #704) and `flint-player` call it, and a new command that loads schemas must too (its `--schemas` is a `Vec<String>` with no default, so "no flags" is visible). `host_schema_dirs(listed, scene)` is a list the host settled (a bundle's manifest, `PlayerApp::set_schema_paths`): existing ones plus what's beside the scene, never an error. The player keeps a `SchemaDirs` (`set_schema_dirs`) and asks `for_scene(next)` at a transition or chunk: flags stay, a manifest is re-read for the new scene's project, discovered and host lists grow. For one release (decision 3, #765) `SchemaDirs::dropped` lists the `schemas/` near the scene that flags used to gain and no longer do (compared by `same_dir_key`), and play/render/validate/spline-edit/`flint-player` print `dropped_warnings()` on stderr; remove both with the warning. `flint-android` resolves too (#797): `packed_schema_dirs(scene, packed)` is the manifest's list when the packed game's `flint.toml` names one (so it can list `engine/schemas/examples`), else `packed` (`data_dir/engine/schemas`, `data_dir/schemas`, what Gradle copies) as a host list; a manifest naming a directory the APK lacks is logged and the pair loads, and the registry goes to `set_schemas`. Type-check it with `cargo ndk -t arm64-v8a --platform 26 check -p flint-android` (the NDK is under `%LOCALAPPDATA%/Android/Sdk/ndk`; set `ANDROID_NDK_HOME`). **Every manifest key has a reader**: `schemas` (above); `scene` is `Project::default_scene()`, what `flint play` / `flint-player` open with no scene argument (`NoDefaultScene`'s message says what to pass) and `flint bundle`'s start scene when `bundle.toml` has none; `id` is the bundle's name when `bundle.toml` has none (`commands/bundle.rs::read_project`; `flint export web` follows); `input` is the player's game input layer (`player_app/input_config.rs`); `strict` (a bool) is read by `flint_scene::diagnose`, which makes `unknown-field` an error (ADR 0115); `save_version` (a whole number, 0 unsaid) is the version the game's saves are at, which the player gives the `persist_*` store (#726). `flint.toml` is packed into a bundle, where `Project::discover` reads it through the vfs (`tests/project_done_when_cli.rs`). `flint init` writes the manifest (#707; `crates/flint-cli/CLAUDE.md`)
- **The project root, for paths that are not searches** (`project/root.rs`, #706) -- `project.root_for(scene_dir)` is the directory a path "from the project root" is joined to: `root`, except for a `Found::Fallback` project, which keeps `guessed_root(scene_dir)`, the scene directory's parent, since with no marker the engine behaves as it did. `guessed_root` is the ONE copy of the old "scene dir's parent" guess; nothing outside `flint_core::project` may derive a root from a scene path (deriving the scene's *own* directory from its file is fine). Its callers: `load_ui` / `load_data` (`ScriptCallContext::project_root_holding`; the project arrives with `ScriptSystem::set_current_scene(path, &project)`), `music_session`'s base, the save file of a game with no id (`flint-player`'s `persist.rs`: `<root_for>/save/persist.toml`; a game with `[project] id` saves under the OS user directory instead, #726, `crates/flint-player/CLAUDE.md`), the procgen disk cache (`<root_for>/.flint/procgen-cache`) and the project-local input override (`<root_for>/.flint/input.user.toml`). What the engine writes goes under `root_for` so a `.flint/` it makes marks the root already in use. Known edge, not changed here: the nearest marker wins, so a `.flint/` beside nested scenes (an old procgen cache) is a root of its own and hides a `flint.toml` above it
- **TEMPORARY, for one release** (ADR 0114 decisions 3 and 5, #765; remove together, with a changelog entry): `SchemaDirs::dropped` / `dropped_warnings()` and the commands' `warn_dropped_schemas`; `KindInfo::old_rule` / `old_list`, `OrderChange`, `Resolution::order_change`, `list_order_changes` and the chunk-script comparison in `transition.rs`; the old-place reads `Project::old_place` / `root_holding` (a file only at `guessed_root` when that differs from `root_for`: `load_ui`, `load_data`, a music manifest), `old_persist_path` and `SaveFiles::old_places` in the player's `persist.rs` (#726: a game with an id reads `<root>/save/persist.toml` once, then saves under the OS user directory; on the web the entry keyed on the input config's `game_id`), and `old_local_override` in `input_config.rs`. `guessed_root` itself stays: it is the Fallback rule
- **One asset resolver** (ADR 0114 step 3, #706; `project/assets.rs`) -- `project.resolve(AssetKind::Particles, "fire", &scene_dir) -> Result<PathBuf, NotFound { kind, name, tried }>` is the one search, over the vfs: `D/<folder>/<name><ext>` for `D` = the scene's directory, each directory above it up to and including the root, then `<root>/engine` (`engine_mount()`: only if that directory exists, never in `Found::Engine`). A kind is data, `AssetKind::info() -> &KindInfo { label, noun, folders, extensions }`, and the walk never branches on the kind: a new kind is an enum variant, a `static KindInfo` and its entry in `AssetKind::ALL` (which `flint asset where --help` and the book's table follow). A name ending in one of the kind's extensions is taken as written; a name may carry subfolders. `explain` is `resolve` with its working shown and nothing logged (`Resolution { found, tried, order_change }`, what `flint asset where` prints); `list(kind, scene_dir)` is every file visible by the same rule, a nearer name hiding a farther one (files directly in the folder only); `search_dirs` the folders in order, existing or not. Paths keep the scene directory's spelling (relative stays relative, which is what a bundle needs) and go absolute only when the spelling runs out; print them with `project::shown` (forward slashes). Two edges, the same for every kind: a scene outside the root is searched beside itself, then the root, then the engine; and a `Found::Fallback` project (no marker, root = the scene's directory) also searches one level above the scene, since with no manifest the engine behaves as it did. `Project::for_scene(scene)` is `for_path` for a loader that must carry on: a bad manifest is a warning and the project without it. TEMPORARY, for one release (decision 3, #765): `KindInfo::old_rule` is a kind's search before the one rule, as `fn(name, scene_dir) -> Option<PathBuf>`; when it would have picked another file than the one rule does (compared by `same_dir_key`; the old rule finding none is not a change), `resolve` and `list` log an `OrderChange` through `tracing::warn!` once a process per (kind, name, old, new), never on stdout. Particles' is `old_particles` (first of `particles/` beside the scene or one level up that exists, and only that folder). - **Parent chains are finite** (#680) -- `FlintWorld::set_parent` is the one writer of the hierarchy, and it refuses a link that would make an entity its own ancestor (`FlintError::ParentCycle { child, parent, chain }`, names, `chain` from the parent up to the child), storing nothing; so every walk up a chain (the matrices, `hidden_entities`, physics, the renderer, IK, the style mask) may assume it ends. `get_world_matrix` / `get_frame_matrix` walk with a loop (`in_parents_frame`: ancestors on a 16-deep stack array, deeper in a Vec) and multiply from the root down in the order the old recursion did, so matrices are bit-identical. A scene's loop is `parent-cycle` from `diagnose_scene_in` (once a loop, on its first entity by name; `flint check` takes it as it takes a dangling parent, no `scene-load` beside it); a script's `set_parent` returns it as a script error

## From the root (#992)

- **`FLINT_*` environment switches are one table** (#715, `flint_core::env`): each is a `Var` (name, kind, default, help, group) read only through its getter (`env::VSYNC.choice()`, `env::LOD_SCALE.f32()`, `.flag()`, `.path()`), which warns once on a value it doesn't take; `flint env [--json]` lists them with their values, and the `--help` of `render`, `play` and `flint-player` ends with theirs. `scripts/ci.sh` refuses a `var("FLINT_` elsewhere, and `cargo test -p flint-core --test env_table` a `"FLINT_..."` name the table lacks: a new switch is a row there, then `flint env --book`. `crates/flint-core/CLAUDE.md`
