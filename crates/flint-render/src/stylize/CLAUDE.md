# flint-render stylize: styles, the style mask, per-entity and user-authored styles (moved out of the root CLAUDE.md by #755)

Flags that switch styles on (`--style`, `--ascii*`, `--look`, `--sweep`) and the stylize goldens: `crates/flint-cli/CLAUDE.md`. Glyph atlas, contour and shading boil, post-processing: `crates/flint-render/CLAUDE.md`.

- **Stylize passes** (#262, ADR 0111) -- `flint_render::stylize`: a style is a module exporting `STYLE: StyleDescriptor` (name, `StyleStage::Hdr` before fog/bloom/tonemap at scene resolution or `Display` after the composite at output resolution, params with ranges, `create`) plus its name in `register_styles!`; its `StylePass::encode` reads a `StyleFrame` (params, depth, camera, `target()` scratch textures, kept bind groups). Styles of a stage chain in registration order (or a table's `order = <n>`, lower first, ties by registration; `stylize::chain_order` / `stage_chain`, F4's chain line with swap buttons, #299) through framework ping-pong targets that live in `PostProcessResources` (rebuilt on resize). Scenes: `[post_process.styles.<name>]` (Kuwahara too since #298: a scene's old `kuwahara_*` keys fold into its table on load via `flint_scene::fold_legacy_style_keys`; numbers are `params`, strings are `options`, e.g. a font or ramp); F4 → Styles (and the player's F3 Styles panel, made when a scene uses a style) is one `flint_debug_ui::StylesEditor` drawn from descriptors (#268): optional `hints: &[StyleHint]` give labels/help/`.integer()`, `<base>_r/_g/_b` params fold into one colour picker (display values) and are one colour setting (`StyleColor`, #315: `tint = [r, g, b]` or `"#rrggbb"` in a table, `tint=#rrggbb` or `r/g/b` on `--style`, `frame.color("tint")` / `variant_color`, Copy TOML writes the array), and each style gets Defaults / Authored / Copy TOML (`stylize::style_toml`); an option can find its choices at run time (`StyleOption::discovered` + `ChoiceScope::files`, #322: ASCII lists the scene's `palettes/`, `fonts/` and the chosen font's ramps through the vfs; hosts pass the scene folder with `RenderDebugPanel::set_scene_dir` / `StylesDebugPanel::with_scene_dir`, and a discovered option is open to `--style`); `ascii` (#265) is the display-stage glyph style, cells in points times `SceneRenderer::pixels_per_point` (hosts set it from the window), fonts found via `frame.assets` (see "Where styles find files"); its edges (#267) are two more passes (`ascii_edges.wgsl`: edge pixels at `StyleFrame::depth_size`; `ascii_edge_cells.wgsl`: one texel a glyph cell summing structure tensors) that the glyph pass draws as line glyphs, and a mask boundary where either side is one of the style's ids (plain or per-entity variant) is always an outline; `encode_to` builds newly enabled styles itself. `invert` is the template. Bloom reads the unstylized HDR unless an HDR style that ran feeds it (#300): `StyleDescriptor::feeds_bloom` (user styles: `feeds_bloom = true` in the `.shader.toml`), overridden per scene by `feeds_bloom` in `[post_process.styles.<name>]`, `--style <name>:feeds_bloom=1`, F4's Feeds bloom checkbox; then the threshold reads the HDR stage's result (`run_bloom`'s `source`, keyed by input id). SSAO/volumetrics read depth only. Demo: `examples/neon_bloom.scene.toml`. Shared edges (#301): a descriptor's `needs: &[StyleNeed::Edges]` gets `StyleFrame::edges` (`stylize/edges.rs`: `Rgba16Float` at the depth's size, r = silhouette / g = crease strength over the shared `[post_process] edge_depth`/`edge_normal` (`--edge-depth`/`--edge-normal`), ba = unit direction, y down; `edges_bind` + `kit::texture_layout`), drawn once a frame before the Hdr stage however many styles read it (`SceneRenderer::style_edge_runs`); `edges_view` shows it, user styles take `inputs = ["edges"]` (`flint_edges`/`flint_edge`). ASCII and pencil still run their own edge passes. A style with frame-to-frame state (ASCII's per-cell history, #277: a cell pass into a ping-ponged `Rgba16Uint` texture via `target_sized`, then the glyph pass) trusts it only when `StyleFrame::frame` follows its last frame and `history_epoch` is unchanged; hosts call `SceneRenderer::reset_style_history()` on a scene change or camera cut (#343: Rhai `reset_style_history()`, and the player's `camera_cut` detector resets on a jump > 2 m or turn > 30° in a frame at > 4x the last frame's rate; `set_camera_cut_detection(false)`; `examples/ascii_cuts.scene.toml`). `temporal = "reproject"` (#344) reads a cell's past where its surface was last frame (scene depth + last frame's `view_proj`, kept by the style; an `R32Float` cell-depth target rejects disocclusions); measured no better than screen-space history on the meadow, so opt-in (`tools/ascii_flips.py --track 8` counts flips along the motion). Book: concepts/stylize-passes.md (reference) and guides/stylized-rendering.md (choosing whole-frame vs per-entity, with the decision's captures). The decision: per-entity *selection* on one screen grid, with full screen its "everything" case and `grid = "object"` opt-in only; glyph-like styles at the Display stage (`docs/adr/0111-stylized-rendering.md`)
- **A game's Rust styles** (#419) -- `stylize::register(&'static StyleDescriptor) -> Result<(), String>` appends to the same append-only snapshot as user styles (`register_runtime`) and records the name in `GAME_STYLES`; it refuses a non-identifier name (`custom::is_identifier`), any registered name (built-in, user, game) and a `component` another style takes, and accepts the same pointer again (several `PlayerApp`s in one process; tests). Call it before `[post_process]` is read. `is_game_style(name)`, `is_native(name)` (= built-in or game): a `.shader.toml` naming a game style is a load error, `replace_runtime` refuses native names (it asks `is_native` **before** locking `SNAPSHOT`, since `register` holds `GAME_STYLES` then reads the snapshot: keep that lock order), the catalog's `source` is `"game"`, F4 tags it `game`, and a game style whose `create` panics is turned off with an error, not a lost device (`ensure_style_resources`). Player hook: `PlayerExtension::styles()`, registered in `add_extension`. Example game: `crates/flint-player/examples/cyanotype/` (two passes into a `frame.target`); the out-of-crate GPU test is `a_style_registered_from_another_crate_draws_its_two_passes` in `tests/stylize.rs`. Only the game's binary knows them: `flint render`/viewer don't. A game style's shader from a bare `include_str!` builds through `kit::shader` but never hot-reloads under `FLINT_STYLE_SHADER_DIR` (next bullet)
- **Built-in shader hot reload** (#418) -- `stylize/dev_shader.rs`: a built-in shader is `kit::wgsl!("a.wgsl", "b.wgsl")` (a `kit::Wgsl { text, files }`: the `include_str!`s concatenated plus the names; `kit::shader` takes `impl Into<Wgsl>`, so a bare `&'static str` still builds but never reloads, so use the macro for a new style's files). `FLINT_STYLE_SHADER_DIR=<dir>` (natively; read once, `dev_shader::set_dir` in tests) makes `kit::shader` read `<dir>/<file>` for each name (vfs), naga-check the concatenation (an error is placed in its file by byte offset) and fall back to the last good text (else the compiled-in one). `StyleSet::ensure` builds every style, and the shared edges/fade/ownership passes, through `dev_shader::build`, which records the files read in a thread-local; every `POLL_FRAMES` = 15 calls it stamps them (`file_watch`) and drops each slot that read a moved file, which this same call builds again. A dropped slot sets `take_rebuilt`, and `ensure_style_resources` then calls `BindCache::clear` (the kept bind groups hold the old pass's buffers: without it a param change after a reload is ignored, which the test catches). A build that panics (wgpu refuses what naga took) is built again with `fallback` (last good texts only) and is not a lost device. Texts become last good only when the whole build succeeds. Errors: `dev_shader::errors()` (style, message), drawn beside `custom::errors()` by the viewer and player. `BlendPass` builds lazily, outside a recorded build, so a reload always resets it. Test: `tests/dev_shader.rs` (its own binary, since the folder is the process's)
- **Entity style mask** (#263) -- `flint_render::style_mask`: a `style_mask { style, enabled }` component (descendants inherit; nearest wins) gives each styled entity an id (`StyleIds`, 1.. in name order). After the scene pass (and MSAA depth resolve) its opaque static/box/skinned draws, its terrain chunks (the host names the terrain entity with `set_terrain_entity`, #310) and then its styled transparents (a styled transparent is a lens: its id replaces what is behind it, #310) are redrawn with their cached transform (+ bone) bind groups into an `Rg16Uint` target in `StyleTargets` (id in `.r`, blend in `.g`, #278), depth-tested in the shader against the single-sample depth with a slope tolerance; ids ride one dynamic-offset uniform buffer. Drawn only while a style whose `uses_mask` asks for it is on (`MaskUse::Always`, or `MaskUse::When(fn(&config, &ids))` per frame, #350: ASCII only with `edges > 0` and an id to outline); styles read `StyleFrame::mask` / `mask_bind` / `style_id`. `--debug-mode style` (`DebugMode::StyleMask`) turns on the `mask_view` display style. Demo: `examples/style_mask.scene.toml`. Veil (#290): just before the mask, unstyled transparents and all particles draw their coverage into an `R8Unorm` "style veil" (read-only scene depth attachment, `fs_veil` entry points in `shader.wgsl`/`skinned_shader.wgsl`/`particle_shader.wgsl`), and the mask writes blend x (1 - coverage): what's in front unmasks by its coverage. A new transparent or particle draw path needs a veil draw too. Demo: `examples/style_veil.scene.toml`
- **Per-entity styles** (#266) -- a descriptor's `component: Some("ascii_style")` makes a style per-entity: an entity with that component (or a `style_mask` naming the style) switches it on for its own pixels with no `[post_process.styles]` table (`is_on(config, &StyleIds)`; `ensure`/`active`/`any_uses_mask` take the ids). Its fields are the descriptor's params/options (ASCII's `font` too, #335: every set in use is stacked into one atlas, each variant row carrying its glyph cell and edge-glyph start; up to `MAX_FONTS` = 8), falling back on the scene's table then defaults (`StyleVariant::param`; a colour `tint = [r, g, b]` or `"#rrggbb"` fills `tint_r/g/b`, #315); each distinct set is a `StyleVariant` with its own id, named for its settings (`ascii{ramp=blocks}`, `ascii@barrel` for `grid = "object"`, `ascii{off}` for `enabled = false`). Styles read `frame.variants()` / `variant_param` / `whole_frame()` / `project`. Scissor (#385): `frame.styled_rect(pad)` is the style's entities' projected draw bounds (skinned ones as posed, from CPU copies of the bone matrices) grown by `pad`, `None` when it covers the frame; `kit::scissored_pass` draws inside it and blits the input around it (byte-identical only while the passthrough is exact outside), `kit::fullscreen_pass_in` for prep passes; pencil and ASCII (glyph + both edge passes) use it; `FLINT_STYLE_SCISSOR=0` / `set_style_scissor(false)` draws full passes. The schema gives `ascii_style` fields no defaults on purpose (the loader fills defaults in). ASCII: `scope = "screen"|"entities"`, `grid = "screen"|"object"`, `--ascii-scope`/`--ascii-grid` (presets only: an entity's own `grid` still wins). Off everywhere (#376): `--style <name>:off` (or `enabled=false`) is `StyleSettings::set_off_everywhere`, which `is_on` and `owner_table` honour, so the props render as plain scene with the rest of the post kept; `set_enabled(name, true)` (a later `--style <name>`, F4's checkbox) lifts it, and a scene table's `enabled = false` stays the table's alone. Demo: `examples/ascii_entities.scene.toml`. Thin features (#288): `outline` (points) and `min_coverage` are ink floors `variant_pixel` passes to `shade`, from the mask edge and the variant's share of the cell's samples; per-entity rows only, slot 0 untouched (`examples/ascii_silhouette.scene.toml`). Whole-cell silhouettes (#338): `silhouette = "cell"` (flag `SNAP`) draws a cell of the variant's grid whole when it covers `cell_share` of the cell's 16 samples, scene pixels included, and drops its own minority cells; the glyph pass's `resolve(p)` asks the pixel's own grid, then each of `snap_grids` (up to `MAX_SNAP_GRIDS` = 8), per pixel; pixel-silhouette variants keep their pixels; outline off on a snapped variant. Scripts (#269): `set_entity_style` / `set_style_param` / `clear_entity_style` queue `ScriptCommand`s that `flint_player::apply_style_command` turns into `flint_render::entity_style` component edits (set/clear fire `style_changed`); `tween_style_param(id, param, target, secs[, easing])` lets the engine ease a number/blend/colour (#370: `flint_player::StyleTweens`, stepped on game time before the frame's commands, start from `entity_style::tween_endpoints`, `style_tween_done` at the end; a `set_style_param` of the param or a clear stops it); `get_entity_style` / `get_entity_style_variant` / `get_style_param` read back (own, inherited or whole-frame; `entity_style::drawn_style` / `style_setting`) through the `flint_script::StyleReader` the player installs (`SceneStyles`, re-copied when `SceneRenderer::post_config_generation` changes, #372); a per-frame param is a variant-table row in the existing uniform, no GPU allocation (`SceneRenderer::kept_post_binds` + hub report test in `tests/stylize.rs`). Demo: `examples/ascii_story.scene.toml`. Whole-frame from scripts (#369): `set_post_style` / `set_post_style_param` / `reset_post_style` edit the renderer's config through `flint_render::post_style` (`flint_player::apply_post_style_command`, fires `post_style_changed`); every style's table takes `blend` 0..1, which `run_stage` draws as the style's input back over its output with blend constant 1 - blend (`stylize/blend.rs`, no per-frame allocation; at 0 `StyleSet::active` leaves the style out of the chain, still built and `is_on`, so the frame is byte-identical to the one without it, #399); demo `examples/dream_story.scene.toml`. Blend (#278): `blend` 0..1 on the style component (or `style_mask`) is the root's, inherited, and rides in the mask's `.g` (`resolve_blended`), never in the variant name, so a ramp keeps one id; an id whose every root is at blend 0 is `StyleIds::is_faded` and asks for nothing, so a style with only faded entities is off, pass and mask skipped (#400; a `scope = "entities"` table is a preset that doesn't hold it on: `StyleDescriptor::covers_frame`); ASCII mixes per pixel (`transition = "fade"`) or turns whole cells by a fixed patch-noise order (`"dissolve"`), each cell ranked in it among its own variant's cells within 8 (#398: `ascii_dissolve{,_order,_rank}.wgsl`, a band a dissolving variant up to `MAX_DISSOLVE` = 8, so a 6x5-cell prop turns exactly round(blend x cells) wherever it sits). Every other mask-reading style gets the blend (and the veil) from the framework's cross-fade (#396, `stylize/fade.rs`: after its pass, its input is mixed back by 1 - `.g` on its own ids, drawn only while `SceneRenderer::style_mask_fades()`); one that draws it itself sets `.blends_itself()` (ASCII; a user style that calls `flint_style_blend`). Demo: `examples/ascii_reveal.scene.toml`; book: stylize-passes.md "Blending in and out" (and how it differs from `--render-mode` tears). Tear source (#397): `blend_source = "tear"` (style component, else `style_mask`; the root's, inherited; `style_mask::follows_tear`) multiplies the blend by the tear's mask at each pixel, in the mask pass (`style_mask.wgsl`'s `written_blend`, the `MaskDraw` uniform now 48 bytes: `torn` + the composite's `mode_params`/mix/post time + the mask's size), so every blend reader gets it. One mask for both: `tear_mask.wgsl` (`tear_mask_at`, plus `hash2`/`value_noise`/`fbm`) is prepended to the composite (`postprocess::COMPOSITE_WGSL`) and the mask (`STYLE_MASK_WGSL`); never copy it. `postprocess::tear_active(config)` (modes 1-4 and 6, mix > 0.001, post on); while false a torn root counts as blend 0 (`StyleIds::shown` pairs, `set_tear`, which `encode_to` calls each frame since a script sets the mode after the world is read) and its draws write blend 0. Render mode 6 is the tear with no look of its own. Demo `examples/ascii_tear.scene.toml`; goldens `ascii-tear*` on `tests/fixtures/scenes/stylize_props_tear.scene.toml`
- **Reveal** (#406) -- `stylize/reveal.rs` + `reveal.wgsl` (prepended with `../tear_mask.wgsl` through `kit::wgsl!`): every style's table takes `reveal` (0..1) and `reveal_shape` (tear|wipe|iris|panel), `reveal_ink`, `reveal_scale`/`_ragged`/`_edge` (points)/`_angle`/`_x`/`_y`/`_boil` (steps a second of post time)/`_seed`, all in `RESERVED_KEYS` (now 15) and `reveal::KEYS`; stored as `StyleSetting::reveal: StyleReveal` (`set`/`set_text`, strict on the command line), read with `StyleSettings::reveal` (None without a `reveal` key), `set_reveal`, `clear_reveal`, `shows` (blend > 0 and reveal > 0: `StyleSet::active` filters by it, so reveal 0 is byte-identical). `BlendPass::draw` hands a reveal in (0, 1) to `RevealPass::draw` in place of the blend: one premultiplied full-screen draw (`One`, `OneMinusSrcAlpha`) putting the style's input back outside the region and the ink on the edge (edge distance in pixels from `fwidth` of the field), uniforms in 16 dynamic-offset 256-byte slots reset per `StyleFrame::frame`. Shapes are a 0..1 field (`base_field`) plus `ragged` x a noise in -1..1 (fbm lobes + ridged teeth and grit that the boil steps; iris lobes only), cut at `reveal::threshold` (exact ends come from the chain and the skip, not the cut). Spec (`--style x:reveal=..`), `post_style::set_post_style_param` and `post_style_number` know the keys; Rhai `tween_post_style_param(style, param, target, secs[, easing])` is `ScriptCommand::TweenPostStyleParam` -> `StyleTweens::tween_post`/`step_post` (core-side, stepped after entity tweens on the lent renderer, `post_style_tween_done`). ~0.09 ms at 1080p on the 4070. Demo `examples/reveal_tear.scene.toml`; goldens `pencil-reveal-*`. F4 (#875): `StylesEditor::reveal_group` under each section's grid (toggle in the header; off stashes the `StyleReveal` in `reveal_stash` and clears it, on restores it at `reveal = 1`), rows from `reveal::NUMBERS` (`reveal_rows`), written back whole with `StyleSettings::replace_reveal`. `StyleDescriptor::table_keys` starts from `RESERVED_KEYS`, so Commit to scene owns `blend` and the reveal keys and removes the ones the config no longer has. Torn paper (#876): `reveal_rim` (points past the line's inner side), `reveal_rim_color` (unset: the style's `paper` colour, else `reveal::DEFAULT_PAPER`, lifted halfway to white; `reveal::style_paper` is that paper, which `RevealPass::draw` passes to `uniform` and F4's Rim colour row shows as its default) and `reveal_shadow` (0..1, reach `SHADOW_POINTS` = 14 down-right) ride in two more vec4s (`RevealUniform` is 112 bytes; `RESERVED_KEYS` 18). In `reveal.wgsl` they are their own uniform branch, so a reveal without them runs the old arithmetic byte for byte (keep it so: `pencil-reveal-tear-half` is the check). Both ask the region by sampling `field()` (rim: a 12-point ring at its width; shadow: 5 steps toward the light), never by `px` past the line: `(f - th) / fwidth(f)` is a distance only at the edge, and reading it further out flecked the sheet with rim and streaked the shadow. `px` only prefilters which pixels sample. In F4 the two numbers are rows like the others (a new reveal number needs a label in `styles_ui.rs`'s `reveal_label`, or its test fails), and the rim colour is a row after them. Rim +0.19 ms, shadow +0.11 ms at 1080p on the 4070; golden `pencil-reveal-torn-paper`
- **Where styles find files** (ADR 0114 step 3, #706) -- never a hand-written directory list: `frame.assets` is the scene's `AssetScope`, and a style resolves a name with `scope.explain(AssetKind::..)` through the shared loaders (`PaletteCache`, `GlyphSetCache`, `images::ImageSlot::get(device, queue, frame.assets, name, poll)`, whose kind is `ImageUse::kind()`: `Papers` / `Strokes`). `ChoiceScope { assets: Option<&AssetScope>, option }`: `scope.files(AssetKind::Palettes)` is `Project::list`'s names sorted, so a discovered list is exactly what the resolver finds (a test offers each name back to the cache); `None` offers the built-ins alone. `catalog_for(scene_dir)` finds the project, `catalog_in(&scope)` / `catalog_text_in` take one. User styles: `custom::load_for(&scope)` registers `scope.list(AssetKind::Styles)` (`load_dir(scene_dir)` wraps it), and `reload_changed_for(&scope)` walks `style_dirs(&scope)` (`search_dirs`) through `file_watch::list` with the same nearest-name-wins rule (not `Project::list`, which would read the disk on the frame thread, #633). **#426's answer**: the nearest `styles/` to the scene wins a name; in one folder a style is its file name, so there is one. The registry is still one for the process, so `load_file` on a file whose name is loaded from another file replaces it in place (`install(.., replace = true)`, as a hot reload does; an `info!`, not a message, so `flint bundle` doesn't refuse it), and a style only an earlier scene's folders had stays registered. Hosts that poll hold the scope (the player's `kept_asset_scope()`, the viewer's `renderer.asset_scope()`)
- **Pencil sketch** (#273) -- `stylize/pencil.rs`, a display style in two passes: a prep pass writes tone, contour (depth steps on the near side, creases from depth-rebuilt normals, mask edges, luma edges by `detail`) and a double-angle stroke direction into `pencil.prep`; the draw pass blurs the direction, hatches up to 4 layers in 15° bins (surface = across grad(1/z), so planes hatch straight), wobbles/doubles contours and lays paper grain. All randomness is integer hashes of row/dash/layer/`seed` (byte-identical runs); `boil` steps the seed by post time. Per-entity via `pencil_style` (same variant table as ASCII, `grid = "object"` anchors the hatching); `grid = "world"` (#389) lays it on the surfaces: triplanar stripes on the depth-rebuilt world position (prep zw then hold the octahedral normal), spacing in octaves of 2^k metres picked per plane and stroke direction from the quad derivatives of the world position and cross-faded like mips, rows hashed by odd part + octave so a stroke survives the climb; a mask id another running style owns (`StyleFrame::foreign_ids`) gets the `FOREIGN` slot and passes through. The `graphite` look uses it. #404: `grazing` (0..1, default 0, the row's ninth vec4 `i.x`) keeps a depth step only where the second difference of 1/z says it is one, so a floor seen edge-on inks one horizon, not a band; no crease within 2 depth texels of the frame's edge (degenerate clamped normals had outlined the frame in every pencil look); a row with `layers = 0` skips the flow taps and the tensor flow passes (`any_tensor`), so line-only is the cheapest pencil; the `rotoscope` look (ink-forward, blank sheet) is built on all three. #883: `clutter` (0..1, default 0, the row's tenth vec4 `j.x`, since #879 took `i.z`/`i.w`) fades a contour where `ink_density` (16 bilinear taps of prep's y on a sunflower spiral, in `pencil.wgsl`) says the lines already cover most of a disc of `clutter_radius` (2 contour widths, >= 3 px) and of one 3x that (min of the two smoothsteps, 0.35-0.65 and 0.30-0.55), so a grass meadow is a sheet, not a black band; the wide disc keeps a small figure's filled limbs; `prep_reach` covers the wide disc; ~0.006 ms at 1080p; rotoscope sets it (goldens `look-rotoscope-meadow`, `-clutter-off` on `tests/fixtures/scenes/pencil_meadow.scene.toml`). #869: `tone = "picture"|"light"` (the row's `i.y`; option, hint and `pencil_style` field) divides the picture's luma by its paint's (`light_luma` in `pencil_prep.wgsl`, both display values; alpha 0 or near-black paint keeps the picture's; a pixel at depth 1, the sky, is tone 1, paper, after brightness and contrast, #890) so hatching follows the light, not dark materials; it reads the **style albedo** (`flint_render::style_albedo`: `StyleDescriptor::uses_albedo: MaskUse`, `stylize::any_uses_albedo`, `StyleFrame::albedo` / `albedo_key`, an `Rgba8Unorm` "style albedo" target drawn by `SceneRenderer::encode_style_albedo` after the style mask: opaque static/procedural/skinned draws, no woozy ones, `fs_albedo` entry points in `shader.wgsl` / `skinned_shader.wgsl`, read-only `LessEqual` against the scene's depth, 4x + resolve under MSAA; ~0.03 ms at 1080p). Pencil's group 2 binding 4 is it, or a blank texel. `rotoscope` takes `tone = "light"` since #887; goldens `look-rotoscope-light`, `look-rotoscope-light-entities-msaa4`. A new opaque draw path the albedo should see needs adding to `encode_style_albedo`. Drawn on (#879): `transition = "fade"|"draw"` (option, hint, `pencil_style` field; the row's `i.z`, and `i.w` is the seed without boil steps, the order's). Under draw a blend in (0, 1) is a front the draw pass reads itself: `u.front` (the uniform's old `_pad0`: the table's blend while the table draws, `whole_frame_front`) times the mask's `.g` on a drawing row's entity pixels (`mask_blend`). Outlines over 0–0.9 of it, each line cut where `draw_order` (2-octave value noise `ORDER_ROWS` = 14 spacings across, flattened through `ORDER_KNOTS`, its measured quantiles) passes `contour_front`; hatch dashes over 0.25–0.95, each from its start, its turn the order at its middle (`dash_progress` / `dash_cut` in `strokes` and `world_strokes`, a `front` above 1 = whole); rubbed shade with the hatching; the paper's wash over 0.4–1 on a 3x broader order. Two modules of one `pencil.wgsl`: `DRAW_SHADER` prepends `pencil_fade.wgsl` (`const DRAW_ON = false`, folding the draw-on code out) and `DRAW_ON_SHADER` `pencil_draw_on.wgsl`; `draws_on_now(rows, front, mask_fades)` picks the second only while a front can be below 1. **Don't put draw-on code in the plain path**: a `* cut` of 1 inside `strokes`, even a branch that only passed `front` in, moved 83 pixels of pencil-full by one level (the driver reassociated the strokes' products), which is why the dash cut is its own `stroke_drawn` / `world_stroke_drawn` the caller multiplies in.
