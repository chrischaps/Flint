# flint-render stylize: styles, the style mask, per-entity and user-authored styles (moved out of the root CLAUDE.md by #755)

Flags that switch styles on (`--style`, `--ascii*`, `--look`, `--sweep`) and the stylize goldens: `crates/flint-cli/CLAUDE.md`. Glyph atlas, contour and shading boil, post-processing: `crates/flint-render/CLAUDE.md`.

- **Stylize passes** (#262, ADR 0111) -- `flint_render::stylize`: a style is a module exporting `STYLE: StyleDescriptor` (name, `StyleStage::Hdr` before fog/bloom/tonemap at scene resolution or `Display` after the composite at output resolution, params with ranges, `create`) plus its name in `register_styles!`; its `StylePass::encode` reads a `StyleFrame` (params, depth, camera, `target()` scratch textures, kept bind groups). Styles of a stage chain in registration order (or a table's `order = <n>`, lower first, ties by registration; `stylize::chain_order` / `stage_chain`, F4's chain line with swap buttons, #299) through framework ping-pong targets that live in `PostProcessResources` (rebuilt on resize). Scenes: `[post_process.styles.<name>]` (Kuwahara too since #298: a scene's old `kuwahara_*` keys fold into its table on load via `flint_scene::fold_legacy_style_keys`; numbers are `params`, strings are `options`, e.g. a font or ramp); F4 → Styles (and the player's F3 Styles panel, made when a scene uses a style) is one `flint_debug_ui::StylesEditor` drawn from descriptors (#268): each `StyleParam` / `StyleOption` carries its own label, help, `.integer()` and `.when`/`.unless` (`StyleUi`, #510: `StyleParam::new(..).label(..).help(..)`; a colour's on its `_r` channel; read back with `label_for` / `help_for` / `is_integer` / `ui`; there is no hints list), `<base>_r/_g/_b` params fold into one colour picker (display values) and are one colour setting (`StyleColor`, #315: `tint = [r, g, b]` or `"#rrggbb"` in a table, `tint=#rrggbb` or `r/g/b` on `--style`, `frame.color("tint")` / `variant_color`, Copy TOML writes the array), and each style gets Defaults / Authored / Copy TOML (`stylize::style_toml`); an option can find its choices at run time (`StyleOption::discovered` + `ChoiceScope::files`, #322: ASCII lists the scene's `palettes/`, `fonts/` and the chosen font's ramps through the vfs; hosts pass the scene folder with `RenderDebugPanel::set_scene_dir` / `StylesDebugPanel::with_scene_dir`, and a discovered option is open to `--style`); `ascii` (#265) is the display-stage glyph style, cells in points times `SceneRenderer::pixels_per_point` (hosts set it from the window), fonts found via `frame.assets` (see "Where styles find files"); its edges (#267) are two more passes (`ascii_edges.wgsl`: edge pixels at `StyleFrame::depth_size`; `ascii_edge_cells.wgsl`: one texel a glyph cell summing structure tensors) that the glyph pass draws as line glyphs, and a mask boundary where either side is one of the style's ids (plain or per-entity variant) is always an outline; `encode_to` builds newly enabled styles itself. `invert` is the template. Bloom reads the unstylized HDR unless an HDR style that ran feeds it (#300): `StyleDescriptor::feeds_bloom` (user styles: `feeds_bloom = true` in the `.shader.toml`), overridden per scene by `feeds_bloom` in `[post_process.styles.<name>]`, `--style <name>:feeds_bloom=1`, F4's Feeds bloom checkbox; then the threshold reads the HDR stage's result (`run_bloom`'s `source`, keyed by input id). SSAO/volumetrics read depth only. Demo: `flint-examples/neon_bloom.scene.toml`. Shared edges (#301): a descriptor's `needs: &[StyleNeed::Edges]` gets `StyleFrame::edges` (`stylize/edges.rs`: `Rgba16Float` at the depth's size, r = silhouette / g = crease strength over the shared `[post_process] edge_depth`/`edge_normal` (`--set post.edge_depth=..`), ba = unit direction, y down; `edges_bind` + `kit::texture_layout`), drawn once a frame before the Hdr stage however many styles read it (`SceneRenderer::style_edge_runs`); `edges_view` shows it, user styles take `inputs = ["edges"]` (`flint_edges`/`flint_edge`). Since #743 the only geometry edge detector here (next bullet but six). A style with frame-to-frame state (ASCII's per-cell history, #277: a cell pass into a ping-ponged `Rgba16Uint` texture via `target_sized`, then the glyph pass) trusts it only when `StyleFrame::frame` follows its last frame and `history_epoch` is unchanged; hosts call `SceneRenderer::reset_style_history()` on a scene change or camera cut (#343: Rhai `reset_style_history()`, and the player's `camera_cut` detector resets on a jump > 2 m, a turn > 30° or a zoom > 1.25x (`tan(fov/2)` or the ortho half-height, #474) in a frame at > 4x the last frame's rate, and on a projection switch; `set_camera_cut_detection(false)`; `flint-examples/ascii_cuts.scene.toml`, whose script's `zoom` cuts by FOV alone. The scene viewer runs no detector: it resets at its own jumps, Space, a projection switch and a hot reload, `flint_viewer::app::reset_style_history`). `temporal = "reproject"` (#344) reads a cell's past where its surface was last frame (scene depth + last frame's `view_proj`, kept by the style; an `R32Float` cell-depth target rejects disocclusions); measured no better than screen-space history on the meadow, so opt-in (`tools/ascii_flips.py --track 8` counts flips along the motion). Book: concepts/stylize-passes.md (reference) and guides/stylized-rendering.md (choosing whole-frame vs per-entity, with the decision's captures). The decision: per-entity *selection* on one screen grid, with full screen its "everything" case and `grid = "object"` opt-in only; glyph-like styles at the Display stage (`docs/adr/0111-stylized-rendering.md`)
- **The registry is a value** (ADR 0129, #742; `stylize/registry.rs`) -- `StyleRegistry`: the built-ins (`builtins()`, the `register_styles!` slice; `builtin(name)`, `is_builtin(name)` are the only free lookups), then game styles in registration order, then user styles in load order, plus the user styles' load failures. No `static` holds a descriptor. `Clone` is cheap (user styles are `Arc`s). Lookups: `find`, `style` (a `Style`), `index_of`, `names`, `iter`, `styles`, `is_game_style`, `is_native`, `is_user_style`; frame-wide: `any_uses_mask`, `any_uses_albedo`, `owner_table`, `foreign_ids(d, ..)`, `stage_chain`. `SceneRenderer` owns the one it draws with (`styles()`, `styles_mut()`, `set_styles`), set by `bind_scene` from `SceneBinding::styles()`; every reader takes `&StyleRegistry` (`post_process_config_from_def(def, &styles)`, `StyleSettings::from_tables(t, &styles)`, `StyleSpec::parse`, `apply_style_spec(s)`, `check_style_specs`, `style_spec_help`, `post_style::*` and `entity_style::*` after their config/world, the `style_mask` resolvers, `catalog::*`, `LookFade::new(.., &styles)`); `StyleFrame::styles` and `StyleDevice::style` carry it into a pass. `Style` is a native `&'static StyleDescriptor` or a user `Arc<custom::Loaded>` (which holds its own descriptor); `StyleDescriptor::params` / `options` and `StyleOption::choices` are `List<T>` (a `'static` slice or an owned `Arc<[T]>`, `Deref` to the slice: iterate `&d.params`). Identity is name + `StyleDescriptor::generation` (0 native, a counter per user install; `Style::same`): `StyleSet` keys built passes by name (`BuiltSlot { from: Style, .. }`), drops a slot whose style is gone or another install, and `StyleFrame::bind`/`depth_bind` mix the generation into the cache key (`keyed`), so a user style's bind names need no generation. User styles' strings are interned (`stylize::intern`, content-keyed, bounded by what was typed). Tests own their registries and need no lock: `RELOAD_POLL` and `under` are gone
- **A game's Rust styles** (#419) -- `StyleRegistry::register(&'static StyleDescriptor) -> Result<(), String>` puts it after the natives, before any user style, and records the name; it refuses a non-identifier name (`custom::is_identifier`), any registered name (built-in, user, game) and a `component` another style takes, and accepts the same pointer again. Register before the scene's `[post_process]` is read against that registry. A `.shader.toml` naming a game style of the registry it loads into is a load error (`load_file`), a reload never replaces one, the catalog's `source` is `"game"`, F4 tags it `game`, and a game style whose `create` panics is turned off with an error, not a lost device (`ensure_style_resources`). Player hook: `PlayerExtension::styles()`, registered in `add_extension`. Example game: `crates/flint-player/examples/cyanotype/` (two passes into a `frame.target`); the out-of-crate GPU test is `a_style_registered_from_another_crate_draws_its_two_passes` in `tests/stylize.rs`. Only the game's binary knows them: `flint render`/viewer don't. A game style's shader from a bare `include_str!` builds through `kit::shader` but never hot-reloads under `FLINT_STYLE_SHADER_DIR` (next bullet)
- **Built-in shader hot reload** (#418) -- `stylize/dev_shader.rs`: a built-in shader is `kit::wgsl!("a.wgsl", "b.wgsl")` (a `kit::Wgsl { text, files }`: the `include_str!`s concatenated plus the names; `kit::shader` takes `impl Into<Wgsl>`, so a bare `&'static str` still builds but never reloads, so use the macro for a new style's files). `FLINT_STYLE_SHADER_DIR=<dir>` (natively; read once, `dev_shader::set_dir` in tests) makes `kit::shader` read `<dir>/<file>` for each name (vfs), naga-check the concatenation (an error is placed in its file by byte offset) and fall back to the last good text (else the compiled-in one). `StyleSet::ensure` builds every style, and the shared edges/fade/ownership passes, through `dev_shader::build`, which records the files read in a thread-local; every `POLL_FRAMES` = 15 calls it stamps them (`file_watch`) and drops each slot that read a moved file, which this same call builds again. A dropped slot sets `take_rebuilt`, and `ensure_style_resources` then calls `BindCache::clear` (the kept bind groups hold the old pass's buffers: without it a param change after a reload is ignored, which the test catches). A build that panics (wgpu refuses what naga took) is built again with `fallback` (last good texts only) and is not a lost device. Texts become last good only when the whole build succeeds. Errors: `dev_shader::errors()` (style, message), drawn beside `StyleRegistry::errors()` by the viewer and player. `BlendPass` builds lazily, outside a recorded build, so a reload always resets it. Test: `tests/dev_shader.rs` (its own binary, since the folder is the process's)
- **Kept style pipelines** (#911) -- `kit::shader` returns a `kit::Shader` (derefs to the `wgpu::ShaderModule`, keeps its WGSL text), and the `kit::fullscreen_pipeline*` functions are generic over what the result is stored as (`kit::KitPipeline`): a `wgpu::RenderPipeline` is always built (a game's style that stores one is unchanged); an `Arc<wgpu::RenderPipeline>`, which every built-in style stores, goes through `pipeline_cache::scoped`. `StyleSet::ensure` runs each `create` under `pipeline_cache::in_scope((name, generation, format))`, and a scoped pipeline's key is that scope, its place in it, label, the SHA-256 of the module's text, entry point, formats, blend and layout count. The layouts' entries aren't in it (wgpu can't read them back): one descriptor at one format builds the same ones every time, so a `create` must build its layouts from nothing but its descriptor and format, never from a setting or the device's limits. The text in the key is why a `FLINT_STYLE_SHADER_DIR` swap or edit never reuses a stale pipeline, and a user style's edit is a new generation. Outside a scope (a lazily built pipeline at encode time) nothing is kept unless the site opens one: fade, ownership, blend and reveal do, by `(name, format)`. A bare `wgpu::ShaderModule` passed to kit is never kept
- **Styles built ahead** (#1121) -- `StyleSet::prepare(device, format, config, ids, styles)` (`SceneRenderer::prepare_styles(device, &config)`, the player's `PlayerApp::prepare_look`, Rhai `prepare_look(name)`) starts a thread per style the config switches on that isn't built, failed or building, plus the shared edges, cross-fade and ownership passes it will need (`off_thread`: a `std::sync::mpsc` channel; on wasm the build runs at the call). Each runs the same body `ensure` runs (`build_style` / `build_edges` / `build_fade` / `build_ownership`: `dev_shader::build`, `catch_unwind`, `pipeline_cache::in_scope`), on a clone of the `Device` and the `Style`; `StylePass: Send + Sync` is what makes that legal. `ensure` takes in whatever arrived at its start (`collect_prepared(name, false, ..)`), so the frame a prepared style is switched on builds nothing; a style it needs that is still building it waits for (`collect_prepared(.., true, ..)`, a `StyleBuild` note `<name> (waited for its prepare)`), never builds twice; a worker that died or couldn't start hangs up, and `ensure` builds it itself. A prepared build that panics is reported by the `ensure` that collects it, as a frame's would be. `preparing()` / `styles_preparing()` list what is still out, `style_built(name)` what is in. Frame notes are per thread, so a worker's builds are never a frame's; `gpu_counts` totals are process-wide, so its pipelines count in the frame they finish during (a count note explains no hitch). Measured (looks tour, release, Vulkan, RTX 5070 Laptop, a fresh NVIDIA shader cache a run): the `ascii_noir` beat 976-1083 ms without (eight runs), 825-1491 ms on DX12 (three), no hitch with (seven). The same tour showed the user-style reload poll (`reload_changed_for`) stalling 150-260 ms a poll: `loaded_from` called `same_path` (which asks the working directory and the disk, `anchor`) on every mismatch, so it now compares spellings first, and the style folders are worked out once a scope (`StyleRegistry::poll_dirs`); test `custom::tests::the_reload_poll_asks_nothing_of_the_disk_for_styles_it_has`. Tests: `tests/pipeline_cache.rs::a_prepared_style_is_built_off_the_frame_and_draws_the_same`, `a_frame_that_needs_a_style_still_preparing_waits_for_it` (cache off, ASCII's pipelines counted once, bytes equal to a style built on its frame)
- **Entity style mask** (#263) -- `flint_render::style_mask`: a `style_mask { style, enabled }` component (descendants inherit; nearest wins) gives each styled entity an id (`StyleIds`, 1.. in name order). After the scene pass (and MSAA depth resolve) its opaque static/box/skinned draws, its terrain chunks (`bind_scene` names the terrain entity when it loads the terrain, #310, #739) and then its styled transparents (a styled transparent is a lens: its id replaces what is behind it, #310) are redrawn with their cached transform (+ bone) bind groups into an `Rg16Uint` target in `StyleTargets` (id in `.r`, blend in `.g`, #278), depth-tested in the shader against the single-sample depth with a slope tolerance; ids ride one dynamic-offset uniform buffer. Drawn only while a style whose `uses_mask` asks for it is on (`MaskUse::Always`, or `MaskUse::When(fn(&config, &ids))` per frame, #350: ASCII only with `edges > 0` and an id to outline); styles read `StyleFrame::mask` / `mask_bind` / `style_id`. `--debug-mode style` (`DebugMode::StyleMask`) turns on the `mask_view` display style. Demo: `flint-examples/style_mask.scene.toml`. Veil (#290): just before the mask, unstyled transparents and all particles draw their coverage into an `R8Unorm` "style veil" (read-only scene depth attachment, `fs_veil` entry points in `shader.wgsl`/`skinned_shader.wgsl`/`particle_shader.wgsl`), and the mask writes blend x (1 - coverage): what's in front unmasks by its coverage. The mask and the veil are selectors over the draw list (#737): the veil takes every unstyled item whose `Blend` blends (echoes too, through `veil_echo`, the skinned veil on front faces only, each by its alpha, a lightening one included), so a new kind of draw is asked by the compiler what it veils. Billboards are `Blend::Opaque` (alpha cut at 0.5, depth written), so the mask's depth test leaves one in front out and the veil has no billboard arm (golden `style-veil-billboard`). A styled billboard is masked (#1011): `MaskShape::Billboard` in `mask_draw`, drawn by `StyleMaskPass::ensure_billboard`'s pipeline from `billboard_mask_source()` (the mask WGSL with its `//FLINT_MESH {` .. `}` blocks cut, so the sprite's groups 0 and 2 take the transform's and bones' slots, then `style_mask_billboard.wgsl`: billboard_shader.wgsl's quad and alpha cut, then fs_main's / fs_msaa's tests); the plain module is byte for byte what it was. Its scissor box is `BillboardDrawCall::world_aabb` (`sprite_bounds`). No albedo draw: a billboard is unlit, so the picture is its albedo. Goldens `style-mask-billboard[-msaa4]`, `style-billboard-ascii`; test `tests/stylize.rs::a_styled_billboard_is_masked_where_it_draws`. A woozy draw is masked through its own vertex stages (`crates/flint-render/CLAUDE.md`, Shallow wooze). Goldens `style-veil-echo`, `style-mask-wooze[-msaa4]` Demo: `flint-examples/style_veil.scene.toml`
- **Per-entity styles** (#266) -- a descriptor's `component: Some("ascii_style")` makes a style per-entity: an entity with that component (or a `style_mask` naming the style) switches it on for its own pixels with no `[post_process.styles]` table (`is_on(config, &StyleIds)`; `ensure`/`active`/`any_uses_mask` take the ids). Its fields are the descriptor's params/options (ASCII's `font` too, #335: every set in use is stacked into one atlas, each variant row carrying its glyph cell and edge-glyph start; up to `MAX_FONTS` = 8), falling back on the scene's table then defaults (`StyleVariant::param`; a colour `tint = [r, g, b]` or `"#rrggbb"` fills `tint_r/g/b`, #315); each distinct set is a `StyleVariant` with its own id, named for its settings (`ascii{ramp=blocks}`, `ascii@barrel` for `grid = "object"`, `ascii{off}` for `enabled = false`). Styles read `frame.variants()` / `variant_param` / `whole_frame()` / `project`. Scissor (#385): `frame.styled_rect(pad)` is the style's entities' projected draw bounds (skinned ones as posed, from CPU copies of the bone matrices) grown by `pad`, `None` when it covers the frame; `kit::scissored_pass` draws inside it and blits the input around it (byte-identical only while the passthrough is exact outside), `kit::fullscreen_pass_in` for prep passes; pencil and ASCII (glyph + both edge passes) use it; `FLINT_STYLE_SCISSOR=0` / `set_style_scissor(false)` draws full passes (`stylize::set_scissor_enabled` before the renderer is made, the web page's `?scissor=0`, #538), all but ASCII's edge cell pass, which stays cut to `frame.styled_area(pad)` (`styled_rect` with the scissor on or off; `StyleFrame::scissor` is the renderer's switch, and the bounds are projected whenever the mask is drawn): the cells past it are empty either way, so the edge history a cell starts the next frame from (#477) is too. Drawn whole, they held unstyled geometry's lines, and the frame after an ASCII prop jumped started from another past (#930; `tests/stylize.rs::a_moving_ascii_crate_draws_the_same_scissored_as_full_frame_after_frame`, 2 pixels on main). State a style keeps from frame to frame belongs inside `styled_area`. The region holds this frame's corner reach: `EDGE_CORNER_REACH` (3 cells) = `GLYPH_RECT_CELLS` (the glyph rect's 2) + the 1 `edge_regions` adds, held by `edge_regions_hold_every_cell_a_drawn_cells_corner_reads`; a thin or corner pass that reads further raises it. `kit::scissored_pass_around` draws the bands with a pipeline the style gives instead of the blit, for a passthrough that isn't a `textureLoad` (#538): watercolor's `fs_passthrough` (its unpainted pixel, `textureSampleLevel` at `in.uv`, an entry point of the same module) around its paint pass, scissored by `Reach::paint` (the widest row's `wobble`, since an unpainted pixel paints where its wobbled mask read lands), its wash V by `Reach::wash` past that (the wobble plus the glazes' 1.5 pt) and its wash H by `Reach::blur` past that (two radii), both `fullscreen_pass_in`; a user style that declares `reach = <points>` in its `.shader.toml` (mask-reading only, 0..`MAX_REACH` = 512) gets its last pass scissored to `styled_rect(reach_pixels(reach, ppp))` with its own passthrough pipeline (the same prelude and epilogue around `return p.color`) around it; target passes stay whole (nothing says how far a later pass reads them), and the promise is the author's (a style that changes a pixel past its reach is cut there, `tests/stylize.rs`'s `utest_leak`). Byte-identical three ways (main, scissor on, off) on `flint-examples/watercolor.scene.toml` at 1280x720, 1920x1080 at 2 points a pixel, MSAA 4 and its fixture, and on `flint-examples/user_styles.scene.toml` with the hologram at `reach = 0`. The schema gives `ascii_style` fields no defaults on purpose (the loader fills defaults in). ASCII: `scope = "screen"|"entities"`, `grid = "screen"|"object"`, `--style ascii:scope=..,grid=..` (presets only: an entity's own `grid` still wins). Off everywhere (#376): `--style <name>:off` (or `enabled=false`) is `StyleSettings::set_off_everywhere`, which `is_on` and `owner_table` honour, so the props render as plain scene with the rest of the post kept; `set_enabled(name, true)` (a later `--style <name>`, F4's checkbox) lifts it, and a scene table's `enabled = false` stays the table's alone. Demo: `flint-examples/ascii_entities.scene.toml`. Thin features (#288): `outline` (points) and `min_coverage` are ink floors `variant_pixel` passes to `shade`, from the mask edge and the variant's share of the cell's samples; per-entity rows only, slot 0 untouched (`flint-examples/ascii_silhouette.scene.toml`). Whole-cell silhouettes (#338): `silhouette = "cell"` (flag `SNAP`) draws a cell of the variant's grid whole when it covers `cell_share` of the cell's 16 samples, scene pixels included, and drops its own minority cells; the snap owner pass decides each cell's holder once (#929, the bullet after #910's), and the glyph pass's `resolve(p)` reads the pixel's own grid's texel, then each of `snap_grids`' (up to `MAX_SNAP_GRIDS` = 8); pixel-silhouette variants keep their pixels; outline off on a snapped variant. Scripts (#269): `set_entity_style` / `set_style_param` / `clear_entity_style` queue `ScriptCommand`s that `flint_player::apply_style_command` turns into `flint_render::entity_style` component edits (set/clear fire `style_changed`); `tween_style_param(id, param, target, secs[, easing])` lets the engine ease a number/blend/colour (#370: `flint_player::StyleTweens`, stepped on game time before the frame's commands, start from `entity_style::tween_endpoints`, `style_tween_done` at the end; a `set_style_param` of the param or a clear stops it); `get_entity_style` / `get_entity_style_variant` / `get_style_param` read back (own, inherited or whole-frame; `entity_style::drawn_style` / `style_setting`) through the `flint_script::StyleReader` the player installs (`SceneStyles`, re-copied when `SceneRenderer::post_config_generation` changes, #372); a per-frame param is a variant-table row in the existing uniform, no GPU allocation (`SceneRenderer::kept_post_binds` + hub report test in `tests/stylize.rs`). Demo: `flint-examples/ascii_story.scene.toml`. Whole-frame from scripts (#369): `set_post_style` / `set_post_style_param` / `reset_post_style` edit the renderer's config through `flint_render::post_style` (`flint_player::apply_post_style_command`, fires `post_style_changed`); every style's table takes `blend` 0..1, which `run_stage` draws as the style's input back over its output with blend constant 1 - blend (`stylize/blend.rs`, no per-frame allocation; at 0 `StyleSet::active` leaves the style out of the chain, still built and `is_on`, so the frame is byte-identical to the one without it, #399); demo `flint-examples/dream_story.scene.toml`. Blend (#278): `blend` 0..1 on the style component (or `style_mask`) is the root's, inherited, and rides in the mask's `.g` (`resolve_blended`), never in the variant name, so a ramp keeps one id; an id whose every root is at blend 0 is `StyleIds::is_faded` and asks for nothing, so a style with only faded entities is off, pass and mask skipped (#400; a `scope = "entities"` table is a preset that doesn't hold it on: `StyleDescriptor::covers_frame`); ASCII mixes per pixel (`transition = "fade"`) or turns whole cells by a fixed patch-noise order (`"dissolve"`), each cell ranked in it among its own variant's cells within 8 (#398: `ascii_dissolve{,_order,_rank}.wgsl`, a band a dissolving variant up to `MAX_DISSOLVE` = 8, so a 6x5-cell prop turns exactly round(blend x cells) wherever it sits; #554: a cell is the variant's when any pixel is, the 16 lattice samples first and then a scan of the cell's pixels inside `Variant::bounds` where they all missed, so slivers are ranked too (a cell clear of the bounds returns before any mask read, which pays for the scan: ASCII's min GPU time over 300 frames at 1080p 0.188 vs main's 0.193 ms close up, 0.160 vs 0.155 far, RTX 4070 on a busy machine); a snapping variant keeps `cell_share` of the samples; tests `a_small_props_dissolve_*` and `a_dissolve_ranks_the_sliver_cells_*` hold every place to half, an odd n's middle cell (rank exactly 0.5) turning by the mask blend's last bit). Every other mask-reading style gets the blend (and the veil) from the framework's cross-fade (#396, `stylize/fade.rs`: after its pass, its input is mixed back by 1 - `.g` on its own ids, drawn only while `SceneRenderer::style_mask_fades()`); one that draws it itself sets `.blends_itself()` (ASCII; a user style that calls `flint_style_blend`). Demo: `flint-examples/ascii_reveal.scene.toml`; book: stylize-passes.md "Blending in and out" (and how it differs from `--render-mode` tears). Tear source (#397): `blend_source = "tear"` (style component, else `style_mask`; the root's, inherited; `style_mask::follows_tear`) multiplies the blend by the tear's mask at each pixel, in the mask pass (`style_mask.wgsl`'s `written_blend`, the `MaskDraw` uniform 48 bytes: `torn` + `postprocess::tear_params` (amount, scale, iris, post time) + the mask's size), so every blend reader gets it. The tear is the frame's since #746: `[post_process] tear` / `tear_scale` / `tear_iris` (descriptor lines, effect `tear`), `--tear`, Rhai `set_tear` / `set_tear_shape`.
