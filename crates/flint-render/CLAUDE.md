# flint-render: renderer notes that are not stylize (moved out of the root CLAUDE.md by #755)

Styles, the style mask and user styles: `src/stylize/CLAUDE.md`. Flags: `crates/flint-cli/CLAUDE.md`. The wooze field, whose clock drives boil and shallow wooze: `crates/flint-procgen/CLAUDE.md`. The root file keeps a short form of the first two bullets and of the lights bullet.

## Frame and GPU rules

- Per-frame GPU allocations are the renderer's CPU cliff: `update_from_world` rebuilds the draw lists every frame, so anything it needs per entity must come from a cache (`draw_bind_cache` for transform/material binds keyed by entity + sub-mesh with a material hash, `box_mesh_cache` for procedural boxes, `GpuMesh` buffers shared via `Arc`, one dynamic-offset uniform buffer for all shadow draws). Never `create_buffer`/`create_bind_group` inside a per-entity loop; a 270-entity scene went from ~17 ms to ~4 ms when those were removed. Skinned draws use the same cache (`SKINNED_DRAW_KEY`, bone binds in `skinned_bone_binds`, #121). On the web every `create_*` is also a JS object: Float's skinned path made 386 buffers and 327 bind groups a frame, and Firefox stalled ~250 ms at each GC. Count WebGPU calls per frame in the browser before trusting a desktop timing (`?perf=1` shows them: the page wraps `submit`/`writeBuffer`/`createBindGroup`/`createBuffer`/`beginRenderPass`, #139)
- One submission a frame (#139): `SceneRenderer::encode_to` records the whole frame (grass, shadows, scene, post-process, depth upscale, world lines) into the caller's encoder, the player adds its HUD and the GPU timer's resolve (`encode_gpu_timings`), submits once, then calls `frame_submitted` (grass and timer read-backs). `render_to` is that with its own submit. Every `queue.write_buffer` lands before the submission, so a uniform buffer may hold one value per frame: steps that differ get slots of their own (bloom's per-step slots), and encoding two cameras into one submission would show the second camera's uniforms to both. Cached draws' transforms live in `TransformArena` pages (`bind_cache.rs`, a 256-byte slot each, one write per page); post-process bind groups live in `PostProcessResources::binds` (dropped on resize); ones over the caller's depth view are kept under the id the caller passes with it (#379: `encode_to`/`render_to` take `impl Into<DepthTarget>`, `RenderContext::depth_target()` / `HeadlessContext::depth_target()`, a `new_depth_id()` each time the texture is made; `BindCache::get_over` drops the old id's groups) and made per frame for a bare `&TextureView`, since wgpu 23 gives a view no identity to key on. A host that makes its own depth texture takes a new id with it, or kept groups bind the old texture
- wgpu v23 on DX12: the shader-visible sampler heap has 2048 slots and every bind group's samplers are copied into it, with no sharing, so samplers in a per-entity or per-material bind group cap how many can live ("Not enough memory left" in `create_bind_group`, DX12 only; test with `WGPU_BACKEND=dx12`). Keep samplers in groups bound once a frame: PBR materials sample with the light group's `material_sampler` (group 2, binding 4), and a material bind group holds none
- HDR format `Rgba16Float` -- all pipelines must use this when post-processing active; `resize_postprocess()` on window resize

## Pipelines

- Skeletal animation: separate `SkinnedVertex`/`skinned_pipeline`; bone matrices in storage buffer (bind group 3)
- Particles: no depth write; one shared storage buffer indexed by `first_instance`; skip draw for 0 alive; `bytemuck::cast_slice` for zero-copy
- glTF `doubleSided` (#623): `ImportedMaterial::double_sided` -> `DrawCall::double_sided` + `MaterialUniforms::double_sided` (the old `_pad_e2` word). Opaque and shadow pipelines for PBR meshes each have a no-cull `*_double_sided` twin (static, skinned, `WoozePipelineSet::opaque_double_sided`, `ShadowWooze`), picked per draw; blended draws already draw both faces in two passes. `fs_main`/`fs_skinned` take `@builtin(front_facing)` and `facing()` turns a back face's normal toward the viewer. A new culling pipeline for meshes needs its twin. Bench: `examples/double_sided.scene.toml`; fixture `testModels/DoubleSidedCard.glb`

## Lights

- Lights are `[entities.x.light]` with a `type`, and a directional `direction` points *toward* the light. The fields and their fallbacks are `schemas/components/light.toml` (`flint schema light`), which a test holds to what `extract_lights_from_world` reads; only `type`, `color` and `intensity` carry a schema default, since a default is written into the component at load and `range` would then beat an authored `radius`. No system reads a `directional_light` table and `flint validate` still passes it (#683), so a scene with only that gets `default_scene_lights` and no warning (the frozen fixtures do, on purpose; the examples no longer do, #681). One point light and no directional means no sun at all. An ambient-only scene says `[environment] default_lights = false` (and `shadows = false`) rather than adding a dummy light; a sun at `intensity = 0` with no `volumetric_intensity` draws no shadow pass anyway (`SceneRenderer::shadows_drawn`, #627). `material.unlit = true` draws base colour x `emissive_scale` + emission with no lighting (`MaterialUniforms::unlit`, both PBR shaders)

## Post-processing and quality

- **Post-processing** -- HDR pipeline (`Rgba16Float`) with bloom, SSAO, fog, volumetric (god rays), Kuwahara (anisotropic painterly filter), vignette; `[post_process]` TOML block; F4 opens the Rendering & Effects debug menu in the player and viewer (all toggles + parameters, ADR 0053); when active, PBR shaders output linear HDR
- **Quality settings** (FlintKart#55) -- `flint_core::quality::QualitySettings` (render_scale, render_scale_auto, msaa, shadows, shadow_resolution, shadow_cascades, shadow_distance, and post caps post_process/bloom/ssao/ssao_samples/fog/volumetric) reaches `SceneRenderer::set_quality` from `--quality k=v,...` (flint-player and `flint render`), the page's `?quality=`, Android's `dev_profile.toml` `[quality]`, and scripts' `set_quality(map)` / `get_quality()` / `gpu_info()`, applied between frames (`PlayerApp::apply_quality`). Post keys are caps over the authored config: the renderer keeps `post_process_config()` (authored) apart from `effective_post_process_config()` (drawn), so a scene load keeps the tier. An MSAA change rebuilds every scene pipeline against equal bind group layouts (wgpu dedupes them), so cached bind groups stay valid; a new scene pipeline must be added to `set_msaa`. Shadow cascades map split depths through the camera's own near/far (they assumed 0.1/200 before, stretching the last cascade to the 1000 m far plane). Book: concepts/quality-settings.md
- **Shading boil and contour** (#214) -- `contour` is a registered HDR style (#599, `stylize/contour.rs` + `contour.wgsl`), registered last of the built-ins so it inks over Kuwahara; `[post_process.styles.contour]` takes `width threshold strength luma color fade boil`: depth as the second difference of 1 / distance, so flat ground draws no lines, plus luminance, one full-screen draw. The old flat `contour_*` keys and `kuwahara_boil` fold into the tables through `LEGACY_STYLE_KEYS` (`PostProcessDef` keeps them as `Option`s; `PostProcessDef::boil`/`set_boil`), and `--contour*` flags are shorthands for its keys. The demo user style once named `contour` is `contour_map` now (it sorts before `hologram`, so it keeps its place in the display chain). Boil is opt-in twice: each style's `boil` above 0, and a `[wooze]` table. Read and write both amounts with `PostProcessConfig::boil_amounts` / `set_boil_amounts` (presets, A/B, `tune_living`; a write of an unchanged amount makes no table); `commit_look` writes a boil into the style's table when the file has one, else the flat key, since a new table would switch the style on (`commit::fit_edits`). `boil_on` stays one shared `[post_process]` key. `flint_core::wooze::BoilClock` counts the field's beats, with six film frames to a beat so that `boil_on` 1, 2 and 3 all land on it, on game time. Whoever owns the clock stamps `SceneRenderer::set_boil(BoilFrame)` each frame (player, viewer, `flint render --boil-time`); the field is sampled at the camera, and `jitter` alone is the strength. A boil of 0 skips the noise entirely, which is what keeps it byte-identical. Bench: `examples/shading_boil.scene.toml`, where nothing else moves, so `--frame-step 1/24` frames come in byte-identical pairs on twos. Book: concepts/post-processing.md

## Shallow wooze

- **Shallow wooze** (#215) -- a `shallow_wooze` component (`amplitude` metres, `wavelength` metres; schema in `schemas/components/`) on an entity with a mesh, or above several, in a scene with a `[wooze]` table: each vertex moves through world-space vector noise on the field's clock, in the main and shadow passes alike. `flint_core::wooze::ShallowClock` counts beats as a prop does, with no phase offset, so meshes in one place share one continuous displacement. `player_app/shallow_wooze.rs` gives each group one clock (the topmost component's), and `SceneRenderer::set_shallow_wooze` takes this frame's `ShallowWoozeDraw`s. Pay-nothing is the point, so don't add to `shader.wgsl` or `shadow_shader.wgsl` for this: woozy draws have their own vertex stages (`wooze_vertex.wgsl`, `wooze_shadow_shader.wgsl`, both prefixed with `wooze_noise.wgsl`) over the existing fragment stages, in `WoozePipelineSet`s and `ShadowPass::wooze`, built on the first woozy draw. The drift rides in padding: the last 48 bytes of a transform arena slot (every arena bind group now binds the whole 256-byte slot) and of a shadow draw slot. A plain `flint render` and the wireframe view show the rest pose; `--time` and `--sweep` draw it (`WoozeClocks`). 268 woozy entities cost about 0.6 ms a frame. A test mirrors the noise in Rust, so change both together. Bench: `examples/shallow_wooze.scene.toml`. Book: concepts/procgen.md

## Glyph atlas

- **Glyph atlas** (#264) -- `flint_render::glyph_atlas`: `GlyphSet` = a coverage atlas (`R8Unorm` via `GpuGlyphAtlas`) + named luminance ramps + edge glyphs, from `fonts/<name>.glyphs.toml` (TTF via ab_glyph, PNG grid, hand-drawn `.txt` cells with `cell = [w, h]`, or the hand-drawn built-in 8x8 set in `builtin_8x8.txt`); `GpuGlyphStack` stacks several atlases in one texture (#335); `GlyphSetCache::get("builtin"|"<name>")`; it and `PaletteCache` hot-reload natively (#323: `poll()` stats the files an entry read or searched, `crate::file_watch::FileStamps`; the ASCII style polls every 15 frames; a glyph set that breaks on reload keeps its last good `Arc` with one warning, #286). Top-level keys like `default_ramp` go before the first `[table]`. Look at one with `cargo run -p flint-render --example glyph_atlas -- out/ [set]`. `ui_text` sprite fonts draw from the same atlases (ADR 0113, #283): `BitmapFont` is layout over a `GlyphAtlas`, `ui_text.font` = `builtin` | a set name / `.glyphs.toml` | a `.font.toml` PNG grid (compat, cut by `from_grid_image`, or `glyphs = "<set>"` + `spacing`); `SceneRenderer::load_ui_font` uploads it once at scene load as white RGBA with coverage alpha (`font:<name>`), extraction only lays out; demo `examples/ui_test/ui_fonts.scene.toml`. Book: concepts/glyph-atlas.md
- **Models and textures are found by the project's resolver** (ADR 0114 step 3, #706) -- `model_loader::ModelLoadConfig { project, scene_dir, overrides, asked_first }`: `resolve_model_path` / `resolve_texture_path` return `Result<PathBuf, flint_core::project::NotFound>`, the catalog override first and then `project.resolve(AssetKind::Models | Textures, name, &scene_dir)`. Build a config with `from_scene_path` (discovers the project, once) or `in_project(project, scene_path)` when the host holds one (the player per frame, `flint render`'s `Stage::project`); never a struct literal with a guessed directory, and no hand-written `scene_dir.parent()` for these kinds. A miss is warned with `config.not_found_text(&missing)`: every path tried, then `asked_first` (what the host asked before the files: the catalog, a procgen spec). The rule itself, the kinds table and the as-written step: `crates/flint-core/CLAUDE.md`. Nothing in this crate searches by hand any more
- **Looks, palettes, glyph sets, fonts and style images are found by the project's resolver too** (ADR 0114 step 3, the last group, #706) -- the handle is `flint_core::project::AssetScope` (project + scene directory). `SceneRenderer::set_asset_scope(scope)` gives it to the renderer (and sets `scene_dir`); a host that only sets `scene_dir` gets the project found from it, once per directory (`asset_scope()`, cached), and with no scene the working directory stands in for the scene's folder (tests and the model previewer rely on it). Styles read it as `StyleFrame::assets`. `PaletteCache::new(scope)` / `GlyphSetCache::new(scope)` (`Default` = no scope = built-ins only) call `scope.explain`, log its `order_change`, and stamp `Resolution::watched()` for `poll()`, so a nearer file appearing later reloads; a miss says what is built in and lists every path tried. `BitmapFont::resolve(spec, &scope)`: a `.font.toml` is `AssetKind::Fonts`, its image `AssetKind::Textures` and then beside the font file (a file a description names beside itself is not a search: a glyph set's `[font] file`, a user style's WGSL and images are the same). `look::find_in` / `resolve_in` / `resolve_scene_in` / `list_in` / `list_checked_in` take a scope; the path-taking `find` / `resolve` / `resolve_scene` / `list` wrap them with `AssetScope::for_scene` (a look path ending `.toml` but not `.look.toml` goes through `AssetKind::Files`, with its own TEMPORARY old-rule compare). Built-ins rank after the search: a palette or look file found shadows the built-in of its name, `builtin` (glyph set) is never searched. The working directory is no longer searched by any of them. In the engine checkout the shipped looks are now read from `<root>/styles/*.look.toml` by the walk (the same text `include_str!` compiled in)
