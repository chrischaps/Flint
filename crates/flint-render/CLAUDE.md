# flint-render: renderer notes that are not stylize (moved out of the root CLAUDE.md by #755)

Styles, the style mask and user styles: `src/stylize/CLAUDE.md`. Flags: `crates/flint-cli/CLAUDE.md`. The wooze field, whose clock drives boil and shallow wooze: `crates/flint-procgen/CLAUDE.md`. The root file keeps a short form of the first two bullets and of the lights bullet.

## Frame and GPU rules

- Per-frame GPU allocations are the renderer's CPU cliff: `update_from_world` rebuilds the draw lists every frame, so anything it needs per entity must come from a cache (`draw_bind_cache` for transform/material binds keyed by entity + sub-mesh with a material hash, `box_mesh_cache` for procedural boxes, `GpuMesh` buffers shared via `Arc`, one dynamic-offset uniform buffer for all shadow draws). Never `create_buffer`/`create_bind_group` inside a per-entity loop; a 270-entity scene went from ~17 ms to ~4 ms when those were removed. Skinned draws use the same cache (`SKINNED_DRAW_KEY`, bone binds in `SkinningState::bone_binds`, #121). On the web every `create_*` is also a JS object: Float's skinned path made 386 buffers and 327 bind groups a frame, and Firefox stalled ~250 ms at each GC. Count WebGPU calls per frame in the browser before trusting a desktop timing (`?perf=1` shows them: the page wraps `submit`/`writeBuffer`/`createBindGroup`/`createBuffer`/`beginRenderPass`, #139)
- **Every GPU object the renderer makes is counted** (#1091, `gpu_counts.rs`) -- `create_buffer`, `create_buffer_init`, `create_bind_group`, `create_texture`, `create_texture_with_data`, `create_render_pipeline`, `create_compute_pipeline`, `queue.write_buffer` and `write_texture` in this crate are `device.create_*_counted` / `queue.write_*_counted` (`use crate::gpu_counts::{CountedDevice, CountedQueue}`; scene_renderer submodules get them through `use super::*`), process-wide relaxed atomics, no allocation; shader modules are counted in `TrustedShader` and the user-style `create_shader_module`. **This crate's own `clippy.toml`** (the root list plus `scripts/clippy-render.toml`, written by `scripts/clippy-conf.sh`) refuses the bare calls, so a new one can't read as a false all-clear; the integration tests allow them at their top (their own targets and read-backs). `frame_submitted` closes a frame: `frame_gpu_calls()` (the totals' difference since the last call), `gpu_calls_reading()` (totals, frames, frames that created any) for a readout's window, and a `NoteKind::GpuObjects` frame note when the frame created any. `gpu_memory()` walks the renderer's own fields into `GpuMemory` (texture bytes by class: scene targets, style targets, shadow maps, model textures, glyph atlases via `StylePass::glyph_atlas_bytes`; mesh buffers), and `gpu_counts::device_memory(device)` is wgpu-hal's live buffer/texture memory (`counters` feature on wgpu here; Vulkan and DX12, `None` on the web). Counts are the process's, so a GPU test that asserts them takes `lease_alone`. Steady `stylize_props_ascii` at 960x540: 0 objects, 17 writes (27.4 KB) a frame; a spawned entity sharing a mesh makes 1 bind group the frame it first draws. Tests: `tests/runtime_mesh.rs` `a_spawned_entity_creates_gpu_objects_*`, `the_renderer_knows_the_memory_*`
- One submission a frame (#139): `SceneRenderer::encode_to` records the whole frame (grass, shadows, scene, post-process, depth upscale, world lines) into the caller's encoder, the player adds its HUD and the GPU timer's resolve (`encode_gpu_timings`), submits once, then calls `frame_submitted` (grass and timer read-backs). `render_to` is that with its own submit. Every `queue.write_buffer` lands before the submission, so a uniform buffer may hold one value per frame: steps that differ get slots of their own (bloom's per-step slots), and encoding two cameras into one submission would show the second camera's uniforms to both (so comic panels submit one a panel, next bullet but one). Cached draws' transforms live in `TransformArena` pages (`bind_cache.rs`, a 256-byte slot each, one write per page); post-process bind groups live in `PostProcessResources::binds` (dropped on resize; a user style's are filed under its install, `BindCache::get_for` / `get_over_for`, and an install the renderer's own registry no longer holds leaves each of its caches at the next frame, `evict_gone_installs`, #427, #1271); ones over the caller's depth view are kept while the caller hands the same view (#379, #960: `encode_to`/`render_to` take `impl Into<DepthTarget>`, a bare `&TextureView` or `RenderContext::depth_target()` / `HeadlessContext::depth_target()`; `DepthKey::Caller(&view)`, and `BindCache::get_over` holds a clone and drops every group over the old view when another comes). **Key a bind group on the handles it binds, never on a proxy** (#960): wgpu 30 compares and hashes every handle by identity (natively wgpu-core's id, an index and an epoch it never hands out again within one `Instance`; on the web a process-wide counter). `BindCache::get_bound(name, variant, &[Bound::View(..), Bound::Buffer(..), Bound::Sampler(..)], make)` (and `get_over`'s `over`, `StyleFrame::bind_over` / `depth_bind_over`, `edges_or` / `albedo_or`) holds clones beside the group and makes it again, in the old one's place, when one of them is another object: the shadow map, the ground fog map, the style mask's growing draw buffer, the MSAA depth, the ocean grab's source, the shared edges and albedo, pencil's images. That replaced `gpu_id()`s taken at creation, size keys (`edges_key`, `albedo_key`), `new_depth_id()` / `depth_id` and image generations; `variant` is left for which of the chain's own views were chosen. Keep two uses that alternate within a frame on different variants (a group with and without the mask), or they'd replace each other every frame. The draw payloads' `Arc`s stay: a `wgpu::Buffer` clone is two reference counts, an `Arc` one. Test `bind_cache::tests::a_bound_group_follows_the_objects_it_binds`, `tests/stylize.rs::the_callers_depth_view_makes_no_bind_groups_a_frame`
- **Pipelines kept across renderers** (#911) -- `pipeline_cache`: off by default; `set_enabled(true)` (`flint goldens` in one process) makes `shared(device, label, parts, build) -> Arc<T>` (and `shared_some` for a build that may make nothing) keep what it builds under (the device itself, by identity since #960; type, label, `Debug` of `parts`), so the next `SceneRenderer` on the device takes it. Measured first: building pipelines was 67% of a golden case's time on Vulkan, 88% on DX12/DXC, 97% on FXC (RTX 4070, debug), the scene set (`ScenePipelines`) the most of it, ASCII's glyph pipeline once a case. Kept: every `ScenePipelines` member but `sprite2d` (it holds a uniform the frame writes), keyed by (format, samples) since their WGSL and layouts are the binary's; the post chain's eight (composite, bloom x3, SSAO x2, volumetric x2, by surface format); and each built-in style's kit pipelines (`stylize/CLAUDE.md`). Only immutable objects (pipelines with their layouts, modules and constant meshes) may be kept: a uniform buffer, history texture, bind group or a style's state stays the renderer's, which is what keeps a case from seeing another's (`tests/pipeline_cache.rs`: a second renderer's first frame is a fresh one's bytes though the first had ASCII history full, and a changed WGSL builds a new pipeline). A later renderer's bind groups fit a kept pipeline because wgpu-core pools bind group layouts by entries (and WebGPU calls equal ones the same). wgpu 23 gave a device no identity, so the key held its address; since #960 it holds a clone of the `Device`, which wgpu 30 compares by identity, so a device that moves still hits. wgpu-core numbers devices per `Instance`, so a second instance's first device equals the first's: a host that drops its device still calls `clear()` (`RenderHost::drop_device`). `counts()` (built, reused by label) is kept on or off; goldens prints it. Not kept: user styles' pipelines (`custom/pass.rs`), the style mask and albedo passes, shadows, FXAA and the MSAA resolve (about 2% of a case together); the blend, ownership, fade and reveal passes' lazily built ones are, each under `in_scope((name, format))`. **Textures ride it too** (#961): `TextureCache::upload` (a model's) and `load_file_with` (a file's) make theirs through `texture_cache::texture_with_data`, which with the cache on is `shared(device, KEPT_TEXTURE_LABEL, (size, levels, format, usage, len, flint_pixels::fingerprint(bytes)), ..)`, so a later renderer takes the texture made from the same pixels (a changed file is a new key). Measured first: on WARP a case's first frame waited 3.2-3.5 s for its uploads (the selection scene's 133 MB of mip chains; 0.01 s on a sphere scene), which on most of CI's runners was 3-13 s a case and ~300 s of the suite. A kept texture is in the cache's `kept` set and `update_rgba` refuses it (the write would reach every renderer drawing it); `upload_rgba`, the glyph atlases, grass masks and style images don't go through it. **So do meshes' vertex and index buffers** (`gpu_mesh::geometry_buffer`, `KEPT_GEOMETRY_LABEL`, key: usage, length and fingerprint): every imported `MeshCache` upload (whole, subset, skinned), never a procedural mesh (a host replaces one at run time, and a cache keyed by its bytes would keep every version: `tests/runtime_mesh.rs::replacing_a_mesh_1000_times_does_not_grow_gpu_memory` failed when they were), the bone buffers (written) or `create_*_buffer_copy`. On local WARP the skinned YBot's 3.5 MB took 0.57 s a case to reach the device, 0.003 s kept; a props case's first frame went from ~0.7 s to ~0.2 s. A buffer kept must stay `VERTEX` / `INDEX` alone (a `debug_assert` holds it). Tests: `tests/pipeline_cache.rs::a_file_texture_is_uploaded_once_a_device_and_never_written_while_kept`, `a_mesh_is_uploaded_once_a_device_by_its_bytes`
- **GPU test harness** (`tests/shared_gpu`, #598, #913) -- each test binary makes one device, the lib's unit tests too (#1275: `src/lib.rs` includes the file by `#[path]` as `crate::shared_gpu`, beside `extern crate self as flint_render`; a lib test takes `crate::shared_gpu::lease()` and keeps the `Lease` bound, never `request_device`: a device per test hung that binary in 3 of 10 runs); its tests share it **side by side** (`lease`; `lease_alone` waits for every other test, for one that counts device-wide objects or switches process-wide state such as the cache or `dev_shader`'s folder; error scopes are per thread since wgpu 28, so they need nothing) with `pipeline_cache` **on**, so a test takes the pipelines earlier tests built. Measured on `tests/stylize.rs` without the cache, one test at a time (RTX 4070, debug): building pipelines was 69% of it on Vulkan, 88% on DX12/DXC, 96% on FXC; the binary went 12.7 to 8.7 s on Vulkan, 95 to 37 s on DXC, 303 to 45 s on FXC. #913 lent it one test at a time because on wgpu 23 side by side stalled DX12 (wgpu-hal 23's `Device::wait` shared one auto-reset event among waiting threads, so of two tests in `device.poll(Wait)` one slept out wgpu-core's 60 s `CLEANUP_WAIT_MS`; stylize 400 s against 37 s in turn). wgpu-hal 30 makes an event per wait and has no 60 s cap, and #948 measured side by side faster everywhere (stylize, min of 3 alternated runs, RTX 4070 debug: Vulkan 8.8 to 3.4 s, DX12/DXC 13.1 to 6.6 s, local WARP 18.9 to 13.2 s; all 7 binaries 20.4 to 13.3 s, 31.9 to 23.2 s, 52.2 to 46.6 s; the small binaries on WARP are 0.3-0.6 s slower side by side, WARP being CPU), so it's the default again; `FLINT_GPU_TEST_PARALLEL=0` gives one at a time. A test that wants pipelines built from nothing or counts builds switches the cache while it holds the device (`tests/pipeline_cache.rs` does, and `clear()`s first); its `Lease` puts the harness's setting back on drop. Pipelines are keyed by their WGSL's hash, so hot reload and `FLINT_STYLE_SHADER_DIR` get new ones (`tests/dev_shader.rs` passes with the cache on). `pipeline_cache::thread_build_time()` is this thread's build time; `FLINT_GPU_TEST_TIMES=1` prints a line per test (held, building), and CI's GPU job sets it. `FLINT_GPU_TEST_PIPELINE_CACHE=0` and `FLINT_GPU_TEST_PARALLEL=0` turn the cache and sharing off for A/Bs. **A lost device names itself** (#560): its lost callback records the reason and the tests holding it, and every test holding or taking it after fails with that line (on main the test that lost it passed and the next failed on "Buffer with 'Grass Blade Vertex Buffer' label is invalid"). wgpu-core 23's panic at `resource.rs:749` (two stylize tests, side by side) was a device loss in disguise: `Device::lose` destroyed every buffer while the thread held the snatch lock, and the recursive-lock guard panicked; wgpu-core 30's `lose` releases nothing. Side by side, a wall-clock bound in a GPU test times a frame after its pipelines are built, since building competes for the CPU with every other test's (`a_loop_that_never_ends_draws_a_frame` took 1.07 s against its 1 s once)
- DX12's shader-visible sampler heap has 2048 slots. wgpu 23 copied every bind group's samplers into it with no sharing, so samplers in a per-entity or per-material bind group capped how many could live ("Not enough memory left" in `create_bind_group`, DX12 only; test with `WGPU_BACKEND=dx12`). wgpu-hal 30 keeps one global heap with each distinct sampler description once (`dx12/sampler.rs`), so the cap is now on distinct samplers, not groups. Keep samplers in groups bound once a frame anyway: PBR materials sample with the light group's `material_sampler` (group 2, binding 4), and a material bind group holds none
- **DX12 compiles shaders with DXC linked in, FXC only as the fallback** (#912, #947; `gpu_select` module docs). flint-render's default feature `static-dxc` turns on wgpu's, and wgpu-hal's `mach_dxcompiler_rs::DxcCreateInstance` resolves to `vendor/static-dxc` (root `[patch.crates-io]`; flint-render asks for exactly its `0.1.947`, which crates.io doesn't have, so a game workspace without the patch fails in cargo's resolver instead of linking mach's prebuilt, #982; a game's root names the patch itself, book: Upgrading the Engine, Cargo): Microsoft's DXC v1.9.2609 built from source as one static library by `tools/dxc-static/build.ps1` (`.github/workflows/dxc-static.yml`; a `dxc-static-v*` tag publishes it as that release's asset). Its build script takes the archive from `FLINT_STATIC_DXC_ARCHIVE`, else the machine-wide cache `FLINT_STATIC_DXC_CACHE` / `%LOCALAPPDATA%\flint\static-dxc\<sha256>.tar.gz`, else downloads it there with curl from the asset URL (no API call); the SHA-256 in `vendor/static-dxc/pin.rs` is checked on every path, and offline with no cache it panics naming the URL and both variables. Linked on x86_64 Windows MSVC only (`gpu_select::STATIC_DXC`), with MSVC at least as new as the archive's (`BUILT_WITH_MSC_VER`). The library is linked `-bundle` (it's ~500 MB). `instance()` passes wgpu's `Dx12Compiler::Auto`, or what `Dx12Compiler::from_env()` reads from `WGPU_DX12_COMPILER` (`fxc`, `dxc`/`dynamicdxc`, `staticdxc`, `auto`); `choose_dx12` turns a `staticdxc` without the link, or a DLL that doesn't load, into FXC with a reason instead of wgpu's panic or instance error. Without static DXC it loads `dxcompiler.dll` by name first (`load_dxc_dll`) and reports the file Windows loaded (`GetModuleFileNameW`); wgpu-hal's load gets the same module. `dx12_shaders()` / `shader_compiler(backend)` / `adapter_line(info)` say which: `DXC (static, v1.9.2609)`, `DXC (<dll path>)`, `FXC (WGPU_DX12_COMPILER=fxc)`, `FXC (fallback: <why>)`; `request_adapter` warns once on a fallback. A new DXC release: bump `build.ps1`'s pin and archive `-<n>`, push the `dxc-static-...` tag, then put the published SHA-256 and `_MSC_VER` in `pin.rs`. A shader DXC rejects is not retried with FXC. Measured on the RTX 4070, debug build, `--style ascii` on pbr_test (#912, DLLs): DXC 5.0 s, FXC 26-27 s, Vulkan 1.1 s. The DX12 downlevel `shader_model: Sm5` wgpu-core logs is `DownlevelCapabilities::default()`, not the HLSL shader model
- HDR format `Rgba16Float` -- all pipelines must use this when post-processing active; `resize_postprocess()` on window resize
- **Comic panels** (#880, ADR 0120) -- a scene's `[panels]` (`schemas/scene/panels.toml`; `[panels.panel.<name>]` with `rect` shares, `order`, `position`/`target`/`fov`, `follow`, `look`, `post_process`) is parsed by `flint_render::panels::PanelLayout` (`parse`, `from_scene_tables`, `with_panel` / `without_panel` / `merge_panel` for scripts' edits, `rects`, `panel_camera`); the drawing is `scene_renderer/panels.rs`. Tests `tests/panels.rs`; `tests/panels_schema.rs` holds `schemas/scene/panels.toml` to `PAGE_KEYS`, `PANEL_KEYS` and the defaults (#976: a new key goes in both, and in the `panel` field's description if a panel takes it); demo `flint-examples/comic_panels.scene.toml`; book concepts/comic-panels.md

## Where scene_renderer code goes (ADR 0118, #736)

`SceneRenderer` is one struct whose methods are spread by concern over `scene_renderer/`. Each file is an `impl SceneRenderer` block or a subsystem the renderer holds as one field. A new feature's state goes in its subsystem's struct, never as a loose `SceneRenderer` field, and its code goes in the file below that owns its concern:

| File | What lives there |
|---|---|
| `mod.rs` | the `SceneRenderer` struct and the per-kind draw payloads (`DrawCall`, `SkinnedDrawCall`, `EchoDrawCall`, the bind-cache types); `build` behind `new`/`new_headless`; `update_from_world`; the public forwards to the subsystems (terrain, skinning, lights, shadows, sky, water, ground fog) |
| `draw_list.rs` | the frame's draws as one list (ADR 0118 decision 4, #737): `DrawItem` (entity, `Blend`, `VertexStage`, `casts_shadow`, its `Draw`), `Draw` (`Static`, `Skinned`, `Echo`, `Billboard`, `Terrain(n)`, `Particles(n)`), the `DrawList` kept a vector per `Layer` in the main pass's order, the cull flags and the back-to-front sort. **A new kind of draw is a new `Draw` variant**: every pass's selector matches on `Draw` with no wildcard arm (shadow caster, per-frame uniforms, main pass, wireframes, style bounds, mask, veil, albedo, selection, stats, culls, shallow wooze), so the compiler asks each one what to do with it |
| `binding.rs` | the scene a host binds once a load (#739): `SceneBinding` (made by registering the scene's user styles), `bind_scene` and what it returns (`BoundScene`, `LoadedTerrain`, `BoundGrass`), and the one terrain loader every host shares |
| `frame.rs` | the frame: `FrameInputs`, `View2d`, `prepare` / `prepare_again` (#739), then `render`, `render_to`, `encode_to` (the order the frame is recorded in), `encode_again_to`, `frame_submitted`, world lines |
| `pipelines.rs` | `ScenePipelines` (every sample-count-baked pipeline) and `SceneLayouts` |
| `extract.rs` | per-entity extraction into the draw list's items (static, skinned, echoes, billboards) and the 2D sprites and UI text |
| `draws.rs` | the bind cache, shared materials, procedural boxes, the LOD and frustum culls (flags on the items, set at each `render_to`), building a draw call's bind groups, shallow wooze's per-draw drift (an item's `VertexStage::Wooze`) |
| `render_passes.rs` | the passes: shadows, per-frame uniforms, main pass, wireframe, post chain, style bounds |
| `post.rs` | post-process and quality config: HDR chain size and render scale, drawn vs authored config, `set_quality`/`set_msaa`, building style and FXAA resources, style text/edge read-outs, `post_time` |
| `assets.rs` | loading: models and their textures, procedural meshes, textures, `ui_text` fonts, ray targets, the asset scope |
| `stats.rs` | `collect_stats`, the GPU timer, debug mode and overlays, tonemapping |
| `describe.rs` | a frame's description (#1084): `describe_next_frame` / `describe_frame`, `FrameHost`, what each pass logs (the scene's draws through `main_pass_draws`, cull reasons, pipeline names), the frame's targets, why a post effect or the shadows are off; naming a capture's image files |
| `capture.rs` | a frame's capture (#1085): `capture_next_frame` / `take_frame_capture`, the taps each pass makes as it ends (`tap_pass`, `tap_step`, the style chain's `run_style_part`), which texture a target id names (`tap_texture`); a host's own pass (`capture_host_pass`), setting a capture aside (`hold_frame_capture`), and what a replay needs of the renderer (`capture_replay_state`, #1086) |
| `msaa.rs`, `sky.rs`, `lights.rs`, `terrain.rs`, `style_mask.rs`, `water.rs`, `skinning.rs`, `grass.rs` | the subsystems below, each with its state and its extract and draw hooks |
| `panels.rs`, `selection.rs`, `particles.rs`, `grass_ground.rs`, `splines.rs`, `helpers.rs` | comic panels' view swap, the selection outline's draw walk, the particle upload bridge, a scene's `grass_ground`, a scene's `spline` / `spline_mesh` (`load_scene_splines`, next section), free helpers |
| `tests.rs` | the module's unit tests (GPU tests are `crates/flint-render/tests/`) |

## Host protocol (ADR 0118 decision 5, #739)

The player, the scene viewer and `flint render` drive the renderer through these entry points, in this order:

1. **`SceneBinding::new(scope)`** (or **`SceneBinding::over(scope, &base)`**, a host's own registry under it) when a scene's settings are read: it makes the `StyleRegistry` the scene is drawn with (ADR 0129, #742: the built-ins, `base`'s game styles, and the user styles the scene can see, `base.for_scene(&scope)`), so it comes before anything reads the scene's `[post_process]`, which is read against `binding.styles()`; `bind_scene` hands it to the renderer (`SceneRenderer::styles`, `styles_mut`, `set_styles`). `binding.restyled(&base)` loads it again over a newer registry (the viewer's scene reload, keeping a hot reload). Its `style_messages()` are the host's to say. `.with_environment(scene_file.environment.as_ref())` hands it the scene's `[environment]` (`flint_scene::EnvironmentDef`), and `.with_archetypes(&registry)` each archetype's placeholder box (`flint_schema::ArchetypeVisual`, its schema's `[archetype.<name>.visual]`, #751): the colour and wireframe a `bounds` box with nothing else to draw takes. The renderer names no archetype (#793: `tests/names_no_archetype.rs` fails on a room-builder or `character` name quoted anywhere in `src/`; `flint-cli`'s `tests/archetype_visual_cli.rs` renders a game's own archetype through its `flint.toml`); a binding without it draws every box grey. The player adds it in `stage_scene` (its held registry), the viewer in `stage_scene`, `flint render` once its schemas load. A material-less imported mesh keeps the first demo's green (`MODEL_FALLBACK_COLOR`, yellow when skinned), now a constant.
2. **`bind_scene(device, queue, &world, &binding) -> BoundScene`** once the world is loaded, before the scene's models: the asset scope, then nothing of the last scene (style history, bone buffers and motion holds, the lighting levers, `shadows` and `default_lights` back to the built-ins, the terrain and grass unloaded), then the scene's `[environment]` levers (#627), its terrain (named for the style mask, #310) and its grass, a `grass_ground`'s over a terrain's. A host's own overrides (`flint render --oren-nayar`, the viewer's F4 panel) go after it; the skybox is still the player's alone. The host takes what it needs of `BoundScene` (the player registers the terrain's collider and keeps its heights). The terrain loader that was copied into the player and `flint render` lives here; the viewer, which had none (so `flint edit` drew no terrain) and read no `[environment]`, binds at load and at each hot reload (`flint_viewer::app::stage_scene`).
3. Each frame: **`set_motion_time(t)` before any bone write** (a host that writes no bones can skip it), then **`prepare(device, queue, &world, &FrameInputs)`**, which takes every per-frame input, reads the world into the draw lists (`update_from_world`) and uploads the particles. Then `encode_to` / `encode_frame_to`, the submit, `frame_submitted`.

`FrameInputs` is one clock (`time`: motion holds, and unless held the ocean, sky, post time and grass wind) with two holds a host may set (`look_time`, `--style-time`; `grass_time`, woozy grass's sway or a still's rest), plus `dt`, the boil, shallow wooze, woozy grass's comb, `pixels_per_point`, the 2D view (`View2d`), the particles, world lines, grass benders and contact hulls' velocities (the player gives a dynamic body's, `PhysicsSystem::dynamic_velocity`, #749). **Every field's default turns its feature off for the frame**, so a host that doesn't know a feature can't leave a stale value behind (a world line or boil from an earlier frame). The boil `prepare` takes is stamped into the drawn config again at `encode_to`, so a config a host sets between them (a look, a panel) can't drop it. A split view's other side is `prepare_again(device, &world, boil, shallow)` then `encode_again_to`, which draws that boil once. A new per-frame input is a `FrameInputs` field with an off default, never a `pub` field or a setter. The player gathers its subsystems' share through `Subsystem::frame_inputs` (the living subsystem's boil, shallow wooze and grass) right before `prepare` in `sync_renderer`; `flint render`'s stages through `HeadlessGame::frame_inputs`; the viewer in `ViewerApp::prepare_frame`, which reads the world every frame (it used to re-read it only on an edit), with its wall clock as `time`, its post time held (`look_time`: 0 or `--style-time`), and its own `ShallowWooze` and `GrassWooze` (`flint_wooze::shallow`, moved from the player by #739 and out of this crate by #1330) on its field's clock, behind its `living` feature (`flint-viewer/src/field_clocks.rs`). Tests: `tests/frame_inputs.rs`, and the viewer's `app_binding_tests.rs`. **These are the only way in** (#739): the per-frame fields are private (`ocean_time`, `grass_time`, `grass_wooze`, `style_dt`, `pixels_per_point`, `camera_offset`, `ortho_height`, `aspect_ratio`, `scene_dir`; read back with `pixels_per_point()`, `scene_dir()`, `asset_scope()`), and `update_from_world`, `set_boil`, `set_shallow_wooze`, `update_particles_from`, `update_grass_entities`, `set_terrain_entity` and `set_asset_scope` are `pub(crate)`. Every host is on them: the player, the viewer, `flint render`, the model previewer, the procgen previewer, `flint gen --strip` and the particle editor (a frame of particles in an empty world). `update_particles` stays public for a host's own particle draws, uploaded after `prepare` (which clears the last frame's). `set_motion_time` stays public as the stamp before bone writes. GPU tests draw a frame the same way (`Gpu::frame_with` in `tests/stylize.rs` takes `FrameInputs`; `tests/quality.rs` hands its shallow wooze and particles over each frame).

**The crate's surface** (ADR 0118 decision 2, #739): the pipeline and GPU-uniform modules are `pub(crate)` (`billboard_pipeline`, `grass_pipeline`, `ocean_pipeline`, `particle_pipeline`, `selection_outline`, `shadow`, `skinned_pipeline`, `sky_pipeline`, `skybox_pipeline`, `sprite2d_pipeline`, `style_albedo`, `terrain_pipeline`, `world_line_pipeline`), and so are their pipeline and uniform types (`*Pipeline`, `*Uniforms`, `*UniformsGpu`, `RenderPipeline`, `SceneLayouts`, `PostProcessPipeline` / `PostProcessResources`, `ParticleBuffers` / `ParticleDrawCall`, `TerrainDrawCall`, `Sprite2dBatch`...). What the hosts and the crate's own GPU tests use stays public: `LightUniforms` (its default ambient), `GrassGround` / `GrassHeight` / `GrassEntityPosition` / `GrassInstanceGpu`, `ParticleDrawData` / `ParticleInstance` / `ParticleBlendMode`, `OceanVisuals`, `SkyParams`, `HDR_FORMAT`, and two constants re-exported at the root, `MAX_BONES` and `WORLD_LINE_DEPTH_SLACK`. Float, FlintKart and Kandinski have no Rust outside `engine/`, so nothing else imports the crate. A new pipeline or uniform type is `pub(crate)`; one a host needs is re-exported by name.

## Splines and sweeps

- **`load_scene_splines(scene_path, world, renderer, device, queue) -> LoadedSplines`** (#750, `scene_renderer/splines.rs`) -- the one loader the player (`scene_entry.rs::stage_scene`, which registers `LoadedSplines::colliders` as static trimeshes) and `flint render` (both paths; colliders dropped) call; it was `flint_player::spline_gen`, which `flint render` reached into. An open spline's last sample has a zero frame (#1016): a smooth profile's normal there falls back to the flat one, since a zero normal shades NaN and bloom spreads it into a black block. ## Lights

- **The lighting WGSL is written once** (#738, `wgsl_sources.rs`) -- every lit shader is its own file with the shared ones concatenated in front (WGSL has no include; `wgsl!` is `concat!` of `include_str!`s): `lights.wgsl` (`LightUniforms` and its lights, `ShadowUniforms`), `light_bindings.wgsl` (group 2, bindings 0-3), `brdf.wgsl` (GGX, Smith, Schlick, `attenuation`, `spot_cone_factor`, `evaluate_light`), `shadows.wgsl` (`shadow_factor`, the spot's map), `direct_light.wgsl` (the loops over every light), `tonemap.wgsl` (`aces_filmic`, the composite's too) and `pbr_surface.wgsl` (the material and every fragment stage of a mesh). `shader.wgsl` and `skinned_shader.wgsl` are only their vertex stages and the `front_facing` entry (`fs_main`; `fs_skinned`, `fs_skinned_lighten`) over `shade()`. Use `wgsl_sources::{SCENE, SKINNED, TERRAIN, OCEAN, GRASS, VOLUMETRIC, WIRE, SHADOW, PARTICLE, WOOZE_SHADOW}` and `wooze_vertex()`, never `include_str!` of one of those files (it no longer compiles alone). **The vertex side too** (#1244): `mesh_vertex.wgsl` holds `TransformUniforms` and its group 0 binding, `world_of` / `clip_of` / `world_normal_of` and, behind `//FLINT_WOOZE ` lines, the drift field and `drifted`; `skinning.wgsl` holds `skin_transform` (each shader binds its own `bone_matrices`); `fog_veil.wgsl` the fog veil's texel. A woozy module is its plain sources through `wgsl_sources::woozy` (the prefix cut). The style mask (`STYLE_MASK_WGSL`, mesh_vertex + skinning in a `//FLINT_MESH` block) and the selection mask (`MASK_VERTEX` in front) call the scene's products, so a depth-matched pass can't drift from the scene's; `the_vertex_side_is_written_once` fails on a second declaration, or on `transform.model` / `transform.view_proj` / `bone_matrices[` outside those files, and `the_transform_is_the_rust_structs_in_every_module` holds the struct to `pipeline::TransformUniforms` (plus the 48-byte drift when woozy). A lighting fix is one edit, and the tests hold it: `the_lighting_is_written_once` fails on a second `struct LightUniforms` / `fn evaluate_light` / `fn shadow_factor`... anywhere in `src/`, `wgsl_layouts_match_rust` holds each struct's WGSL size to the Rust one in all six. The volumetric pass's group 2 takes the scene's slot order since #738 (lights 0, maps 1, sampler 2, shadow 3). What sharing changed: terrain takes the cascades' normal offset, area sources, the clay levers and the meshes' specular denominator; skinned meshes take the clay levers (`diffuse_wrap`, `oren_nayar`, sheen) and area sources; the ocean takes PCSS under a sun with `angular_size` (no normal offset: the swell would move it). Against main's binary (2026-11-17): of the 114 stylize goldens only `style-terrain` and `style-terrain-mask` moved (re-blessed; the `.warp` variant still to bless from CI). 49 example scenes rendered byte-identical, among them meshes, the ocean (`shoreline`), grass (`mesh_meadow`), volumetric and the composite. Only `rolling_meadow` (terrain) and `phase4_runtime` (its skinned characters) moved. The other 52 examples weren't rendered (the run was stopped for low memory)
- Lights are `[entities.x.light]` with a `type`, and a directional `direction` points *toward* the light. The fields and their fallbacks are `schemas/components/light.toml` (`flint schema light`), which a test holds to what `scene_renderer/lights.rs` reads; only `color` and `intensity` carry a schema default, since a default is written into the component at load (`range` would then beat an authored `radius`, and `type` would hide a light that forgot it). No system reads a `directional_light` table: `flint validate` warns about it as an unknown component (#683), and a scene with only that gets `default_scene_lights` (no scene in the repo keeps one since #796). One point light and no directional means no sun at all. An ambient-only scene says `[environment] default_lights = false` (and `shadows = false`) rather than adding a dummy light; a sun at `intensity = 0` with no `volumetric_intensity` draws no shadow pass anyway (`SceneRenderer::shadows_drawn`, #627). `material.unlit = true` draws base colour x `emissive_scale` + emission with no lighting (`MaterialUniforms::unlit`, both PBR shaders)
- **How lights are read** (#682, `scene_renderer/lights.rs`) -- `gather(world, motion_hold) -> Gathered` reads every visible light through `world.view` (ADR 0115), in name order: an unknown `type` is `bad-enum-value` "so this light is off" and counted `unusable`; a missing one is directional with a `missing-field` warning; when every light entity is unusable and the built-ins stand in, one line says so (`said_fallback`). Each light's matrix is `MotionHold::matrix` of its world matrix (identity with no transform): the position, and, with no `direction`, the direction (`turned(&m, local)`: a spot's local -Y, a directional's toward-light local +Y, so unturned a spot points down and a sun is overhead). A written `direction` is world space. Spot cones: `<key>_deg` (degrees) wins over `<key>` (radians, the older form, `two-forms` when both), a radian value past pi/2 warns `out-of-range` naming the `_deg` key (`cone_angle`). `LightState::extract` writes the directionals now (strongest first, the rest past `MAX_DIRECTIONAL_LIGHTS` said once), keeps every point and spot in `points`/`spots`, and `upload(queue, camera_pos)` (in `encode_to`, so each comic panel's camera chooses its own) runs `place`: `nearest::<_, N>` keeps all in name order under the cap (byte-identical) and the N nearest the camera, still in name order, past it. Each left out is `light-cap`, logged once a scene by name (`cap_warned`, emptied by `forget_warnings` in `bind_scene`); not in `world.read_reports()`, since the camera isn't known while the world is. Tests: `lights::tests`, `crates/flint-cli/tests/render_lights_cli.rs` (17 lamps draw byte for byte as the 16 nearest; a parented spot swings both ways)
- **Spot light shadows** (#504, ADR 0124) -- `light.cast_shadows = true` on a spot: the first by name that asks gets `SpotLight::shadow = 1.0` in `lights::gather` (the former `_pad1`; another asking and a directional saying `false` are `shadow-cap` through `view.report`; a point light asking casts its own since #1112, next bullet but one), the mark rides the camera's `nearest` choice, and `LightState::shadow_spot` / `lights::casting_spot` find it among the uploaded spots after `upload`. Its map is layer `shadow::SPOT_SHADOW_LAYER` (3) of the cascades' array (`SHADOW_LAYERS` = 4; `layer_views`), drawn by `render_shadow_pass` as one more entry of its `layers` list with or without a sun (`clear_cascades` when only the spot casts), through `spot_shadow_frustum` (perspective, near `range * 0.004`, far `range`, half-angle outer + margin, capped 80 deg; up +Z near vertical). `ShadowUniforms` grew at its end (`spot_view_proj`, `spot` = near, far, tan_half, drawn). `spot_shadow_factor` (`shadows.wgsl`, #738) is PCSS on `source_radius` with linearized depths, 16 + 32 taps capped at 48 texels, the disk turned per pixel by interleaved gradient noise, each tap held under the receiver's plane by its slope toward the lamp (else a grazed face shadows itself); 0 is 3x3 PCF. Tests: `lights::tests`, `shadow::tests`, `crates/flint-cli/tests/render_spot_shadow_cli.rs`; demo `flint-examples/spot_shadow.scene.toml`
- **Point light shadows** (#1112, ADR 0132) -- `cast_shadows = true` on a point light: the first by name gets `PointLight::shadow = 1.0` (the former `_pad0`) in `lights::gather` (`casts_first(view, kind, ..)` is both kinds' rule; a second point asking is `shadow-cap` naming the first; the spot and point budgets are separate), `LightState::shadow_point` / `lights::casting_point` find it after `upload`. ## Post-processing and quality

- **Post-processing** -- HDR pipeline (`Rgba16Float`) with bloom, SSAO, fog, volumetric (god rays), Kuwahara (anisotropic painterly filter), vignette; `[post_process]` TOML block; F4 opens the Rendering & Effects debug menu in the player and viewer (all toggles + parameters, ADR 0053); when active, PBR shaders output linear HDR
- **Post effect descriptors** (#741, `flint_schema::post_effects`) -- every flat `[post_process]` key of a built-in effect is ONE line of the `post_effects!` X-macro (effect, key, kind `bool|f32|u32|rgb`, default, `[min, max]` tuned range, F4 widget, label, help). The macro hands the list to a caller's macro, which makes the fields: `flint_scene::PostProcessDef` (`post_process_def!` in format.rs: fields, `#[serde(default)]` + `Default`, `param`/`param_mut` by name), `PostProcessConfig` (`post_process_config!` in postprocess.rs: the same fields and defaults, then the renderer's own fields with explicit defaults; `param`/`param_mut`; `copy_params` is the def-to-config copy), `EFFECTS` (`--list-effects`, `range_warnings`, `PostParam::range_error`), the `[table.post_process]` schema fields (the registry adds them on loading `post_process.toml`; the file lists only `look`, `styles` and the old style keys) and the F4 sections (`render_panel.rs::param_widget`, by `PostParamMut`). **A new post key is its descriptor line, its uniform field and its WGSL**, plus the `PostProcessUniforms` fill line; nothing else names it. A key's range warns (`post-range`, `flint_scene::diagnose`) in a scene and is refused in a look (`look::overlay`) or `--sweep post.<key>`. `tests/table_schemas.rs::every_shipped_post_value_lies_in_its_range` holds every scene and look in the repo inside the ranges. The renderer-only fields (`enabled`, ground fog, `boil`, `styles`) are not keys: their F4 rows are hand-written after their effect's (`match effect.name`). `flint render --set post.<key>=v` is `param_mut(..).set(..)` (#708; the old flat flags it replaced went in #1144). Not on it yet: quality caps, and the pass order (bloom, SSAO, volumetric, FXAA are still fixed stages)
- **Dither styles** (#503) -- `dither_style` (u32, rides the uniform's old `_pad2`): `0` adds Bayer in linear light, before the sRGB target's encode, so one step's intensity is ~13 levels near black and under one in the light (kept byte for byte as the default look); `1` (Bayer) and `2` (Roberts' R2 remapped to a triangular PDF) encode with the exact sRGB curve, add `d * dither_intensity` in display levels, and decode for the target, so `1/255` is one step at every brightness. They assume an sRGB target (every host's scene view is; `context.rs` adds the suffix). ## Motion on twos

- **Motion on twos** (#405, `motion_hold.rs`) -- the renderer alone holds what it draws of an entity on ticks; the world (physics at 1/60, IK, scripts) moves smoothly and is never written. `held_rates(world, whole)` is who is held: the nearest `motion_hold { rate }` up the hierarchy (`rate = 0` lets a branch move), else `[post_process] motion_hold` (`PostProcessConfig::motion_hold`, `--set post.motion_hold=12` on render (#708), `--motion-hold` on play/player); empty and unwalked with neither. `MotionHold` (a `SceneRenderer` field) keeps each held entity's world matrix (`matrix`, in `update_from_world`'s loop, so draws, shadows, culling and the ray scene all see the held one) and gates its bone writes (`bones_due`, first in `update_bone_matrices`: a skipped write keeps the buffer and the CPU copies), once a tick, `tick(time, rate) = floor(time * rate + TICK_EARLY)` on `post_time(seconds)` (`flint_core::step_clock::tick`: the stepped clock's `warp` with no glide, the one the living props hold and glide on, #747) (the f32 wrap styles see). Pencil's `effective_seed` steps by the same `tick`, so `rate` = `boil` turns pose and lines on one frame. **Hosts stamp `set_motion_time(t)` before uploading bones** (player: `bones_posed`, `clock.total_time`; `flint render`: the Stage's `capture` moment, the `--frames` loop, the still path), and `prepare` stamps `FrameInputs::time` again (#739): uploads come before `update_from_world`, so the rates are last frame's and `update_from_world` calls `bones_shown` for a hold that starts this frame. Never stamped, nothing is held. The editors (#871): the scene viewer's `FrameInputs::time` is its own wall clock (`ViewerApp::motion_clock`; its post time stands still, so stamping that would never turn a tick), and it prepares every frame, so a dragged held entity steps on its ticks; the viewer plays no animation and runs no physics, so only drags step there. The model previewer stamps the clip's playback time (`PreviewApp::motion_time`, the timeline's), so scrubbing steps through drawings, and calls `release_motion_hold(entity)` (`MotionHold::release`) when the pose changes by hand (layers, posed bones, a clip switch), which a paused hold would otherwise never show. A whole-frame rate also holds `SceneRenderer::post_time()` (styles' `StyleFrame::time`, the composite's grain/mode time, the tear) to the tick's start; the ocean, sky, grass and live particles stay smooth. **What a held entity carries** (#873): `tick`, `post_time`, `held_rate(world, id, whole)` and `held_rates` live in `flint_ecs::motion_hold` (re-exported here) so flint-particles, which can't see this crate, holds on the same ticks. `update_from_world` sets the rates *before* `LightState::extract`, and point/spot positions come from `lights::light_position` = `MotionHold::matrix` (the same kept matrix the entity's draw reads later in the frame); directional lights have no position, and their `direction` is world-space, so nothing there is held. Emitters: `ParticleSync::set_motion_time(t)` / `set_motion_hold(whole)` (stamped by the player in `bones_posed` beside `set_motion_time`, before the particles step; by `flint render`'s `Stage::step_particles_to` once per fixed step) give `EmitterHold`, which keeps each held emitter's matrix a tick; `EffectInstance::set_held_transform(held, live, ..)` births at the held point (`EmitterFrame::held` skips the `prev -> position` lerp; emission per metre still counts the jump) and takes velocity from the live positions, so `inherit_velocity` never sees a jump. The still `--particle-time` path stamps nothing (its world doesn't move). `write_entity_bones` (living props) is not gated. Tests: `motion_hold::tests`, `flint_ecs::motion_hold::tests`, `flint_particles::sync::tests::a_held_emitter_emits_from_its_drawing`, `crates/flint-cli/tests/render_motion_hold_cli.rs` (`a_held_entitys_point_light_steps_on_its_ticks`: two lanterns with nothing drawn, only their pools move). Example: `flint-examples/motion_hold.scene.toml` (each bob a lantern: light + soot trail, beads when held)

## Shallow wooze

- **The renderer links no flint-wooze** (#1330) -- what the field's clocks hand a frame is plain data in `flint_core::field_frame`: `BoilFrame` (`FrameInputs::boil`), `ShallowWoozeDraw` and `WAVELENGTH_MIN` (`FrameInputs::shallow_wooze`, `grass_wooze`; re-exported at this crate's root and from `flint_wooze`). The clocks that work them out (`BoilClock`, `ShallowWooze`, `GrassWooze`) read the field and live in flint-wooze, which only `living` builds link. `scripts/headless-check.sh` fails if `cargo tree -p flint-render` shows flint-wooze again: a new wooze input is a `field_frame` type, never a `flint_wooze` path here. `wooze_pipeline.rs` (the woozy vertex stages, the drift's uniforms through the crate-private `DriftUniforms` trait) stays in this crate on purpose: it takes only that plain data, and it moves with the other renderer features in the modularity plan's Phase 4 (epic #1328)

- **Shallow wooze** (#215) -- a `shallow_wooze` component (`amplitude` metres, `wavelength` metres; schema in `schemas/components/`) on an entity with a mesh, or above several, in a scene with a `[wooze]` table: each vertex moves through world-space vector noise on the field's clock, in the main and shadow passes alike, and in the style mask (#737: `style_mask_wooze.wgsl`'s `vs_static_wooze` / `vs_skinned_wooze` in a second module, `style_mask::woozy_mask_source`, which turns on `mesh_vertex.wgsl`'s `//FLINT_WOOZE` drift field and `drifted`, #1244; `StyleMaskPass::ensure_wooze` builds the 1x and 4x pairs on the first styled woozy draw, and a draw is masked woozy only when the main pass drew it woozy, `masks_woozy`), and in the style and fog veils (#1241: `wooze_pipeline::vertex_module` over their own `fs_veil` / `fs_fog_veil*`, made on the first woozy blended draw, chosen by `MainPipe::woozy`; golden `style-veil-wooze`). The selection outline does the same, with one `//FLINT_WOOZE` line of its own in `selection_mask.wgsl`. `flint_wooze::ShallowClock` counts beats as a prop does, with no phase offset, so meshes in one place share one continuous displacement. `flint_wooze::shallow::ShallowWooze` gives each group one clock (the topmost component's; the player's living subsystem and the viewer each keep one), and the frame's `ShallowWoozeDraw`s go to `prepare` as `FrameInputs::shallow_wooze` (#739). Pay-nothing is the point, so don't add to `shader.wgsl` or `shadow_shader.wgsl` for this: woozy draws have their own vertex stages (`wooze_vertex.wgsl`, `wooze_shadow_shader.wgsl`, both prefixed with `wooze_noise.wgsl`) over the existing fragment stages, in `WoozePipelineSet`s (`ScenePipelines::wooze_standard`/`wooze_skinned`, so an MSAA change rebuilds them) and `ShadowPass::wooze`, built on the first woozy draw. The drift rides in padding: the last 48 bytes of a transform arena slot (every arena bind group now binds the whole 256-byte slot) and of a shadow draw slot. A plain `flint render` and the wireframe view show the rest pose; `--time` and `--sweep` draw it (the capture's `LivingSubsystem`, #725). 268 woozy entities cost about 0.6 ms a frame. A test mirrors the noise in Rust, so change both together. Bench: `flint-examples/shallow_wooze.scene.toml`. Book: concepts/procgen.md

## Glyph atlas

- **Glyph atlas** (#264) -- `flint_render::glyph_atlas`: `GlyphSet` = a coverage atlas (`R8Unorm` via `GpuGlyphAtlas`) + named luminance ramps + edge glyphs, from `fonts/<name>.glyphs.toml` (TTF via ab_glyph, PNG grid, hand-drawn `.txt` cells with `cell = [w, h]`, or the hand-drawn built-in 8x8 set in `builtin_8x8.txt`); `GpuGlyphStack` stacks several atlases in one texture (#335); `GlyphSetCache::get("builtin"|"<name>")`; it and `PaletteCache` hot-reload natively (#323: `poll()` stats the files an entry read or searched, `crate::file_watch::FileStamps`; the ASCII style polls every 15 frames; a glyph set that breaks on reload keeps its last good `Arc` with one warning, #286). Top-level keys like `default_ramp` go before the first `[table]`. Look at one with `cargo run -p flint-render --example glyph_atlas -- out/ [set]`. `ui_text` sprite fonts draw from the same atlases (ADR 0113, #283): `BitmapFont` is layout over a `GlyphAtlas`, `ui_text.font` = `builtin` | a set name / `.glyphs.toml` | a `.font.toml` PNG grid (compat, cut by `from_grid_image`, or `glyphs = "<set>"` + `spacing`); `SceneRenderer::load_ui_font` uploads it once per name and `AssetScope` at scene load as white RGBA with coverage alpha (`font:<name>`), extraction only lays out; a load from another scope (a transition into another folder) forgets every font and its texture first (#312; `loaded_ui_font(name)` is what draws; test `scene_entry_tests::fonts_resolve_beside_the_scene_a_transition_reaches`); demo `flint-examples/ui_test/ui_fonts.scene.toml`. A TTF atlas takes the printable ASCII its font has, so emoji and other-script fonts load (#935); ramp and edge glyphs must all be in the font. Eleven sets over OFL fonts live in `flint-examples/fonts/` (`phosphor`, `kana`, `moon`, `cuneiform`...), each font subset by `flint-examples/fonts/ofl/subset.py` with its `OFL.txt` beside it; only OFL or public-domain fonts go in the engine repo, since every game carries the subtree. Book: concepts/glyph-atlas.md
- **Models and textures are found by the project's resolver** (ADR 0114 step 3, #706) -- `model_loader::ModelLoadConfig { project, scene_dir, overrides, asked_first }`: `resolve_model_path` / `resolve_texture_path` return `Result<PathBuf, flint_core::project::NotFound>`, the catalog override first and then `project.resolve(AssetKind::Models | Textures, name, &scene_dir)`. - **Looks, palettes, glyph sets, fonts and style images are found by the project's resolver too** (ADR 0114 step 3, the last group, #706) -- the handle is `flint_core::project::AssetScope` (project + scene directory). `SceneRenderer::set_asset_scope(scope)` gives it to the renderer (and sets `scene_dir`); a host that only sets `scene_dir` gets the project found from it, once per directory (`asset_scope()`, cached), and with no scene the working directory stands in for the scene's folder (tests and the model previewer rely on it).
