## Frame and GPU rules

- Per-frame GPU allocations are the renderer's CPU cliff: `update_from_world` rebuilds the draw lists every frame, so anything it needs per entity must come from a cache (`draw_bind_cache` for transform/material binds keyed by entity + sub-mesh with a material hash, `box_mesh_cache` for procedural boxes, `GpuMesh` buffers shared via `Arc`, one dynamic-offset uniform buffer for all shadow draws). Never `create_buffer`/`create_bind_group` inside a per-entity loop; a 270-entity scene went from ~17 ms to ~4 ms when those were removed. Skinned draws use the same cache (`SKINNED_DRAW_KEY`, bone binds in `SkinningState::bone_binds`, #121). On the web every `create_*` is also a JS object: Float's skinned path made 386 buffers and 327 bind groups a frame, and Firefox stalled ~250 ms at each GC. Count WebGPU calls per frame in the browser before trusting a desktop timing (`?perf=1` shows them: the page wraps `submit`/`writeBuffer`/`createBindGroup`/`createBuffer`/`beginRenderPass`, #139)
- One submission a frame (#139): `SceneRenderer::encode_to` records the whole frame (grass, shadows, scene, post-process, depth upscale, world lines) into the caller's encoder, the player adds its HUD and the GPU timer's resolve (`encode_gpu_timings`), submits once, then calls `frame_submitted` (grass and timer read-backs). `render_to` is that with its own submit. Every `queue.write_buffer` lands before the submission, so a uniform buffer may hold one value per frame: steps that differ get slots of their own (bloom's per-step slots), and encoding two cameras into one submission would show the second camera's uniforms to both (so comic panels submit one a panel, next bullet but one). Cached draws' transforms live in `TransformArena` pages (`bind_cache.rs`, a 256-byte slot each, one write per page); post-process bind groups live in `PostProcessResources::binds` (dropped on resize; names `bind_cache::retire`d, a replaced user style's, leave every cache at its next frame, #427); ones over the caller's depth view are kept under the id the caller passes with it (#379: `encode_to`/`render_to` take `impl Into<DepthTarget>`, `RenderContext::depth_target()` / `HeadlessContext::depth_target()`, a `new_depth_id()` each time the texture is made; `BindCache::get_over` drops the old id's groups) and made per frame for a bare `&TextureView`, since wgpu 23 gave a view no identity to key on (wgpu 30's `TextureView` and `Device` hash by identity, so that reason is gone; nothing has moved to it yet). A host that makes its own depth texture takes a new id with it, or kept groups bind the old texture
- **Pipelines kept across renderers** (#911) -- `pipeline_cache`: off by default; `set_enabled(true)` (`flint goldens` in one process) makes `shared(device, label, parts, build) -> Arc<T>` (and `shared_some` for a build that may make nothing) keep what it builds under (device address, type, label, `Debug` of `parts`), so the next `SceneRenderer` on the device takes it. Measured first: building pipelines was 67% of a golden case's time on Vulkan, 88% on DX12/DXC, 97% on FXC (RTX 4070, debug), the scene set (`ScenePipelines`) the most of it, ASCII's glyph pipeline once a case. Kept: every `ScenePipelines` member but `sprite2d` (it holds a uniform the frame writes), keyed by (format, samples) since their WGSL and layouts are the binary's; the post chain's eight (composite, bloom x3, SSAO x2, volumetric x2, by surface format); and each built-in style's kit pipelines (`stylize/CLAUDE.md`). Only immutable objects (pipelines with their layouts, modules and constant meshes) may be kept: a uniform buffer, history texture, bind group or a style's state stays the renderer's, which is what keeps a case from seeing another's (`tests/pipeline_cache.rs`: a second renderer's first frame is a fresh one's bytes though the first had ASCII history full, and a changed WGSL builds a new pipeline). A later renderer's bind groups fit a kept pipeline because wgpu-core pools bind group layouts by entries (and WebGPU calls equal ones the same). wgpu 23 gave a device no identity, so the key holds its address: a host that drops its device calls `clear()` (`RenderHost::drop_device`). `counts()` (built, reused by label) is kept on or off; goldens prints it. Not kept: user styles' pipelines (`custom.rs`), the style mask and albedo passes, shadows, FXAA and the MSAA resolve (about 2% of a case together); the blend, ownership, fade and reveal passes' lazily built ones are, each under `in_scope((name, format))`
- **GPU test harness** (`tests/shared_gpu`, #598, #913) -- each test binary makes one device; its tests share it **side by side** (`lease`; `lease_alone` waits for every other test, for one that counts device-wide objects or switches process-wide state such as the cache or `dev_shader`'s folder; error scopes are per thread since wgpu 28, so they need nothing) with `pipeline_cache` **on**, so a test takes the pipelines earlier tests built. Measured on `tests/stylize.rs` without the cache, one test at a time (RTX 4070, debug): building pipelines was 69% of it on Vulkan, 88% on DX12/DXC, 96% on FXC; the binary went 12.7 to 8.7 s on Vulkan, 95 to 37 s on DXC, 303 to 45 s on FXC. #913 lent it one test at a time because on wgpu 23 side by side stalled DX12 (wgpu-hal 23's `Device::wait` shared one auto-reset event among waiting threads, so of two tests in `device.poll(Wait)` one slept out wgpu-core's 60 s `CLEANUP_WAIT_MS`; stylize 400 s against 37 s in turn). wgpu-hal 30 makes an event per wait and has no 60 s cap, and #948 measured side by side faster everywhere (stylize, min of 3 alternated runs, RTX 4070 debug: Vulkan 8.8 to 3.4 s, DX12/DXC 13.1 to 6.6 s, local WARP 18.9 to 13.2 s; all 7 binaries 20.4 to 13.3 s, 31.9 to 23.2 s, 52.2 to 46.6 s; the small binaries on WARP are 0.3-0.6 s slower side by side, WARP being CPU), so it's the default again; `FLINT_GPU_TEST_PARALLEL=0` gives one at a time. A test that wants pipelines built from nothing or counts builds switches the cache while it holds the device (`tests/pipeline_cache.rs` does, and `clear()`s first); its `Lease` puts the harness's setting back on drop. Pipelines are keyed by their WGSL's hash, so hot reload and `FLINT_STYLE_SHADER_DIR` get new ones (`tests/dev_shader.rs` passes with the cache on). `pipeline_cache::thread_build_time()` is this thread's build time; `FLINT_GPU_TEST_TIMES=1` prints a line per test (held, building), and CI's GPU job sets it. `FLINT_GPU_TEST_PIPELINE_CACHE=0` and `FLINT_GPU_TEST_PARALLEL=0` turn the cache and sharing off for A/Bs
- DX12's shader-visible sampler heap has 2048 slots. wgpu 23 copied every bind group's samplers into it with no sharing, so samplers in a per-entity or per-material bind group capped how many could live ("Not enough memory left" in `create_bind_group`, DX12 only; test with `WGPU_BACKEND=dx12`). wgpu-hal 30 keeps one global heap with each distinct sampler description once (`dx12/sampler.rs`), so the cap is now on distinct samplers, not groups. Keep samplers in groups bound once a frame anyway: PBR materials sample with the light group's `material_sampler` (group 2, binding 4), and a material bind group holds none
- **DX12 compiles shaders with DXC linked in, FXC only as the fallback** (#912, #947; `gpu_select` module docs). flint-render's default feature `static-dxc` turns on wgpu's, and wgpu-hal's `mach_dxcompiler_rs::DxcCreateInstance` resolves to `vendor/static-dxc` (root `[patch.crates-io]`; flint-render asks for exactly its `0.1.947`, which crates.io doesn't have, so a game workspace without the patch fails in cargo's resolver instead of linking mach's prebuilt, #982; a game's root names the patch itself, book: Upgrading the Engine, Cargo): Microsoft's DXC v1.9.2609 built from source as one static library by `tools/dxc-static/build.ps1` (`.github/workflows/dxc-static.yml`; a `dxc-static-v*` tag publishes it as that release's asset). Its build script takes the archive from `FLINT_STATIC_DXC_ARCHIVE`, else the machine-wide cache `FLINT_STATIC_DXC_CACHE` / `%LOCALAPPDATA%\flint\static-dxc\<sha256>.tar.gz`, else downloads it there with curl from the asset URL (no API call); the SHA-256 in `vendor/static-dxc/pin.rs` is checked on every path, and offline with no cache it panics naming the URL and both variables. Linked on x86_64 Windows MSVC only (`gpu_select::STATIC_DXC`), with MSVC at least as new as the archive's (`BUILT_WITH_MSC_VER`). The library is linked `-bundle` (it's ~500 MB). `instance()` passes wgpu's `Dx12Compiler::Auto`, or what `Dx12Compiler::from_env()` reads from `WGPU_DX12_COMPILER` (`fxc`, `dxc`/`dynamicdxc`, `staticdxc`, `auto`); `choose_dx12` turns a `staticdxc` without the link, or a DLL that doesn't load, into FXC with a reason instead of wgpu's panic or instance error. Without static DXC it loads `dxcompiler.dll` by name first (`load_dxc_dll`) and reports the file Windows loaded (`GetModuleFileNameW`); wgpu-hal's load gets the same module. `dx12_shaders()` / `shader_compiler(backend)` / `adapter_line(info)` say which: `DXC (static, v1.9.2609)`, `DXC (<dll path>)`, `FXC (WGPU_DX12_COMPILER=fxc)`, `FXC (fallback: <why>)`; `request_adapter` warns once on a fallback. A new DXC release: bump `build.ps1`'s pin and archive `-<n>`, push the `dxc-static-...` tag, then put the published SHA-256 and `_MSC_VER` in `pin.rs`. A shader DXC rejects is not retried with FXC. Measured on the RTX 4070, debug build, `--style ascii` on pbr_test (#912, DLLs): DXC 5.0 s, FXC 26-27 s, Vulkan 1.1 s. The DX12 downlevel `shader_model: Sm5` wgpu-core logs is `DownlevelCapabilities::default()`, not the HLSL shader model
- HDR format `Rgba16Float` -- all pipelines must use this when post-processing active; `resize_postprocess()` on window resize
- **Comic panels** (#880, ADR 0120) -- a scene's `[panels]` (`schemas/scene/panels.toml`; `[panels.panel.<name>]` with `rect` shares, `order`, `position`/`target`/`fov`, `follow`, `look`, `post_process`) is parsed by `flint_render::panels::PanelLayout` (`parse`, `from_scene_tables`, `with_panel` / `without_panel` / `merge_panel` for scripts' edits, `rects`, `panel_camera`); the drawing is `scene_renderer/panels.rs`. Each panel is a `ViewSlot` (the size-keyed fields: `postprocess_resources`, the `MsaaView`, the water's `OceanGrab`, `scaled_depth`/`depth_upscale`, `surface_size`, the `StylePasses` (mask and albedo), `selection_outline`) swapped in around the unchanged `encode_to` with the panel's camera and, if it has its own look, its config (masked by quality, on the frame's boil); made once by `resize_postprocess` on an empty slot, kept by panel name for the scene (`set_panels(layout, base_def)` at scene load forgets them; `set_panel_layout` is a script's cut and keeps them), remade on a size, format, MSAA or render-scale change. **A new size-keyed field on `SceneRenderer` goes into `ViewSlot` and `swap_view`**, or a panel thrashes or shares it. Each panel but the last is its own encoder and submission (its uniforms land first); the last and `PanelCompositor`'s page (clear to the gutter, `textureLoad` the picture inside, the border's ink round it, scissored per panel, 16 dynamic slots) go in the caller's. Hosts call `encode_frame_to` / `render_frame_to` (world for `follow`): the player's frame, `flint render`'s stills, `--frames` and the Stage. A whole-frame panel with no gutter is byte-identical to the frame. `BindCache::first_write` is per writer now (a process-wide last writer per name), since panels' caches write their texel sizes into the pipeline's shared buffers. Tests `tests/panels.rs`; demo `examples/comic_panels.scene.toml`; book concepts/comic-panels.md

## Where scene_renderer code goes (ADR 0118, #736)

`SceneRenderer` is one struct whose methods are spread by concern over `scene_renderer/`. Each file is an `impl SceneRenderer` block or a subsystem the renderer holds as one field. A new feature's state goes in its subsystem's struct, never as a loose `SceneRenderer` field, and its code goes in the file below that owns its concern:

| File | What lives there |
|---|---|
| `mod.rs` | the `SceneRenderer` struct and the draw types (`DrawCall`, `SkinnedDrawCall`, `EchoDrawCall`, the bind-cache types); `build` behind `new`/`new_headless`; `update_from_world`; the public forwards to the subsystems (terrain, skinning, lights, shadows, sky, water, ground fog) |
| `binding.rs` | the scene a host binds once a load (#739): `SceneBinding` (made by registering the scene's user styles), `bind_scene` and what it returns (`BoundScene`, `LoadedTerrain`, `BoundGrass`), and the one terrain loader every host shares |
| `frame.rs` | the frame: `FrameInputs`, `View2d`, `prepare` / `prepare_again` (#739), then `render`, `render_to`, `encode_to` (the order the frame is recorded in), `encode_again_to`, `frame_submitted`, world lines |
| `pipelines.rs` | `ScenePipelines` (every sample-count-baked pipeline) and `SceneLayouts` |
| `extract.rs` | per-entity extraction into the draw lists (static, skinned, echoes, billboards, sprites, UI text) |
| `draws.rs` | the bind cache, shared materials, procedural boxes, LOD and frustum culls, building a draw call's bind groups, shallow wooze's per-draw drift |
| `render_passes.rs` | the passes: shadows, per-frame uniforms, main pass, wireframe, post chain, style bounds |
| `post.rs` | post-process and quality config: HDR chain size and render scale, drawn vs authored config, `set_quality`/`set_msaa`, building style and FXAA resources, style text/edge read-outs, `post_time` |
| `assets.rs` | loading: models and their textures, procedural meshes, textures, `ui_text` fonts, ray targets, the asset scope |
| `stats.rs` | `collect_stats`, the GPU timer, debug mode and overlays, tonemapping |
| `msaa.rs`, `sky.rs`, `lights.rs`, `terrain.rs`, `style_mask.rs`, `water.rs`, `skinning.rs`, `grass.rs` | the subsystems below, each with its state and its extract and draw hooks |
| `panels.rs`, `selection.rs`, `particles.rs`, `grass_ground.rs`, `splines.rs`, `helpers.rs` | comic panels' view swap, the selection outline's draw walk, the particle upload bridge, a scene's `grass_ground`, a scene's `spline` / `spline_mesh` (`load_scene_splines`, next section), free helpers |
| `tests.rs` | the module's unit tests (GPU tests are `crates/flint-render/tests/`) |

## Host protocol (ADR 0118 decision 5, #739)

The player, the scene viewer and `flint render` drive the renderer through these entry points, in this order:

1. **`SceneBinding::new(scope)`** when a scene's settings are read: it registers the user styles the scene can see (`stylize::custom::load_for`), so it comes before anything reads the scene's `[post_process]`. Its `style_messages()` are the host's to say. `.with_environment(scene_file.environment.as_ref())` hands it the scene's `[environment]` (`flint_scene::EnvironmentDef`), and `.with_archetypes(&registry)` each archetype's placeholder box (`flint_schema::ArchetypeVisual`, its schema's `[archetype.<name>.visual]`, #751): the colour and wireframe a `bounds` box with nothing else to draw takes. The renderer names no archetype; a binding without it draws every box grey. The player adds it in `stage_scene` (its held registry), the viewer in `stage_scene`, `flint render` once its schemas load. A material-less imported mesh keeps the first demo's green (`MODEL_FALLBACK_COLOR`, yellow when skinned), now a constant.
2. **`bind_scene(device, queue, &world, &binding) -> BoundScene`** once the world is loaded, before the scene's models: the asset scope, then nothing of the last scene (style history, bone buffers and motion holds, the lighting levers, `shadows` and `default_lights` back to the built-ins, the terrain and grass unloaded), then the scene's `[environment]` levers (#627), its terrain (named for the style mask, #310) and its grass, a `grass_ground`'s over a terrain's. A host's own overrides (`flint render --oren-nayar`, the viewer's F4 panel) go after it; the skybox is still the player's alone. The host takes what it needs of `BoundScene` (the player registers the terrain's collider and keeps its heights). The terrain loader that was copied into the player and `flint render` lives here; the viewer, which had none (so `flint edit` drew no terrain) and read no `[environment]`, binds at load and at each hot reload (`flint_viewer::app::stage_scene`).
3. Each frame: **`set_motion_time(t)` before any bone write** (a host that writes no bones can skip it), then **`prepare(device, queue, &world, &FrameInputs)`**, which takes every per-frame input, reads the world into the draw lists (`update_from_world`) and uploads the particles. Then `encode_to` / `encode_frame_to`, the submit, `frame_submitted`.

`FrameInputs` is one clock (`time`: motion holds, and unless held the ocean, sky, post time and grass wind) with two holds a host may set (`look_time`, `--style-time`; `grass_time`, woozy grass's sway or a still's rest), plus `dt`, the boil, shallow wooze, woozy grass's comb, `pixels_per_point`, the 2D view (`View2d`), the particles, world lines, grass benders and contact hulls' velocities (the player gives a dynamic body's, `PhysicsSystem::dynamic_velocity`, #749). **Every field's default turns its feature off for the frame**, so a host that doesn't know a feature can't leave a stale value behind (a world line or boil from an earlier frame). The boil `prepare` takes is stamped into the drawn config again at `encode_to`, so a config a host sets between them (a look, a panel) can't drop it. A split view's other side is `prepare_again(device, &world, boil, shallow)` then `encode_again_to`, which draws that boil once. A new per-frame input is a `FrameInputs` field with an off default, never a `pub` field or a setter. The player gathers its subsystems' share through `Subsystem::frame_inputs` (the living subsystem's boil, shallow wooze and grass) right before `prepare` in `sync_renderer`; `flint render`'s stages through `HeadlessGame::frame_inputs`; the viewer in `ViewerApp::prepare_frame`, which reads the world every frame (it used to re-read it only on an edit), with its wall clock as `time`, its post time held (`look_time`: 0 or `--style-time`), and its own `ShallowWooze` and `GrassWooze` (`flint_render::shallow_wooze`, moved from the player) on its field's clock. Tests: `tests/frame_inputs.rs`, and the viewer's `app_binding_tests.rs`. **These are the only way in** (#739): the per-frame fields are private (`ocean_time`, `grass_time`, `grass_wooze`, `style_dt`, `pixels_per_point`, `camera_offset`, `ortho_height`, `aspect_ratio`, `scene_dir`; read back with `pixels_per_point()`, `scene_dir()`, `asset_scope()`), and `update_from_world`, `set_boil`, `set_shallow_wooze`, `update_particles_from`, `update_grass_entities`, `set_terrain_entity` and `set_asset_scope` are `pub(crate)`. Every host is on them: the player, the viewer, `flint render`, the model previewer, the procgen previewer, `flint gen --strip` and the particle editor (a frame of particles in an empty world). `update_particles` stays public for a host's own particle draws, uploaded after `prepare` (which clears the last frame's). `set_motion_time` stays public as the stamp before bone writes. GPU tests draw a frame the same way (`Gpu::frame_with` in `tests/stylize.rs` takes `FrameInputs`; `tests/quality.rs` hands its shallow wooze and particles over each frame).

**The crate's surface** (ADR 0118 decision 2, #739): the pipeline and GPU-uniform modules are `pub(crate)` (`billboard_pipeline`, `grass_pipeline`, `ocean_pipeline`, `particle_pipeline`, `selection_outline`, `shadow`, `skinned_pipeline`, `sky_pipeline`, `skybox_pipeline`, `sprite2d_pipeline`, `style_albedo`, `terrain_pipeline`, `world_line_pipeline`), and so are their pipeline and uniform types (`*Pipeline`, `*Uniforms`, `*UniformsGpu`, `RenderPipeline`, `SceneLayouts`, `PostProcessPipeline` / `PostProcessResources`, `ParticleBuffers` / `ParticleDrawCall`, `TerrainDrawCall`, `Sprite2dBatch`...). What the hosts and the crate's own GPU tests use stays public: `LightUniforms` (its default ambient), `GrassGround` / `GrassHeight` / `GrassEntityPosition` / `GrassInstanceGpu`, `ParticleDrawData` / `ParticleInstance` / `ParticleBlendMode`, `OceanVisuals`, `SkyParams`, `HDR_FORMAT`, and two constants re-exported at the root, `MAX_BONES` and `WORLD_LINE_DEPTH_SLACK`. Float, FlintKart and Kandinski have no Rust outside `engine/`, so nothing else imports the crate. A new pipeline or uniform type is `pub(crate)`; one a host needs is re-exported by name.

## Pipelines

- One constructor body (ADR 0118, #736): `SceneRenderer::new` (a window's `RenderContext`) and `new_headless` (a device, queue, format and size) both call the private `SceneRenderer::build(device, queue, surface_format, size, config)`, so a new `SceneRenderer` field is initialised in one place
- Feature subsystems own their state (ADR 0118 step 3, #736), each in its own file under `scene_renderer/`, held by `SceneRenderer` as one field: `msaa.rs` `MsaaTargets` (the 4x colour and depth at the view's size as an `MsaaView`, which a comic panel's `ViewSlot` swaps whole, and the sample-0 depth resolve; `prepare`, `drop_targets` on an MSAA change, `depth_at(w, h)` for the style mask and albedo). `style_mask.rs` `StyleMaskState` (style ids, each styled entity's mask id, blend and tear, `veiled`, `scissor`, and the mask and albedo `StylePasses`; `resolve`/`clear` in `update_from_world`, `fades`, `draw_stats`). The draws the two passes take are gathered in the same file by `SceneRenderer::encode_style_mask` / `encode_style_albedo` from the renderer's draw lists, which the state never holds (#737 gives them one `DrawItem` list). `water.rs` `WaterRenderer` (the ocean's uniform, transform and sea-body buffers, the wave spectrum and look, the contact-foam hulls (every `ocean_contact` read from its world matrix by `hull_on_water`, up to `ocean_pipeline::MAX_CONTACTS` = 4 in the uniform's `hulls` array, the nearest the camera past that with a warning per name left out, each with its own differenced velocity unless `FrameInputs::contact_velocities` gives one; #749, `water::contact_tests`), water bodies set by a game or a `water_body` component, and the refraction grab as an `OceanGrab` a panel swaps; `extract_ocean` / `extract_contact` / `extract_bodies` in `update_from_world`, `ensure_grab`, and the hooks `upload` (handed a `WaterFrame`: the clock, tonemapping, the sky's colours, the tear's mode) and `draw`; `SceneRenderer::water_active` and the public water-body methods forward, and the clock is `FrameInputs::time`, or `look_time` while `--style-time` holds it, #739). `skinning.rs` `SkinningState` (each entity's own bone buffer and the CPU copy the style scissor bounds with, shadow bones, living props' echoes and `echo_lighten`, part tints and softness, and the skinned draws' `bone_binds`; the host setters `update_bone_matrices`, `write_entity_bones`, `write_entity_shadow_bones`, `write_entity_echo_bones`, `set_entity_echo_*`, `set_entity_part_*` and `clear_entity_bone_buffers` keep their signatures on `SceneRenderer` and forward; the skinned extraction in `extract.rs` reads the tables while it builds the draws). `grass.rs` `GrassRenderer` (the 29 fields the renderer had as `grass_*`: the compute's and the draw's buffers and bind groups, the instance buffer and indirect args, the count read back in `frame_submitted`, the cascades' shadow binds, the placement slots, the config and the ground or terrain it grows on, the ground's mask); the methods that build and drive it (`load_grass`, `set_grass_ground`, `update_grass_mask`, `unload_grass`, `read_grass_blades`, `set_grass_config` / `reload_grass_config`, `update_grass_entities`, `dispatch_grass_compute`) are `SceneRenderer`'s, in the same file as an `impl` block, since they read its pipelines, layouts and shadow pass. The grass's clock and comb come in with the frame's inputs (`FrameInputs::grass_time`, `grass_wooze`, #739). `sky.rs` `SkyRenderer` (the procedural sky's uniforms and the scene's `SkyParams`, which the ocean reflects; the texture skybox's binds; `extract` writes a `sky` component's ambient into the light uniforms, `draw` picks the procedural sky over the panorama). `lights.rs` `LightState` (the `LightUniforms`, their buffer and group-2 bind group, rebound by `rebind` when the shadow pass is remade; the `[environment]` levers: ambient, diffuse wrap, Oren-Nayar, sheen, `shadows`, `default_lights`; `extract` reads the light entities, `sun_casts` says whether directional 0 gives light or god rays; `LightingLevers` is re-exported from `scene_renderer`). `terrain.rs` `TerrainRenderer` (the per-chunk `draws`, the one `material_bind_group` and `material_buffer` they share, chunk counts for stats, and the `entity` a style mask reads; the three loaders `load_terrain`, `load_terrain_from_data` and `reload_terrain_geometry` side by side, bodies as written, taking the pipeline, texture cache and transform layout as arguments; `SceneRenderer`'s methods of the same names forward, #918 folds the loaders' repeated chunk upload and material bind group into one helper each). New state for one of these goes in its struct, not on `SceneRenderer`
- Skeletal animation: separate `SkinnedVertex`/`skinned_pipeline`; bone matrices in storage buffer (bind group 3)
- Particles: no depth write; one shared storage buffer indexed by `first_instance`; skip draw for 0 alive; `bytemuck::cast_slice` for zero-copy
- glTF `doubleSided` (#623): `ImportedMaterial::double_sided` -> `DrawCall::double_sided` + `MaterialUniforms::double_sided` (the old `_pad_e2` word). Opaque and shadow pipelines for PBR meshes each have a no-cull `*_double_sided` twin (static, skinned, `WoozePipelineSet::opaque_double_sided`, `ShadowWooze`), picked per draw; blended draws already draw both faces in two passes. `fs_main`/`fs_skinned` take `@builtin(front_facing)` and `facing()` turns a back face's normal toward the viewer. A new culling pipeline for meshes needs its twin. Bench: `examples/double_sided.scene.toml`; fixture `tests/fixtures/models/DoubleSidedCard.glb`
- **Built-in shader modules go through `TrustedShader`** (#944, `trusted_shader.rs`) -- every module made from WGSL that ships in Flint (this crate's pipelines, the style kit's `kit::shader`, the player's world text, the CLI's windows, test harnesses) is `device.create_trusted_shader_module(desc)` (`use flint_render::TrustedShader`): `create_shader_module_trusted` with `force_loop_bounding: false` and every other check on (bounds, integer division), since naga 25+'s loop bounding made ASCII 2.6x slower on the GPU and Kuwahara and pencil about 25% (spike #934). With bounding off a loop that never ends can hang the GPU, so **every loop in built-in WGSL must end on every input**: a constant bound, or one clamped on the CPU or in the shader (#945 audited all 112: kuwahara's `radius` is capped at 32 and the selection outline's `reach` at 64 for this; a `<=` bound that could reach `i32::MAX` wraps and never ends). `FLINT_SHADER_CHECKS=all` puts loop bounding back on for the built-in modules (the A/B, and a first test when a GPU hangs); unset is the default. `kit::shader` is public, so a game's own Rust style is trusted code too. **User style WGSL never goes through it**: `stylize/custom.rs`'s `pipeline` keeps the checked `create_shader_module` (Flint guards those loops itself, #411). Clippy holds it: the workspace `clippy.toml` disallows `wgpu::Device::create_shader_module` (and its `_trusted` and `_unchecked` forms), `wgpu::Surface::get_current_texture` and `egui::Context::run_ui` (flint-player/CLAUDE.md), and flint-render, flint-player, flint-viewer, flint-cli and flint-debug-ui deny `disallowed_methods` in their `[lints.clippy]` (CI's clippy job fails on it); each sanctioned call carries `#[allow(clippy::disallowed_methods)]`. A new crate that links wgpu or egui adds the same `[lints.clippy]` table
- **Windows take their frame through `AcquireFrame`** (#944, `surface_frame.rs`) -- `surface.acquire()` (`use flint_render::AcquireFrame`) returns `Result<SurfaceTexture, flint_render::SurfaceError>`, never wgpu's `get_current_texture`, which since wgpu 29 returns a `CurrentSurfaceTexture` enum (#945 maps it). There is no `OutOfMemory`: wgpu 29's enum has no such case, so #948 removed the variant and the editors' fatal arm; a suboptimal frame counts as a frame. Present it with `queue.present(frame)`. `SceneRenderer::render` returns the same error type
- **Waits on the GPU go through `wait_for_gpu`** (#948, `gpu_wait.rs`) -- `flint_render::wait_for_gpu(&device)` is `device.poll(PollType::Wait)` with `FLINT_GPU_WAIT_TIMEOUT` seconds as its timeout when set (unset: no limit, as a game wants) and a panic naming the variable when a wait reaches it, since the work is still queued and the next wait would block too. wgpu 23 gave up every wait at wgpu-core's 60 s `CLEANUP_WAIT_MS` and broke the device on WARP (#910, #912); wgpu 27+ waits as long as it takes, so without a timeout a hung GPU on CI would sit to the job's 60-minute limit. CI's GPU job sets 120. Clippy's `disallowed_methods` refuses `PollType::wait_indefinitely` (the read-backs, the GPU timer's resolve, the grass count, the tests); `PollType::Poll` is fine
- **Line pipelines take no depth bias** (#944) -- the overlay and skeleton line pipelines (`pipeline.rs`) and the skinned wireframe (`skinned_pipeline.rs`) draw `LessEqual` with `DepthBiasState::default()`. WebGPU and wgpu 29+ reject a bias on a line topology; Vulkan never applied one to lines, and DX12 on the RTX 4070 gave the same bytes too (every stylize golden and a `--wireframe-overlay` render, against main's binary). Don't add one back

## Splines and sweeps

- **`load_scene_splines(scene_path, world, renderer, device, queue) -> LoadedSplines`** (#750, `scene_renderer/splines.rs`) -- the one loader the player (`scene_entry.rs::stage_scene`, which registers `LoadedSplines::colliders` as static trimeshes) and `flint render` (both paths; colliders dropped) call; it was `flint_player::spline_gen`, which `flint render` reached into. It reads every `spline.file` through `flint_geometry::spline_file::SplineFile::read` (found by `Project::file_or_beside`; a mistake is one `tracing::warn!` of `file:line:col: message`, and the spline is skipped), stores `spline_data`, and sweeps each `spline_mesh` with `flint_geometry::sweep` (`sweep` or `sweep_chunks`). The component is read through `world.view` (`mesh_def`): a box `width` x `height`, or `profile` (`[right, up]` points) with `profile_closed` and `smooth`; a missing field is `missing-field`, a profile that is no polygon `bad-spline`, both via `view.report`. Constants are named `components::SPLINE_*` (the schema test greps for that form). Progress is `tracing::debug!`/`info!`, never `eprintln!`. **Byte-identity**: FlintKart's six tracks render identically to `spline_gen`'s, though the box's faces are now emitted in profile order (top, right, bottom, left) rather than top, bottom, left, right; keep a flat box's normals and UVs computed as `sweep.rs` does (`combine` leaves out a term with an exact 0 factor; an edge listed downward reads u upward). An open spline's last sample has a zero frame (#1016): a smooth profile's normal there falls back to the flat one, since a zero normal shades NaN and bloom spreads it into a black block. Tests: `flint_geometry::sweep::tests`, `spline_file::tests`, `crates/flint-cli/tests/spline_sweep_cli.rs`. Demo: `examples/sweep_garden.scene.toml`

## Lights

- Lights are `[entities.x.light]` with a `type`, and a directional `direction` points *toward* the light. The fields and their fallbacks are `schemas/components/light.toml` (`flint schema light`), which a test holds to what `LightState::extract` (`scene_renderer/lights.rs`) reads; only `type`, `color` and `intensity` carry a schema default, since a default is written into the component at load and `range` would then beat an authored `radius`. No system reads a `directional_light` table: `flint validate` warns about it as an unknown component (#683), and a scene with only that gets `default_scene_lights` (the frozen fixtures keep one on purpose, #681). One point light and no directional means no sun at all. An ambient-only scene says `[environment] default_lights = false` (and `shadows = false`) rather than adding a dummy light; a sun at `intensity = 0` with no `volumetric_intensity` draws no shadow pass anyway (`SceneRenderer::shadows_drawn`, #627). `material.unlit = true` draws base colour x `emissive_scale` + emission with no lighting (`MaterialUniforms::unlit`, both PBR shaders)

## Post-processing and quality

- **Post-processing** -- HDR pipeline (`Rgba16Float`) with bloom, SSAO, fog, volumetric (god rays), Kuwahara (anisotropic painterly filter), vignette; `[post_process]` TOML block; F4 opens the Rendering & Effects debug menu in the player and viewer (all toggles + parameters, ADR 0053); when active, PBR shaders output linear HDR
- **Post effect descriptors** (#741, `flint_schema::post_effects`) -- every flat `[post_process]` key of a built-in effect is ONE line of the `post_effects!` X-macro (effect, key, kind `bool|f32|u32|rgb`, default, `[min, max]` tuned range, F4 widget, label, help). The macro hands the list to a caller's macro, which makes the fields: `flint_scene::PostProcessDef` (`post_process_def!` in format.rs: fields, `#[serde(default)]` + `Default`, `param`/`param_mut` by name), `PostProcessConfig` (`post_process_config!` in postprocess.rs: the same fields and defaults, then the renderer's own fields with explicit defaults; `param`/`param_mut`; `copy_params` is the def-to-config copy), `EFFECTS` (`--list-effects`, `range_warnings`, `PostParam::range_error`), the `[table.post_process]` schema fields (the registry adds them on loading `post_process.toml`; the file lists only `look`, `styles` and the old style keys) and the F4 sections (`render_panel.rs::param_widget`, by `PostParamMut`). **A new post key is its descriptor line, its uniform field and its WGSL**, plus the `PostProcessUniforms` fill line; nothing else names it. A key's range warns (`post-range`, `flint_scene::diagnose`) in a scene and is refused in a look (`look::overlay`) or `--sweep post.<key>`. `tests/table_schemas.rs::every_shipped_post_value_lies_in_its_range` holds every scene and look in the repo inside the ranges. The renderer-only fields (`enabled`, ground fog, `boil`, `render_mode`, `mode_mix`, `mode_params`, `styles`) are not keys: their F4 rows are hand-written after their effect's (`match effect.name`). Not on it yet: the flat `flint render` flags (#708's `--set` will be `param_mut(..).set(..)`), quality caps, and the pass order (bloom, SSAO, volumetric, FXAA are still fixed stages)
- **Quality settings** (FlintKart#55) -- `flint_core::quality::QualitySettings` (render_scale, render_scale_auto, msaa, shadows, shadow_resolution, shadow_cascades, shadow_distance, and post caps post_process/bloom/ssao/ssao_samples/fog/volumetric) reaches `SceneRenderer::set_quality` from `--quality k=v,...` (flint-player and `flint render`), the page's `?quality=`, Android's `dev_profile.toml` `[quality]`, and scripts' `set_quality(map)` / `get_quality()` / `gpu_info()`, applied between frames (`PlayerApp::apply_quality`). Post keys are caps over the authored config: the renderer keeps `post_process_config()` (authored) apart from `effective_post_process_config()` (drawn), so a scene load keeps the tier. Every pipeline that bakes in the sample count is a field of `ScenePipelines` (`scene_renderer/pipelines.rs`, ADR 0118, #735), and the sample count lives only there (`pipelines.samples()`): `ScenePipelines::build(device, format, samples, &layouts, present)` makes the set, `SceneRenderer::build` calls it, and `set_msaa` replaces the whole set with `rebuilt`, the optional ones (shallow wooze's, built on first use; grass, ocean, sky, left out when their shaders fail) rebuilt only when `present`. A new scene pipeline goes in `ScenePipelines` and `build` (its struct literal and `present()` name every field, so it won't compile until placed), never as a `SceneRenderer` field, built through `pipeline_cache::shared` with the set's `(format, samples)` key unless it holds something a frame writes (#911); its buffers stay outside it, as `ParticleBuffers` do. The three shared bind group layouts and the material sampler are `SceneLayouts`, made once; each pipeline's own layouts are remade equal (wgpu dedupes them), so cached bind groups stay valid. `tests/quality.rs::msaa_switches_with_every_draw_kind_on_screen` switches 1 to 4 to 1 with every draw kind on screen: give a new draw kind a place in its scene. Style mask and albedo passes key their 4x pipelines by sample count themselves. Shadow cascades map split depths through the camera's own near/far (they assumed 0.1/200 before, stretching the last cascade to the 1000 m far plane). Book: concepts/quality-settings.md
- **Shading boil and contour** (#214) -- `contour` is a registered HDR style (#599, `stylize/contour.rs` + `contour.wgsl`), registered last of the built-ins so it inks over Kuwahara; `[post_process.styles.contour]` takes `width threshold strength luma color fade boil`: depth as the second difference of 1 / distance, so flat ground draws no lines, plus luminance, one full-screen draw. The old flat `contour_*` keys and `kuwahara_boil` fold into the tables through `LEGACY_STYLE_KEYS` (`PostProcessDef` keeps them as `Option`s; `PostProcessDef::boil`/`set_boil`), and `--contour*` flags are shorthands for its keys. The demo user style once named `contour` is `contour_map` now (it sorts before `hologram`, so it keeps its place in the display chain). Boil is opt-in twice: each style's `boil` above 0, and a `[wooze]` table. Read and write both amounts with `PostProcessConfig::boil_amounts` / `set_boil_amounts` (presets, A/B, `tune_living`; a write of an unchanged amount makes no table); `commit_look` writes a boil into the style's table when the file has one, else the flat key, since a new table would switch the style on (`commit::fit_edits`). `boil_on` stays one shared `[post_process]` key. `flint_wooze::BoilClock` counts the field's beats, with six film frames to a beat so that `boil_on` 1, 2 and 3 all land on it, on game time. Whoever owns the clock hands the frame's `BoilFrame` to `prepare` as `FrameInputs::boil` (the player's living subsystem, `flint render`'s stages, held by `--boil-time`, the viewer's own clock); the field is sampled at the camera, and `jitter` alone is the strength. A boil of 0 skips the noise entirely, which is what keeps it byte-identical. Bench: `examples/shading_boil.scene.toml`, where nothing else moves, so `--frame-step 1/24` frames come in byte-identical pairs on twos. Book: concepts/post-processing.md

## Motion on twos

- **Motion on twos** (#405, `motion_hold.rs`) -- the renderer alone holds what it draws of an entity on ticks; the world (physics at 1/60, IK, scripts) moves smoothly and is never written. `held_rates(world, whole)` is who is held: the nearest `motion_hold { rate }` up the hierarchy (`rate = 0` lets a branch move), else `[post_process] motion_hold` (`PostProcessConfig::motion_hold`, `--motion-hold` on render/play/player); empty and unwalked with neither. `MotionHold` (a `SceneRenderer` field) keeps each held entity's world matrix (`matrix`, in `update_from_world`'s loop, so draws, shadows, culling and the ray scene all see the held one) and gates its bone writes (`bones_due`, first in `update_bone_matrices`: a skipped write keeps the buffer and the CPU copies), once a tick, `tick(time, rate) = floor(time * rate + TICK_EARLY)` on `post_time(seconds)` (`flint_core::step_clock::tick`: the stepped clock's `warp` with no glide, the one the living props hold and glide on, #747) (the f32 wrap styles see). Pencil's `effective_seed` steps by the same `tick`, so `rate` = `boil` turns pose and lines on one frame. **Hosts stamp `set_motion_time(t)` before uploading bones** (player: `bones_posed`, `clock.total_time`; `flint render`: the Stage's `capture` moment, the `--frames` loop, the still path), and `prepare` stamps `FrameInputs::time` again (#739): uploads come before `update_from_world`, so the rates are last frame's and `update_from_world` calls `bones_shown` for a hold that starts this frame. Never stamped, nothing is held. The editors (#871): the scene viewer's `FrameInputs::time` is its own wall clock (`ViewerApp::motion_clock`; its post time stands still, so stamping that would never turn a tick), and it prepares every frame, so a dragged held entity steps on its ticks; the viewer plays no animation and runs no physics, so only drags step there. The model previewer stamps the clip's playback time (`PreviewApp::motion_time`, the timeline's), so scrubbing steps through drawings, and calls `release_motion_hold(entity)` (`MotionHold::release`) when the pose changes by hand (layers, posed bones, a clip switch), which a paused hold would otherwise never show. A whole-frame rate also holds `SceneRenderer::post_time()` (styles' `StyleFrame::time`, the composite's grain/mode time, the tear) to the tick's start; the ocean, sky, grass and live particles stay smooth. **What a held entity carries** (#873): `tick`, `post_time`, `held_rate(world, id, whole)` and `held_rates` live in `flint_ecs::motion_hold` (re-exported here) so flint-particles, which can't see this crate, holds on the same ticks. `update_from_world` sets the rates *before* `LightState::extract`, and point/spot positions come from `lights::light_position` = `MotionHold::matrix` (the same kept matrix the entity's draw reads later in the frame); directional lights have no position, and their `direction` is world-space, so nothing there is held. Emitters: `ParticleSync::set_motion_time(t)` / `set_motion_hold(whole)` (stamped by the player in `bones_posed` beside `set_motion_time`, before the particles step; by `flint render`'s `Stage::step_particles_to` once per fixed step) give `EmitterHold`, which keeps each held emitter's matrix a tick; `EffectInstance::set_held_transform(held, live, ..)` births at the held point (`EmitterFrame::held` skips the `prev -> position` lerp; emission per metre still counts the jump) and takes velocity from the live positions, so `inherit_velocity` never sees a jump. The still `--particle-time` path stamps nothing (its world doesn't move). `write_entity_bones` (living props) is not gated. Tests: `motion_hold::tests`, `flint_ecs::motion_hold::tests`, `flint_particles::sync::tests::a_held_emitter_emits_from_its_drawing`, `crates/flint-cli/tests/render_motion_hold_cli.rs` (`a_held_entitys_point_light_steps_on_its_ticks`: two lanterns with nothing drawn, only their pools move). Example: `examples/motion_hold.scene.toml` (each bob a lantern: light + soot trail, beads when held)

## Shallow wooze

- **Shallow wooze** (#215) -- a `shallow_wooze` component (`amplitude` metres, `wavelength` metres; schema in `schemas/components/`) on an entity with a mesh, or above several, in a scene with a `[wooze]` table: each vertex moves through world-space vector noise on the field's clock, in the main and shadow passes alike. `flint_wooze::ShallowClock` counts beats as a prop does, with no phase offset, so meshes in one place share one continuous displacement. `flint_render::shallow_wooze::ShallowWooze` gives each group one clock (the topmost component's; the player's living subsystem and the viewer each keep one), and the frame's `ShallowWoozeDraw`s go to `prepare` as `FrameInputs::shallow_wooze` (#739). Pay-nothing is the point, so don't add to `shader.wgsl` or `shadow_shader.wgsl` for this: woozy draws have their own vertex stages (`wooze_vertex.wgsl`, `wooze_shadow_shader.wgsl`, both prefixed with `wooze_noise.wgsl`) over the existing fragment stages, in `WoozePipelineSet`s (`ScenePipelines::wooze_standard`/`wooze_skinned`, so an MSAA change rebuilds them) and `ShadowPass::wooze`, built on the first woozy draw. The drift rides in padding: the last 48 bytes of a transform arena slot (every arena bind group now binds the whole 256-byte slot) and of a shadow draw slot. A plain `flint render` and the wireframe view show the rest pose; `--time` and `--sweep` draw it (the capture's `LivingSubsystem`, #725). 268 woozy entities cost about 0.6 ms a frame. A test mirrors the noise in Rust, so change both together. Bench: `examples/shallow_wooze.scene.toml`. Book: concepts/procgen.md

## Glyph atlas

- **Glyph atlas** (#264) -- `flint_render::glyph_atlas`: `GlyphSet` = a coverage atlas (`R8Unorm` via `GpuGlyphAtlas`) + named luminance ramps + edge glyphs, from `fonts/<name>.glyphs.toml` (TTF via ab_glyph, PNG grid, hand-drawn `.txt` cells with `cell = [w, h]`, or the hand-drawn built-in 8x8 set in `builtin_8x8.txt`); `GpuGlyphStack` stacks several atlases in one texture (#335); `GlyphSetCache::get("builtin"|"<name>")`; it and `PaletteCache` hot-reload natively (#323: `poll()` stats the files an entry read or searched, `crate::file_watch::FileStamps`; the ASCII style polls every 15 frames; a glyph set that breaks on reload keeps its last good `Arc` with one warning, #286). Top-level keys like `default_ramp` go before the first `[table]`. Look at one with `cargo run -p flint-render --example glyph_atlas -- out/ [set]`. `ui_text` sprite fonts draw from the same atlases (ADR 0113, #283): `BitmapFont` is layout over a `GlyphAtlas`, `ui_text.font` = `builtin` | a set name / `.glyphs.toml` | a `.font.toml` PNG grid (compat, cut by `from_grid_image`, or `glyphs = "<set>"` + `spacing`); `SceneRenderer::load_ui_font` uploads it once per name and `AssetScope` at scene load as white RGBA with coverage alpha (`font:<name>`), extraction only lays out; a load from another scope (a transition into another folder) forgets every font and its texture first (#312; `loaded_ui_font(name)` is what draws; test `scene_entry_tests::fonts_resolve_beside_the_scene_a_transition_reaches`); demo `examples/ui_test/ui_fonts.scene.toml`. A TTF atlas takes the printable ASCII its font has, so emoji and other-script fonts load (#935); ramp and edge glyphs must all be in the font. Eleven sets over OFL fonts live in `examples/fonts/` (`phosphor`, `kana`, `moon`, `cuneiform`...), each font subset by `examples/fonts/ofl/subset.py` with its `OFL.txt` beside it; only OFL or public-domain fonts go in the engine repo, since every game carries the subtree. Book: concepts/glyph-atlas.md
- **Models and textures are found by the project's resolver** (ADR 0114 step 3, #706) -- `model_loader::ModelLoadConfig { project, scene_dir, overrides, asked_first }`: `resolve_model_path` / `resolve_texture_path` return `Result<PathBuf, flint_core::project::NotFound>`, the catalog override first and then `project.resolve(AssetKind::Models | Textures, name, &scene_dir)`. Build a config with `from_scene_path` (discovers the project, once) or `in_project(project, scene_path)` when the host holds one (the player per frame, `flint render`'s `Stage::project`); never a struct literal with a guessed directory, and no hand-written `scene_dir.parent()` for these kinds. A miss is warned with `config.not_found_text(&missing)`: every path tried, then `asked_first` (what the host asked before the files: the catalog, a procgen spec). The rule itself, the kinds table and the as-written step: `crates/flint-core/CLAUDE.md`. Nothing in this crate searches by hand any more
- **Looks, palettes, glyph sets, fonts and style images are found by the project's resolver too** (ADR 0114 step 3, the last group, #706) -- the handle is `flint_core::project::AssetScope` (project + scene directory). `SceneRenderer::set_asset_scope(scope)` gives it to the renderer (and sets `scene_dir`); a host that only sets `scene_dir` gets the project found from it, once per directory (`asset_scope()`, cached), and with no scene the working directory stands in for the scene's folder (tests and the model previewer rely on it). Styles read it as `StyleFrame::assets`. `PaletteCache::new(scope)` / `GlyphSetCache::new(scope)` (`Default` = no scope = built-ins only) call `scope.explain`, log its `order_change`, and stamp `Resolution::watched()` for `poll()`, so a nearer file appearing later reloads; a miss says what is built in and lists every path tried. `BitmapFont::resolve(spec, &scope)`: a `.font.toml` is `AssetKind::Fonts`, its image `AssetKind::Textures` and then beside the font file (a file a description names beside itself is not a search: a glyph set's `[font] file`, a user style's WGSL and images are the same). `look::find_in` / `resolve_in` / `resolve_scene_in` / `list_in` / `list_checked_in` take a scope; the path-taking `find` / `resolve` / `resolve_scene` / `list` wrap them with `AssetScope::for_scene` (a look path ending `.toml` but not `.look.toml` goes through `AssetKind::Files`, with its own TEMPORARY old-rule compare). Built-ins rank after the search: a palette or look file found shadows the built-in of its name, `builtin` (glyph set) is never searched. The working directory is no longer searched by any of them. In the engine checkout the shipped looks are now read from `<root>/styles/*.look.toml` by the walk (the same text `include_str!` compiled in)
