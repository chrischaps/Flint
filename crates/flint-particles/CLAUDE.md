# flint-particles: particle effects (moved out of the root CLAUDE.md by #755)

The particle draw gotcha: `crates/flint-render/CLAUDE.md`. The effect editor and `--particle-time`: `crates/flint-cli/CLAUDE.md`.

- **Particles** -- inline `particle_emitter` or reusable `particles/*.particles.toml` effects via `particle_effect` (multi-emitter, curves, forces, bursts, sub-emitters; ADR 0068). Deterministic: per-emitter seeds from entity *names*, fixed-step `simulate_to`, `flint render --particle-time`. One shared `ParticleInstance` type; every consumer hands its `ParticleSync` to `SceneRenderer::prepare` as `FrameInputs::particles` after `ParticleSystem::pack` (#739). Scripts: `play_effect`/`stop_effect`/`set_effect_param`. F3 Particles panel in the player; F4 Particles section in the viewer
- **An inline emitter is never silently the default one** (#690) -- `EmitterConfig::from_toml(table) -> Result<_, EmitterProblem>`; `EmitterProblem { key, message, unknown, hint }` displays as `key: message (hint)`, the key coming from the `in` line serde adds and from `resolve_keyed` (`bursts[1]`, `lifetime` or `lifetime_max`). `ParticleSync::sync_from_world` warns by entity name (`inline_config`) and keeps the instance's config on a bad edit, or makes no instance (`rejected`, keyed by the table's fingerprint, so said once) when the table is bad when first seen; unknown keys warn and the rest applies. `EmitterDef::known_keys()` and `ParticleEffect`'s top-level keys are the serde derive's own field names (`effect::field_names::of::<T>()`, a deserializer that records what `deserialize_struct` is handed), never a hand-kept list; `known_keys_are_the_structs_fields` also holds `schemas/components/particle_emitter.toml` to the struct both ways (every field a key the struct reads, every key a field, #1051) and its defaults to the reader: the table of every schema `default` resolves as the empty table does. `EmitterDef::problems(table)` is what `flint check` / `flint validate` report as `bad-emitter` (`crates/flint-cli/src/check/scene.rs::particle_emitters`, which drops the schema pass's `unknown-field` / `bad-type` / `bad-enum-value` on the component, so a mistake is said once, in the reader's words)
- **The schema's defaults never outvote a modern key** (#1051) -- the loader writes each schema `default` into an emitter that leaves the key out, so a legacy key the reader only consults when written (`rotation_min`/`_max`, `angular_velocity_min`/`_max`, `shape_radius`) has none; the many-form keys (`lifetime`, `size`, `shape`, ...) are `type = "any"`, declared so a load says nothing about them. `tests/inline_component.rs` runs emitters through `load_scene_string` with the engine's schemas: a modern emitter loads without a word, and each plays as it reads written
- **Effects come through the one asset resolver** (ADR 0114 step 3, #706) -- `load_particle_effects_from_world(&project, scene_path, &mut system)` loads `project.list(AssetKind::Particles, scene_dir)`: every `*.particles.toml` in `particles/` beside the scene, beside each directory above it up to the project root, then under `<root>/engine/`, a nearer file hiding a farther one of the same stem. An effect is still registered under the `name` its file gives (the stem when it gives none); two visible files giving one name keep the nearer. The call also hands the sync its search (`ParticleSync::set_search`), so `missing_effect_report(name)` (the `particle_effect` warning in `sync_from_world`, and the player's `play_effect` warning) lists every path `project.resolve` tried, or names the file that is there but registered under another name. Callers pass the host's `Project`: the player's own (`PlayerApp::project()`, refreshed per scene), `Project::for_scene(scene)` in `flint render`, the viewer and tests. `load_visible_effects` is the same list with each load's result. An effect's `texture` is a resolver kind too (`AssetKind::ParticleTextures`: `particles/<file>`, then `<file>` beside the scene, level by level): hosts call `flint_render::load_scene_particle_textures(renderer, device, queue, &sync, &project, scene_dir)`, and `texture_search_dirs` / `resolve_particles_dir` are gone (`load_particle_textures` with a list of directories remains for the effect editor's own layout). Sub-emitters name emitters inside their own effect, so nothing crosses files. The effect editor opens a file by path and searches nothing
- **Motion on twos for emitters** (#873) -- an emitter on an entity under a `motion_hold` (its own, an ancestor's or the whole frame's) emits from where its carrier was drawn when the tick began, once the host stamps `ParticleSync::set_motion_time` (and `set_motion_hold` for the whole-frame rate); unstamped, nothing is held. Particles are born at the held point, velocity comes from the live world, and live particles move smoothly. Detail: the Motion on twos bullet in `crates/flint-render/CLAUDE.md`
