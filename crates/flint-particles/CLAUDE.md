# flint-particles: particle effects (moved out of the root CLAUDE.md by #755)

The particle draw gotcha: `crates/flint-render/CLAUDE.md`. The effect editor and `--particle-time`: `crates/flint-cli/CLAUDE.md`.

- **Particles** -- inline `particle_emitter` or reusable `particles/*.particles.toml` effects via `particle_effect` (multi-emitter, curves, forces, bursts, sub-emitters; ADR 0068). Deterministic: per-emitter seeds from entity *names*, fixed-step `simulate_to`, `flint render --particle-time`. One shared `ParticleInstance` type; every consumer uploads through `SceneRenderer::update_particles_from` after `ParticleSystem::pack`. Scripts: `play_effect`/`stop_effect`/`set_effect_param`. F3 Particles panel in the player; F4 Particles section in the viewer
- **Effects come through the one asset resolver** (ADR 0114 step 3, #706) -- `load_particle_effects_from_world(&project, scene_path, &mut system)` loads `project.list(AssetKind::Particles, scene_dir)`: every `*.particles.toml` in `particles/` beside the scene, beside each directory above it up to the project root, then under `<root>/engine/`, a nearer file hiding a farther one of the same stem. An effect is still registered under the `name` its file gives (the stem when it gives none); two visible files giving one name keep the nearer. The call also hands the sync its search (`ParticleSync::set_search`), so `missing_effect_report(name)` (the `particle_effect` warning in `sync_from_world`, and the player's `play_effect` warning) lists every path `project.resolve` tried, or names the file that is there but registered under another name. Callers pass the host's `Project`: the player's own (`PlayerApp::project()`, refreshed per scene), `Project::for_scene(scene)` in `flint render`, the viewer and tests. `load_visible_effects` is the same list with each load's result. An effect's `texture` is a resolver kind too (`AssetKind::ParticleTextures`: `particles/<file>`, then `<file>` beside the scene, level by level): hosts call `flint_render::load_scene_particle_textures(renderer, device, queue, &sync, &project, scene_dir)`, and `texture_search_dirs` / `resolve_particles_dir` are gone (`load_particle_textures` with a list of directories remains for the effect editor's own layout). Sub-emitters name emitters inside their own effect, so nothing crosses files. The effect editor opens a file by path and searches nothing
- **Motion on twos for emitters** (#873) -- an emitter on an entity under a `motion_hold` (its own, an ancestor's or the whole frame's) emits from where its carrier was drawn when the tick began, once the host stamps `ParticleSync::set_motion_time` (and `set_motion_hold` for the whole-frame rate); unstamped, nothing is held. Particles are born at the held point, velocity comes from the live world, and live particles move smoothly. Detail: the Motion on twos bullet in `crates/flint-render/CLAUDE.md`
