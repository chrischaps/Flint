# flint-script: Rhai scripting detail (moved out of the root CLAUDE.md by #755)

The root file keeps the callback list and the Rhai version gotcha. Script UI drawing: `crates/flint-player/CLAUDE.md`. Style functions (`set_entity_style`, `set_post_style`): `crates/flint-render/src/stylize/CLAUDE.md`.

- **Scripts come through the one asset resolver** (ADR 0114 step 3, #706) -- `ScriptSystem::load_scripts_from_scene(scene_path, &project)` gives `ScriptSync` a search (`set_search(project, scene_dir)`), not a directory: each `script.source` is `project.explain(AssetKind::Scripts, source, scene_dir)` (`ScriptSync::locate`), so a `scripts/` beside the scene no longer hides the project's, and a miss warns with every path tried. `import "m"` is the script `lib/m.rhai` by the same search (`ModuleBase::Project` in `module_resolver.rs`; `ModuleBase::Dir` is the one-folder form `set_scripts_dir`/`set_module_base` keep for tests and hosts with their own layout). Hot reload follows it: each script keeps the file it loaded and the nearer paths it wasn't found at (`Located`), and a poll that sees one of those appear (`file_watch::stamp`) re-locates and reloads from the nearer file; `lib_dirs()` is every `scripts/lib/` in the search, all of them scanned (`scan_libs`), so a nearer module appearing resets the module cache like any lib change. A chunk's scripts go through `load_script_named(id, source, chunk_dir)` (`locate_for`), searched from the chunk's folder then the scene's; `load_script_for_entity(id, path)` still loads a path as given and is not watched by name. Not on the resolver: `load_ui` / `load_data`, which join a path to `project_root_for` (the scene directory's parent; one of the root guesses #726 replaces). `load_ui` / `load_data` paths are from the project root: `ScriptSystem::set_current_scene(path, &project)` hands the project in and `ScriptCallContext::project_root_holding(what, rel)` is the root to join (`Project::root_holding`, which for one release still reads a file that is only at the old guessed place); `api::project_root_for` is gone
- **Scripting via Rhai** -- `script` component with `.rhai` files in `scripts/`; callbacks: `on_init`, `on_update`, `on_collision`, `on_trigger_enter/exit`, `on_action`, `on_interact`, `on_draw_ui`, `on_scene_exit/enter`, `on_animation_end`, `on_sequence_cue`, `on_event` (custom events from `fire_event_data`, the engine or `ExtensionCtx::fire_event`), `on_persist_migrate(from)` (save data loaded at a version below `[project] save_version`; `ScriptEngine::migrate_persistent_store`, run by `ScriptSystem::initialize` and `update` after scripts load and before `on_init`, only inside a state scope, and only when a loaded script defines it, else the data stays pending; #726), `on_expression(state)` (state from outside the process: `--expression-timeline <file>` on the game clock or `--expression-listen 127.0.0.1:<port>`, newline-delimited JSON read off the frame thread, loopback only; `expression()` reads the latest, any JSON object as a map with float numbers; `player_app/expression_feed.rs`, #518); `ScriptCommand` for deferred effects; `quit_game()` ends the run as the close button does (exit 0, saves flushed, `--exit-after`'s report; on the web the page's `window.flintQuit` leaves full screen and goes back to its game list, #659); `DrawCommand` for immediate-mode 2D UI; `set_scale`/`get_scale`, and `set_visible`/`is_visible` over a `visibility { visible }` component that hides an entity's subtree from every draw, shadow, light and ray target (`FlintWorld::hidden_entities`, empty and unwalked when nothing is hidden; #628). An entity setter given `-1` or a gone id warns once per script and function (`ScriptCallContext::setter_target`, #635); a declared function takes it as an `Entity` argument, which does the same for getters too (below). Book's scripting page, "Script state": top-level `let`s reach callbacks, not helper `fn`s
- `ScriptCallContext` holds raw pointers (world, physics, state machine, persistent store), set only for a host's call scope (`WorldScope`, `StateScope`); the only way to them is `try_world`/`try_world_mut`/`try_physics`/`try_state_machine(_mut)`/`try_persistent_store(_mut)`, `None` outside the scope. `unsafe` is in `context.rs` alone (`layout_tests::unsafe_lives_in_context_rs_alone` holds it, and `no_source_file_is_over_1500_lines` the crate's file sizes). `engine/` is split by seam (#697): `mod.rs` the engine (setup, compiling, the script table, module search, timing, drains), `instance.rs` one loaded script, `callbacks.rs` calling the callbacks, `interact.rs` the nearest interactable; tests sit beside what they test (`engine/tests.rs`, `engine/hot_reload_tests.rs`, `api/entity_tests.rs`, `api/conducted_tests.rs`, `api/host_io_tests.rs`, helpers in `engine/test_support.rs`)
- `on_update()` is parameterless -- use `delta_time()` API; `on_interact` checks `interactable.range` + `.enabled`
- `on_draw_ui()` ALWAYS runs even when scripts paused (pause menus need it)
- `random()` / `random_range()` / `seed_random(n)` (#580) are one SplitMix64 per engine, `random::ScriptRandom`, seeded from the clock once in `ScriptEngine::new`; `ScriptSystem::seed_random` (the player's `--seed` / `--frame-step`, `flint render --scripts`) reseeds that same state, so one seed gives one sequence however it arrives. Top-level statements run again before every callback, so a script seeds in `on_init`, never at the top

## The declared API (ADR 0116): how to add a function

A new function is declared through the builder in `src/api/builder.rs`, in its module's file under `src/api/` (`entity.rs` is the pattern). Every engine function is declared (ADR 0116 step 2, #695): `api.rs` is the module list and `register_all`, and `flint script api --json` counts 0 undeclared. The modules: `entity`, `input`, `time` (with a deterministic run's `timestamp()`, `api::forbid_wall_clock`), `audio`, `animation`, `physics` + `physics_2d` (`physics.rs`, with `move_character` and `get_collider_extents`), `camera`, `post_process`, `quality`, `math` (with `random.rs`'s three), `event`, `log`, `draw` (the 2D draw calls, clip and over-UI stacks, `screen_width`/`height`, `measure_text*`), `draw_world` (`draw_line_3d*`, `draw_world_line`/`text`), `view` (`world_to_screen`, `screen_to_*`, `ground_height`, `raycast_meshes`), `ui` (data-driven UI), `screen_ui`, `sprite` (with the sprite animator), `camera_2d` (the follow/shake integrator is `follow_step`/`advance_shake`), `touch`, `style` (entity and whole-frame styles, looks, the style readers), `particle`, `spline` (the sampling is `closest_point`/`gap_at`/`sample_at` over the `spline_data` table), `ocean` (the module owns the spectrum cache), `terrain`, `chunk`, `scene`, `state`, `persistence`, `data` (`data::load_data`), `expression`, and three a subsystem owns, named for #698 to gate: `wooze`, `living` (Living Props' knobs and presets), `conducted` (the music session), and `debug` (the Living Props A/B and `commit_living`, the panel's actions). `opts.rs` holds the draw modules' shared helpers (the opts-map reader `Opts::read` / `read_opts`, `TextOpts`, `world_text_from_opts`, `measure_text_with`); `convert.rs` the TOML conversions (`toml_to_dynamic`, `dynamic_to_toml`, `map_to_toml`). Only a game extension's raw `rhai_engine_mut()` registration is undeclared. A declaration:

```rust
let mut m = api.module("entity");
m.func("set_position", "Move the entity to a position in its parent's space.")
    .arg("id", Entity).arg("x", Num).arg("y", Num).arg("z", Num)
    .run(|call, (id, x, y, z)| {
        if let Some(comps) = call.world_mut()?.get_components_mut(id) { /* ... */ }
        Ok(())
    });
```

- **The doc is one line and required** (`declared_tests.rs` fails on an empty one). `.returns(kind, "shape in words")` says what comes back (a map's keys, `-1` on failure); none means `()`.
- **Kinds** (`builder::kind`): `Num` (int or float, as `f64`), `Int` (an int or a whole float), `Bool`, `Entity` (a live `EntityId`), `MaybeEntity` (`Option<EntityId>`, no warning: for `entity_exists`), `Str` (`ImmutableString`), `Map`, `Array`, `Color` (`[r,g,b(,a)]` or `"#rrggbb(aa)"`, as `[f32; 4]`), `Any` (`Dynamic`), `Fn` (`FnPtr`). Up to 14 parameters. An argument that doesn't convert is a script error naming the function, the parameter and the kind, at the call's line.
- **A kind that takes its argument (`Str`, `Map`, `Array`, `Any`, `Fn`: `Kind::TAKES`) converts the first one from a copy.** Rhai hands a raw function its first argument by reference when the script passed a variable there, so `mem::take` on it emptied the script's variable: `let s = "hp"; measure_text(s, 16.0); draw_text(.., s, ..)` drew `()` (`showcase_hud.rhai`, 121 errors a capture). The other arguments are temporaries and are still taken. A new taking kind sets `TAKES`; `declared_tests::a_variable_passed_first_is_left_as_it_was` holds it
- **`Entity` warns once and skips**: `-1` or a gone id never reaches the body; the call returns the return type's empty value (`#{}`, `()`, `0`, `false`, `""`) or `.or_return(v)` (`get_parent` gives `-1`, `distance` `f64::MAX`), and warns once per script and function (`ScriptCallContext::entity_target`, #635/#701). For every function, getters included. With no world in scope (a script's top level at load) it skips silently, as `setter_target` always did.
- **The "missing" convention** (#701), also `registry::CONVENTIONS`, which `flint script api` prints above the functions: an `Entity` argument that names nothing skips the body and warns once; a setter or command then does nothing and **queues nothing** (a command carries an `EntityId` the builder resolved, never a raw `i64`: `SetVelocity2D { entity }`); a getter returns its return type's empty value (`()` for a `Dynamic` map-or-unit, `#{}`, `[]`, `false`, `0`, `""`) unless `.or_return` names a sentinel (`-1` an id, `-1.0` a time: `audio_position`; `f64::MAX` `distance`). A query that finds nothing for a live entity (no hit, no component, no body, no physics) returns `()` where the answer is a map or value, `-1` for an id, `-1.0` for a time; the entity module's transform getters return `#{}` (kept from before). Say which in `.returns(kind, note)`. `declared_tests::every_function_taking_an_entity_warns_once_on_a_dead_id` calls every registry entry with an `entity` parameter at `-1` and at a despawned id, so a new one is covered by being declared (it needs a sample value for any new kind: `sample()`).
- **A name Rhai already has** (`log`, `abs`, `min`, `sin`, `PI`...): Rhai tries a call's exact types in every module, its packages too, before any `Dynamic` signature, and this engine's own functions before its packages. The `Num` twin (all floats) therefore wins for float calls, an all-int `abs`/`min`/`max` still reaches Rhai's integer one (an int back, as before), and `Dynamic` catches the rest (`sin(1)`). Where a built-in's exact types must reach yours, `.also_exact(&[TypeId::of::<rhai::FLOAT>()])` registers the body under them too: `log(3.5)` logs, where Rhai's base-10 `log(FLOAT)` used to win (the logarithm is `log(x, 10.0)`).
- **One arity, two shapes**: overloads that differed only by a parameter's type become one function with an `Any` parameter the body tells apart, erroring with `call.error(..)` otherwise (`play_sound_at`'s fifth: a volume or an options map).
- **The world only through `call`**: `call.world()?` / `call.world_mut()?` (a script error when there is none, not a panic), `call.physics()`, `call.ctx()` for the rest of `ScriptCallContext`, `call.entity(id)` for an id inside a map. No `unsafe` in a declared function: the pointers are `context.rs`'s (`try_world`, `try_world_mut`, `try_physics`). The body returns a value or `CallResult<value>`.
- **Overloads by arity**: declare each arity (`set_material_emissive` has 5 and 6). Two of the same arity are one function now that kinds convert.
- **`.run()` registers twice, or three times**: an exact-typed twin (floats for `Num`, ints for `Entity`) that Rhai finds on its first lookup, and an all-`Dynamic` one for every other mix; a function with four or more `Num` parameters (`INT_COPY_MIN_NUMS`) also gets an all-int copy (ints for `Num`, the twin's types for the rest), automatically, so `draw_rect(10, 10, 100, 50, 1, 1, 1, 1)` is an exact lookup too (ADR 0116, Decisions, 2026-11-11). `.without_int_copy()` (doc-hidden) is for the harness only. Measured (docs/design/script-api-overhead.md): as fast as a typed closure for float calls. An int in a `Num` slot of a function under four `Num`s, or a call mixing ints and floats, is found by Rhai's search over the `Dynamic` mixes (2^n hashes for n parameters), which Rhai caches per block: free when the callback made any native call before the loop, ~4 us a call for 8 arguments when the loop's call is the callback's first. `.run_typed()` registers on Rhai's typed path only (`Num` is then float-only, listed as `float`): the escape hatch, for a hot function where that matters.
- **`.run_pure(|(a, b)| ...)` for a function of its arguments alone** (the math module, `random*`): the same registrations and registry entry as `.run()`, but the body gets no `call`, so nothing locks the `ScriptCallContext` (`.run()` locks it for every call, even a body that never touches it). Its kinds must be `PureKind`s: anything but `Entity` / `MaybeEntity`. Use it for anything pure and likely called in a loop; measured in docs/design/script-api-overhead.md ("Pure functions").
- **Names and opts maps** (#702, `registry::CONVENTIONS` `names` and `opts_maps`, the book's "Names and opts maps"): verb first (`play_sprite`, `shake_camera`); `get_<noun>`/`set_<noun>` with one noun for what a script can change, no `get_` for what nothing sets (`mouse_x`, `delta_time`, `screen_width`) or a calculation (`distance`); a module-owned family keeps its prefix (`persist_`, `ui_`, `spline_`, `conducted_`); no aliases, no `_ex`. A rename is a loop: `for (name, old) in [("get_lod_scale", None), ("lod_scale", Some("use get_lod_scale"))] { m.func(name, ..).deprecated(old).run(..) }`, one body, the old name for one release (`naming_tests::RENAMES` lists them; a test holds each old name deprecated, same params and returns). A draw primitive is two overloads of one name: what places it plus `r, g, b, a`, and what places it plus an `opts` map (`MapKind` last), read by `opts::read_opts(call.ctx(), "fn", &map, KEYS)`: `KEYS` is the function's list, a key not in it or of the wrong shape warns once per function and key (`ScriptCallContext::opts_warned`) and is ignored; colours go through the `Color` kind's parser (`[r,g,b(,a)]` or hex). A new key is a field on `Opts`, an arm in `Opts::take` and a line in `wants`. A map costs 0.15 to 0.22 us a call over the positional form (docs/design/script-api-overhead.md, `--opts`)
- **Then regenerate the book**: `cargo run --bin flint -- script api --book` rewrites `docs/book/src/reference/script-api.md` (and the scripting chapter's tables) from the declarations; commit it with the function. CI's headless job runs `--check-book` and fails a PR whose page is stale, or whose chapters call a function at an arity it isn't declared at (a renamed or re-shaped function's old calls in the book). A new module shows up on the reference page by itself; a chapter table names its module (`module:x`) or functions in its `script-api:begin` comment.
- **Registry**: `ScriptEngine::api_registry()`, `ScriptSystem::api_listing()` (declared + undeclared + callbacks; the undeclared part needs the `metadata` feature, which flint-cli turns on). Native only: on wasm `ApiRegistry` is empty and the builder drops docs and return notes (param names stay, for the errors). `ScriptSystem::script_api()` / `PlayerExtension::declare_script_api` let a host or game declare into the same registry; `rhai_engine_mut()` still works and lists as undeclared. The callbacks' docs are `registry::CALLBACKS` (a test holds them to `CALLBACK_ARITIES`).
- `api::overhead` (doc-hidden) holds the measurement's subjects; `cargo run --release -p flint-script --example api_overhead` reruns it.
- **`flint script check` is `check.rs`** (#694, the `check` feature: `metadata` + Rhai's `internals`, native tools only). `Api::of(&mut ScriptSystem)` is what a call may name (the listing, an extension's raw registrations, Rhai's packages from `gen_fn_signatures`; `allow`/`add` for a game's own), `Checker::check(Vec<ScriptFile>)` compiles each file with `engine::compiler()` (optimizer off), follows its imports through `ModuleBase`, and returns `Diagnostic`s with `line`/`column`; `check_source` checks a string. Callbacks are judged from `registry::CALLBACKS`. A game binary can check its own scripts with `Api::of(&mut app.core.script)`. `.deprecated("use x")` on a `Func` (ADR 0116 decision 3) marks the entry (`ApiEntry::deprecated`), which `flint script api` lists, the book's reference page marks (chapter tables leave it out) and the checker warns at; `.deprecated(None)` marks nothing, for a loop declaring a name and its old one. The CLI side and the rules: `crates/flint-cli/CLAUDE.md`

## Commands and the one host interface (ADR 0116 decision 4, #697)

A script function that affects anything but the world it is lent (a sound, a style, a scene change, the camera) queues a `ScriptCommand` (`context.rs`). A host drains them (`ScriptSystem::drain_commands`) and hands them to `host::apply` / `apply_all` (`host.rs`), **the one `match` over `ScriptCommand`**: each variant becomes a call to its `ScriptHost` method. Every method has a default that calls `unsupported(command)` (warns once per host and command; a host with its own record overrides it), except `log`, which every host can do. The hosts: the player (`impl ScriptHost for PlayerApp`, `flint-player/src/player_app/script_commands.rs`) and a headless capture (`HeadlessHost` in `headless_scripts.rs`, what `flint render --scripts` runs). There are no `take_*` channels: what a frame keeps one value of (the camera, post-processing overrides, fog colour, render mode, time scale, low-pass, touch controls, distance scales, cursor, quality) lives in `ScriptCallContext::requests` (`FrameRequests`), where the last call in a frame wins and `apply_camera_shake` / `get_lod_scale()` read it back, and `take_commands` turns it into commands (`SetCamera`, `SetPostProcess`, `SetFogColor`, `SetRenderMode`, `SetTimeScale`, `SetAudioLowpass`, `SetTouchControls`, `SetLodScales`, `SetCursorCaptured`, `SetQuality`) after the queued ones, one each for what was asked. A command carries a resolved `EntityId`, never a raw id (the `Entity` kind skips the call before anything is queued, #701).

**Adding a command** is a variant, a registration and a host method:

1. **The variant**, on `ScriptCommand` in `context.rs`, with a doc line naming the script function. Ids are `EntityId`s from an `Entity` argument.
2. **The registration**: the declared function in its `api/<module>.rs` that pushes it, `call.ctx().commands.push(ScriptCommand::X { .. })` (or a field on `FrameRequests` and a line in `take_commands`, for a one-value-a-frame setting).
3. **The host method**: a method on `ScriptHost` in `host.rs` named for the script function, defaulting to `self.unsupported("fn_name")`, and its arm in `host::apply` (the compiler refuses the match without it).

Then each host that can do it overrides the method: the player always (`script_commands.rs`); a headless capture if it changes the picture or the world, else its name goes on `flint_player::PRESENTATION_ONLY` (`headless_scripts.rs`) with why. `headless_host_tests::every_command_is_applied_headless_or_presentation_only` reads the variants from `context.rs`, so it fails until the new one has a sample in `one_of_each` and is one or the other. Regenerate the book (`flint script api --book`) for the function. Walked through with `set_camera_cut_detection`: `ScriptCommand::SetCameraCutDetection` (context.rs), the function in `api/style.rs`, `ScriptHost::set_camera_cut_detection` and its arm (host.rs), the player's method (script_commands.rs), and `PRESENTATION_ONLY` (a capture has no cut detection), and nowhere else.

**When the player applies them**: it drains twice a frame (`PlayerApp::dispatch_script_commands`): after the fixed physics steps, for what `on_update` (and the last frame's late callbacks) asked, so a camera a script set is the one `on_draw_ui` and the frame see; then after `on_draw_ui`, for what it asked. Style tweens step just before the first drain, so a tween asked for this frame starts moving the next. The player holds the one-value settings in `script_requests` until the step of the frame that applies each (camera before `on_draw_ui`, post-processing and quality before the draw, low-pass, touch, distance levers and cursor at the frame's end), as the old channels were read.
