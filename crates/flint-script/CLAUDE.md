# flint-script: Rhai scripting detail (moved out of the root CLAUDE.md by #755)

The root file keeps the callback list and the Rhai version gotcha. Script UI drawing: `crates/flint-player/CLAUDE.md`. Style functions (`set_entity_style`, `set_post_style`): `crates/flint-render/src/stylize/CLAUDE.md`.

- **Scripts come through the one asset resolver** (ADR 0114 step 3, #706) -- `ScriptSystem::load_scripts_from_scene(scene_path, &project)` gives `ScriptSync` a search (`set_search(project, scene_dir)`), not a directory: each `script.source` is `project.explain(AssetKind::Scripts, source, scene_dir)` (`ScriptSync::locate`), so a `scripts/` beside the scene no longer hides the project's, and a miss warns with every path tried. `import "m"` is the script `lib/m.rhai` by the same search (`ModuleBase::Project` in `module_resolver.rs`; `ModuleBase::Dir` is the one-folder form `set_scripts_dir`/`set_module_base` keep for tests and hosts with their own layout). Hot reload follows it: each script keeps the file it loaded and the nearer paths it wasn't found at (`Located`), and a poll that sees one of those appear (`file_watch::stamp`) re-locates and reloads from the nearer file; `lib_dirs()` is every `scripts/lib/` in the search, all of them scanned (`scan_dirs`), so a nearer module appearing resets the module cache like any lib change. The folders are worked out once, when the search is set (`ScriptSync::set`), never in a poll: `search_dirs` stats the disk (each level's `same_dir_key`, the engine mount), which cost every frame 0.2-0.3 ms and a busy disk's frame up to 35 ms (#1122). A poll's every question about a file goes through `file_watch`; `hot_reload_tests::a_poll_asks_the_disk_only_through_file_watch` counts the vfs calls ten polls make (none). The poll's steps are scopes: `script::poll_take_finished`, `poll_failed_at_load`, `poll_scan_libs`, `poll_each_script`. A chunk's scripts go through `load_script_named(id, source, chunk_dir)` (`locate_for`), searched from the chunk's folder then the scene's; `load_script_for_entity(id, path)` still loads a path as given and is not watched by name. Not on the resolver: `load_ui` / `load_data`, which join a path to `project_root_for` (the scene directory's parent; one of the root guesses #726 replaces). `load_ui` / `load_data` paths are from the project root: `ScriptSystem::set_current_scene(path, &project)` hands the project in and `ScriptCallContext::project_root_holding(what, rel)` is the root to join (`Project::root_holding`, which for one release still reads a file that is only at the old guessed place); `api::project_root_for` is gone
- **Scripting via Rhai** -- `script` component with `.rhai` files in `scripts/`; callbacks: `on_init`, `on_update`, `on_collision`, `on_trigger_enter/exit`, `on_action`, `on_interact`, `on_draw_ui`, `on_scene_exit/enter`, `on_animation_end`, `on_sequence_cue`, `on_event` (custom events from `fire_event_data`, the engine or `ExtensionCtx::fire_event`), `on_persist_migrate(from)` (save data loaded at a version below `[project] save_version`; `ScriptEngine::migrate_persistent_store`, run by `ScriptSystem::initialize` and `update` after scripts load and before `on_init`, only inside a state scope, and only when a loaded script defines it, else the data stays pending; #726), `on_expression(state)` (state from outside the process: `--expression-timeline <file>` on the game clock or `--expression-listen 127.0.0.1:<port>`, newline-delimited JSON read off the frame thread, loopback only; `expression()` reads the latest, any JSON object as a map with float numbers; `player_app/expression_feed.rs`, #518); `ScriptCommand` for deferred effects; `quit_game()` ends the run as the close button does (exit 0, saves flushed, `--exit-after`'s report; on the web the page's `window.flintQuit` leaves full screen and goes back to its game list, #659); `DrawCommand` for immediate-mode 2D UI; `set_scale`/`get_scale`, and `set_visible`/`is_visible` over a `visibility { visible }` component that hides an entity's subtree from every draw, shadow, light and ray target (`FlintWorld::hidden_entities`, empty and unwalked when nothing is hidden; #628). An entity setter given `-1` or a gone id warns once per script and function (`ScriptCallContext::setter_target`, #635); a declared function takes it as an `Entity` argument, which does the same for getters too (below). Book's scripting page, "Script state": top-level `let`s reach callbacks, not helper `fn`s
- `ScriptCallContext` holds raw pointers (world, physics, state machine, persistent store), set only for a host's call scope (`WorldScope`, `StateScope`); the only way to them is `try_world`/`try_world_mut`/`try_physics`/`try_state_machine(_mut)`/`try_persistent_store(_mut)`, `None` outside the scope. `unsafe` is in `context.rs` alone (`layout_tests::unsafe_lives_in_context_rs_alone` holds it, and `no_source_file_is_over_1500_lines` the crate's file sizes). `engine/` is split by seam (#697): `mod.rs` the engine (setup, compiling, the script table, module search, timing, drains), `instance.rs` one loaded script, `callbacks.rs` calling the callbacks, `interact.rs` the nearest interactable; tests sit beside what they test (`engine/tests.rs`, `engine/hot_reload_tests.rs`, `api/entity_tests.rs`, `api/conducted_tests.rs`, `api/host_io_tests.rs`, helpers in `engine/test_support.rs`)
- **Every callback goes through `ScriptEngine::call(entity, callback, args)`** (`engine/callbacks.rs`, #693): it sets `current_entity`, calls `call_fn`, and records a failure in `ScriptEngine::errors` (`errors.rs`, `ScriptErrors`); never a `call_fn` with its own `warn!` (a test-free rule: `grep call_fn` finds one). It is also where every callback is timed (#703): with `set_timing(true)` (the player's `--perf` / `?perf=1`) each call adds to `<source>:<callback>` (`scripts/hud.rhai:on_draw_ui`), and `ScriptSystem::take_times` drains them (the player takes after every phase, so `on_draw_ui` lands in its own frame); `[hot reload]` and `[load]` are the system's own steps, less the callbacks inside them (`engine/output.rs`, `Times`). `ScriptEngine::enter(entity)` is the one place `current_entity` is set (`call`, `lend`, `reload_script`), and it sets `ScriptCallContext::speaker` too. `Failure::eval` takes the innermost error's message and position (walking `ErrorInFunctionCall`, whose name, when not the callback, is `function`, and whose source, when set, is an imported module's file); `Failure::compile` splits Rhai's ` (line N, position M)` off a `ParseError`'s text; `Failure::load` is a script the search didn't find. One `ScriptError` per (file, callback, line, message), with `count`, `first_frame`/`last_frame` (`next_frame` at the top of `ScriptSystem::update`; 0 is load and `on_init`), `entity_name` and `also_on`, `current` (false after `file_reloaded` or `scene_cleared`). Logged on the first (`[script] {location}: {entity}, {callback}: {message}`) and at 10, 100, 1000..., except a call into a module that isn't enabled (#856): `builder::not_enabled` tags its text's `Dynamic` with `errors::ONCE_A_SCENE`, `Failure::eval` reads the tag into `once_a_scene`, and `record` logs such an entry only when it becomes `current` (new, or after `scene_cleared` / `file_reloaded`), never at a count; `ScriptErrors::lines_logged()` (doc-hidden) is what tests read; `MAX_KEPT` 64 distinct, the rest counted. Callbacks named `load`, `compile`, `top level` (`add_named_script` names the entity and file before the top level runs). A script that didn't compile at load is kept in `ScriptSync::failed_at_load` and discovered afresh when its file's mtime moves. Hosts: `ScriptSystem::errors()`; `on_screen()` is the player's card, `summary()` the end-of-run lines, `strict_failure()` `--strict-scripts`' message, `merge` folds sweep cells. Tests: `errors::tests`, `engine/error_tests.rs`
- **Time inside a script, by function** (#1100; `fn_times.rs`, tests `engine/fn_time_tests.rs`) -- while a callback is timed or `profile::recording()`, `ScriptEngine::call` brackets it with `fn_times::begin(trace)` / `end(&mut fn_took)` (a per-thread sink; a call nested in another's call is the outer's) and every function it calls is counted: calls, total and worst ms (outermost calls only, so a recursion isn't counted twice). In the trace (sites interned by `fn_times::id_of`, made on the first traced call) a script function's call is a `profile::Scope` nested under the callback's `<source>:<callback>` scope, and **an engine function's calls are summed** (#1288): each is a `profile::Call` (a level, no record), folded into the innermost traced scope's `Sink::summed` frame, and flushed as one `profile::record_calls` record a function when that scope closes (`Open::drop` before the wrapper's scope drops; `fn_times::end` for the callback's, which `ScriptEngine::call` calls while `_named` is still open). A call that recorded anything inside it (an engine `scope!`, a call back into a script) is recorded as a scope of its own instead. Float made 800 records a frame, most of them per-call `get_field()`/`clamp()`, which wrapped the 5 s ring in 0.85 s. **Engine functions**: `register_converting` and `register_typed` in `api/builder.rs` wrap every declared body with `fn_times::enter_engine(engine_fn(name))` (script functions' wrappers call `enter`), `name()` for all its overloads; off, a thread-local flag read (an extension's raw `rhai_engine_mut()` registration and Rhai's own functions, `timestamp`, `elapsed`, aren't timed). **Script functions**: no Rhai hook short of its debugger (a callback on every node). Instead a profiled call runs on `ScriptInstance::profiled` (`make_profiled`, made from `calls` on first need, reset with it in `top_level_ran`): each `fn f(a, b)` is a wrapper compiled from text, `let __flint_fn_timer = __flint_fn_enter(<id>); __flint_fn_<id>(a, b)`, beside the original renamed `__flint_fn_<id>`; the guard (`FnGuard`, a `Dynamic` whose clone is inert) closes when Rhai rewinds the wrapper's scope (a return, an error and the end alike). Never splice a statement into a parsed body: Rhai resolves a variable to its slot counted from the scope's end at parse time, so a `let` at the top made every parameter read the guard. Not wrapped: callbacks, functions with a `this` type or reading `this`, closures (`anon$`: Rhai 1.24 keeps a closure's def in the expression that makes it), module functions. A profiled call runs with twice `max_call_levels` (a wrapper is a level), so a recursion fails at the same depth (`a_recursion_fails_at_the_depth_it_would_untimed`). `Failure::eval` skips `fn_times::is_inner` names, so an error names the user's function. `__flint_fn_enter` is left out of `api_listing`'s undeclared. Out: `ScriptSystem::take_function_times() -> Vec<FnTime>` (`callback` label, `function`, `calls`, `total_ms`, `worst_ms`), taken with `take_times`; the player's `--perf` names each callback's slowest. Measured (release, `fn_time_tests::fn_call_cost`, `--ignored`): off, unchanged against main (script call 387-392 ns vs 391-398, engine call 246-250 vs 251-256, loop included); on, +45 ns an engine call, +0.48 us a script function call. Book: guides/profiling.md, Inside a script
- **A script's `print` and `debug` are the log's, never stdout** (#703, `engine/output.rs` `route_speech`): `tracing::info!` under target `script` with `file` and `entity` fields (`debug` adds `line`, or a module's own source). Every runtime message of the crate is `tracing`: `lib.rs` denies `clippy::print_stdout` and `print_stderr` outside `cfg(test)` (#1010), so `cargo clippy` fails on a `println!` or `eprintln!` in `src/`. The reload lines use target `script`, as `log()` does; each script's `Loaded:` line and `Script system initialized (n scripts)` are `debug` under target `load` (#716), which `flint`'s default filter shows and `RUST_LOG=warn` quiets. `flint`'s and `flint-player`'s default filters include `script=info`; `flint` writes its log to stderr. Tests: `engine/output_tests.rs`, `render_scripts_cli::a_script_print_never_reaches_the_json_report`, `render_scripts_cli::rust_log_quiets_the_script_load_lines`
- **The callback table is one** (#700) -- `flint_core::callbacks`'s `callbacks!` rows: each is the `Callback` variant, the `ON_*` name constant, the parameter names and the doc line, and `CALLBACKS` (book order) is what everything reads: `ScriptInstance::defines(Callback::X)` (a `[bool; Callback::COUNT]` set at load and reload by `instance::scan`), `flint script check`, `flint script api` and the book's table. A callback is defined only at the table's count; one at another count (no overload at the right one) is warned once a load and **never called**, and an `fn` one edit from a callback (`on_updte`, `onInit`) that the script doesn't call or name (`call("f")`, `Fn("f")`, `instance::names_function`) is warned "did you mean `on_update`?". The load warning and the checker are one finder, `instance::callback_problems`. Adding a callback: its row, then its dispatch in `engine/callbacks.rs` (`script.defines(Callback::X)`, `cb::ON_X`), then `flint script api --book`. Tests: `engine/callback_tests.rs`
- **`tween(entity, "component.field", target, seconds[, easing])`** (#734; `api/tween.rs`, `tween.rs`) -- eases any number or list of numbers a component holds on the engine's one `flint_core::tween::Tween`. The call checks the path (`FieldPath::parse`: `component.field`, deeper through tables), the easing and, with a world lent, `tween::endpoints` (the field exists and has the target's shape), each a script error at its line, then queues `ScriptCommand::Tween`. `FieldTweens` (no player deps) is owned by the player's `GameCore::field_tweens`: `start` (replaces a running tween of the field; no time sets it now and returns its `tween_done`), `step(world, dt)` beside the style tweens while scripts run, `clear` at a transition. A tween ends quietly when its field no longer holds what it last wrote (`set_field`, physics: anything else takes over) or its entity or component is gone; an integer field moves as a float and arrives as an integer when the target is whole. `TWEEN_DONE` (`"tween_done"`, `#{ entity, path }`). `tween_style_param` keeps its own path (style ranges, the scene table's fallback) on the same `Tween`. Example: `flint-examples/tween_lantern.scene.toml`
- **`set_post(key, value)` is every `[post_process]` key** (#853; `api/post_process.rs`) -- `PostProcessOverrides` (`context.rs`) is a map of `flint_schema::post_effects` keys to `PostValue`s, each checked when set (`set`: `post_effects::param(key)` then `PostParam::value_of`, by `PostParamMut::set`'s kind rules), so an unknown key is a script error from `post_effects::unknown_key` (an effect's name lists its keys, else a did-you-mean, then every key) and a wrong kind names the key; `flint script check` refuses a literal key that names nothing (`check.rs` `NAMED_ARGS`, `bad-argument`). Hosts write it with `headless_game::stamp_post` (`config.param_mut(key)` + `PostParamMut::put`). The old setters (`set_vignette` ... `set_tear_shape`) are deprecated bodies that `put` the same keys; `set_vignette(v)` also puts `vignette_enabled = v > 0.001`. `api/post_process_tests.rs` `OLD_AND_NEW` holds each against its `set_post` words. Remove them in the release after (the changelog fragment names it). `set_lod_scale` / `set_draw_distance_scale` are no post key and stay
- **UI documents are the one structured UI** (#731; `src/ui/`) -- `loader.rs` is strict: element keys (`ELEMENT_KEYS`, with the types each is for), types, anchors, `[ui]` keys, parents, `nav_*` targets, parent cycles, classes the style file lacks (`parse_document`), style properties and value shapes (`style::property_problem`) are all problems, each `<file>: element `id`: ...`, returned together; `UiSystem::load(path, root, owner) -> Result<i64, String>` and `load_ui` turns the `Err` into a script error (`call.error`). `check_document` / `check_document_at` are the same without loading (`flint check`'s `bad-ui`). Element order is the file's (`element_order` through `toml_edit`, since `toml::Table` sorts). Types `button`/`list`/`slider` (`element.rs`); a `list`'s `items` make buttons `<list>.<i>` right after it (`list_items`, `replace_items`). `layout.rs` sizes `text`/`button` with no width/height by `LayoutInputs::measurer` (the host's `TextMeasurer`, set through `ScriptSystem::set_text_measurer` -> `UiSystem::set_measurer`), styles each element by `element_style` (type defaults, class, its `focus`/`pressed`/`disabled` sub-tables from `Interaction::states`, overrides); controls advance a stack by their rect, older types by their class's `height` (kept so layouts that place children with runtime `y` keep their places); an `anchored` child is placed in its parent's content box and takes no room. `draw.rs` draws by type; visibility is the whole ancestor chain (`UiDocument::is_shown`). `focus.rs`: focus, spatial nav (centre to centre, `along + 2 * across`), list steps with wrap, slider steps, hover/click/drag, touch press/tap/drag, `autofocus`; **a direction with nothing focused does nothing** (no stolen movement keys). `UiInput::from_snapshot` reads the `ui_*` actions (`focus::UI_UP` ..., bound in `flint_runtime::InputConfig::built_in_defaults`, never Escape: #639) with a held direction's repeat. Routing runs first in `ScriptEngine::call_draw_uis` (paused or not), then `on_ui(element_id, event)` goes to the document's owner (the `current_entity` at `load_ui`; every `on_ui` script when none), up to four rounds a frame. A state change during routing sets `restyle`; the next draw or rect lays out again. Tests: `ui/focus_tests.rs`, `ui/tests.rs`, `engine/ui_tests.rs` (the showcase's real pause menu through Rhai). `scripts/lib/menu.rhai` at the engine root is the helper module (`import "menu"`)
- **The style field** (#859; `api/style_field.rs`) -- `field_disc` / `field_ring` / `field_cone` (each with an optional `strength` last) push `flint_core::style_field::FieldShape`s into `ScriptCallContext::style_field`, converted from logical points (`screen_width`/`screen_height`) to screen uv and heights, angles from degrees clockwise from up. Immediate mode, not a command: the host takes the frame's with `ScriptSystem::drain_style_field()` once, after `on_draw_ui` (`script_ui_drawn`), and hands it to the renderer as `FrameInputs::style_field`. Past 16 shapes a frame the rest are dropped with one warning a run (`style_field_warned`). What follows it: `blend_source = "field"`, `crates/flint-render/src/stylize/CLAUDE.md`
- `on_update()` is parameterless -- use `delta_time()` API; `on_interact` checks `interactable.range` + `.enabled`
- `on_draw_ui()` ALWAYS runs even when scripts paused (pause menus need it)
- `random()` / `random_range()` / `seed_random(n)` (#580) are one SplitMix64 per engine, `random::ScriptRandom`, seeded from the clock once in `ScriptEngine::new`; `ScriptSystem::seed_random` (the player's `--seed` / `--frame-step`, `flint render --scripts`) reseeds that same state, so one seed gives one sequence however it arrives. A script may seed at its top level, which runs once (next bullet)
- **A script's top level runs once, with the world lent** (#692) -- `add_script` only stores the script (`top_level_pending`); its top-level statements run at the next `ScriptEngine::lend(world)`, which every callback batch in `callbacks.rs` starts with (never `WorldScope::new` there), in `in_order`, each with `current_entity` its own, so a top-level `get_entity("door")` finds the door and `self_entity()` is the script's entity. Callbacks are called on `ScriptInstance::calls` (`instance::callable`: the functions plus the top-level `import`s and one `const NAME = <value>` for each constant the script reads as `global::NAME`, needing Rhai's `internals`, now on in every build), never on `ast`: Rhai's `call_fn` runs an AST's statements first, which used to run a top-level `log` before each callback. The imports run again per call, which `VfsModuleResolver`'s `by_name` cache makes a lookup. Rhai keeps imports and `global::` constants in a call's global state, not the scope, and fills `global::` only as a `const` statement runs (#1012: every `global::` read failed after #692), so `calls` is rebuilt (`ScriptInstance::top_level_ran`) after the top level runs and after a reload, from the scope's values (`instance::global_reads` finds the names by an AST walk; a script with none gets no extra statement). Test a script-semantics change on a game's scripts too: no script in this tree uses `global::`, Float's do 41 times. `flint script check` reports a `global::NAME` with no top-level `const NAME` as `unknown-global` (#1007, `check::globals`; a `let` read that way is the usual slip, and fails every call), never in a module, whose `global::` is its own; `top_level_tests::a_global_read_with_no_constant_fails_where_the_checker_says` holds the checker to what the engine fails on, and `floats_global_shapes_run_frame_after_frame` to Float's shapes `reload_script(world, id, ast)` and `ScriptSync::check_hot_reload(engine, world)` lend the world to the new source's top level. Tests: `engine/top_level_tests.rs`; `declared_tests::no_function_panics_without_a_world` calls every declared function with no world

## The declared API (ADR 0116): how to add a function

A new function is declared through the builder in `src/api/builder.rs`, in its module's file under `src/api/` (`entity.rs` is the pattern). Every engine function is declared (ADR 0116 step 2, #695): `api.rs` is the module list and `register_all`, and `flint script api --json` counts 0 undeclared. The modules: `entity`, `input`, `time` (with a deterministic run's `timestamp()`, `api::forbid_wall_clock`), `audio`, `animation`, `physics` + `physics_2d` (`physics.rs`, with `move_character` and `get_collider_extents`), `nav` (`find_path`, `move_along_path`; one `flint_physics::NavGrid` per settings asked for and each walker's place along its path in module state `NavState`, taken out of the context around the search so `call.physics()` can be borrowed; #969), `camera`, `post_process`, `quality`, `math` (with `random.rs`'s three), `event`, `log`, `draw` (the 2D draw calls, clip and over-UI stacks, `screen_width`/`height`, `measure_text*`), `draw_world` (`draw_line_3d*`, `draw_world_line`/`text`), `view` (`world_to_screen`, `screen_to_*`, `ground_height`, `raycast_meshes`), `ui` (data-driven UI), `screen_ui`, `sprite` (with the sprite animator), `camera_2d` (the follow/shake integrator is `follow_step`/`advance_shake`), `touch`, `style` (entity and whole-frame styles, looks, the style readers), `particle`, `spline` (the sampling is `closest_point`/`attr_span`/`sample_at` over the `spline_data` table; `attr_span` reads a control point attribute's spans, `gap_after` among them, #855), `ocean` (the module owns the spectrum cache), `terrain`, `chunk`, `scene`, `state`, `persistence`, `data` (`data::load_data`), `expression`, `music` (`music_beat` and the rest, for any scene) and `test` (#714: `test_assert`, `test_fail`, `test_pass`, `test_log`, writing `ScriptCallContext::test`, a `testing::TestRecord` kept for the run: assertions counted per file, line and message, the first verdict, `test_log` values as JSON through `testing::dynamic_to_json`; `ScriptSystem::test_record()` / `test_decided()`; a failure is one `warn!` under target `script::test`, which a playtest's warning count leaves out). The modules an optional feature owns are not here (#698, "Modules an optional feature owns" below): `wooze`, `living` and `debug` are the player's living props (`flint-player/src/player_app/living_api.rs`), `conducted` its music (`flint-player/src/music/conducted.rs`). `opts.rs` holds the draw modules' shared helpers (the opts-map reader `Opts::read` / `read_opts`, `TextOpts`, `world_text_from_opts`, `measure_text_with`); `convert.rs` the TOML conversions (`toml_to_dynamic`, `dynamic_to_toml`, `map_to_toml`). Only a game extension's raw `rhai_engine_mut()` registration is undeclared. A declaration:

```rust
let mut m = api.module("entity");
m.func("set_position", "Move the entity to a position in its parent's space.")
    .arg("id", Entity).arg("x", Num).arg("y", Num).arg("z", Num)
    .run(|call, (id, x, y, z)| {
        if let Some(mut comps) = call.world_mut()?.get_components_mut(id) { /* a ComponentsMut: its writes keep the index (#691) */ }
        Ok(())
    });
```

- **The doc is one line and required** (`declared_tests.rs` fails on an empty one). `.returns(kind, "shape in words")` says what comes back (a map's keys, `-1` on failure); none means `()`.
- **Kinds** (`builder::kind`): `Num` (int or float, as `f64`), `Int` (an int or a whole float), `Bool`, `Entity` (a live `EntityId`), `MaybeEntity` (`Option<EntityId>`, no warning: for `entity_exists`), `Str` (`ImmutableString`), `Map`, `Array`, `Color` (`[r,g,b(,a)]` or `"#rrggbb(aa)"`, as `[f32; 4]`), `Any` (`Dynamic`), `Fn` (`FnPtr`). Up to 14 parameters. An argument that doesn't convert is a script error naming the function, the parameter and the kind, at the call's line.
- **A kind that takes its argument (`Str`, `Map`, `Array`, `Any`, `Fn`: `Kind::TAKES`) converts the first one from a copy.** Rhai hands a raw function its first argument by reference when the script passed a variable there, so `mem::take` on it emptied the script's variable: `let s = "hp"; measure_text(s, 16.0); draw_text(.., s, ..)` drew `()` (`showcase_hud.rhai`, 121 errors a capture). The other arguments are temporaries and are still taken. A new taking kind sets `TAKES`; `declared_tests::a_variable_passed_first_is_left_as_it_was` holds it
- **`Entity` warns once and skips**: `-1` or a gone id never reaches the body; the call returns the return type's empty value (`#{}`, `()`, `0`, `false`, `""`) or `.or_return(v)` (`get_parent` gives `-1`, `distance` `f64::MAX`), and warns once per script and function (`ScriptCallContext::entity_target`, #635/#701). For every function, getters included. With no world in scope (a script's top level at load) it skips silently, as `setter_target` always did.
- **The "missing" convention** (#701), also `registry::CONVENTIONS`, which `flint script api` prints above the functions: an `Entity` argument that names nothing skips the body and warns once; a setter or command then does nothing and **queues nothing** (a command carries an `EntityId` the builder resolved, never a raw `i64`: `SetVelocity2D { entity }`); a getter returns its return type's empty value (`()` for a `Dynamic` map-or-unit, `#{}`, `[]`, `false`, `0`, `""`) unless `.or_return` names a sentinel (`-1` an id, `-1.0` a time: `audio_position`; `f64::MAX` `distance`). A query that finds nothing for a live entity (no hit, no component, no body, no physics) returns `()` where the answer is a map or value, `-1` for an id, `-1.0` for a time; the entity module's transform getters return `#{}` (kept from before). Say which in `.returns(kind, note)`. `declared_tests::every_function_taking_an_entity_warns_once_on_a_dead_id` calls every registry entry with an `entity` parameter at `-1` and at a despawned id, so a new one is covered by being declared (it needs a sample value for any new kind: `sample()`).
- **A name Rhai already has** (`log`, `abs`, `min`, `sin`, `PI`...): Rhai tries a call's exact types in every module, its packages too, before any `Dynamic` signature, and this engine's own functions before its packages. The `Num` twin (all floats) therefore wins for float calls, an all-int `abs`/`min`/`max` still reaches Rhai's integer one (an int back, as before), and `Dynamic` catches the rest (`sin(1)`). Where a built-in's exact types must reach yours, `.also_exact(&[TypeId::of::<rhai::FLOAT>()])` registers the body under them too: `log(3.5)` logs, where Rhai's base-10 `log(FLOAT)` used to win (the logarithm is `log(x, 10.0)`).
- **One arity, two shapes**: overloads that differed only by a parameter's type become one function with an `Any` parameter the body tells apart, erroring with `call.error(..)` otherwise (`play_sound_at`'s fifth: a volume or an options map).
- **The world only through `call`**: `call.world()?` / `call.world_mut()?` (a script error when there is none, not a panic), `call.physics()`, `call.ctx()` for the rest of `ScriptCallContext`, `call.entity(id)` for an id inside a map. No `unsafe` in a declared function: the pointers are `context.rs`'s (`try_world`, `try_world_mut`, `try_physics`). The body returns a value or `CallResult<value>`.
- **Overloads by arity**: declare each arity (`set_material_emissive` has 5 and 6). Two of the same arity are one function now that kinds convert.
- **`.run()` registers twice, or three times**: an exact-typed twin (floats for `Num`, ints for `Entity`) that Rhai finds on its first lookup, and an all-`Dynamic` one for every other mix; a function with four or more `Num` parameters (`INT_COPY_MIN_NUMS`) also gets an all-int copy (ints for `Num`, the twin's types for the rest), automatically, so `draw_rect(10, 10, 100, 50, 1, 1, 1, 1)` is an exact lookup too (ADR 0116, Decisions, 2026-11-11). `.without_int_copy()` (doc-hidden) is for the harness only. Measured (docs/design/script-api-overhead.md): as fast as a typed closure for float calls. An int in a `Num` slot of a function under four `Num`s, or a call mixing ints and floats, is found by Rhai's search over the `Dynamic` mixes (2^n hashes for n parameters), which Rhai caches per block: free when the callback made any native call before the loop, ~4 us a call for 8 arguments when the loop's call is the callback's first. `.run_typed()` registers on Rhai's typed path only (`Num` is then float-only, listed as `float`): the escape hatch, for a hot function where that matters.
- **`.run_pure(|(a, b)| ...)` for a function of its arguments alone** (the math module, `random*`): the same registrations and registry entry as `.run()`, but the body gets no `call`, so nothing locks the `ScriptCallContext` (`.run()` locks it for every call, even a body that never touches it). Its kinds must be `PureKind`s: anything but `Entity` / `MaybeEntity`. Use it for anything pure and likely called in a loop; measured in docs/design/script-api-overhead.md ("Pure functions").
- **Names and opts maps** (#702, `registry::CONVENTIONS` `names` and `opts_maps`, the book's "Names and opts maps"): verb first (`play_sprite`, `shake_camera`); `get_<noun>`/`set_<noun>` with one noun for what a script can change, no `get_` for what nothing sets (`mouse_x`, `delta_time`, `screen_width`) or a calculation (`distance`); a module-owned family keeps its prefix (`persist_`, `ui_`, `spline_`, `conducted_`); no aliases, no `_ex`. A rename is a loop: `for (name, old) in [("get_lod_scale", None), ("lod_scale", Some("use get_lod_scale"))] { m.func(name, ..).deprecated(old).run(..) }`, one body, the old name for one release (`naming_tests::RENAMES` lists them; a test holds each old name deprecated, same params and returns). A draw primitive is two overloads of one name: what places it plus `r, g, b, a`, and what places it plus an `opts` map (`MapKind` last), read by `opts::read_opts(call.ctx(), "fn", &map, KEYS)`: `KEYS` is the function's list, a key not in it or of the wrong shape warns once per function and key (`ScriptCallContext::opts_warned`) and is ignored; colours go through the `Color` kind's parser (`[r,g,b(,a)]` or hex). A new key is a field on `Opts`, an arm in `Opts::take` and a line in `wants`. A map costs 0.15 to 0.22 us a call over the positional form (docs/design/script-api-overhead.md, `--opts`)
- **Then regenerate the book**: `cargo run --bin flint -- script api --book` rewrites `docs/book/src/reference/script-api.md` (and the scripting chapter's tables) from the declarations; commit it with the function. CI's headless job runs `--check-book` and fails a PR whose page is stale, or whose chapters call a function at an arity it isn't declared at (a renamed or re-shaped function's old calls in the book). A new module shows up on the reference page by itself; a chapter table names its module (`module:x`) or functions in its `script-api:begin` comment.
- **Registry**: `ScriptEngine::api_registry()`, `ScriptSystem::api_listing()` (declared + undeclared + callbacks; the undeclared part needs the `metadata` feature, which flint-cli turns on). Native only: on wasm `ApiRegistry` is empty and the builder drops docs and return notes (param names stay, for the errors). `ScriptSystem::script_api()` / `PlayerExtension::declare_script_api` let a host or game declare into the same registry; `rhai_engine_mut()` still works and lists as undeclared. The callbacks are `registry::CALLBACKS`, a re-export of the one table (next bullet).
- `api::overhead` (doc-hidden) holds the measurement's subjects; `cargo run --release -p flint-script --example api_overhead` reruns it.
- **`flint script check` is `check.rs`** (#694, the `check` feature: `metadata`, native tools only; Rhai's `internals` is in every build since #692). `Api::of(&mut ScriptSystem)` is what a call may name (the listing, an extension's raw registrations, Rhai's packages from `gen_fn_signatures`; `allow`/`add` for a game's own), `Checker::check(Vec<ScriptFile>)` compiles each file with `engine::compiler()` (optimizer off), follows its imports through `ModuleBase`, and returns `Diagnostic`s with `line`/`column`; `check_source` checks a string. Callbacks are judged from `registry::CALLBACKS`. A game binary can check its own scripts with `Api::of(&mut app.core.script)`. `.deprecated("use x")` on a `Func` (ADR 0116 decision 3) marks the entry (`ApiEntry::deprecated`), which `flint script api` lists, the book's reference page marks (chapter tables leave it out) and the checker warns at; `.deprecated(None)` marks nothing, for a loop declaring a name and its old one. The CLI side and the rules: `crates/flint-cli/CLAUDE.md`

## Modules an optional feature owns (#698, ADR 0116 decision 5)

- **A `ScriptModule`** (`module.rs`: `name`, `enabled_when`, `declare(&mut Module)`) is a module the crate with the feature declares, not flint-script: `ScriptSystem::declare_module(&dyn ScriptModule)` (once per name) registers it through `ScriptApi::gated_module(Gate)`, whose `Func::run` checks `ScriptCallContext::module_enabled` before converting the arguments. Not enabled, a call is a script error at its line: `tune_living: the living module is not enabled here; it is enabled when the scene has living props, ...` (`builder::not_enabled`). `run_pure` / `run_typed` panic on a gated module (they can't check). The registry keeps the gates (`ApiRegistry::gates`, `ApiListing::gates` / `enabled_when`), which `flint script api` prints on the module's line and the book under its heading; the `modules` convention states the rule.
- **Enabling is the host's**: `ScriptSystem::set_enabled_modules(vec![..])`, the whole set, which the player's `GameCore::enable_script_modules` sets from its subsystems' `script_modules()` whenever they change (built before a scene's scripts load, dropped at its unload). Never set, no gated module runs.
- **Commands** are one variant, `ScriptCommand::Module(ModuleCommand)`: the function's name (`function()`, what a capture's refusal and `unsupported` use) and an `Arc` payload of the owner's type (`payload::<T>()`; through the trait object, since the blanket `ModulePayload` impl would answer for the `Arc` itself). The owning subsystem takes it in `script_command`; one nobody takes reaches `ScriptHost::module_command` (default `unsupported(function)`).
- **State** for its functions: `ScriptSystem::set_module_state(T)`, one value per type in `ScriptCallContext::module_state` (`ModuleState::get_mut::<T>()` makes a `Default` on first ask), persistent like the host's other per-frame inputs. The rhythm session's `ConductedSnapshot` is one.
- The player's list is `flint_player::script_system()` (every subsystem file's `SCRIPT_MODULES`, build.rs), which `flint script api`, `--book`, `flint script check` and `flint check` use; a bare `ScriptSystem::new()` has the core alone. Tests: `declared_tests::a_gated_module_runs_only_where_the_host_enabled_it` (a toy module), and the player's `living_api_tests.rs`, `music/conducted_tests.rs`, `subsystems/toy.rs`.

## Commands and the one host interface (ADR 0116 decision 4, #697)

A script function that affects anything but the world it is lent (a sound, a style, a scene change, the camera) queues a `ScriptCommand` (`context.rs`). A host drains them (`ScriptSystem::drain_commands`) and hands them to `host::apply` / `apply_all` (`host.rs`), **the one `match` over `ScriptCommand`**: each variant becomes a call to its `ScriptHost` method. Every method has a default that calls `unsupported(command)` (warns once per host and command; a host with its own record overrides it), except `log`, which every host can do. The player's game core does every command that changes the game, the same for the player and a headless capture (`CoreCommands` in `flint-player/src/player_app/game_core.rs`, #725); each host does what `game_core::for_the_host` names as the presentation's (`impl ScriptHost for PlayerApp` in `script_commands.rs`; `CaptureFrame` in `headless_game.rs`, what `flint render --scripts` runs). There are no `take_*` channels: what a frame keeps one value of (the camera, the `[post_process]` keys `set_post` sets, render mode, time scale, low-pass, touch controls, distance scales, cursor, quality) lives in `ScriptCallContext::requests` (`FrameRequests`), where the last call in a frame wins and `apply_camera_shake` / `get_lod_scale()` read it back, and `take_commands` turns it into commands (`SetCamera`, `SetPostProcess`, `SetRenderMode`, `SetTimeScale`, `SetAudioLowpass`, `SetTouchControls`, `SetLodScales`, `SetCursorCaptured`, `SetQuality`) after the queued ones, one each for what was asked. A command carries a resolved `EntityId`, never a raw id (the `Entity` kind skips the call before anything is queued, #701).

**Adding a command** is a variant, a registration and a host method:

1. **The variant**, on `ScriptCommand` in `context.rs`, with a doc line naming the script function. Ids are `EntityId`s from an `Entity` argument.
2. **The registration**: the declared function in its `api/<module>.rs` that pushes it, `call.ctx().commands.push(ScriptCommand::X { .. })` (or a field on `FrameRequests` and a line in `take_commands`, for a one-value-a-frame setting).
3. **The host method**: a method on `ScriptHost` in `host.rs` named for the script function, defaulting to `self.unsupported("fn_name")`, its arm in `host::apply` and its name in `host::command_name` (the compiler refuses either match without it). `command_name` is the pure table a capture's refusal reads (#1013): never find a command's name by applying it to a probe host, whose default `log` (the one default that does something) printed every script line twice under `flint render --scripts`. `headless_host_tests::the_name_table_is_what_each_default_reports` holds the table to the defaults.

Then the method is overridden once: on `CoreCommands` (`game_core.rs`) if it changes the game, or, if it's the window's (sound, a scene, the pads), added to `game_core::for_the_host` and overridden on each host (`script_commands.rs`, and `CaptureFrame` in `headless_game.rs` if a capture can show it). What a capture can't do goes on `flint_player::PRESENTATION_ONLY` (`headless_game.rs`) with why. `headless_host_tests::every_command_is_applied_headless_or_presentation_only` reads the variants from `context.rs`, so it fails until the new one has a sample in `one_of_each` and is one or the other. Regenerate the book (`flint script api --book`) for the function. Walked through with `set_camera_cut_detection`: `ScriptCommand::SetCameraCutDetection` (context.rs), the function in `api/style.rs`, `ScriptHost::set_camera_cut_detection` and its arm (host.rs), `for_the_host` and the player's method (game_core.rs, script_commands.rs), and `PRESENTATION_ONLY` (a capture has no cut detection), and nowhere else.

**When the player applies them**: it drains twice a frame (`PlayerApp::dispatch_script_commands`): after the fixed physics steps, for what `on_update` (and the last frame's late callbacks) asked, so a camera a script set is the one `on_draw_ui` and the frame see; then after `on_draw_ui`, for what it asked. Style tweens step just before the first drain, so a tween asked for this frame starts moving the next. The player holds the one-value settings in `script_requests` until the step of the frame that applies each (camera before `on_draw_ui`, post-processing and quality before the draw, low-pass, touch, distance levers and cursor at the frame's end), as the old channels were read.

## Rhai, callbacks and script UI (from the root, #992)

- Rhai v1.24 `sync`: `call_fn()` Scope visible only to direct callee, NOT sub-functions; entity IDs as `i64`
- **Scripting via Rhai** -- `script` component with `.rhai` files in `scripts/`; callbacks: `on_init`, `on_update`, `on_collision`, `on_trigger_enter/exit`, `on_action`, `on_interact`, `on_draw_ui`, `on_scene_exit/enter`, `on_animation_end`, `on_sequence_cue`, `on_event`, `on_expression(state)`, `on_persist_migrate(from)`; `ScriptCommand` for deferred effects; `DrawCommand` for immediate-mode 2D UI
- **All game UI is script-driven** -- no hardcoded HUD; `hud_controller` entity + `hud.rhai` pattern; engine provides draw primitives (`draw_text/rect/circle/line/sprite`), scripts compose UI. A menu is a UI document (`.ui.toml` + `.style.toml`, `load_ui`): `button`/`list`/`slider`, focus from keys, pads, mouse and touch, `on_ui(element_id, event)`, `scripts/lib/menu.rhai`; a mistake in one is a script error and `flint check`'s `bad-ui`; `flint render --scripts --ui-show <id>` draws it headless (#731; `crates/flint-script/CLAUDE.md`, the book's "When to use each UI system")
