# flint-script: Rhai scripting detail (moved out of the root CLAUDE.md by #755)

The root file keeps the callback list and the Rhai version gotcha. Script UI drawing: `crates/flint-player/CLAUDE.md`. Style functions (`set_entity_style`, `set_post_style`): `crates/flint-render/src/stylize/CLAUDE.md`.

- **Scripts come through the one asset resolver** (ADR 0114 step 3, #706) -- `ScriptSystem::load_scripts_from_scene(scene_path, &project)` gives `ScriptSync` a search (`set_search(project, scene_dir)`), not a directory: each `script.source` is `project.explain(AssetKind::Scripts, source, scene_dir)` (`ScriptSync::locate`), so a `scripts/` beside the scene no longer hides the project's, and a miss warns with every path tried. `import "m"` is the script `lib/m.rhai` by the same search (`ModuleBase::Project` in `module_resolver.rs`; `ModuleBase::Dir` is the one-folder form `set_scripts_dir`/`set_module_base` keep for tests and hosts with their own layout). Hot reload follows it: each script keeps the file it loaded and the nearer paths it wasn't found at (`Located`), and a poll that sees one of those appear (`file_watch::stamp`) re-locates and reloads from the nearer file; `lib_dirs()` is every `scripts/lib/` in the search, all of them scanned (`scan_libs`), so a nearer module appearing resets the module cache like any lib change. A chunk's scripts go through `load_script_named(id, source, chunk_dir)` (`locate_for`), searched from the chunk's folder then the scene's; `load_script_for_entity(id, path)` still loads a path as given and is not watched by name. Not on the resolver: `load_ui` / `load_data`, which join a path to `project_root_for` (the scene directory's parent; one of the root guesses #726 replaces). `load_ui` / `load_data` paths are from the project root: `ScriptSystem::set_current_scene(path, &project)` hands the project in and `ScriptCallContext::project_root_holding(what, rel)` is the root to join (`Project::root_holding`, which for one release still reads a file that is only at the old guessed place); `api::project_root_for` is gone
- **Scripting via Rhai** -- `script` component with `.rhai` files in `scripts/`; callbacks: `on_init`, `on_update`, `on_collision`, `on_trigger_enter/exit`, `on_action`, `on_interact`, `on_draw_ui`, `on_scene_exit/enter`, `on_animation_end`, `on_sequence_cue`, `on_event` (custom events from `fire_event_data`, the engine or `ExtensionCtx::fire_event`), `on_persist_migrate(from)` (save data loaded at a version below `[project] save_version`; `ScriptEngine::migrate_persistent_store`, run by `ScriptSystem::initialize` and `update` after scripts load and before `on_init`, only inside a state scope, and only when a loaded script defines it, else the data stays pending; #726), `on_expression(state)` (state from outside the process: `--expression-timeline <file>` on the game clock or `--expression-listen 127.0.0.1:<port>`, newline-delimited JSON read off the frame thread, loopback only; `expression()` reads the latest, any JSON object as a map with float numbers; `player_app/expression_feed.rs`, #518); `ScriptCommand` for deferred effects; `quit_game()` ends the run as the close button does (exit 0, saves flushed, `--exit-after`'s report; on the web the page's `window.flintQuit` leaves full screen and goes back to its game list, #659); `DrawCommand` for immediate-mode 2D UI; `set_scale`/`get_scale`, and `set_visible`/`is_visible` over a `visibility { visible }` component that hides an entity's subtree from every draw, shadow, light and ray target (`FlintWorld::hidden_entities`, empty and unwalked when nothing is hidden; #628). An entity setter given `-1` or a gone id warns once per script and function (`ScriptCallContext::setter_target`, #635); a declared function takes it as an `Entity` argument, which does the same for getters too (below). Book's scripting page, "Script state": top-level `let`s reach callbacks, not helper `fn`s
- `ScriptCallContext` uses raw `*mut FlintWorld` -- only valid during `call_update()`/`process_events()` scope
- `on_update()` is parameterless -- use `delta_time()` API; `on_interact` checks `interactable.range` + `.enabled`
- `on_draw_ui()` ALWAYS runs even when scripts paused (pause menus need it)
- `random()` / `random_range()` / `seed_random(n)` (#580) are one SplitMix64 per engine, `random::ScriptRandom`, seeded from the clock once in `ScriptEngine::new`; `ScriptSystem::seed_random` (the player's `--seed` / `--frame-step`, `flint render --scripts`) reseeds that same state, so one seed gives one sequence however it arrives. Top-level statements run again before every callback, so a script seeds in `on_init`, never at the top

## The declared API (ADR 0116): how to add a function

A new function is declared through the builder in `src/api/builder.rs`, in its module's file under `src/api/` (`entity.rs` is the pattern). Ported so far: `entity`, `input`, `time`, `audio`, `animation`, `physics` + `physics_2d` (`physics.rs`), `camera`, `post_process`, `math` (with `random.rs`'s three), `event`, `log`; the other `register_*_api` functions in `api.rs` are ported by step 2 (#697):

```rust
let mut m = api.module("entity");
m.func("set_position", "Move the entity to a position in its parent's space.")
    .arg("id", Entity).arg("x", Num).arg("y", Num).arg("z", Num)
    .run(|call, (id, x, y, z)| {
        if let Some(comps) = call.world_mut()?.get_components_mut(id) { /* ... */ }
        Ok(())
    });
```

- **The doc is one line and required** (`declared_tests.rs` fails on an empty one). `.returns(kind, "shape in words")` says what comes back (a map's keys, `-1` on failure); none means `()`.
- **Kinds** (`builder::kind`): `Num` (int or float, as `f64`), `Int` (an int or a whole float), `Bool`, `Entity` (a live `EntityId`), `MaybeEntity` (`Option<EntityId>`, no warning: for `entity_exists`), `Str` (`ImmutableString`), `Map`, `Array`, `Color` (`[r,g,b(,a)]` or `"#rrggbb(aa)"`, as `[f32; 4]`), `Any` (`Dynamic`), `Fn` (`FnPtr`). Up to 12 parameters. An argument that doesn't convert is a script error naming the function, the parameter and the kind, at the call's line.
- **`Entity` warns once and skips**: `-1` or a gone id never reaches the body; the call returns the return type's empty value (`#{}`, `()`, `0`, `false`, `""`) or `.or_return(v)` (`get_parent` gives `-1`, `distance` `f64::MAX`), and warns once per script and function (`ScriptCallContext::entity_target`, #635/#701). For every function, getters included. With no world in scope (a script's top level at load) it skips silently, as `setter_target` always did.
- **The "missing" convention** (#701), also `registry::CONVENTIONS`, which `flint script api` prints above the functions: an `Entity` argument that names nothing skips the body and warns once; a setter or command then does nothing and **queues nothing** (a command carries an `EntityId` the builder resolved, never a raw `i64`: `SetVelocity2D { entity }`); a getter returns its return type's empty value (`()` for a `Dynamic` map-or-unit, `#{}`, `[]`, `false`, `0`, `""`) unless `.or_return` names a sentinel (`-1` an id, `-1.0` a time: `audio_position`; `f64::MAX` `distance`). A query that finds nothing for a live entity (no hit, no component, no body, no physics) returns `()` where the answer is a map or value, `-1` for an id, `-1.0` for a time; the entity module's transform getters return `#{}` (kept from before). Say which in `.returns(kind, note)`. `declared_tests::every_function_taking_an_entity_warns_once_on_a_dead_id` calls every registry entry with an `entity` parameter at `-1` and at a despawned id, so a new one is covered by being declared (it needs a sample value for any new kind: `sample()`).
- **A name Rhai already has** (`log`, `abs`, `min`, `sin`, `PI`...): Rhai tries a call's exact types in every module, its packages too, before any `Dynamic` signature, and this engine's own functions before its packages. The `Num` twin (all floats) therefore wins for float calls, an all-int `abs`/`min`/`max` still reaches Rhai's integer one (an int back, as before), and `Dynamic` catches the rest (`sin(1)`). Where a built-in's exact types must reach yours, `.also_exact(&[TypeId::of::<rhai::FLOAT>()])` registers the body under them too: `log(3.5)` logs, where Rhai's base-10 `log(FLOAT)` used to win (the logarithm is `log(x, 10.0)`).
- **One arity, two shapes**: overloads that differed only by a parameter's type become one function with an `Any` parameter the body tells apart, erroring with `call.error(..)` otherwise (`play_sound_at`'s fifth: a volume or an options map).
- **The world only through `call`**: `call.world()?` / `call.world_mut()?` (a script error when there is none, not a panic), `call.physics()`, `call.ctx()` for the rest of `ScriptCallContext`, `call.entity(id)` for an id inside a map. No `unsafe` in a declared function: the pointers are `context.rs`'s (`try_world`, `try_world_mut`, `try_physics`). The body returns a value or `CallResult<value>`.
- **Overloads by arity**: declare each arity (`set_material_emissive` has 5 and 6). Two of the same arity are one function now that kinds convert.
- **`.run()` registers twice**: an exact-typed twin (floats for `Num`, ints for `Entity`) that Rhai finds on its first lookup, and an all-`Dynamic` one for every other mix. Measured (docs/design/script-api-overhead.md): as fast as a typed closure for float calls. An int in a `Num` slot is found by Rhai's search over the `Dynamic` mixes (2^n hashes for n parameters), which Rhai caches per block: free when the callback made any native call before the loop, ~4 us a call for 8 arguments when the loop's call is the callback's first. `.run_typed()` registers on Rhai's typed path only (`Num` is then float-only, listed as `float`): the escape hatch, for a hot function where that matters.
- **Registry**: `ScriptEngine::api_registry()`, `ScriptSystem::api_listing()` (declared + undeclared + callbacks; the undeclared part needs the `metadata` feature, which flint-cli turns on). Native only: on wasm `ApiRegistry` is empty and the builder drops docs and return notes (param names stay, for the errors). `ScriptSystem::script_api()` / `PlayerExtension::declare_script_api` let a host or game declare into the same registry; `rhai_engine_mut()` still works and lists as undeclared. The callbacks' docs are `registry::CALLBACKS` (a test holds them to `CALLBACK_ARITIES`).
- `api::overhead` (doc-hidden) holds the measurement's subjects; `cargo run --release -p flint-script --example api_overhead` reruns it.
