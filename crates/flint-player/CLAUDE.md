# flint-player: extensions, UI, input, capture, perf, web (moved out of the root CLAUDE.md by #755)

The input system and touch controls are evaluated in flint-runtime; their notes are here beside the player that drives them. Web audio's code is in flint-audio (`crates/flint-audio/CLAUDE.md` has the audio clock). Android has one note, in `scripts/CLAUDE.md` (`cargo ndk -p flint-android`). `flint export web`: `crates/flint-cli/CLAUDE.md`. The showcase film rig: `flint-examples/film/CLAUDE.md`.

## Extensions and script UI

- **Player extensions** (ADRs 0071-0075) -- a game binary embeds `PlayerApp` and installs `PlayerExtension`s (`add_extension`): `register_script_api` (native Rhai fns; same signature replaces Flint's), `pre_update(ExtensionCtx)` before scripts' `on_update` (world, clock, input, last frame's camera, `gpu` for `upload_mesh`/`remove_mesh`, `attach_mesh`, `fire_event` -> scripts' `on_event` same frame, and `scene_table(name)` / `scene_table_as::<T>(name)` / `scene_tables`: the current scene's top-level tables as written, #686, from `PlayerApp::scene_tables`, which a host sets with `SceneFile::scene_tables()` and a transition replaces; `apply_scene_settings` also settles living props' `[living]` / `[wooze]` on a copy, `flint_procgen::settle_scene`, so a preset the scene names is filled in for a game binary too; a game declares its own as `[table.<name>]` in its `schemas/scene/`), `on_window_event` (only input events consumable) and `ui(&mut egui::Ui)` drawn between script UI and the Foreground debug panels: the frame's root `Ui` from `run_ui`, eframe's `App::ui` shape (ADR 0121, #959), so panels show on it and windows from it (`Ui` derefs to `Context`). The frame calls `extension::draw_ui`, which goes through the deprecated `root_ui` (#946's hook, default calls `ui`) so a game still overriding it draws; rustc doesn't warn on implementing a deprecated trait method. Tests: `extension_tests.rs` `a_games_side_panel_*`, `a_games_floating_window_*` (two frames: a window's first is egui's invisible sizing pass). `crates/flint-player/examples/cave_game` draws a panel and a window through it. `fonts(&mut FontDefinitions)` edits egui's fonts before each install (ADR 0081); `fonts/fonts.toml` `[egui] proportional/monospace` names egui's default faces, and every named family falls back to egui's fonts. A script's `font: "monospace"` / `"proportional"` is egui's own family (#1179, `fonts::family_of`, which `resolve_font_id` and `text_measurer` both ask, so drawing and measuring agree; a project family of the name wins), and a `fonts.toml` alias's `file` may be a path from the manifest's folder, keyed in `font_data` by that path (`alias_key`) and a family under the alias only. A file egui can't open as a face is left out of `ProjectFonts::read` with a warning naming it (#1262, `fonts::face_error`: skrifa, epaint's own reader and version, opens face 0 as epaint does and reads `head`, `maxp` and `cmap`, since a truncated file opens by its directory alone), because epaint panics on one at `set_fonts`; its family is unknown, so its text falls back. Tests: `fonts::tests::a_face_egui_cannot_parse_*`, `egui_s_own_faces_pass_*`; bump the workspace's `skrifa` with egui. With any extension installed, egui sees input first; a release follows its press. Runtime meshes are frustum-culled per draw by their AABBs (every game). Picking: `Camera::screen_to_ground` / Rhai `screen_to_ground`. Book: guides/player-extensions.md
- **Extension hooks of the subsystems' shape** (ADR 0117 decision 5, #754; `extension.rs`) -- `PlayerExtension` has `update(Stage, &mut ExtensionCtx)` (`Stage` is the subsystems' enum, `pub` and `#[non_exhaustive]`, re-exported as `flint_player::Stage`; called by `game_core::run_stage` through `FrameHost::extensions_at` right after the subsystems, at every stage they hear, `Clock` included), `scene_loaded` / `scene_unloading` (from `subsystems_enter_scene`, after the subsystems, and `subsystems_leave_scene`, before them), `script_command(&ScriptCommand, ctx) -> bool` (`dispatch_commands` asks `FrameHost::extension_takes` after the subsystems pass) and `script_modules() -> &[&'static dyn ScriptModule]` (declared in `add_extension` and kept in `GameCore::extension_modules`, which `enable_script_modules` unions with the subsystems' every time it sets the enabled list, so a scene's entry no longer drops them). All default to nothing. Every hook goes through `PlayerApp::each_extension(f)` (frame.rs), which builds the `ExtensionCtx` (now with a private `script` for `ExtensionCtx::set_module_state<T>`) and returns at `extensions.is_empty()`. A capture (`HeadlessGame`) has no extensions: `flint render` links no game's Rust. Not exposed, as no game has needed them yet: `on_input`, `pre_render`, `post_encode`, `exit_report`, a policy name. Tests: `player_app/extension_hooks_tests.rs` (`Laps`, a module read at `PreScripts` and a command it takes; every stage after a `Probe` subsystem; a transition keeps the module)
- **A game's procgen generators** (ADR 0119, #195) -- `PlayerExtension::register_generators(&mut GeneratorRegistry)`, called once from `add_extension` with `procgen_resolver.registry_mut()` (built-ins already in; same name replaces one). The disk tier rebuilds the resolver after extensions are added, so `PlayerApp::use_procgen_disk` moves the registry across (`mem::take` into `ProcGenResolver::with_registry`): never rebuild the resolver with `with_config`, which drops a game's generators. Player only: `flint gen`/`edit`/`render` and `HeadlessGame::resolve_procgen` build from the built-ins. Example game binary: `crates/flint-player/examples/cave_game/` (`rock_v1`; `--screenshot <png>`). Tests: `procgen_assets_tests.rs` `a_games_generator*`
- **A game's Rust styles** (#419) -- `PlayerExtension::styles() -> Vec<&'static StyleDescriptor>`, registered by `add_extension` into the player's own registry, `GameCore::styles` (ADR 0129, #742; a refusal is a `tracing::error!`, the rest still register), and handed to a renderer that exists already (`set_styles`). It works even after `apply_scene_settings`, because `scene.post_process` keeps the def and `scene_post_config()` reads its tables (and `launch.style_specs`) against `core.styles` only when the renderer is made, and `stage_scene` gives the renderer `core.styles` after `bind_scene`. **The player's styles are `core.styles`**: `apply_scene_settings` makes the scene's (`SceneBinding::over(scope, &core.styles)`: the game's styles kept, the scene's user styles in place of the last scene's) and keeps it there; script style commands, tweens and the style reader read it; the reload poll (`poll_user_styles`) reloads into it and hands the renderer a copy. Example game binary: `crates/flint-player/examples/cyanotype/` (`--style`, `--scene`, `--input-script`, `--screenshot [--at]`). Test: `extension_tests.rs` `game_styles`. Detail: `crates/flint-render/src/stylize/CLAUDE.md`
- **All game UI is script-driven** -- no hardcoded HUD; `hud_controller` entity + `hud.rhai` pattern; engine provides draw primitives (`draw_text/rect/circle/line/sprite`), scripts compose UI. Text `stroke` up to 2 pt is eight offset copies; wider, and any `glow: [r,g,b,a,radius]` (`.style.toml` `glow_color`/`glow_radius`), is one CPU-rasterised picture from egui's font atlas (distance band + blur), cached per label (`player_app/text_halo.rs`, #626; golden `crates/flint-player/tests/golden/text-halo-neon-60.png`, `FLINT_BLESS=1`)
- `render_draw_commands()` is a free function to avoid borrow conflicts; `load_pending_sprites()` before egui borrow
- **The HUD headless** (#731; `player_app/headless_hud.rs`, `flint_player::HeadlessHud`, native only) -- the player's painter (`render_draw_commands`) with the project's fonts (`ProjectFonts::find`) and sprites (`AssetKind::Sprites`), an `egui_wgpu::Renderer` for the target's format without its sRGB suffix (as the player's `hud_view`, so colours blend in display space), egui on a clock of 0; one empty pass at `new` builds the fonts and uploads the atlas, so `measurer()` (`fonts::text_measurer(ctx, None)`, the one closure the player's `install_text_measurer` uses too) is real from the first script. `HeadlessGame::script_ui_drawn` keeps the step's draw calls plus `generate_ui_draw_commands` as `hud()` (it used to drop them with a note); `set_text_measurer`, `with_ui`. `flint render`'s use: `crates/flint-cli/CLAUDE.md`
- Screen size for draw commands must be egui logical points, NOT physical pixels
- The HUD blends in display space. Since egui 0.31 `Color32::from_white_alpha` / `from_rgba_unmultiplied` (and `ColorImage::from_rgba_unmultiplied`) premultiply in display values, so a translucent colour built with them blends as written; egui 0.30 premultiplied in linear light, and a translucent white read several times too bright. **Scripts take 0.36's blend too** (#958; #945 had kept 0.30's bytes behind a shim, now gone): their `draw_*` colours and world text (`hud_render::to_color32`, which is `from_rgba_unmultiplied`), text halos (`text_halo.rs`'s `premul`, through `to_color32`) and HUD sprites (`ColorImage::from_rgba_unmultiplied` in `load_ui_texture`). A 50% white over black is 128, where 0.30 drew 188; a game gets a light colour's old look back with alpha^(1/2.2), and a dark one is unchanged (the book's Upgrading the Engine page, HUD colours). Flint's own Rust UI (overlays, touch controls) uses egui's constructors or `from_rgba_premultiplied`. "Display space" holds only in a pass drawn into `RenderContext::hud_view(&texture)` with an `egui_wgpu::Renderer` built for `hud_format` (the player and, since #428, the scene viewer): into the swapchain's sRGB view egui-wgpu blends in linear light, and a 90% charcoal card over a 210 sky measured 73 instead of 35. The model previewer, procgen, terrain, texture and particle editors still draw into the sRGB view
- **A test's egui frame is `flint_debug_ui::run_headless_frame(ctx, input, |ui| ..)`** (#944), never `ctx.run_ui`: the closure gets the frame's root `egui::Ui` (`ui.ctx()` for the context; egui 0.36 has no `Context::run`, #945), and it returns the `FullOutput` with its texture updates cleared, since nothing uploads a test's textures and egui 0.36 asserts in debug builds when a `FullOutput` drops with them (55 of the 60 tests that failed on spike #934's egui 0.36 branch). flint-player takes flint-debug-ui as a dev-dependency for it, whatever the features. Clippy refuses a bare `egui::Context::run_ui` (the workspace `clippy.toml`). A real frame (the player, the viewer, the CLI's windows) allows it, and clears `full_output.textures_delta` after uploading and freeing ("Applied above"); a new egui host does the same, and takes its swapchain frame before running egui, so a frame it can't get never drops egui's texture updates unapplied (`tex_edit`, #945)

- **`PlayerApp`'s fields are grouped** (#724, ADR 0117 step 1; `player_app/state.rs`) -- about 45 top-level fields, each a part: `launch` (`LaunchOptions`, pub: what the host set before `run_app`, the CLI flags), `scene` (`SceneSettings`, pub: what the scene file says, replaced whole by `apply_scene_settings`), `post` (`PostOverrides`: scripts' post values this frame, `take_from` the frame requests, `any`, `stamp` over the config), `subsystems` (declared first: the optional features, see Subsystems; `[living]`/`[wooze]` settings are in `scene`, their state in `LivingSubsystem`), `hud` (egui, draw commands, world text, fonts), `stats` (F2 + perf readout), `saves`, `outcome` (exit request, init and scene failures), `style`, `input_layers`, `focus`, `quality`, `assets`. A new field goes into the group it belongs to, not on `PlayerApp`. Games set `app.launch.*` and `app.scene.*` (changelog)

- **Subsystems** (ADR 0117 step 3, #724; `player_app/subsystem.rs`) -- an optional feature is a `Subsystem` (internal trait, `: Any`) in `GameCore::subsystems`, not fields and inline calls. **Adding one is one new file** in `player_app/subsystems/` with a `pub(crate) fn for_scene(&mut SceneCtx) -> Option<Box<dyn Subsystem>>`: `build.rs` lists every file there as a module and its builder (`$OUT_DIR/subsystems.rs`, file-name order; a file with `#![cfg(test)]` is listed in tests only, as `subsystems/toy.rs` is), and nothing else is edited. Each file also declares `pub(crate) const POLICY: Option<&str>`: the name a game state pauses it by (`Some(LivingSubsystem::NAME)`, `"living"`) or `None`; the subsystem then reads it as `ctx.runs(self.name())` (#727); and `pub(crate) const SCRIPT_MODULES: &[&dyn ScriptModule]`, the script modules it owns (#698: `living.rs` the `wooze`, `living` and `debug` of `living_api.rs`, `music.rs` the `conducted` of `music/conducted.rs`, `&[]` for none), which `flint_player::script_system()` declares for every scene (`GameCore::new` uses it) and the subsystem's `script_modules()` enables where it runs; and `pub(crate) const DEBUG_KEYS: flint_runtime::DebugKeyGroup` (#717: owner, when, keys; `subsystem_debug_keys()`, an empty `keys` for none), the debug keys its subsystem returns from `debug_keys()`. **The scene's subsystems are built before its scripts load** (`subsystems_build`, in `start_scene_systems` just before `load_scripts_from_world`; then `enable_script_modules`), so `on_init` can call their modules, as a capture's always could; `scene_loaded` still comes last. **A capture builds them from the same list** (#1252): `subsystem::build_for_scene(ctx)` is the one walk of `for_scene_builders()`, and `HeadlessGame::start_subsystems(tables, CaptureStart { wooze, moment, scripts })` (flint render's `Stage::load`, where `start_living` was, before the models and `start_scripts`) hands it a `SceneCtx` with `capture: Some(..)` (the player's `scene_ctx!` says `None`), the scene file's `scene_tables()`, a default `SceneSettings` and `LaunchOptions`, and no renderer, audio or pads. A file that builds otherwise in a capture asks `ctx.capture` (living: `LivingSubsystem::in_capture`, posed at once, takes `wooze`; music: the music's alone, no chart judged; music and `field` only when `scripts`); one that doesn't runs there unchanged, so the one-new-file rule holds in `flint render --scripts` too. `Subsystem::presentation_only() -> Option<&'static str>` (default `None`) is a subsystem only a window shows: built by the player, dropped by the capture after its builder made it (so only a scene that uses it is named) with one note, `<name>: a headless capture doesn't run this subsystem (<why>)`. `headless_game.rs` names no scene subsystem: what flint render reads of the grove (`wooze()`, `upload_living`) is an `impl HeadlessGame` in `living_subsystem.rs` (`HeadlessGame::core` is `pub(super)` for it). Tests: `subsystems/toy.rs` `a_capture_builds_the_toy_*` (the toy and its module in a `HeadlessGame`, three steps heard) and `a_capture_names_a_subsystem_it_leaves_out_*` (`[toy] window = true`). Hooks: `lasts()` (`Lasts::Scene`, the default, built at `enter_scene` only if the scene uses it and dropped after its unload; `Lasts::Run`: the host's, the expression feed), `scene_loaded` (last step of `enter_scene`), `scene_unloading` (after `on_scene_exit`, before teardown clears anything), `update(Stage, &mut StageCtx)` at each of `Stage::UPDATES` (the host's `Stage::Clock` at the frame's very start, before the clock ticks and in place of the pad polling while a subsystem holds the pads, then `game_core::step`'s; a capture has no `Clock`), `script_command` (before `apply_all`; true takes it), `debug_keys()` / `on_debug_key(action, key, &mut StageCtx)` (its file's `DEBUG_KEYS.keys`, dispatched by the debug-key table while it is in the scene; see Debug keys), `on_input(PlayerInput::Click | Escape, ..)` (before egui and the game, and a real Escape before `Escape::decide`), `frame_inputs(&FrameCtx, &mut FrameInputs)` (its share of the renderer's frame inputs, gathered right before `prepare` in `sync_renderer`: the living subsystem's boil, shallow wooze and woozy grass, #739), `post_encode(&mut EncodeCtx)` (after `encode_to`, before the HUD: the encoder, frame texture, depth view, formats, renderer, world, camera, resolver), `ui(&egui::Context)` (in the HUD pass, over the game's UI), `exit_report(&ReportCtx, ..)`. Contexts lend fields one by one through `stage_ctx!` / `scene_ctx!` (world, clock, input (`&mut`), script, camera, renderer, gpu, the procgen resolver, project, scene path, pixels per point, cursor, panels, the frame's `requests` (`core.script_requests`, which a subsystem fills before the drain: the rhythm ladder's post values at `Stage::Procgen`), `audio` (the engine, `None` headless), `pads` (`subsystem::Pads`: `take()` stops the player's polling and its rumble, `give_back()` opens a fresh gilrs; `PlayerApp::pads_lent` skips `poll_gamepad_events` meanwhile), `quit` (the run's exit flag); a scene's settings, tables, `launch`, audio and pads), so the list can be walked while they are lent. A subsystem's debug key that opens or closes a panel moves the cursor as F3's do (`handle_debug_key`). Declared before `audio`; run in insertion order, torn down last added first. No subsystem: each hook returns at `is_empty`. Clients: the expression feed (`expression_feed::ExpressionSubsystem`), the music (`subsystems/music.rs`, whose subsystems are `crate::music`'s, next bullet), and living props (`living_subsystem::LivingSubsystem`: the wooze field, its clock, boil, shallow wooze, woozy grass, hand tuning, the A/B with its split in `post_encode`; a scene with props, `[living]`/`[wooze]`, `shallow_wooze` or `grass.wooze`). Its methods are `impl LivingSubsystem` in `living_tuning.rs` / `living_ab.rs`, taking a `StageCtx`; the props are `GameCore::living_props` (`flint_living::LivingProps`, #1024), added at load before the subsystem exists and lent to every context as `living` beside `resolver`, which lends them its specs, generators and leftover budget. `--compare` is `LaunchOptions::compare` / `compare_at_start`, handed to each scene's subsystem and back at its unload. The living tests reach it through generated `PlayerApp` methods (`living_test_glue.rs`, test-only: `app.living()`, `app.with_living(..)`, `tick_procgen_for_test(dt)`). Not yet a hook: the living debug panel is still made in `create_scene_debug_panels` (F3 order). Tests: `player_app/subsystem_tests.rs`

## Scenes, input, touch

- **Scene transitions** -- `TransitionPhase` lifecycle with script-driven visuals; `PersistentStore` survives transitions; `GameStateMachine` pushdown automaton, each state a `StateConfig` of `Run`/`Pause` by system name (#727): `flint_runtime::state::{PHYSICS, SCRIPTS, ANIMATION, PARTICLES, AUDIO}`, read as `config.runs(PHYSICS)` in `game_core.rs`, plus each scene subsystem whose file declares a `POLICY` (`living`), which `subsystem::state_machine()` adds for the player and `flint render --scripts` alike; `register_state` errors on any other key and on `rendering`/`transparent`/`"hidden"`, which nothing implements. The frame's events are `GameCore::events` (an `EventBus`): `PhysicsSystem::fixed_update(world, dt, &mut events)` pushes contacts, extensions, style tweens and `fire_event` push directly, `collect_game_events` drains it; a transition drops only contacts (`GameEvent::is_contact`), so a script's event reaches the next scene. ## Capture, perf, pacing

- **Script commands: one dispatcher, the core's** (ADR 0116 decision 4, #697; #725) -- `game_core::dispatch(host)` drains the scripts' commands twice a frame (after the physics steps: what `on_update` asked, so the camera is set before `on_draw_ui`, style tweens stepping just before; and after `on_draw_ui`). In order: `FrameHost::refuses` drops what the host won't do (a capture's `PRESENTATION_ONLY`), each subsystem's `script_command` takes its own (`ScriptCommand::Module` with a `LivingCommand` payload: living, wooze, debug), then each command goes through `flint_script::host::apply` (the one `match`; recipe for a new command: `crates/flint-script/CLAUDE.md`) either to `CoreCommands` (`game_core.rs`: events, particles, entity styles and tweens, post styles and style history on the lent renderer, the frame requests, time scale, states, 2D velocity, and `module_command`, a module command whose subsystem went with its scene) or, when `game_core::for_the_host` says it's the presentation's (sound, rumble, camera-cut detection, `set_look`, `set_quality`, `reset_post_style`, scenes, chunks, quit, `transition_complete`), to `FrameHost::host_command`: `impl ScriptHost for PlayerApp` (`script_commands.rs`) holds only those. A new command that changes the game goes in `CoreCommands`; one that is the window's goes in `for_the_host` and each host. The second group is on it too: scripts (`load_scripts_from_world(&project, ..)`; a chunk's through `ScriptSystem::load_script_named` from the chunk's folder then the scene's, with its own TEMPORARY old-rule compare in `transition.rs`), specs (`procgen_assets::discover_specs(resolver, &project, scene)` indexes `project.list(AssetKind::Specs, ..)`, one file a `[meta] name`, the nearest; `resolve_scene` takes the project from the sink's `ModelLoadConfig`; `spec_dirs` is gone), wooze presets (`flint_procgen::list_presets_in` / `write_preset_in` with `self.project`; `find_preset` discovers it from the scene), the input config's game layer (`input_config::resolve_input_paths(&project, ..)`: the scene's `input_config`, else the manifest's `[project] input` from the root, else `config/input.toml`, the first and last through `AssetKind::Files`), the skybox, terrain heightmap and splat map, grass mask and spline files (`Project::file_or_beside`; the free loaders `load_terrain`, `load_scene_grass_ground` and `flint_render::load_scene_splines` (#750; the player registers its colliders) discover the project from the scene path rather than take one), particle textures (`flint_render::load_scene_particle_textures`) and a transition's target (`resolve_scene_path(&project, current, target)`, `AssetKind::Scenes`; a target the search doesn't find is returned as written, a path from the working directory, and only then warned about if that isn't there either). Still on guesses of their own, deliberately: fonts and the style assets (next), `procgen_disk_config`'s root, `persist.rs`'s root, `music_session`'s base directory (the scene directory's parent) and `.flint/input.user.toml` beside the scene. **Paths from the project root** (#706, the last step): the save file (`persist.rs`), the procgen disk cache (`init.rs::procgen_disk_config`), `music_session`'s base (`music::base_dir`) and the project-local input override all ask `self.project.root_for(scene_dir)`; never derive a root from `scene_path` (`flint_core::project::guessed_root` is the one copy of that guess, see `crates/flint-core/CLAUDE.md`). `flint-player` with no scene opens `Project::default_scene()`
- **The schema registry is read once and kept** (ADR 0115, #683; `player_app/schemas.rs`, `HeldSchemas`) -- a host hands over the registry it loaded the first scene with: `app.set_schemas(registry, schema_dirs)` (`flint-player`, `flint play`, the web player, whose registry is the compiled-in engine schemas under the bundle's). `load_chunk` uses it as it is (`held_or_read`); a transition asks `schema_dirs.for_scene(next)` as before and then `HeldSchemas::for_dirs`: the same directory list is no read, a list that grew (a discovered or host list) loads only the added directories over a clone of what is held, and another list (another project's manifest) is read whole. **A read that fails logs an error and returns the registry held**, so a scene never loads with an empty one (it used to: `schemas_for_scene` fell back to `SchemaRegistry::new()` and archetype and schema defaults vanished). `set_schema_dirs` / `set_schema_paths` alone (an embedding game) still work: the directories are read on first use, once. Consequence: a schema file edited while the game runs is not seen by the next transition. **The game's schema lints are said once** (#1064): `HeldSchemas::set` (every registry held: `set_schemas`, the first read, a transition's read) logs the `game_lints()` no earlier registry had (`said`, one-line keys, kept across `forget`), one `diagnostic::log_summary_of(file, "flint check", ..)` a file, the file spelled from the working directory; so a transition that reads nothing says nothing, a grown list says only its new files', and the start's load tally counts them. Scene diagnostics at load come from `flint_scene::load_scene` itself (one summary line and the first five through `tracing::warn!`, at start and at each transition) and from `load_chunk` for a chunk; nothing in the player calls `diagnose` directly
