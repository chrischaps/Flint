# flint-player: extensions, UI, input, capture, perf, web (moved out of the root CLAUDE.md by #755)

The input system and touch controls are evaluated in flint-runtime; their notes are here beside the player that drives them. Web audio's code is in flint-audio (`crates/flint-audio/CLAUDE.md` has the audio clock). Android has one note, in the root file's gotchas (`cargo ndk -p flint-android`). `flint export web`: `crates/flint-cli/CLAUDE.md`. The showcase film rig: `tools/showcase/CLAUDE.md`.

## Extensions and script UI

- **Player extensions** (ADRs 0071-0075) -- a game binary embeds `PlayerApp` and installs `PlayerExtension`s (`add_extension`): `register_script_api` (native Rhai fns; same signature replaces Flint's), `pre_update(ExtensionCtx)` before scripts' `on_update` (world, clock, input, last frame's camera, `gpu` for `upload_mesh`/`remove_mesh`, `attach_mesh`, `fire_event` -> scripts' `on_event` same frame, and `scene_table(name)` / `scene_table_as::<T>(name)` / `scene_tables`: the current scene's top-level tables as written, #686, from `PlayerApp::scene_tables`, which a host sets with `SceneFile::scene_tables()` and a transition replaces; `apply_scene_settings` also settles living props' `[living]` / `[wooze]` on a copy, `flint_procgen::settle_scene`, so a preset the scene names is filled in for a game binary too; a game declares its own as `[table.<name>]` in its `schemas/scene/`), `on_window_event` (only input events consumable) and `ui(egui)` drawn between script UI and the Foreground debug panels. `fonts(&mut FontDefinitions)` edits egui's fonts before each install (ADR 0081); `fonts/fonts.toml` `[egui] proportional/monospace` names egui's default faces, and every named family falls back to egui's fonts. With any extension installed, egui sees input first; a release follows its press. Runtime meshes are frustum-culled per draw by their AABBs (every game). Picking: `Camera::screen_to_ground` / Rhai `screen_to_ground`. Book: guides/player-extensions.md
- **A game's procgen generators** (ADR 0119, #195) -- `PlayerExtension::register_generators(&mut GeneratorRegistry)`, called once from `add_extension` with `procgen_resolver.registry_mut()` (built-ins already in; same name replaces one). The disk tier rebuilds the resolver after extensions are added, so `PlayerApp::use_procgen_disk` moves the registry across (`mem::take` into `ProcGenResolver::with_registry`): never rebuild the resolver with `with_config`, which drops a game's generators. Player only: `flint gen`/`edit`/`render` and `HeadlessGame::resolve_procgen` build from the built-ins. Example game binary: `crates/flint-player/examples/cave_game/` (`rock_v1`; `--screenshot <png>`). Tests: `procgen_assets_tests.rs` `a_games_generator*`
- **A game's Rust styles** (#419) -- `PlayerExtension::styles() -> Vec<&'static StyleDescriptor>`, registered by `add_extension` through `flint_render::stylize::register` (a refusal is a `tracing::error!`, the rest still register). It works even after `apply_scene_settings`, because `scene.post_process` keeps the def and `scene_post_config()` reads its tables (and `launch.style_specs`) against the registry only when the renderer is made. Example game binary: `crates/flint-player/examples/cyanotype/` (`--style`, `--scene`, `--input-script`, `--screenshot [--at]`). Test: `extension_tests.rs` `game_styles`. Detail: `crates/flint-render/src/stylize/CLAUDE.md`
- **All game UI is script-driven** -- no hardcoded HUD; `hud_controller` entity + `hud.rhai` pattern; engine provides draw primitives (`draw_text/rect/circle/line/sprite`), scripts compose UI. Text `stroke` up to 2 pt is eight offset copies; wider, and any `glow: [r,g,b,a,radius]` (`.style.toml` `glow_color`/`glow_radius`), is one CPU-rasterised picture from egui's font atlas (distance band + blur), cached per label (`player_app/text_halo.rs`, #626; golden `crates/flint-player/tests/golden/text-halo-neon-60.png`, `FLINT_BLESS=1`)
- `render_draw_commands()` is a free function to avoid borrow conflicts; `load_pending_sprites()` before egui borrow
- Screen size for draw commands must be egui logical points, NOT physical pixels
- egui 0.30's `Color32::from_white_alpha` / `from_rgba_unmultiplied` premultiply in linear light, but the HUD blends in display space: a translucent white drawn with them reads several times too bright. Build translucent light colours with `from_rgba_premultiplied(a, a, a, a)`

- **`PlayerApp`'s fields are grouped** (#724, ADR 0117 step 1; `player_app/state.rs`) -- about 45 top-level fields, each a part: `launch` (`LaunchOptions`, pub: what the host set before `run_app`, the CLI flags), `scene` (`SceneSettings`, pub: what the scene file says, replaced whole by `apply_scene_settings`), `post` (`PostOverrides`: scripts' post values this frame, `take_from` the frame requests, `any`, `stamp` over the config), `subsystems` (declared first: the optional features, see Subsystems; `[living]`/`[wooze]` settings are in `scene`, their state in `LivingSubsystem`), `hud` (egui, draw commands, world text, fonts), `stats` (F2 + perf readout), `saves`, `outcome` (exit request, init and scene failures), `style`, `input_layers`, `focus`, `quality`, `assets`. A new field goes into the group it belongs to, not on `PlayerApp`. Games set `app.launch.*` and `app.scene.*` (changelog)

- **Subsystems** (ADR 0117 step 3, #724; `player_app/subsystem.rs`) -- an optional feature is a `Subsystem` (internal trait, `: Any`) in `GameCore::subsystems`, not fields and inline calls. **Adding one is one new file** in `player_app/subsystems/` with a `pub(crate) fn for_scene(&mut SceneCtx) -> Option<Box<dyn Subsystem>>`: `build.rs` lists every file there as a module and its builder (`$OUT_DIR/subsystems.rs`, file-name order; a file with `#![cfg(test)]` is listed in tests only, as `subsystems/toy.rs` is), and nothing else is edited. Each file also declares `pub(crate) const POLICY: Option<&str>`: the name a game state pauses it by (`Some(LivingSubsystem::NAME)`, `"living"`) or `None`; the subsystem then reads it as `ctx.runs(self.name())` (#727); and `pub(crate) const SCRIPT_MODULES: &[&dyn ScriptModule]`, the script modules it owns (#698: `living.rs` the `wooze`, `living` and `debug` of `living_api.rs`, `music.rs` the `conducted` of `music/conducted.rs`, `&[]` for none), which `flint_player::script_system()` declares for every scene (`GameCore::new` uses it) and the subsystem's `script_modules()` enables where it runs. **The scene's subsystems are built before its scripts load** (`subsystems_build`, in `start_scene_systems` just before `load_scripts_from_world`; then `enable_script_modules`), so `on_init` can call their modules, as a capture's always could; `scene_loaded` still comes last. Hooks: `lasts()` (`Lasts::Scene`, the default, built at `enter_scene` only if the scene uses it and dropped after its unload; `Lasts::Run`: the host's, the expression feed), `scene_loaded` (last step of `enter_scene`), `scene_unloading` (after `on_scene_exit`, before teardown clears anything), `update(Stage, &mut StageCtx)` at each of `Stage::UPDATES` (the host's `Stage::Clock` at the frame's very start, before the clock ticks and in place of the pad polling while a subsystem holds the pads, then `game_core::step`'s; a capture has no `Clock`), `script_command` (before `apply_all`; true takes it), `on_key(KeyPress, &mut StageCtx)` (first in `handle_debug_key`), `on_input(PlayerInput::Click | Escape, ..)` (before egui and the game, and a real Escape before `Escape::decide`), `pre_render(&mut RenderCtx)` (at render's start, after the renderer's default boil), `post_encode(&mut EncodeCtx)` (after `encode_to`, before the HUD: the encoder, frame texture, depth view, formats, renderer, world, camera, resolver), `ui(&egui::Context)` (in the HUD pass, over the game's UI), `exit_report(&ReportCtx, ..)`. Contexts lend fields one by one through `stage_ctx!` / `scene_ctx!` (world, clock, input (`&mut`), script, camera, renderer, gpu, the procgen resolver, project, scene path, pixels per point, cursor, panels, the frame's `requests` (`core.script_requests`, which a subsystem fills before the drain: the rhythm ladder's post values at `Stage::Procgen`), `audio` (the engine, `None` headless), `pads` (`subsystem::Pads`: `take()` stops the player's polling and its rumble, `give_back()` opens a fresh gilrs; `PlayerApp::pads_lent` skips `poll_gamepad_events` meanwhile), `quit` (the run's exit flag); a scene's settings, tables, `launch`, audio and pads), so the list can be walked while they are lent. A key a subsystem takes that opens or closes a panel moves the cursor as F3's do (`handle_debug_key`). Declared before `audio`; run in insertion order, torn down last added first. No subsystem: each hook returns at `is_empty`. Clients: the expression feed (`expression_feed::ExpressionSubsystem`), the music (`subsystems/music.rs`, whose subsystems are `crate::music`'s, next bullet), and living props (`living_subsystem::LivingSubsystem`: the wooze field, its clock, boil, shallow wooze, woozy grass, hand tuning, the A/B with its split in `post_encode`; a scene with props, `[living]`/`[wooze]`, `shallow_wooze` or `grass.wooze`). Its methods are `impl LivingSubsystem` in `living_tuning.rs` / `living_ab.rs`, taking a `StageCtx`; the props stay in `ProcGenResolver`. `--compare` is `LaunchOptions::compare` / `compare_at_start`, handed to each scene's subsystem and back at its unload. The living tests reach it through generated `PlayerApp` methods (`living_test_glue.rs`, test-only: `app.living()`, `app.with_living(..)`, `tick_procgen_for_test(dt)`). Not yet a hook: the living debug panel is still made in `create_scene_debug_panels` (F3 order). Tests: `player_app/subsystem_tests.rs`
- **Features** (#754, ADR 0117 decision 6; `Cargo.toml`) -- default `debug-hud`, `audio`, `gamepad`, `music`, `rhythm` (implies `music`), `living` (implies `procgen`); `procgen` and `profile` otherwise. `--no-default-features` links neither flint-music nor flint-procgen (nor flint-rhythm, flint-input-capture, flint-debug-ui): `cargo tree -p flint-player --no-default-features -e normal` shows it. `music` gates `src/music/` (lib.rs); `procgen` gates `procgen_assets.rs`, `GameCore::procgen_resolver`, the contexts' `resolver`, the disk tier and `PlayerExtension::register_generators`; `living` gates `living_*.rs`, `shallow_wooze.rs`, `SceneSettings::{living, wooze}`, `settle_scene` (main.rs, flint_web.rs, `apply_scene_settings`, `read_scene`), `HeadlessGame`'s living methods, the Living Props panel (`flint-debug-ui/living`; the workspace takes flint-debug-ui with default features off, flint-cli and flint-viewer turn it on) and `--compare`. A subsystem file stays unconditional and gates its own insides: `subsystems/living.rs` keeps its `POLICY` (`"living"`, so a state naming it registers in every build) and with the feature off has `SCRIPT_MODULES = &[]` and a `for_scene` that prints the line and makes nothing; `subsystems/music.rs` likewise. **A scene that uses a missing feature says so once at its entry** (`missing_features.rs`, compiled and tested in every build): `[music] ...` for a `music_session`, `[living] ... the scene's living props, [wooze], ... stand still`, `[procgen] ... N assets named by a spec (...) load from files` (at `stage_scene`, from `Project::list(Specs)` and each spec's `[meta] name`). flint-cli's player turns on all of them. `cave_game` has `required-features = ["procgen"]`. Check every single-feature build when changing a gate: `cargo check -p flint-player --all-targets --no-default-features --features <f>` for each, all warning-free
- **The music** (#745, ADR 0117 step 5; `src/music/`, outside `player_app/`, which names none of it) -- a scene with a `music_session` (engine schema `schemas/components/music_session.toml`, `flint_core::components::MUSIC_SESSION`; paths from the project root, `Project::root_holding`) gets `music::MusicSubsystem`: the suite validated against flint-music's contract and its stems (a failure is printed and no subsystem made), started on the shared kira manager at `scene_loaded` or, waiting for a device (the web's Begin), at the next `Stage::Clock`; its `events` script pushed into the session's scheduler and pumped each frame; at `Stage::PreScripts` `ScriptSystem::set_music(MusicClock)` for `music_beat()`/`music_bar()`/`music_section()` (flint-script `api/music.rs`), from `SuiteSession::now()` in play and from the game clock (`GameClockMusic`: the two-beat count-in, then the suite, latency 0) under `--frame-step` or with no device, so a capture lands each beat on the same frame; the stems stop (`SuiteSession::stop`, 50 ms) at `scene_unloading`, before `audio.clear()` (ADR 0017). `HeadlessGame::start_scripts` adds it too (`music::for_capture`), so `flint render --scripts --time T` reads the beat at T. A component with a `chart` in a build with the **`rhythm` feature** (default; flint-cli's player turns it on) is `music::rhythm::RhythmSubsystem` instead, around `rhythm/session.rs` (the old `music_session.rs`): it starts the `ChartSession` and takes the pads (`Pads::take`), drains the capture into input at `Stage::Clock` (and on a natural finish gives the pads back, queues the post restore, drops its panels, and with `quit_on_finish` sets `quit`), sets the `conducted_*` snapshot (`set_module_state(ConductedSnapshot)`, `music/conducted.rs`) and the music clock at `PreScripts`, and enables `conducted` (as `MusicSubsystem` does for a charted suite it doesn't judge: a capture, a build without `rhythm`, where the getters read the neutral state), merges the ladder into `requests.post` at `Procgen` (scripts' values win), adds the Music Guide / Manifest Map panels (`rhythm/guide_panel.rs`, `timeline_panel.rs`, debug-hud) at its first stage and takes Backquote, Backslash and F9 (`on_key`; with no chart the player's own arm says so). Without the feature the player links neither flint-rhythm nor flint-input-capture, and a charted suite plays as music with a console line. Tests: `music/tests.rs` (a two-bus suite with no chart, beat and bar read by a script, headless), `music::clock_tests`

## Scenes, input, touch

- **Scene transitions** -- `TransitionPhase` lifecycle with script-driven visuals; `PersistentStore` survives transitions; `GameStateMachine` pushdown automaton, each state a `StateConfig` of `Run`/`Pause` by system name (#727): `flint_runtime::state::{PHYSICS, SCRIPTS, ANIMATION, PARTICLES, AUDIO}`, read as `config.runs(PHYSICS)` in `game_core.rs`, plus each scene subsystem whose file declares a `POLICY` (`living`), which `subsystem::state_machine()` adds for the player and `flint render --scripts` alike; `register_state` errors on any other key and on `rendering`/`transparent`/`"hidden"`, which nothing implements. The frame's events are `GameCore::events` (an `EventBus`): `PhysicsSystem::fixed_update(world, dt, &mut events)` pushes contacts, extensions, style tweens and `fire_event` push directly, `collect_game_events` drains it; a transition drops only contacts (`GameEvent::is_contact`), so a script's event reaches the next scene. Tests: `player_app/event_bus_tests.rs`. `advance_transition` (`transition.rs`) ends Exiting/Entering by itself when `ScriptSystem::can_complete_transition()` is false (no loaded script names `complete_transition` or imports a module: `ScriptInstance::completes_transition`, set at load and hot reload from the AST's `Debug` form, since Rhai's walk needs `internals`; #362): Exiting loads that same frame, and Loading goes straight to Idle. A phase a script could end is ended after `TRANSITION_PHASE_TIMEOUT` (10 s game time) with a warning. Tests: `player_app/transition_tests.rs`
- **`GameCore` and the one frame order** (ADR 0117 decision 4, #725; `player_app/game_core.rs`) -- `PlayerApp::core: GameCore` holds the game with no window: the subsystems (declared first, so they drop first, and the core before `audio`), world, scene path, project, clock, physics, animation, particles, scripts, the state machine, the persistent store (`core.store`; `saves` keeps only when to write it), style tweens and the style reader's generation, the procgen resolver and `script_requests`. `PlayerApp` keeps input, the camera, the window, renderer, audio, HUD/egui, transitions, extensions and debug tools. A frame is `game_core::step(host)`, generic over `FrameHost`: `tick` ticks the clock, plays scripted input, calls `step(self)`, then `finish_frame`. The step runs the stages in order and calls the host back where presentation falls: `before_events` (transition, extensions' `pre_update`), `phase_done` (perf), `window_for_scripts` (transition phase, screen, pointer, cursor, chunks, audio clock, conducted), `listener` (FPS or script camera), `capture`, `refuses`, `host_command` (the dispatcher's), `script_ui_drawn` (HUD draw lists, world lines, world text), `sound` (before animation), `bones_posed`, `sync` (renderer sync, post overrides, quality); every hook but `lend`/`core` defaults to nothing. `lend()` returns the core and a `Lent` (input, camera, renderer and gpu as `Option`s, pixels per point, cursor, `scene_file_writable`, panels): what a stage and its `StageCtx` borrow (`GameCore::with_subsystems(lent, policy, |subsystems, ctx| ..)`). The renderer stays an `Option` in `StageCtx` and `Lent`: a host without one (a test) runs every stage; `pre_render`/`post_encode`/`ui` are presentation and only a host with a renderer calls them. A change to the frame order goes in `step`, never in `tick`. Two hosts drive it: the player and `flint render`'s `HeadlessGame` (next bullet but one); `flint playtest` (#714) is to be the third. A game binary reaches `app.core.world`, `app.core.script`, `app.core.clock`...
- **One bring-up** (#723; `player_app/scene_entry.rs`) -- startup (`finish_initialize`) and every transition (`execute_scene_transition`) bring a scene up through `enter_scene(SceneEntry::Start | Transition)`: input bindings, a fresh camera with the scene's `[camera]` over it, fonts, `stage_scene` (the renderer's share: procgen and models, splines, `reset_ambient` then the levers, `clear_skybox` then the scene's, `set_post_process_config(scene_post_config())`, terrain), the scene's debug panels, then physics, audio, animation, particles, scripts (`on_init` in a `state_scope`, then `on_scene_enter` at a transition). `Start` alone installs the text measurer and reads the save file. Settings come from the file through `apply_scene_settings` (every host calls it, and `install_scene` does at a transition), which **replaces** each one: a block the scene doesn't author is the default, never the last scene's. Never add an `if let Some` that only sets: reset first. `scene_post_config()` returns a `PostProcessConfig` (the defaults for no block), not an `Option`. A transition reads its target first (`read_scene`) and tears down only once it has parsed: a failure logs `scene '<target>' failed to load from <path>: <why>`, keeps the scene playing, goes on to `Entering` when a script can call `complete_transition()` (else straight to `Idle`, #362), and sets `scene_failure`, which `run_failure` reports so the binary exits non-zero. Per-scene state a teardown must drop lives in `teardown_current_scene` (style tweens, `post.mode_was_active`, world texts...): a new field that names entities or one scene's settings goes there too, unless it belongs to a subsystem, whose `scene_unloading` drops it. Tests: `player_app/scene_entry_tests.rs` (a scene with post, skybox, ambient, ortho camera and input config to one with none, headless and on a `HeadlessContext` handed over as `test_gpu`; a missing target)
- **Save data** (#726; `player_app/persist.rs`, `flint_runtime::persist`, `flint_runtime::atomic_file`) -- the `persist_*` store's place is decided once, in `load_persistent_store` (startup, after the input config, before scripts), as a `SaveFiles` (`SaveFiles::locate(project, scene, input_game_id, save_dir, config_dir)`) installed in the store as its `SaveBackend`; nothing re-derives it at a transition. In order: `--save-dir <dir>` (`PlayerApp::save_dir`; `<dir>/<slot>.toml`, no other read); a game with an id (`[project] id`, else the input config's `game_id` unless empty or `flint`) -> `<config>/<id>/saves/<slot>.toml` under `user_files::config_dir()`; no id, or one `user_folder_name` refuses -> `<Project::root_for>/save/persist.toml` as before, named slots `save/<slot>.toml`. Android always takes the in-project rule (the scene's `files` ancestor, `save_root`; unbuilt here, code path unchanged). Web: default slot `flint:/config/flint/save_<id>.toml` (the entry #104 made), named slots `/config/flint/saves_<id>/<slot>.toml`. The default slot is `default.toml`, except in-project where it is `persist.toml`. TEMPORARY, one release: `SaveFiles::old_places` (default slot only: `<root>/save/persist.toml`, then `old_persist_path`; on the web the entry keyed on the input `game_id`), read when the slot has no file, marked dirty so the debounce writes the new place, old file untouched, one `warn`. **Writes** all go through `user_files::write` = `flint_runtime::atomic_file::write`: `<file>.tmp`, `sync_all`, rename over the target (replaces on Windows; a refused rename removes the temp and returns the error); about 4 ms a save on this machine against 0.2 ms for the old in-place write, on the frame thread, at most once a second. **A file that doesn't parse** is `user_files::set_aside` -> `<file>.bak`, then `.bak.1`, `.bak.2` (first free; never replaces), logged at `error` with both paths, `PersistentStore::corrupt()` set (`persist_corrupt()` in Rhai); if it can't be moved, `write_blocked` refuses saves to that slot for the run. A save failure is logged once per message (`persist_save_error`), not every second. **Slots**: `PersistentStore::open_slot(name)` (name checked by `check_slot_name`: `[a-z0-9_-]{1,32}`, not `persist` or a Windows device) saves the slot held if dirty (a failure refuses the switch), then loads; the run starts in `default`. **Version**: `[meta] version` in the file (absent = 0, written only when non-zero or the game has a key `meta`, which is saved as `meta.key_meta`); the game's is `[project] save_version` (`set_game_version`); a lower loaded version sets `pending_migration`, and `ScriptEngine::migrate_persistent_store` (called from `ScriptSystem::initialize` and `update`, after scripts load and before `on_init`) calls `on_persist_migrate(from)` then `finish_migration`. A `PlayerApp` that never loaded a store (headless tests) has no backend and saves nothing. In this crate's unit tests `user_files::config_dir()` is a temp folder, and `PlayerApp::user_config_dir` lets a test name its own
- **Input system** -- TOML-based `InputConfig` with layered loading (built-in -> game -> user overrides -> CLI); keyboard/mouse/gamepad/touch unified via `Binding` enum
- **Pads and rumble** (#748) -- `gilrs: Option<Gilrs>` is `flint_runtime::pad`'s, none of it through flint-input-capture (that crate is the rhythm session's alone, `music/rhythm/session.rs`, behind the `rhythm` feature). A script's `rumble(pad, strength, seconds)` is `ScriptCommand::Rumble` -> `ScriptHost::rumble` -> `PadRumble::rumble` (flint-runtime's `rumble.rs`), which holds each gilrs `Effect` until its time is up (`poll_gamepad_events` lets go of the finished ones); no `gilrs` (no backend, a build without `gamepad`) or a subsystem holding the pads (the rhythm session: `Pads::take`, `stop_all` then `gilrs = None`), and it does nothing. Headless captures list it presentation-only
- **On-screen touch controls** (#133) -- an input config's `[touch_controls]` block (sticks, buttons, look region, menu; a later layer's block replaces the whole) is evaluated by `flint_runtime::TouchControls` inside `InputState` and painted by the player (`touch_overlay.rs`) on its own Foreground egui layer. The one engine-drawn UI, since a stick is a device: a finger on a stick/button skips egui and extensions (`taken_before_the_game`), is held by touch id and never reaches scripts' touch list; look drags feed `raw_mouse_delta` and are shared. Shown after a real touch, hidden by a key or pad (`--touch-controls auto|always|never`, web `?touch=`); geometry in points inside the web page's safe-area insets. `--input-script` has `touch`/`drag`/`lift`. A button's `value` (default 1; -1 drives an axis's other end) and scripts' `set_touch_controls(false)` (put away under a menu so taps reach it, #134); a finger counts for `any_input_just_pressed`. Scripts read the same insets with `safe_area()` (`TouchControls::insets`) and `is_touch_device()` (`InputState::touch_device`: `pointer: coarse` or Android, from frame one; #660), and flint-player's `--safe-area L,T,R,B` / `--touch-device` stand in on a desktop. `?perf=1`'s panel takes pointer events only on its Copy button. The shipped games' layouts live in their repos (Float, FlintKart `config/input.toml`). Book: concepts/touch-controls.md, guides/playing-on-mobile.md
- A character always starts facing +Z (there's no starting yaw), so lay a scene's way in along it. It reads mouse look inside the fixed-step loop, so a frame of two physics steps turns it twice as far: `--input-script` routes with `look` need `--frame-step 0.0166667`, not 1/30

## `flint play` window flags

   Window flags (#611; `flint_player::WindowArgs`, flattened into `flint play` and `flint-player`, applied in `create_window`): `--width`/`--height` (physical px, default 1280x720, the size is `PlayerApp::window_size`), `--position X,Y` (outer top-left, physical desktop px; negatives as `--position=-1920,0`), `--borderless`, `--always-on-top`, `--no-activate` (opens without taking the keyboard, `with_active(false)`; refuses `--fullscreen`, since winit's fullscreen path on Windows presses Alt to take the foreground). Esc exits and Alt+F4 closes a borderless window. A game embedding `PlayerApp` sets `window_options`.

## Capture, perf, pacing

- **Script commands: one dispatcher, the core's** (ADR 0116 decision 4, #697; #725) -- `game_core::dispatch(host)` drains the scripts' commands twice a frame (after the physics steps: what `on_update` asked, so the camera is set before `on_draw_ui`, style tweens stepping just before; and after `on_draw_ui`). In order: `FrameHost::refuses` drops what the host won't do (a capture's `PRESENTATION_ONLY`), each subsystem's `script_command` takes its own (`ScriptCommand::Module` with a `LivingCommand` payload: living, wooze, debug), then each command goes through `flint_script::host::apply` (the one `match`; recipe for a new command: `crates/flint-script/CLAUDE.md`) either to `CoreCommands` (`game_core.rs`: events, particles, entity styles and tweens, post styles and style history on the lent renderer, the frame requests, time scale, states, 2D velocity, and `module_command`, a module command whose subsystem went with its scene) or, when `game_core::for_the_host` says it's the presentation's (sound, rumble, camera-cut detection, `set_look`, `set_quality`, `reset_post_style`, scenes, chunks, quit, `transition_complete`), to `FrameHost::host_command`: `impl ScriptHost for PlayerApp` (`script_commands.rs`) holds only those. A new command that changes the game goes in `CoreCommands`; one that is the window's goes in `for_the_host` and each host. The one-value-a-frame requests (`SetCamera`, `SetPostProcess`, `SetFogColor`, `SetRenderMode`, `SetLodScales`, `SetAudioLowpass`, `SetTouchControls`, `SetCursorCaptured`) wait in `core.script_requests` for the step that applies each; `SetQuality` in `quality.script_request`. **The headless host** is `HeadlessGame` (`headless_game.rs`, what `flint render` steps): a `GameCore` and `CaptureFrame`, its `FrameHost` for a step (`capture()` true: no physics, the core's animation and IK skipped for `--anim-time`'s `HeadlessAnimation`, stepped in `bones_posed`, particles stepped by the stage on their fixed step, state changes to the log, not stdout). It refuses `PRESENTATION_ONLY` (`Skipped { command, why }`; `why: None` is dropped without a note: sound, low-pass, cursor, touch) and particle commands while the capture draws none, noting each once (`notes()`); takes `set_look` as a request the stage lays at capture (`take_look_request`), `set_quality` at once, the post overrides into `look()` at its `sync`, and the distance levers onto the renderer there. Living props run in the player's `LivingSubsystem`, built by `for_capture(field, moment)` (`capture: Some(Capture)`: poses made at once by `step_living_now`, blended at capture by `upload_living`, shallow wooze only in a moment); `boil`, `apply_grass`, `wooze` and `living_props` read it. `headless_host_tests.rs` holds every variant to done or on the list
- **`HeadlessAnimation`** (#307, `player_app/headless_animation.rs`) -- the player's animation load (`register_skeletal_data`, node clips, `.anim.toml`, sprite clips, sequences: each loader has a `_saying` form that hands its lines to a closure instead of stdout, which `flint render --report json` keeps for JSON) and the animation share of a frame (`update`, `publish_bone_probes`, `run_ik`), on a clock the caller keeps; `flint render --anim-time`. `publish_bone_probes` is the player's own, moved out of `frame.rs`. Cues and sprite ends are counted and dropped
- Offline capture: `flint-player --frame-step S` advances the clock exactly S seconds per frame (wall time ignored) and seeds scripts' `random()` with `flint render --scripts`'s seed (`--seed N` for another; `ScriptSystem::seed_random`, #635; unseeded it is the same SplitMix64 started from the clock once, and Rhai's `seed_random(n)` reseeds it, #580), and with `--screenshot-every S` every frame is written; `--input-script FILE` plays timed `down`/`up`/`tap` keys, `axis` values and gamepad `press`/`release` (on pad slot 9) at game times (format in `player_app/input_script.rs`); a scripted key also goes through the debug keys (`handle_debug_key`), so `tap F2` opens the stats overlay, and `--stats` opens it from the first frame. A debug key with nothing to act on (F3 with no panels, F4 with no renderer, the music keys with no chart playing, F8 with no prop) calls `hud.key_note.say(key, text)` (`player_app/key_note.rs`, #367; a subsystem's is `ctx.note`): a `[debug] <key>: <text>` console line and a note at the window's top centre held 1.6 s and faded over 0.6 s on egui's clock. Never `tracing::info!` for a key's answer: the player's filter doesn't print it. Together they make deterministic, smooth gameplay footage and scripted regression runs; egui runs on the stepped clock too, so a menu opening lands the same frame every run. `--pixels-per-point S` pins the scale point-sized things draw at (ASCII cells, egui, HUD) instead of the window's, so a capture matches across displays, and `--look <name>` plays every scene under a look, over its own keys and the look it names, as `flint render --look` does (`flint_render::look`, #435).
- Perf switches: `flint-player --exit-after N` prints `[perf] avg ms/frame`, the spread of dt and of present-to-present times (p50/p90/p99/max and frames over 1.5x p50), and the average draw calls, entity draws, culled draws and triangles on exit; `FLINT_VSYNC=0|mailbox` picks the present mode (Fifo can pace at a virtual display's rate, e.g. 7 Hz with Virtual Desktop attached); `FLINT_FRAME_LATENCY=1..3` sets the swapchain's frame latency (default 2); `FLINT_PACING=0` turns off vsync pacing; `FLINT_SHADOWS=0` disables the shadow pass at start; `FLINT_LOD_SCALE` / `FLINT_DRAW_DISTANCE_SCALE` start the distance levers (#56: glTF `extras.flint_lod` bands per primitive, `lod.draw_distance` per entity, Rhai `set_lod_scale` / `set_draw_distance_scale`; `FLINT_LOD_SCALE=1000` holds every model at full detail; book: Rendering); `--render-scale 0.25..1|auto` draws the 3D scene at that fraction of the window on each side (HDR chain + its own depth, upscaled by the composite, depth copied back so world text/lines still test against it) under a full-resolution HUD, `auto` stepping down to hold 60 fps; the web caps the scene at DPR 1.5 by default and takes `?scale=` (#122, `SceneRenderer::set_render_scale`); `--perf` prints a line every 10 s with each frame phase's CPU time, the worst scripts and each pass's GPU time, and the web page's `?perf=1` (`?perf=cpu` without GPU timing) shows the same in a corner with a Copy line button (#120, docs/design/web.md). Both name the present mode (`RenderContext::present_mode_in_use`, an `Auto` mode resolved as wgpu-core 23 does) and say `under vsync` / `no vsync` beside the GPU time, with `at idle clocks` when the GPU was busy under 75% of the wall clock under vsync (#380, `perf.rs::gpu_vsync_note`, also on `--exit-after`'s `[perf] avg GPU`): measured 1.4x high on the RTX 4070 laptop, 5x in #270 on DX12. The share is against the mean frame, never p50: Fifo bursts here
- Vsync pacing: under Fifo the player gives `GameClock` the monitor's refresh period (`set_vsync_period`, re-read when the window moves), and `delta_time` comes in whole refresh periods that keep game time on the wall clock. On a hybrid-GPU laptop Fifo lets frames through in bursts (6, 6, 6, then 45 ms at a 60 Hz mean); paced, every frame steps 16.7 ms. Stalls over 250 ms pass through, and frames faster than the refresh on average fall back to raw time. `raw_delta_time` is the unpaced wall time. See the book's Profiling guide
- Living Props A/B (#238) is the one place a frame takes two submissions: a split (`F7`, `--compare A,B --split`) submits the shown side's drawing, then writes the other side's bones and boil and draws it with `encode_again_to` into a `SplitView` whose half is copied over the frame byte for byte (both views are the swapchain format without its sRGB suffix). Each side is a `LivingProps::fork` with its own field, boil clock and shallow wooze (`player_app/living_ab.rs`); a flip (`F6`) swaps which is the scene's own and calls `redraw_all`, since the bone buffers held the other's. Anything a blend skips because "nothing changed" has to assume nothing about the renderer: a remembered tint of 0 once kept the other side's leaf tints. `F5` freezes the living clock

## Web

- Web frame loop (#121): `flint_web.rs` runs winit with `ControlFlow::Wait` and `about_to_wait` requests a redraw, so the player draws once per `requestAnimationFrame` and the main thread sleeps between frames. Never `ControlFlow::Poll` on the web: it chains `scheduler.postTask` tasks back to back, Chrome shrugs but Firefox starved its refresh driver (83 ms frames, multi-second stalls, half the audio buffers late). `?loop=poll` brings the old loop back for comparisons
- Web player (#102): draw the swapchain through `RenderContext::frame_view` (sRGB view of a plain WebGPU canvas), never a default view. Sound and pointer lock need a gesture: the page's Begin calls `flint_player::web_begin()` (`?begin=auto` lifts the gate with no click, for `tools/web-perf/run.mjs`, the checked-in CDP driver for `?perf=1` runs, #381), and on wasm `set_cursor_captured(true)` is a wish that `sync_pointer_lock` turns into a lock while the page has activation; mouse look flows only while the lock is held. Headless Chrome never grants pointer lock, and headed Chrome only with the window focused (`Page.bringToFront`). Touch (#132): winit's web backend sends `pointerType == "touch"` as `WindowEvent::Touch` scaled by `devicePixelRatio`, and `touch_to_surface` rescales to canvas pixels (they differ under Chrome's device emulation on a scaled desktop). A `(pointer: coarse)` page asks for no pointer lock. Test with CDP `Emulation.setTouchEmulationEnabled` + `Input.dispatchTouchEvent`
- Web audio (#136): the browser mixes in an `AudioWorklet`, on the audio thread, running a second wasm (`crates/flint-audio-worklet`: kira only, no imports, `[profile.worklet]` opt-level 3, built by Trunk.toml's `pre_build` hook and copied beside the page). The pages share no memory with it (no COOP/COEP on Pages), so `AudioEngine` calls become `flint_audio::remote` commands posted once a frame and each sound crosses once as samples; handles are `engine::SoundHandle` / `SpatialTrack`. A new engine call that plays or changes sound needs a `protocol::Command` too. `?mixer=main` (or a scene with a `music_session`, which needs `manager_mut`) keeps the old main-thread cpal stream, which is also the fallback when the worklet fails
- Web size (#123): the site builds with `trunk build --release --cargo-profile web-release` (workspace `[profile.web-release]`: opt-level z, fat LTO, 1 codegen unit, panic = abort, with `opt-level = 3` package overrides for the hot crates and `+simd128` in `.cargo/config.toml` (#137); 3.6 MB gzipped, down from 5.1). Speed-build a crate only when the phone shows it hot: each override costs bytes, and the 4 MB gzip line holds. The workspace `image` dep is PNG/JPEG/HDR only and `flint-render` restores image's defaults natively, so add a format for desktop there, not in the workspace. rhai's `no_optimize`/`no_custom_syntax`/`only_i64` are on for wasm only (flint-script's Cargo.toml): web scripts see `i64` integers and nothing else. Measure a size change with trunk and record it in web.md's Size table
- play.chaps.dev (#103): `.github/workflows/play.yml` builds the player with trunk, runs `flint export web` on every game in `tools/play-site/games.toml` (each pinned to a commit; `build.py` passes games.toml's words as `--meta`), and deploys this repo's Pages from Actions. `?game=<id>` plays `games/<id>/<id>.flintpack`; `?embed=1` is the iframe view. `index.html`'s doorway shows the chooser, or the game's film when WebGPU is missing, before any wasm loads: `Trunk.toml`'s loader awaits `window.flintDoorway` and preloads only the JS glue. Keep the two together, or a browser that can't play downloads 7 MB of wasm (docs/design/web.md)
- **Looks, user styles and fonts take the player's project too** (ADR 0114 step 3, the last group, #706) -- `asset_scope()` (refreshes the project first: right before the renderer exists and straight after a transition) and `kept_asset_scope()` (the project as last found, for a poll) give the `AssetScope` that `load_user_styles_in`, `scene_post_process_in`, `look::resolve_in`, `reload_changed_for`, the F4 panels (`set_asset_scope` / `with_asset_scope`) and the renderer (`set_asset_scope` at init and each transition) search from. `fonts::ProjectFonts::find(project, scene_dir)` is the HUD's fonts: `project.list(AssetKind::FontFaces, ..)` (every `fonts/` the scene sees, nearest of a name) and the nearest `fonts/fonts.toml` (`AssetKind::Files`); `hud.fonts_root` holds the last set read, so a transition re-reads only when the files differ. `load_user_styles(path)` and `project_font_definitions(path)` keep their signatures for games and find the project themselves (`scene_loading::scene_post_process(..)`, the path-taking form, went with the old transition, #723)
- **The player's asset searches go through `self.project`** (ADR 0114 step 3, #706) -- `refresh_project()` runs before the first model load and at each transition; `build_model_load_config(&project, ..)` (models, textures; says the catalog and procgen were asked first), `load_ui_texture` (`AssetKind::Sprites`; a miss is warned once per scene folder and name, since a draw command asks every frame), `load_animations_from_world` / `load_sprite_animations_from_world` / `load_sequences_from_world` (`visible_files`: `Project::list`, farthest folder first so the nearest file's clips are registered last and win) and `load_audio_from_world` (`resolve` for an `audio_source.file`, `list` for the preload, each kept as `audio/<file name>`) all take the project. `procgen_assets::AssetSink::missing_file` gives the placeholder outcome its paths tried. Tests: `player_app/asset_search_tests.rs` (a scene two folders deep, per kind). The second group is on it too: scripts (`load_scripts_from_world(&project, ..)`; a chunk's through `ScriptSystem::load_script_named` from the chunk's folder then the scene's, with its own TEMPORARY old-rule compare in `transition.rs`), specs (`procgen_assets::discover_specs(resolver, &project, scene)` indexes `project.list(AssetKind::Specs, ..)`, one file a `[meta] name`, the nearest; `resolve_scene` takes the project from the sink's `ModelLoadConfig`; `spec_dirs` is gone), wooze presets (`flint_procgen::list_presets_in` / `write_preset_in` with `self.project`; `find_preset` discovers it from the scene), the input config's game layer (`input_config::resolve_input_paths(&project, ..)`: the scene's `input_config`, else the manifest's `[project] input` from the root, else `config/input.toml`, the first and last through `AssetKind::Files`), the skybox, terrain heightmap and splat map, grass mask and spline files (`Project::file_or_beside`; the free loaders `load_terrain`, `load_scene_grass_ground` and `spline_gen` discover the project from the scene path rather than take one), particle textures (`flint_render::load_scene_particle_textures`) and a transition's target (`resolve_scene_path(&project, current, target)`, `AssetKind::Scenes`; a target the search doesn't find is returned as written, a path from the working directory, and only then warned about if that isn't there either). Still on guesses of their own, deliberately: fonts and the style assets (next), `procgen_disk_config`'s root, `persist.rs`'s root, `music_session`'s base directory (the scene directory's parent) and `.flint/input.user.toml` beside the scene. **Paths from the project root** (#706, the last step): the save file (`persist.rs`), the procgen disk cache (`init.rs::procgen_disk_config`), `music_session`'s base (`music::base_dir`) and the project-local input override all ask `self.project.root_for(scene_dir)`; never derive a root from `scene_path` (`flint_core::project::guessed_root` is the one copy of that guess, see `crates/flint-core/CLAUDE.md`). `flint-player` with no scene opens `Project::default_scene()`
- **The schema registry is read once and kept** (ADR 0115, #683; `player_app/schemas.rs`, `HeldSchemas`) -- a host hands over the registry it loaded the first scene with: `app.set_schemas(registry, schema_dirs)` (`flint-player`, `flint play`, the web player, whose registry is the compiled-in engine schemas under the bundle's). `load_chunk` uses it as it is (`held_or_read`); a transition asks `schema_dirs.for_scene(next)` as before and then `HeldSchemas::for_dirs`: the same directory list is no read, a list that grew (a discovered or host list) loads only the added directories over a clone of what is held, and another list (another project's manifest) is read whole. **A read that fails logs an error and returns the registry held**, so a scene never loads with an empty one (it used to: `schemas_for_scene` fell back to `SchemaRegistry::new()` and archetype and schema defaults vanished). `set_schema_dirs` / `set_schema_paths` alone (flint-android, an embedding game) still work: the directories are read on first use, once. Consequence: a schema file edited while the game runs is not seen by the next transition. Scene diagnostics at load come from `flint_scene::load_scene` itself (one summary line and the first five through `tracing::warn!`, at start and at each transition) and from `load_chunk` for a chunk; nothing in the player calls `diagnose` directly
