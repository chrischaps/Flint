# flint-player: extensions, UI, input, capture, perf, web (moved out of the root CLAUDE.md by #755)

The input system and touch controls are evaluated in flint-runtime; their notes are here beside the player that drives them. Web audio's code is in flint-audio (`crates/flint-audio/CLAUDE.md` has the audio clock). Android has one note, in the root file's gotchas (`cargo ndk -p flint-android`). `flint export web`: `crates/flint-cli/CLAUDE.md`. The showcase film rig: `tools/showcase/CLAUDE.md`.

## Extensions and script UI

- **Player extensions** (ADRs 0071-0075) -- a game binary embeds `PlayerApp` and installs `PlayerExtension`s (`add_extension`): `register_script_api` (native Rhai fns; same signature replaces Flint's), `pre_update(ExtensionCtx)` before scripts' `on_update` (world, clock, input, last frame's camera, `gpu` for `upload_mesh`/`remove_mesh`, `attach_mesh`, `fire_event` -> scripts' `on_event` same frame, and `scene_table(name)` / `scene_table_as::<T>(name)` / `scene_tables`: the current scene's top-level tables as written, #686, from `PlayerApp::scene_tables`, which a host sets with `SceneFile::scene_tables()` and a transition replaces; `apply_scene_settings` also settles living props' `[living]` / `[wooze]` on a copy, `flint_procgen::settle_scene`, so a preset the scene names is filled in for a game binary too; a game declares its own as `[table.<name>]` in its `schemas/scene/`), `on_window_event` (only input events consumable) and `ui(&mut egui::Ui)` drawn between script UI and the Foreground debug panels: the frame's root `Ui` from `run_ui`, eframe's `App::ui` shape (ADR 0121, #959), so panels show on it and windows from it (`Ui` derefs to `Context`). The frame calls `extension::draw_ui`, which goes through the deprecated `root_ui` (#946's hook, default calls `ui`) so a game still overriding it draws; rustc doesn't warn on implementing a deprecated trait method. Tests: `extension_tests.rs` `a_games_side_panel_*`, `a_games_floating_window_*` (two frames: a window's first is egui's invisible sizing pass). `examples/cave_game` draws a panel and a window through it. `fonts(&mut FontDefinitions)` edits egui's fonts before each install (ADR 0081); `fonts/fonts.toml` `[egui] proportional/monospace` names egui's default faces, and every named family falls back to egui's fonts. With any extension installed, egui sees input first; a release follows its press. Runtime meshes are frustum-culled per draw by their AABBs (every game). Picking: `Camera::screen_to_ground` / Rhai `screen_to_ground`. Book: guides/player-extensions.md
- **Extension hooks of the subsystems' shape** (ADR 0117 decision 5, #754; `extension.rs`) -- `PlayerExtension` has `update(Stage, &mut ExtensionCtx)` (`Stage` is the subsystems' enum, `pub` and `#[non_exhaustive]`, re-exported as `flint_player::Stage`; called by `game_core::run_stage` through `FrameHost::extensions_at` right after the subsystems, at every stage they hear, `Clock` included), `scene_loaded` / `scene_unloading` (from `subsystems_enter_scene`, after the subsystems, and `subsystems_leave_scene`, before them), `script_command(&ScriptCommand, ctx) -> bool` (`dispatch_commands` asks `FrameHost::extension_takes` after the subsystems pass) and `script_modules() -> &[&'static dyn ScriptModule]` (declared in `add_extension` and kept in `GameCore::extension_modules`, which `enable_script_modules` unions with the subsystems' every time it sets the enabled list, so a scene's entry no longer drops them). All default to nothing. Every hook goes through `PlayerApp::each_extension(f)` (frame.rs), which builds the `ExtensionCtx` (now with a private `script` for `ExtensionCtx::set_module_state<T>`) and returns at `extensions.is_empty()`. A capture (`HeadlessGame`) has no extensions: `flint render` links no game's Rust. Not exposed, as no game has needed them yet: `on_input`, `pre_render`, `post_encode`, `exit_report`, a policy name. Tests: `player_app/extension_hooks_tests.rs` (`Laps`, a module read at `PreScripts` and a command it takes; every stage after a `Probe` subsystem; a transition keeps the module)
- **A game's procgen generators** (ADR 0119, #195) -- `PlayerExtension::register_generators(&mut GeneratorRegistry)`, called once from `add_extension` with `procgen_resolver.registry_mut()` (built-ins already in; same name replaces one). The disk tier rebuilds the resolver after extensions are added, so `PlayerApp::use_procgen_disk` moves the registry across (`mem::take` into `ProcGenResolver::with_registry`): never rebuild the resolver with `with_config`, which drops a game's generators. Player only: `flint gen`/`edit`/`render` and `HeadlessGame::resolve_procgen` build from the built-ins. Example game binary: `crates/flint-player/examples/cave_game/` (`rock_v1`; `--screenshot <png>`). Tests: `procgen_assets_tests.rs` `a_games_generator*`
- **A game's Rust styles** (#419) -- `PlayerExtension::styles() -> Vec<&'static StyleDescriptor>`, registered by `add_extension` through `flint_render::stylize::register` (a refusal is a `tracing::error!`, the rest still register). It works even after `apply_scene_settings`, because `scene.post_process` keeps the def and `scene_post_config()` reads its tables (and `launch.style_specs`) against the registry only when the renderer is made. Example game binary: `crates/flint-player/examples/cyanotype/` (`--style`, `--scene`, `--input-script`, `--screenshot [--at]`). Test: `extension_tests.rs` `game_styles`. Detail: `crates/flint-render/src/stylize/CLAUDE.md`
- **All game UI is script-driven** -- no hardcoded HUD; `hud_controller` entity + `hud.rhai` pattern; engine provides draw primitives (`draw_text/rect/circle/line/sprite`), scripts compose UI. Text `stroke` up to 2 pt is eight offset copies; wider, and any `glow: [r,g,b,a,radius]` (`.style.toml` `glow_color`/`glow_radius`), is one CPU-rasterised picture from egui's font atlas (distance band + blur), cached per label (`player_app/text_halo.rs`, #626; golden `crates/flint-player/tests/golden/text-halo-neon-60.png`, `FLINT_BLESS=1`)
- `render_draw_commands()` is a free function to avoid borrow conflicts; `load_pending_sprites()` before egui borrow
- **The HUD headless** (#731; `player_app/headless_hud.rs`, `flint_player::HeadlessHud`, native only) -- the player's painter (`render_draw_commands`) with the project's fonts (`ProjectFonts::find`) and sprites (`AssetKind::Sprites`), an `egui_wgpu::Renderer` for the target's format without its sRGB suffix (as the player's `hud_view`, so colours blend in display space), egui on a clock of 0; one empty pass at `new` builds the fonts and uploads the atlas, so `measurer()` (`fonts::text_measurer(ctx, None)`, the one closure the player's `install_text_measurer` uses too) is real from the first script. `HeadlessGame::script_ui_drawn` keeps the step's draw calls plus `generate_ui_draw_commands` as `hud()` (it used to drop them with a note); `set_text_measurer`, `with_ui`. `flint render`'s use: `crates/flint-cli/CLAUDE.md`
- Screen size for draw commands must be egui logical points, NOT physical pixels
- The HUD blends in display space. Since egui 0.31 `Color32::from_white_alpha` / `from_rgba_unmultiplied` (and `ColorImage::from_rgba_unmultiplied`) premultiply in display values, so a translucent colour built with them blends as written; egui 0.30 premultiplied in linear light, and a translucent white read several times too bright. **Scripts take 0.36's blend too** (#958; #945 had kept 0.30's bytes behind a shim, now gone): their `draw_*` colours and world text (`hud_render::to_color32`, which is `from_rgba_unmultiplied`), text halos (`text_halo.rs`'s `premul`, through `to_color32`) and HUD sprites (`ColorImage::from_rgba_unmultiplied` in `load_ui_texture`). A 50% white over black is 128, where 0.30 drew 188; a game gets a light colour's old look back with alpha^(1/2.2), and a dark one is unchanged (the book's Upgrading the Engine page, HUD colours). Flint's own Rust UI (overlays, touch controls) uses egui's constructors or `from_rgba_premultiplied`. "Display space" holds only in a pass drawn into `RenderContext::hud_view(&texture)` with an `egui_wgpu::Renderer` built for `hud_format` (the player and, since #428, the scene viewer): into the swapchain's sRGB view egui-wgpu blends in linear light, and a 90% charcoal card over a 210 sky measured 73 instead of 35. The model previewer, procgen, terrain, texture and particle editors still draw into the sRGB view
- **A test's egui frame is `flint_debug_ui::run_headless_frame(ctx, input, |ui| ..)`** (#944), never `ctx.run_ui`: the closure gets the frame's root `egui::Ui` (`ui.ctx()` for the context; egui 0.36 has no `Context::run`, #945), and it returns the `FullOutput` with its texture updates cleared, since nothing uploads a test's textures and egui 0.36 asserts in debug builds when a `FullOutput` drops with them (55 of the 60 tests that failed on spike #934's egui 0.36 branch). flint-player takes flint-debug-ui as a dev-dependency for it, whatever the features. Clippy refuses a bare `egui::Context::run_ui` (the workspace `clippy.toml`). A real frame (the player, the viewer, the CLI's windows) allows it, and clears `full_output.textures_delta` after uploading and freeing ("Applied above"); a new egui host does the same, and takes its swapchain frame before running egui, so a frame it can't get never drops egui's texture updates unapplied (`tex_edit`, #945)

- **`PlayerApp`'s fields are grouped** (#724, ADR 0117 step 1; `player_app/state.rs`) -- about 45 top-level fields, each a part: `launch` (`LaunchOptions`, pub: what the host set before `run_app`, the CLI flags), `scene` (`SceneSettings`, pub: what the scene file says, replaced whole by `apply_scene_settings`), `post` (`PostOverrides`: scripts' post values this frame, `take_from` the frame requests, `any`, `stamp` over the config), `subsystems` (declared first: the optional features, see Subsystems; `[living]`/`[wooze]` settings are in `scene`, their state in `LivingSubsystem`), `hud` (egui, draw commands, world text, fonts), `stats` (F2 + perf readout), `saves`, `outcome` (exit request, init and scene failures), `style`, `input_layers`, `focus`, `quality`, `assets`. A new field goes into the group it belongs to, not on `PlayerApp`. Games set `app.launch.*` and `app.scene.*` (changelog)

- **Subsystems** (ADR 0117 step 3, #724; `player_app/subsystem.rs`) -- an optional feature is a `Subsystem` (internal trait, `: Any`) in `GameCore::subsystems`, not fields and inline calls. **Adding one is one new file** in `player_app/subsystems/` with a `pub(crate) fn for_scene(&mut SceneCtx) -> Option<Box<dyn Subsystem>>`: `build.rs` lists every file there as a module and its builder (`$OUT_DIR/subsystems.rs`, file-name order; a file with `#![cfg(test)]` is listed in tests only, as `subsystems/toy.rs` is), and nothing else is edited. Each file also declares `pub(crate) const POLICY: Option<&str>`: the name a game state pauses it by (`Some(LivingSubsystem::NAME)`, `"living"`) or `None`; the subsystem then reads it as `ctx.runs(self.name())` (#727); and `pub(crate) const SCRIPT_MODULES: &[&dyn ScriptModule]`, the script modules it owns (#698: `living.rs` the `wooze`, `living` and `debug` of `living_api.rs`, `music.rs` the `conducted` of `music/conducted.rs`, `&[]` for none), which `flint_player::script_system()` declares for every scene (`GameCore::new` uses it) and the subsystem's `script_modules()` enables where it runs; and `pub(crate) const DEBUG_KEYS: flint_runtime::DebugKeyGroup` (#717: owner, when, keys; `subsystem_debug_keys()`, an empty `keys` for none), the debug keys its subsystem returns from `debug_keys()`. **The scene's subsystems are built before its scripts load** (`subsystems_build`, in `start_scene_systems` just before `load_scripts_from_world`; then `enable_script_modules`), so `on_init` can call their modules, as a capture's always could; `scene_loaded` still comes last. Hooks: `lasts()` (`Lasts::Scene`, the default, built at `enter_scene` only if the scene uses it and dropped after its unload; `Lasts::Run`: the host's, the expression feed), `scene_loaded` (last step of `enter_scene`), `scene_unloading` (after `on_scene_exit`, before teardown clears anything), `update(Stage, &mut StageCtx)` at each of `Stage::UPDATES` (the host's `Stage::Clock` at the frame's very start, before the clock ticks and in place of the pad polling while a subsystem holds the pads, then `game_core::step`'s; a capture has no `Clock`), `script_command` (before `apply_all`; true takes it), `debug_keys()` / `on_debug_key(action, key, &mut StageCtx)` (its file's `DEBUG_KEYS.keys`, dispatched by the debug-key table while it is in the scene; see Debug keys), `on_input(PlayerInput::Click | Escape, ..)` (before egui and the game, and a real Escape before `Escape::decide`), `frame_inputs(&FrameCtx, &mut FrameInputs)` (its share of the renderer's frame inputs, gathered right before `prepare` in `sync_renderer`: the living subsystem's boil, shallow wooze and woozy grass, #739), `post_encode(&mut EncodeCtx)` (after `encode_to`, before the HUD: the encoder, frame texture, depth view, formats, renderer, world, camera, resolver), `ui(&egui::Context)` (in the HUD pass, over the game's UI), `exit_report(&ReportCtx, ..)`. Contexts lend fields one by one through `stage_ctx!` / `scene_ctx!` (world, clock, input (`&mut`), script, camera, renderer, gpu, the procgen resolver, project, scene path, pixels per point, cursor, panels, the frame's `requests` (`core.script_requests`, which a subsystem fills before the drain: the rhythm ladder's post values at `Stage::Procgen`), `audio` (the engine, `None` headless), `pads` (`subsystem::Pads`: `take()` stops the player's polling and its rumble, `give_back()` opens a fresh gilrs; `PlayerApp::pads_lent` skips `poll_gamepad_events` meanwhile), `quit` (the run's exit flag); a scene's settings, tables, `launch`, audio and pads), so the list can be walked while they are lent. A subsystem's debug key that opens or closes a panel moves the cursor as F3's do (`handle_debug_key`). Declared before `audio`; run in insertion order, torn down last added first. No subsystem: each hook returns at `is_empty`. Clients: the expression feed (`expression_feed::ExpressionSubsystem`), the music (`subsystems/music.rs`, whose subsystems are `crate::music`'s, next bullet), and living props (`living_subsystem::LivingSubsystem`: the wooze field, its clock, boil, shallow wooze, woozy grass, hand tuning, the A/B with its split in `post_encode`; a scene with props, `[living]`/`[wooze]`, `shallow_wooze` or `grass.wooze`). Its methods are `impl LivingSubsystem` in `living_tuning.rs` / `living_ab.rs`, taking a `StageCtx`; the props stay in `ProcGenResolver`. `--compare` is `LaunchOptions::compare` / `compare_at_start`, handed to each scene's subsystem and back at its unload. The living tests reach it through generated `PlayerApp` methods (`living_test_glue.rs`, test-only: `app.living()`, `app.with_living(..)`, `tick_procgen_for_test(dt)`). Not yet a hook: the living debug panel is still made in `create_scene_debug_panels` (F3 order). Tests: `player_app/subsystem_tests.rs`
- **Features** (#754, ADR 0117 decision 6; `Cargo.toml`) -- default `debug-hud`, `audio`, `gamepad`, `music`, `rhythm` (implies `music`), `living` (implies `procgen`), `frame-history` (#1076, next section); `procgen` and `profile` otherwise. `--no-default-features` links neither flint-music nor flint-procgen (nor flint-rhythm, flint-input-capture, flint-debug-ui): `cargo tree -p flint-player --no-default-features -e normal` shows it. `music` gates `src/music/` (lib.rs); `procgen` gates `procgen_assets.rs`, `GameCore::procgen_resolver`, the contexts' `resolver`, the disk tier and `PlayerExtension::register_generators`; `living` gates `living_*.rs`, `SceneSettings::{living, wooze}`, `settle_scene` (main.rs, flint_web.rs, `apply_scene_settings`, `read_scene`), `HeadlessGame`'s living methods, the Living Props panel (`flint-debug-ui/living`; the workspace takes flint-debug-ui with default features off, flint-cli and flint-viewer turn it on) and `--compare`. A subsystem file stays unconditional and gates its own insides: `subsystems/living.rs` keeps its `POLICY` (`"living"`, so a state naming it registers in every build) and with the feature off has `SCRIPT_MODULES = &[]` and a `for_scene` that prints the line and makes nothing; `subsystems/music.rs` likewise. **A scene that uses a missing feature says so once at its entry** (`missing_features.rs`, compiled and tested in every build): `[music] ...` for a `music_session`, `[living] ... the scene's living props, [wooze], ... stand still`, `[procgen] ... N assets named by a spec (...) load from files` (at `stage_scene`, from `Project::list(Specs)` and each spec's `[meta] name`). flint-cli's player turns on all of them. `cave_game` has `required-features = ["procgen"]`. Check every single-feature build when changing a gate: `cargo check -p flint-player --all-targets --no-default-features --features <f>` for each, all warning-free
- **The music** (#745, ADR 0117 step 5; `src/music/`, outside `player_app/`, which names none of it) -- a scene with a `music_session` (engine schema `schemas/components/music_session.toml`, `flint_core::components::MUSIC_SESSION`; paths from the project root, `Project::root_holding`) gets `music::MusicSubsystem`: the suite validated against flint-music's contract and its stems (a failure is printed and no subsystem made), started on the shared kira manager at `scene_loaded` or, waiting for a device (the web's Begin), at the next `Stage::Clock`; its `events` script pushed into the session's scheduler and pumped each frame; at `Stage::PreScripts` `ScriptSystem::set_music(MusicClock)` for `music_beat()`/`music_bar()`/`music_section()` (flint-script `api/music.rs`), from `SuiteSession::now()` in play and from the game clock (`GameClockMusic`: the two-beat count-in, then the suite, latency 0) under `--frame-step` or with no device, so a capture lands each beat on the same frame; the stems stop (`SuiteSession::stop`, 50 ms) at `scene_unloading`, before `audio.clear()` (ADR 0017). `HeadlessGame::start_scripts` adds it too (`music::for_capture`), so `flint render --scripts --time T` reads the beat at T. A component with a `chart` in a build with the **`rhythm` feature** (default; flint-cli's player turns it on) is `music::rhythm::RhythmSubsystem` instead, around `rhythm/session.rs` (the old `music_session.rs`): it starts the `ChartSession` and takes the pads (`Pads::take`), drains the capture into input at `Stage::Clock` (and on a natural finish gives the pads back, queues the post restore, drops its panels, and with `quit_on_finish` sets `quit`), sets the `conducted_*` snapshot (`set_module_state(ConductedSnapshot)`, `music/conducted.rs`) and the music clock at `PreScripts`, and enables `conducted` (as `MusicSubsystem` does for a charted suite it doesn't judge: a capture, a build without `rhythm`, where the getters read the neutral state), merges the ladder into `requests.post` at `Procgen` (scripts' values win), adds the Music Guide / Manifest Map panels (`rhythm/guide_panel.rs`, `timeline_panel.rs`, debug-hud) at its first stage and declares `music_guide` (Backquote), `manifest_map` (Backslash) and `music_force_fail` (F9) (`rhythm::DEBUG_KEYS`, debug-hud; with no charted session they are the game's). Without the feature the player links neither flint-rhythm nor flint-input-capture, and a charted suite plays as music with a console line. Tests: `music/tests.rs` (a two-bus suite with no chart, beat and bar read by a script, headless), `music::clock_tests`

- **Debug panels: one sync loop, and a component's own panel from its schema** (#744) -- `render()` builds one `flint_debug_ui::PanelCtx` (world, renderer, device, camera, `core.particles.sync`, and a `PanelHost` for what panels tell the player: F4's freeze switch, a look, committed styles, `particles_render_enabled`) and calls `DebugPanel::sync` on every panel; each engine panel's write-through and live mirror is its own `sync` (grass, ocean, camera, particles, styles, Rendering & Effects), so `frame.rs` never compares a panel's name. Columns balance by `DebugPanel::weight()`. **A game's controller gets a panel from its schema**: a field's `panel = "status" | "tune" | "trigger"` (or a table; `flint_schema::panel`, the keys in the book's Debug Panels page) gives every entity carrying the component a `flint_debug_ui::ComponentPanel`, made by `create_component_panels` (`debug_panels.rs`) from the held registry at each scene's panels, sorted by title then entity. No game's component is named in this crate or flint-debug-ui: Float's five panels (`time_of_day`, `weather`, `reality`, `raft_visitor`, `dead_calm`) are schema lines in Float. Tests: `player_app/component_panel_tests.rs` (a game in a `MemorySource` with its own `flint.toml` and `schemas/`), `flint-debug-ui` `component_panel.rs`, `flint-schema` `panel.rs`

## Scenes, input, touch

- **Scene transitions** -- `TransitionPhase` lifecycle with script-driven visuals; `PersistentStore` survives transitions; `GameStateMachine` pushdown automaton, each state a `StateConfig` of `Run`/`Pause` by system name (#727): `flint_runtime::state::{PHYSICS, SCRIPTS, ANIMATION, PARTICLES, AUDIO}`, read as `config.runs(PHYSICS)` in `game_core.rs`, plus each scene subsystem whose file declares a `POLICY` (`living`), which `subsystem::state_machine()` adds for the player and `flint render --scripts` alike; `register_state` errors on any other key and on `rendering`/`transparent`/`"hidden"`, which nothing implements. The frame's events are `GameCore::events` (an `EventBus`): `PhysicsSystem::fixed_update(world, dt, &mut events)` pushes contacts, extensions, style tweens and `fire_event` push directly, `collect_game_events` drains it; a transition drops only contacts (`GameEvent::is_contact`), so a script's event reaches the next scene. Tests: `player_app/event_bus_tests.rs`. `advance_transition` (`transition.rs`) ends Exiting/Entering by itself when `ScriptSystem::can_complete_transition()` is false (no loaded script names `complete_transition` or imports a module: `ScriptInstance::completes_transition`, set at load and hot reload from the AST's `Debug` form, written before every build had Rhai's `internals` (#692); #362): Exiting loads that same frame, and Loading goes straight to Idle. A phase a script could end is ended after `TRANSITION_PHASE_TIMEOUT` (10 s game time) with a warning. Tests: `player_app/transition_tests.rs`
- **`GameCore` and the one frame order** (ADR 0117 decision 4, #725; `player_app/game_core.rs`) -- `PlayerApp::core: GameCore` holds the game with no window: the subsystems (declared first, so they drop first, and the core before `audio`), world, scene path, project, clock, physics, animation, particles, scripts, the state machine, the persistent store (`core.store`; `saves` keeps only when to write it), style tweens and the style reader's generation, the procgen resolver and `script_requests`. `PlayerApp` keeps input, the camera, the window, renderer, audio, HUD/egui, transitions, extensions and debug tools. A frame is `game_core::step(host)`, generic over `FrameHost`: `tick` ticks the clock, plays scripted input, calls `step(self)`, then `finish_frame`. The step runs the stages in order and calls the host back where presentation falls: `before_events` (transition, extensions' `pre_update`), `phase_done` (perf), `window_for_scripts` (transition phase, screen, pointer, cursor, chunks, audio clock, conducted), `listener` (FPS or script camera), `capture`, `refuses`, `host_command` (the dispatcher's), `script_ui_drawn` (HUD draw lists, world lines, world text), `sound` (before animation), `bones_posed`, `sync` (renderer sync, post overrides, quality); every hook but `lend`/`core` defaults to nothing. `lend()` returns the core and a `Lent` (input, camera, renderer and gpu as `Option`s, pixels per point, cursor, `scene_file_writable`, panels): what a stage and its `StageCtx` borrow (`GameCore::with_subsystems(lent, policy, |subsystems, ctx| ..)`). The renderer stays an `Option` in `StageCtx` and `Lent`: a host without one (a test) runs every stage; `frame_inputs`/`post_encode`/`ui` are presentation and only a host with a renderer calls them. A change to the frame order goes in `step`, never in `tick`. Two hosts drive it: the player and `flint render`'s `HeadlessGame` (next bullet but one); `flint playtest` (#714) is the player itself with no window (`player_app/playtest.rs`, below). A game binary reaches `app.core.world`, `app.core.script`, `app.core.clock`...
- **One bring-up** (#723; `player_app/scene_entry.rs`) -- startup (`finish_initialize`) and every transition (`execute_scene_transition`) bring a scene up through `enter_scene(SceneEntry::Start | Transition)`: input bindings, a fresh camera with the scene's `[camera]` over it, fonts, `stage_scene` (the renderer's share: procgen and models, splines, `reset_ambient` then the levers, `clear_skybox` then the scene's, `set_post_process_config(scene_post_config())`, terrain), the scene's debug panels, then physics, audio, animation, particles, scripts (`on_init` in a `state_scope`, then `on_scene_enter` at a transition). `Start` alone installs the text measurer and reads the save file. Settings come from the file through `apply_scene_settings` (every host calls it, and `install_scene` does at a transition), which **replaces** each one: a block the scene doesn't author is the default, never the last scene's. Never add an `if let Some` that only sets: reset first. `scene_post_config()` returns a `PostProcessConfig` (the defaults for no block), not an `Option`. A transition reads its target first (`read_scene`) and tears down only once it has parsed: a failure logs `scene '<target>' failed to load from <path>: <why>`, keeps the scene playing, goes on to `Entering` when a script can call `complete_transition()` (else straight to `Idle`, #362), and sets `scene_failure`, which `run_failure` reports so the binary exits non-zero. Per-scene state a teardown must drop lives in `teardown_current_scene` (style tweens, `post.mode_shim`, world texts...): a new field that names entities or one scene's settings goes there too, unless it belongs to a subsystem, whose `scene_unloading` drops it. Tests: `player_app/scene_entry_tests.rs` (a scene with post, skybox, ambient, ortho camera and input config to one with none, headless and on a `HeadlessContext` handed over as `test_gpu`; a missing target)
- **Save data** (#726; `player_app/persist.rs`, `flint_runtime::persist`, `flint_runtime::atomic_file`) -- the `persist_*` store's place is decided once, in `load_persistent_store` (startup, after the input config, before scripts), as a `SaveFiles` (`SaveFiles::locate(project, scene, input_game_id, save_dir, config_dir)`) installed in the store as its `SaveBackend`; nothing re-derives it at a transition. ## One launch: `flint play` and `flint-player`

- **One set of flags, one launch** (#705; `src/player_args.rs`) -- `flint_player::PlayerArgs` (a clap `Args`) is every flag of the desktop player; `flint play` flattens it whole (`commands/play.rs` holds nothing else), `flint-player` flattens it beside `--bundle` as `flint_player::PlayerCli` (main.rs is `PlayerCli::parse()`, `logging::init(&cli.args.log)`, `.run()`). The web and Android build their `PlayerApp` from their own sources. Tests (flint-cli `commands::play::tests`): the two commands' arguments are the same but `bundle`, id, long and help; a scene with `[environment] shadows = false`, `default_lights = false` and a user style's `[post_process.styles.<x>]` prepares the same through both
- **What the player says: one log, by target** (#716; `src/logging.rs`, `player_app/console.rs`) -- no `println!`/`eprintln!` in the player but `--list-gpus`' answer on stdout (and test code): everything is `tracing` under a short target, `load` (each file a `debug` event with a `kind` field, `count` for one event standing for N; the summary at info), `transition` (scenes, chunks), `perf` (`--perf`'s 10 s line), `report` (the exit report), `script`, `input` (the controls line), `music`, `player` (debug keys, looks, bundles, living tuning). `logging::init(&LogArgs)` (both binaries' `main`; `flint`'s main calls it for `play` only, after parsing) installs one subscriber on stderr: `--log-format text|json` (json: `flatten_event`, one object a line), `--quiet` (`QUIET_FILTER`: warn, `perf`, `report`), `DEFAULT_FILTER` otherwise, `RUST_LOG` over either; ANSI only on a terminal; `try_init`, so the `log` crate's records (flint-animation) arrive too. The load summary: `LoadTally`'s layer (its own `filter_fn`: `load` at every level, warn and error of every target) counts `kind`s and the engine's own warnings (`flint_target`: a `flint*` target or a short one; a library's wgpu or gilrs warning is left out), quoting each one's first line; `enter_scene` ends with `say_loaded` (`installed_tally().take()`: `Loaded <scene>: N entities, 1 model, 15 scripts ... in X ms; no warnings`, fields `scene`, `entities`, `warnings`, `errors`, `ms`) and `say_controls`; `execute_scene_transition` starts with `begin_load_count`. Said again only when it changes (`said_controls`). `flint`'s other commands keep their own subscriber with `load=debug`, so `flint render` still lists every file it loads. Tests: `logging::tests` (JSON lines, quiet, the tally), `console::tests` (a kart config, the Ruins' `pause` + controller, the 2d template's script-read WASD), flint-script `a_string_literal_is_found_in_a_script_and_a_comment_is_not`
- Window flags (#611; `flint_player::WindowArgs`, flattened into `flint play` and `flint-player`, applied in `create_window`): `--width`/`--height` (physical px, default 1280x720, the size is `PlayerApp::window_size`), `--position X,Y` (outer top-left, physical desktop px; negatives as `--position=-1920,0`), `--borderless`, `--always-on-top`, `--no-activate` (opens without taking the keyboard, `with_active(false)`; refuses `--fullscreen`, since winit's fullscreen path on Windows presses Alt to take the foreground). ## Capture, perf, pacing

- **Script commands: one dispatcher, the core's** (ADR 0116 decision 4, #697; #725) -- `game_core::dispatch(host)` drains the scripts' commands twice a frame (after the physics steps: what `on_update` asked, so the camera is set before `on_draw_ui`, style tweens stepping just before; and after `on_draw_ui`). In order: `FrameHost::refuses` drops what the host won't do (a capture's `PRESENTATION_ONLY`), each subsystem's `script_command` takes its own (`ScriptCommand::Module` with a `LivingCommand` payload: living, wooze, debug), then each command goes through `flint_script::host::apply` (the one `match`; recipe for a new command: `crates/flint-script/CLAUDE.md`) either to `CoreCommands` (`game_core.rs`: events, particles, entity styles and tweens, post styles and style history on the lent renderer, the frame requests, time scale, states, 2D velocity, and `module_command`, a module command whose subsystem went with its scene) or, when `game_core::for_the_host` says it's the presentation's (sound, rumble, camera-cut detection, `set_look`, `set_quality`, `reset_post_style`, scenes, chunks, quit, `transition_complete`), to `FrameHost::host_command`: `impl ScriptHost for PlayerApp` (`script_commands.rs`) holds only those. A new command that changes the game goes in `CoreCommands`; one that is the window's goes in `for_the_host` and each host. The one-value-a-frame requests (`SetCamera`, `SetPostProcess`, `SetFogColor`, `SetRenderMode`, `SetLodScales`, `SetAudioLowpass`, `SetTouchControls`, `SetCursorCaptured`) wait in `core.script_requests` for the step that applies each; `SetQuality` in `quality.script_request`. **The headless host** is `HeadlessGame` (`headless_game.rs`, what `flint render` steps): a `GameCore` and `CaptureFrame`, its `FrameHost` for a step (`capture()` true: no physics, the core's animation and IK skipped for `--anim-time`'s `HeadlessAnimation`, stepped in `bones_posed`, particles stepped by the stage on their fixed step, state changes to the log, not stdout). It refuses `PRESENTATION_ONLY` (`Skipped { command, why }`; `why: None` is dropped without a note: sound, low-pass, cursor, touch) and particle commands while the capture draws none, noting each once (`notes()`); takes `set_look` as a request the stage lays at capture (`take_look_request`), `set_quality` at once, the post overrides into `look()` at its `sync`, and the distance levers onto the renderer there. Living props run in the player's `LivingSubsystem`, built by `for_capture(field, moment)` (`capture: Some(Capture)`: poses made at once by `step_living_now`, blended at capture by `upload_living`, shallow wooze only in a moment); `boil`, `apply_grass`, `wooze` and `living_props` read it. `headless_host_tests.rs` holds every variant to done or on the list
- **The live world, asked** (#713; `player_app/inspect.rs`, `world_dump.rs`, `loopback.rs`) -- two run subsystems (`Lasts::Run`, handed over from `LaunchOptions::inspect` / `world_dump` in `subsystems_build` at `Start`, desktop only), both reading the world at `Stage::Sync` (after scripts, physics, animation, procgen; before `render`'s `--exit-after` check, so a dump at the exit time is the last world). A frame counter lives in each subsystem (GameClock has none). Both say what they do under the `tracing` target `inspect` (`[inspect] listening on ...`, `[dump] <file> at t=..`), which `DEFAULT_FILTER` and `QUIET_FILTER` both keep (#716's one log). Tests: the three modules' own
- **`HeadlessAnimation`** (#307, `player_app/headless_animation.rs`) -- the player's animation load (`register_skeletal_data`, node clips, `.anim.toml`, sprite clips, sequences: each loader has a `_saying` form that hands its lines to a closure instead of stdout, which `flint render --report json` keeps for JSON) and the animation share of a frame (`update`, `publish_bone_probes`, `run_ik`), on a clock the caller keeps; `flint render --anim-time`. `publish_bone_probes` is the player's own, moved out of `frame.rs`. The second group is on it too: scripts (`load_scripts_from_world(&project, ..)`; a chunk's through `ScriptSystem::load_script_named` from the chunk's folder then the scene's, with its own TEMPORARY old-rule compare in `transition.rs`), specs (`procgen_assets::discover_specs(resolver, &project, scene)` indexes `project.list(AssetKind::Specs, ..)`, one file a `[meta] name`, the nearest; `resolve_scene` takes the project from the sink's `ModelLoadConfig`; `spec_dirs` is gone), wooze presets (`flint_procgen::list_presets_in` / `write_preset_in` with `self.project`; `find_preset` discovers it from the scene), the input config's game layer (`input_config::resolve_input_paths(&project, ..)`: the scene's `input_config`, else the manifest's `[project] input` from the root, else `config/input.toml`, the first and last through `AssetKind::Files`), the skybox, terrain heightmap and splat map, grass mask and spline files (`Project::file_or_beside`; the free loaders `load_terrain`, `load_scene_grass_ground` and `flint_render::load_scene_splines` (#750; the player registers its colliders) discover the project from the scene path rather than take one), particle textures (`flint_render::load_scene_particle_textures`) and a transition's target (`resolve_scene_path(&project, current, target)`, `AssetKind::Scenes`; a target the search doesn't find is returned as written, a path from the working directory, and only then warned about if that isn't there either). Still on guesses of their own, deliberately: fonts and the style assets (next), `procgen_disk_config`'s root, `persist.rs`'s root, `music_session`'s base directory (the scene directory's parent) and `.flint/input.user.toml` beside the scene. **Paths from the project root** (#706, the last step): the save file (`persist.rs`), the procgen disk cache (`init.rs::procgen_disk_config`), `music_session`'s base (`music::base_dir`) and the project-local input override all ask `self.project.root_for(scene_dir)`; never derive a root from `scene_path` (`flint_core::project::guessed_root` is the one copy of that guess, see `crates/flint-core/CLAUDE.md`). `flint-player` with no scene opens `Project::default_scene()`
- **The schema registry is read once and kept** (ADR 0115, #683; `player_app/schemas.rs`, `HeldSchemas`) -- a host hands over the registry it loaded the first scene with: `app.set_schemas(registry, schema_dirs)` (`flint-player`, `flint play`, the web player, whose registry is the compiled-in engine schemas under the bundle's). `load_chunk` uses it as it is (`held_or_read`); a transition asks `schema_dirs.for_scene(next)` as before and then `HeldSchemas::for_dirs`: the same directory list is no read, a list that grew (a discovered or host list) loads only the added directories over a clone of what is held, and another list (another project's manifest) is read whole. **A read that fails logs an error and returns the registry held**, so a scene never loads with an empty one (it used to: `schemas_for_scene` fell back to `SchemaRegistry::new()` and archetype and schema defaults vanished). `set_schema_dirs` / `set_schema_paths` alone (an embedding game) still work: the directories are read on first use, once. Consequence: a schema file edited while the game runs is not seen by the next transition. Scene diagnostics at load come from `flint_scene::load_scene` itself (one summary line and the first five through `tracing::warn!`, at start and at each transition) and from `load_chunk` for a chunk; nothing in the player calls `diagnose` directly
