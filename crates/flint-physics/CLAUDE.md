# flint-physics: joints (moved out of the root CLAUDE.md by #755)

The Rapier version gotcha and the fixed timestep are in the root file. The character controller's split between the frame (look, jump press) and the fixed step (walk, fall), and its starting facing (`start_yaw`): `crates/flint-player/CLAUDE.md`.

- **Physics joints** (ADR 0069) -- `joint` component (hinge/prismatic/spherical/fixed) on a dynamic entity, attached to `joint.parent` or the transform parent. Bodies are placed from `get_world_matrix` (rigid: scale is the collider's, next bullet) and dynamic poses write back as local `position` + `rotation_quat`, divided by the parent's world scale; a joint's `anchor` stays metres along the child's axes, unscaled (scenes are written that way: motion_hold's bobs), and a scaled jointed body is warned once (`joint_scale_warned`). TOML units are degrees/metres, converted to Rapier radians at sync. Scripts drive `motor_target` via `set_joint_target` and pose rest-quaternion nodes with `rotate_local` / `set_rotation_quat` (`set_rotation` still deletes the quaternion). Bench: `flint-examples/joint_test.scene.toml`
- **Scale, layers, mesh shapes, the reverse map** (#729; `sync.rs` `collider_shape`, `mesh_shape`, `groups_of`; `layers.rs`; tests `layer_tests.rs`) -- **Scale**: `world_scale` (the world matrix's axis lengths, `unit_snapped` so an unscaled rotated entity is exactly 1 and keeps its old bits) multiplies `size`, `offset` and the bounds centre; exact for any shape when uniform, else for an unrotated box, a capsule/cylinder with x == z, and mesh/convex; otherwise one `tracing::warn!` per entity (`shape_warned`) naming what it took. Shapes are made once with the body; a later `set_scale` doesn't resize them. **Layers**: `CollisionLayers` (`default` is bit 0, then the project's `[project.physics] layers`, `Project::physics_layers` in flint-core, at most 31 more), set by the host with `set_layers` before `initialize` and kept by `clear`. Every collider gets `collision_groups(groups_of(col))`: membership = `collider.layer` (`col.choice` over the names, so an unknown one is `bad-enum-value` and reads `default`), filter = `collider.mask` (every layer when unsaid; an unknown entry is reported as `mask[i]` and left out). No layer and no mask is `(GROUP_1, ALL)`, which meets everything as `all()/all()` did. Host trimeshes (terrain, splines) go in on `default` and take their entity's `collider` layer at the next `sync_to_rapier` (`trimesh_pending`). Queries: `LayerMask::query_groups` is `(ALL, mask)`, so a ray meets colliders on its mask whatever their own masks; `raycast_masked`, `move_character_masked` (default: the collider's own groups, which the character controller uses too). **Mesh/convex**: physics reads no files; `PhysicsSystem::collider_mesh_requests(world)` lists `(entity, collider.model or model.asset)`, the host hands `Arc<ColliderMesh>` over with `set_collider_mesh` before the bodies are made, and `mesh_shape` bakes `collider.rotation`, `offset` and the scale into the points, cached in `mesh_shapes` by (Arc address, convex, bits). A dynamic body's `mesh` is made convex (Rapier has no trimesh-trimesh contacts), with a `needs-component` warning; no triangles, or none that make a shape, is a box of `size` with a warning. The player's side is `player_app/collider_meshes.rs` (requests read before `stage_scene`, since model expansion removes the parent's `model`; `flint_import::import_gltf_geometry` skips the textures; `ImportResult::triangles()` places the nodes and keeps the nearest LOD). **Reverse map**: `collider_entity` beside `collider_map`, kept by `insert_collider` / `remove_collider`; contacts, rays and `overlap_rect` use `entity_of`, never a scan. Heightfield colliders are not done (terrain is still a trimesh)
- **Components are read through the typed view** (ADR 0115 step 4, #685; the view itself: `crates/flint-core/CLAUDE.md`) -- `rigidbody`, `collider`, `joint`, `character_controller` via `world.view(id, comp::X)`; the allowed strings are `sync::BODY_TYPES` (`static`, `dynamic`, `kinematic`, `kinematic_position`, `kinematic_velocity`), `COLLIDER_SHAPES`, `JOINT_TYPES` (with the `slider` / `ball` aliases). An unknown one is reported once and takes the default it always took (static, box, hinge). **The defaults in these readers are the real ones**: the schema files for these components write fields under `[component.x]` with no `.fields`, so they load with no fields and their defaults are never applied; where the two differ (`rigidbody.angular_damping` reader 0.0 / schema 0.05; eye height with no `character_controller.height` reader 1.5 / schema 1.8 * 0.85 = 1.53; the schema's `body_type` values lack the two `kinematic_*` spellings) the reader's stands until someone decides. `bounds` (`compute_bounds_center`) and `sprite` (`sprite_anchor_offset_y(world, id)`) go through the view too since #802. **A collider with no rigidbody** is never given to Rapier (`sync_to_rapier` loops over `rigidbody`); `report_lone_colliders` says so (`needs-component`) the second pass it sees one, so a script adding the two a step apart is not told off. Terrain and spline trimeshes are in `synced_entities` and are skipped. `flint_scene::diagnose` says it before the game runs too (`lone_collider`, #804: a `collider` written or from the archetype, no `rigidbody`, no `terrain` or `spline_mesh`), so `flint validate` and the load summary carry it; keep the two messages the same. Tests: `lib.rs` (`an_unknown_body_type_warns...`, `a_collider_without_a_rigidbody_warns_once`, `an_integer_move_speed_moves_at_that_speed`, which walks a character for a second)
- **Navigation** (ADR 0130, #969; `nav.rs`, tests `nav_tests.rs`, cost `nav_cost` `--ignored`) -- `NavGrid::new(NavSettings)` (`validate` first: `cell` under the agent's diameter) answers `find_path(&physics, from, to) -> Option<Vec<[f32; 3]>>` and `nearest_floor`. Columns `cell` square from the world origin, each a list of floor heights (`Tile`: 16 x 16, `heights` + `start` offsets), baked when a search first reaches the tile by `bake_column`: a ray down from over the fixed colliders' bounds, `solid = false`, on from 0.01 under each hit (a ray from inside a solid meets its underside, which faces down); a hit is a floor when its normal is within `max_slope_deg` and `has_room` (a cylinder of the radius from `lift` up, and a thin core from just over the floor, which catches a floor met from inside a solid and a low beam). Queries go through the grid's **own** `QueryPipeline` (`refresh` rebuilds it from the collider set), so a grid works before the first step, and through `QueryFilter::only_fixed().exclude_sensors()`: doors, lifts and agents aren't on it. **`PhysicsWorld::static_generation`** (process-wide counter, bumped by `insert_collider_with_parent` / `remove_rigid_body` / `remove_collider` on a fixed body and by `update_sensor_flags` turning a fixed collider sensor) is what `refresh` compares; never a count. A\* (`search`) over `Node { ix, iz, level }`, ties broken by node so a path is the same every run, bounded by `max_nodes`; `pull_straight` two passes over `walkable_line`, which also holds a leg's height within `FOLLOW` (0.1 m) of the floor, so a path bends at a ramp's foot and top. A test's own `sys.raycast` sees nothing until a `fixed_update` has updated Rapier's pipeline: `nav_tests::ready` steps once. The script side is `flint-script/src/api/nav.rs`
